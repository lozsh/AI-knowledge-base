    智能体总览

    更新于 2026-11-05

    一句话定义：智能体是"从会说话到会行动"的系统——以 LLM 为大脑，靠驾驶舱（Harness）把记忆、工具、规划、反馈组织成可观察-思考-行动-反馈的闭环；它正沿三条前线扩展：接上世界（工具/浏览器/桌面）、在时间里持续行动（记忆/规划/协作/自我改进）、走进物理与科学世界（具身智能 / AI for Science）。

    智能体成为现实的三个汇合条件：基础模型具备通用语言理解与局部推理；外部世界以 API/网页/文档/软件界面形式暴露为可访问接口；推断成本降低、工具生态成熟。大模型的价值在于把"写死规则"替换为"在开放状态空间里做近似判断"，让原本只有人类能接住的灰色地带变成可处理的区域。但今天只是"能力阈值刚被跨过"——脆弱性、评测困难和治理难题仍非常明显。

    核心概念

    闭环与三大代表范式

    闭环四步：观察 → 思考 → 行动 → 反馈。与纯对话的本质差别：智能体在与外部世界反复交互，正确性既看"说得对不对"，更看"上一步有没有把状态推进到目标附近"。决定能力的不是推理强弱，而是闭环能否稳定——观察粒度、动作接口、反馈可验证性。

    三种闭环实现范式（同一闭环在不同约束下的变体，产品中常同时存在）： - ReAct（2022-10）：推理痕迹与动作交替生成，想一步做一步，最贴近原始定义。 - ReWOO（2023-05）：把规划与外部观察解耦——先一次性写出整套计划（工具与变量），再分别执行，降低重复上下文、便于小模型执行子步、工具失败时更鲁棒。 - CodeAct（2024-02）：动作统一为可执行 Python 代码，可组合多工具、保留中间变量、动态修改方案——解释了代码为何成为智能体行动的通用中介。

    核心公式：Agent = LLM + 上下文 + 工具 + Harness

    现代 AI Agent 的最小公式是 Agent = LLM（大脑）+ 上下文（眼睛）+ 工具（手脚），三个组件恰好对应强化学习的概念：

    直觉 组件 RL 学术概念 职责
    大脑 LLM 策略（Policy） 理解意图、思考规划、决定下一步
    眼睛 上下文 观察空间（Observation Space） 决策点能看到的一切信息
    手脚 工具 动作空间（Action Space） 能做的所有事情的集合

    要让它从能跑的 Demo 变成可靠的产品，还需在模型之外加上约束、验证、纠正三层工程外壳，即扩展公式：

    Agent = LLM + [上下文 + 工具 + 约束 + 验证 + 纠正] = Model + Harness

    最小公式是 Demo 视角，扩展公式是生产视角。三层保障各有一条核心原则： - 约束（Constrain）：划定行为边界。核心原则"故障安全默认值"——能力默认关闭，显式开放（类似手机 App 权限）。 - 验证（Verify）：自动判断操作对错。核心原则"输入隔离"——安全检查只看结构化数据而非模型自由文本（防提示注入）。 - 纠正（Correct）：失败时自动修正/回退。核心原则"确认无法恢复前不暴露中间态"——先静默重试，连续失败熔断转人工。

    例：上下文嵌入退款政策属"上下文"；校验退款金额不超订单金额属"约束"；API 超时自动重试属"纠正"。Claude Code 的 Harness 绝大部分代码是约束/验证/纠正（流程状态管理、多层上下文压缩、权限分类、熔断器、错误恢复），工具本身只占一小部分。

    上下文的组成与轨迹（API 视角）

    • 系统提示词（静态）：开发者的"岗位说明书"，定义身份、权限、行为准则；含跨会话用户记忆与动态环境状态。
    • 工具定义（静态）：名称、功能描述、参数格式；与系统提示词构成静态前缀。
    • 用户消息（动态）：可能含 RAG 检索引入的外部知识。
    • 模型回复（动态）：最多含 reasoning（思考链）+ content（回复文本）+ tool_calls（工具调用请求）三部分，一次回复中不必然同时出现。
    • 工具执行结果（动态）：闭环控制的直接依据。

    关键事实：上下文 = 静态前缀 + 轨迹（trajectory，动态消息历史）。消融实验结论：去掉工具定义 → 完全丧失行动能力；去掉工具结果 → 反复调用同一工具、盲目循环；剥离 reasoning → 前后决策矛盾；去掉历史 → "失忆"、重复执行已完成步骤。

    ReAct 循环（想 → 做 → 看）每轮都把结果追加进轨迹，每次 LLM 调用都能看到完整轨迹——这带来上下文累积性与结构化可解释性。轨迹数据可用于分析行为模式、沉淀知识库，甚至经强化学习训练更好的模型。

    工作流 vs 智能体

    工作流是预定义步骤（每步做什么、先后顺序由人写死，模型只做局部执行器）；智能体根据环境变化做条件性决策（"边看边改"）。两者不对立：最稳定的做法是"工作流包住智能体"——高风险强约束部分做明确流程，局部适应探索交给智能体。结构化约束本身就是可靠性的来源。选择原则是"从简单到复杂"：先优化单次 LLM 调用 → 固定子任务用工作流 → 需要动态决策才用自主 Agent。自主 Agent 本质是"在循环中使用工具的 LLM"，必须有明确停止条件（任务完成 / 无工具调用返回 / 最大轮次 / 错误超限）。实践中常混合：合规关键流程走工作流，灵活部分走自主。

    把任务定义清楚（智能体设计的地基）

    • 任务/环境/状态：任务规定目标，环境规定可观察对象与可执行动作，状态记录已发生什么、还剩什么。很多"智能体不稳定"根子在任务定义、环境接口和状态表示没设计清楚，而非模型不聪明。
    • 部分可观测与状态歧义：输入里没写出来的部分恰恰决定行动后果（按钮为什么灰？报错指向参数还是依赖服务？）。成熟智能体要为"确认"本身留预算——拿不准就补观测、换信息源，而不是把猜测写进状态往下走。
    • 目标澄清与成功判据：评价重心从"回答得像不像"变为"任务算不算完成"。执行前先追问澄清：交付物是什么、哪些约束必须满足、哪些风险动作需人工确认。目标要从抽象愿望变成可检查的终态。
    • 自主性分层与授权：自主性不是单一开关，从人主导模型建议，到受限环境自动完成短流程，到长链条独立推进。分界线朴素：可回滚、有自动校验的放手，支付/删除/对外发布保留人工确认。授权逐层声明（读取/写入/支付/外发/再委托），退出机制同样重要（连续失败暂停、预算耗去八成回人工、越权即交还控制权）。
    • 可逆动作优先：不确定性高时优先做可逆动作（检索、读取、沙箱试跑），把不可逆动作推迟到证据和目标更清晰之后——越早进入不可逆状态，修正代价越高。

    预算、失败与可验证性

    • 预算意识：行动带时间/成本/工具预算。不同工具代价结构不同（token、API 费用、人工审批时间、下游配额），要区分哪些适合频繁探索、哪些只能在证据充分时触发。很多"能力问题"其实是预算分配问题。
    • 失败方式：观察错误（读错页面、把局部当全局）、计划错误（拆解不合理）、行动失败（参数错、点错按钮、误覆盖）、伪成功（流程完整、解释充分，实际没完成任务）——最危险，因为人会把"看起来做完了"误当"真的做完了"。
    • 可验证性：系统要在追求"看起来很会"与追求"可被验证"之间选后者——搜索可看日志、改文件可看 diff、提交可看页面状态、测试可看结果。评测因此从最终答案扩展到整条轨迹（走了几步、何时走偏、有无自我修正、有无绕过约束）。

    核心原理

    驾驶舱（Harness）与组件

    智能体基本组成：模型核心 + 环境接口（工具/检索/浏览器/终端）+ 状态与记忆模块 + 执行控制层（循环、超时、重试、停止条件、异常处理）+ 评审与约束模块。驾驶舱六职责：循环控制、工具调度、上下文管理、安全检查、记忆管理、日志与回放。驾驶舱是工程不是算法：同一模型套编程驾驶舱是代码助手、套浏览器驾驶舱是网页操作员。业界共识：决定智能体好不好用的往往是驾驶舱成熟度而非底层模型。驾驶舱同时是责任边界——谁提目标、谁授权、谁复核、谁收尾；没有责任边界的驾驶舱进不了高价值流程。

    驾驶舱之上是可复用技能（Skills）：把做某类任务的完整套路（说明、脚本、模板、检查清单）打包成目录，按需加载。比喻：工具是锅铲、协议是水电、技能是菜谱。

    推断负载的特殊性：智能体调用碎片化——短而频繁的决策调用、结构化输出（超时几百毫秒就影响整条链）、工具等待让 GPU 计算与外部 I/O 交错、强弱模型混用。推断系统因此成为"多级推断运行时"，优化目标是任务闭环效率而非单次生成速度。

    工具与环境（接口层）

    • 工具五分类（按互动方向）：感知工具（访问信息：搜索引擎、文件系统、API/数据库）、执行工具（改变世界：代码执行、文件操作、系统命令）、协作工具（与其他 Agent 分工、请求人类确认）、事件触发工具（非 Agent 主动调用，由外部输入驱动启动：新邮件、定时点、Webhook）、用户沟通工具（主动向用户传递进展：消息、语音、邮件）。工具调用四步：上下文声明工具 → 模型自主决定是否调用/调哪个/传什么参数 → 工具结果追加到上下文 → 模型决定下一步。设计原则：工具保持通用性（提供 Python 代码解释器优于专用计算器；提供文件读写优于专用日志工具），让 Agent 组合基础能力创造性地解决问题。
    • 函数调用演进：从 JSON Schema 声明 → 通用"工具"与多调用 → 结构化输出硬约束 → 统一进完整 Agent API。工具能力不会自动提升可靠性——工具越多错误类型越多（调错工具、参数错、顺序颠倒、重复执行）。
    • MCP 与两种先例的区别：Function Calling 解决"这一次对话里能用什么工具"（生命周期绑单次请求）；OpenAPI/GraphQL 给程序员描述 Web API（缺权限/副作用/示例语义）；MCP（Anthropic 2024-11）是客户端-服务器协议，server 持续暴露 tools/resources/prompts 三类资产，解决"长期运行的工具生态被多个模型应用共享接入"。三者回答不同时间尺度的问题，不互斥。
    • Skill 与 MCP：判断力与能力两条路：MCP 解决"连到哪里去"，Skill 解决"该按什么流程做"——访问不到资源缺 MCP，不知道怎么做缺 Skill。
    维度 Skill（技能） MCP
    本质 含 SKILL.md 的文件夹 + 可选脚本/资源 MCP server（本地 stdio，远程 Streamable HTTP）
    交付方式 做法说明按需加载进上下文 把外部工具/资源暴露为运行时接口
    状态 无状态 可有状态（认证、session、连接）
    部署成本 一个 .md 文件随仓库提交 要写服务、启动、管理进程
    典型场景 团队代码规范、code review 流程 GitHub、Slack、数据库、浏览器

    技能 = 指令（自然语言操作手册）+ 代码（只在需要精确执行处）+ 资源（模板、风格指南等隐性知识载体）。工具告诉智能体"你能做什么"，技能告诉它"该怎么做"——工具是能力，技能是经验。技能还让非程序员也能"教"智能体：Markdown 指令 + 模板即成技能，各行业专家可沉淀经验；软件形态正从"功能按钮"转向"可复用的工作流"。最佳实践是两者并用：MCP 接数据库（能力），Skill 教公司的数据模型与查询规范（判断力）。 - 工具检索：工具上百后要像文档一样建索引——描述语义检索（坑：描述敷衍、风格差异大、用例分布偏移）、两阶段检索、工具图谱检索、基于轨迹的检索。工具库需统一描述格式（schema/副作用声明/权限/失败模式）、分类层级、版本管理、执行沙箱、监控配额。 - RAG 与检索质量：朴素 RAG 两步走（向量检索 Top-k → 拼提示生成），解决知识时效性与私有性。真正瓶颈在检索工程：切块粒度决定检索精度（按语义边界切，别按字数；递归/语义/晚切块/Anthropic 上下文检索）；嵌入模型质量决定"相关"判定（"订购产品"与"取消订单"向量可能很近但意图相反，靠重排/领域微调补救）；纯向量对精确字符串弱（"2024-Q3"与"Q4"向量几乎一样，需 BM25/元数据/混合检索兜底）；混合检索（BM25+稠密嵌入 + RRF/reranker 融合，企业默认配方）、reranker 标配（召回 100-500 → 精排 5-10）、多向量检索（ColBERT late interaction）；文档质量决定上限。幻觉形态从"模型胡编"变为"基于错误资料回答"或"资料没有模型补脑"——强制引用来源是基本防线。Agentic RAG：检索纳入决策闭环，判断搜什么、何时停、证据够不够；工程重点从"召回几个片段"转向"管理一次调查"（记录检索意图、被舍弃证据、冲突来源、停止理由）。 - 浏览器/终端/桌面与 ACI：真实任务多活在脏乱的 GUI 世界（状态不结构化、反馈不即时）。Computer Use（整台电脑）与 Browser Use（网页任务）是同一问题切在不同边界，未来更可能是混合型。ACI（Agent-Computer Interface）：把人机界面改造成机机界面——降低歧义、暴露关键信息、提供可验证反馈、缩小动作空间；GUI grounding 是持续状态感知问题（把视觉元素与语义动作对应），不是识别一次就完事。 - 安全接口工程：沙箱三级隔离（进程级 → 容器/微 VM → 虚拟机，分层防御）；警惕沙箱逃逸（写共享日志、临时目录后门）。幂等性：模型可能因网络抖动/状态误读重复发起动作，接口要区分预览/执行/确认/提交，写操作带请求标识。最小授权：权限划定错误最大扩散范围——只读低风险先给，关键动作前申请短时权限；临时凭证把风险压缩在时间窗内；执行会话把资源/配额/审计绑定在同一边界。观测接口与差分反馈：既暴露命令也暴露可验证状态（元素树、diff、版本号、错误码），返回"什么变了"而非全部状态。 - 护栏三位置：输入侧（相关性分类器、安全分类器、内容审核、规则保护；注意越狱 = 用户自己绕过限制，提示注入 = 攻击者借外部数据间接操纵，二者不同）、执行侧（工具风险评级：按可逆性、权限等级、财务影响分低/中/高，高风险需人工确认）、输出侧（PII 过滤、品牌一致性验证）。工业实践如 Constitutional Classifiers：用自然语言"宪法"生成合成数据训练分类器、上下文联合判断（提问与回答放一起检查）、两级筛查（轻量探针全量初筛，可疑才交强分类器复审）。人工干预（Human in the loop）触发条件：超过失败阈值（重试/操作次数上限）、高风险不可逆操作（取消订单、大额退款）。

    记忆、规划与执行（状态层）

    • 上下文不是记忆：上下文窗口只是临时工作台——容量有限、信息平铺、"看得到"不等于"记得住、用得对"。记忆越相关才越有用，堆量反而拖累检索。
    • 记忆层次：工作记忆（本轮决策即时所需）→ 长期记忆（跨任务经验与事实）→ 外部记忆（数据库/向量库/文件，可查询可审计可更新）。显式记忆（参数外存储，明确可审计可迁移可编辑）vs 隐式记忆（编码进权重，调用便宜但不可解释不可删除）。工业实践：稳定低风险长期复用的（风格、术语）走隐式，动态敏感需审计的（用户档案、合同）走显式。
    • 写入、遗忘与压缩：记忆写入是面向未来使用场景的整理（稳定事实长期保留 / 中间状态放短期 / 猜测带低置信标记）；会忘和会记一样重要（版本化、过期、显式更新规则）。环境抽象层把原始观测压缩成任务状态（"测试在第三个模块失败""证据还缺两条"），压缩强弱要按任务节奏调整。
    • 规划与执行：任务分解 → 计划应分层（高层里程碑方向、低层按局部反馈补全）且带可验证里程碑（找到三条独立证据、生成可运行补丁，而非"继续调查"）。常用规划方法：Plan-and-Execute（先列大纲再逐节执行）、递归分解（层层剥洋葱）、搜索式规划（多路径评估择优；未必在模型内部，也可在外层驾驶舱做多候选采样验证）。计划监控持续检查目标成立与否、里程碑推进、是否重复低收益动作；节奏分层（局部步骤保持流动，阶段切换点/成本陡增点/风险上升点主动触发校验）。ReAct 交替执行的真正价值：把不确定性留给环境去消解；但需配合停止条件、检查点和回溯，否则表面忙碌实际低效。
    • 失败恢复：重试 → 回滚与检查点（关键节点保存可恢复快照：当前工作区、关键变量、已执行副作用、待办、回滚方式）→ 停止条件（完成信号、失败次数、成本/时间上限、风险等级综合）。
    • 反思与自我改进三层：Self-Refine（自优化：生成→反馈→修订循环，无需训练；若模型能力不足以识别错误，会把对的改错）；Reflexion（把语言反思写入外部经验笔记/情景记忆，下次读回，不改权重）；自进化三层路径——经验积累（工作日记）→ 技能提炼（反复做对的流程固化为技能）→ 自我微调（最激进，需防错误自我强化、灾难性遗忘、成本，工业部署仍少）。Generator-Evaluator 分离：模型很难可靠评估自己的输出（系统性偏宽），把生成与评估拆给不同角色、以白纸黑字的判据约束——创意可能不是来自模型更聪明，而来自评估侧持续不让步。

    多智能体协作

    • 何时需要：多智能体不是默认升级版。任务天然可分解、交付物可分段验收、协作成本换得来更高可靠性时才值得；否则单智能体更便宜更易调试。常见误区是过早把问题切得太碎。
    • 通信结构四种：链式（稳定但线性不可回头）、广播（并行评审但需仲裁）、层级（责任清晰但经理是瓶颈）、对等（最灵活最易乱）。实践中混合使用。
    • 交接协议：角色间传递"工作包"（任务目标、当前阶段、证据引用、未决问题、置信度、风险标记、建议动作），像接口契约与交班记录；"结构化要点 + 可回看原始证据"双轨保留。对话历史膨胀的对策：压缩、角色化过滤、结构化交付物、摘要+详情双轨。
    • 共享事实底座与版本控制：不同角色必须围绕同一份"事实"工作（结构化文档/任务面板/证据表/版本化工作区），否则会出现"研究员基于旧证据分析、执行者按新约束行动"的分裂；多智能体越往生产走越像在做轻量版本控制。
    • 收口机制：多智能体最怕责任边界模糊——谁决定结束、谁裁决冲突、谁维护状态必须明确指定。仲裁规则、终止条件、分歧升级路径（局部复核 → 仲裁角色 → 人工）都要结构化。没有收口点的协作会从"认真讨论"滑向"无限循环"。
    • 局部最优与组织韧性：每个角色优化自己的局部目标（检索求多、评审求严、执行求快），叠加起来可能整体失败——需共享全局成功判据。瓶颈角色会让名义多智能体实际收缩为单点；成熟系统考虑替补/分片/降级路径。任务切片是接口设计问题：切太粗难接手，切太细耗在交接同步里。
    • 人机介入四深度：监督（只看结果）→ 审核（关键步骤人工确认）→ 交互（持续反馈迭代）→ 协同（同工件互补）。
    • 长任务训练要点：轨迹数据是新基础数据形态（观察/动作/参数/返回/状态变化/人工接管点都要保留，不能压成事后总结）。PPO 的剪切项强制新旧策略小步改进，防"数据分布漂移"导致学崩；奖励作弊（reward hacking）是最大坑——优化"测试通过率"就硬编码期望值，对策：稀疏/稠密奖励取舍、奖励塑形、分层奖励、RLHF（但人类偏好本身有偏差）。

    训练、评测与系统工程（从演示到生产）

    • 模型即 Agent（Model as Agent）与三种学习范式：先进模型通过后训练（尤其 RL）把工具调用决策内化为原生能力——何时调用、调哪个、传什么参数由模型自决，无需人工编排。但要分清归属：RL 内化的是决策策略（"用不用、怎么用"），工具本身及执行（web_search、代码沙盒）仍在模型之外的基础设施里；编排循环没有消失，只是从客户端移到了服务端。智能体的三种学习范式：后训练（训练时 RL 修改模型权重，永久通用、成本高更新慢）、上下文学习 ICL（推理时注意力做模式检索式适配，快至毫秒但临时、会话结束即失——本质是模式匹配而非真学习，能套用已见过的模式、不能发现全新规律）、外部化学习（运行时固化为知识库 + 可执行工具代码，持久、可更新、可验证）。基座方面，最成功的智能体场景都离不开代码——合格基座要擅长严格遵循格式（工具调用）、长程推理、写改代码、错误中恢复；不擅长代码的模型做智能体"像不会看地图的人送外卖"。
    • 训练三步与工程范式演进：针对任务的后训练按 SFT（喂高质量智能体轨迹学"做事的样子"）→ 强化学习（模拟环境跑真实任务按结果给奖励，学长程目标导向；开放任务的奖励设计本身是研究问题）→ 工具使用训练（见过大量调用/错误/组合样本，知道"锤子不是拿来拧螺丝的"）三步展开。智能体产品 = 合格的基座模型 + 精心设计的驾驶舱 + 针对任务的后训练，缺一不可。工程范式则层层包含而非替代：软件工程 → 提示工程（优化指令）→ 上下文工程（系统性管理模型能看到的一切）→ Harness 工程（模型所在系统的全部基础设施）→ Loop 工程（跨轮次持续自主运转：谁发现下一件事、何时验证、何时算完成）。模型能力趋同后，竞争优势转移到模型之外的工程实践：仅靠 Harness 改进（自动检查执行结果、检测重复循环、优化思考策略）就能把 Terminal Bench 2.0 成绩从 52.8% 提到 66.5%，模型未变。与"苦涩的教训"的关系：方向认同（模型会持续"吃掉"Harness——工具调用、长程规划已从外部编排变成原生能力），节奏务实（训练以月计，模型无法一次内化所有业务约束；模型此刻的能力边界就是 Harness 此刻的价值——模型做不稳的先补上，模型每内化一层就卸下一层）。
    • 轨迹是共同语言：训练、评测、排障、复盘共用——高质量轨迹含任务目标、环境状态、工具调用与返回、模型决策、人工接管点、最终结果；成功轨迹给可模仿路径，失败轨迹暴露边界与难例。训练路径：模仿学习打底 → 规则/奖励模型筛选排序 → 受控环境探索（沙箱、只读、可回滚是安全前提）。
    • 评测：任务成功率之外还要看轨迹质量（路径合理性、证据链、是否走回头路）；基准各覆盖不同切面（WebArena 网页、SWE-bench 代码、OSWorld 桌面、GAIA 通用助手）。任务画像分层：按步数、工具依赖、写权限、可逆性、人工需求分箱——80% 低风险任务成功率 95% 很漂亮，跨币种/改旧表那 5% 可能只有 50%，均值掩盖关键退化。评测集三层：稳定回归集（旧能力不退化）、滚动更新集（跟环境漂移）、高风险难例集（越权、误删、状态污染）。评判器本身也要校准：标注协议先写清"什么叫成功"；模型裁判不能直接当客观真理，分层评判（规则可判的交给程序，策略合理性交人工，分歧进仲裁池）。
    • 概率复合视角：每步成功率 95%，50 步后整体仅约 7.7%——可靠性是智能体工程最大瓶颈；检查点、反思、人在环都是打破指数衰减的机制。
    • 发布与运营：离线分好不等于线上好，发布判据是一组门槛清单（离线回归不退化、难例集事故级错误零次、影子运行差异率不上升、接管率/成本/高风险动作频率达标，任一不达标即拦下）。部署路径：离线回放 → 沙箱 → 影子运行（看它会怎么做但不真做）→ 灰度放量，分级授权绑定（读操作早开放，写/支付/删改晚开放）。运营闭环（监控/告警/降级/值班）与研发闭环（数据/评测/迭代）双层并行；环境也要版本化（"模型突然变差"常因外部世界悄悄换了形状——接口字段漂移）；每次事故沉淀五类资产：新门禁规则、新难例样本、新监控指标、值班 runbook、工具接口修订建议。

    具身智能（走进物理世界）

    • 摩拉维克悖论：下棋写证明对计算机容易，走路抓杯子却难得要命——后者是几十亿年演化打磨的感知与运动控制。
    • 经典三支柱：感知（传感器）、规划（路径/动作序列）、控制（反馈控制 PID），在结构化环境很好用，非结构化环境力不从心。Brooks《大象不下棋》：智能未必从抽象推理开始，从身体与环境的实时耦合中长出。
    • VLA（视觉-语言-动作模型）：输入图像 + 语言指令，输出动作，一个大神经网络统一学习。关键洞察：世界知识（互联网语料）与操作技能（机器人演示）分开积累、合起来使用。动作表示三种思路：动作词元化（RT-1/RT-2，离散成格子当词元，复用语言模型架构但精度受限速度慢）；动作分块（ACT，一次预测未来 50-100 步，减少误差累积、捕捉多步连贯）；扩散动作头 / 流匹配（Diffusion Policy / π0，动作当连续分布，能建模多峰"多解"，流匹配更快）。代表：RT-1（13 台机械臂 13 万次演示，"自然语言是机器人接口"）、RT-2（从 PaLI-X 等视觉-语言模型微调，能执行"把灭绝的动物拿起来"——从预训练借常识）、Open X-Embodiment（34 机构 22 种机器人 100 万条轨迹）、π0（PaliGemma 3B 骨干 + 3 亿参数动作专家，"大脑+小脑"分层：慢思考语义理解 + 快反应流匹配动作）、π0.5（高层语言模型规划子目标 + 低层策略执行，多时间尺度分层）、开源侧 OpenVLA/Octo/RDT-1B（清华，中文指令双臂）。
    • 世界模型：输入"状态+动作"预测"下一状态"，让机器人在想象中训练（Dreamer V3 用同一套超参数攻克 Minecraft 从头采钻石）、想象中规划（内部搜索动作序列）、想象中评估（真机前的安全过滤器）。视频世界模型（NVIDIA Cosmos、Genie 从游戏视频学潜动作）与 JEPA（LeCun：不预测像素只预测"意义"）是两条分支。局限：短时间尺度准、长时间尺度漂移、分布外外推会错。VLA 负责"我想做什么"，世界模型负责"这么做会怎样"——两者可能合流。
    • Sim-to-Real：域随机化（仿真里大范围随机化纹理/光照/摩擦/重量，学出鲁棒策略）、残差策略学习（真机只学小修正量）、数据混合（仿真给量真实给质）、系统辨识（先校准仿真参数）、自动域随机化（随策略进步扩大随机范围）。教师-学生蒸馏：教师看"上帝视角信息"，学生只看传感器信息来模仿——双足行走的主流管线（Isaac Gym 大规模并行 RL + PPO）。
    • 数据是护城河：ALOHA（约 2 万美元双臂遥操作系统）把采集成本从几十万降到几万，ACT 用少量演示学会穿线折毛巾，Mobile ALOHA 走进厨房——复刻大语言模型"算力数据算法三位一体"的逻辑，但机器人数据更难采。
    • 现实阶段判断：当前分三类——工厂受控试点（Figure 02 在宝马、Apollo 与奔驰、Digit 仓储）、家庭早期探索（1X NEO、π 系列演示，离商品很远）、低成本研究平台（宇树 G1 约 1.6 万美元）。做人形的理由：整个文明按人类体型设计，人形能少改造环境、复用人类工具与演示。挑战：安全（越靠近人动作越慢力越小权限越低）、可靠性（每步 99% × 100 步 ≈ 36.6%）、成本（是"会走路的汽车"非买断家电）、数据稀缺（触觉数据尤其缺，Sparsh/UniTouch 等触觉基础模型在补）、伦理（隐私、责任、就业、依赖）。

    AI for Science（第四范式）

    • 科研四范式：经验 → 理论 → 计算 → 数据驱动（Jim Gray, 2007）。深度学习让第四范式真正有力量。
    • AlphaFold：50 年的蛋白质折叠问题（Levinthal 悖论），CASP 竞赛 20 多年挤牙膏（GDT 20→40-50），AlphaFold 1（CASP13 约 60 分）→ AlphaFold 2（CASP14 接近实验级 ~90）。技术核心：多序列比对（演化保守信号）+ 成对距离预测 + 端到端训练 + 注意力。免费公开超 2 亿预测结构（"高质量地图，不能替代实地勘探"）。AlphaFold 3 扩展到蛋白质与小分子/DNA/RNA 的复合结构（用扩散模型采样），开源侧 Boltz-1/2 追赶并加入结合亲和力预测。Hassabis、Jumper 与蛋白质设计先驱 Baker 同获 2024 诺贝尔化学奖（同周 Hopfield、Hinton 获物理学奖）。
    • 其他战线：药物发现（分子属性预测/药物-靶点结合/生成式分子设计，AI 辅助候选已进临床试验，但临床试验是终极考场）；蛋白质从头设计（Baker 团队 RFDiffusion + AlphaFold 验证闭环，Foldit 游戏玩家曾是论文共同作者）；基因组（AlphaMissense 给 7100 万错义突变打分，Evo/Evo 2 DNA 基础模型——是"统计规律的候选生成器"，不是万能编辑器）；单细胞生物学（聚类细胞类型、发现稀有亚群）；连接组（FlyWire 果蝇全脑 14 万神经元 5000 万突触）；材料（GNoME 筛出约 220 万候选晶体、38 万高稳定，"超级筛沙机"）；气象（GraphCast/Pangu-Weather 用 40 年 ERA5 数据训练，达到或超过传统 NWP 且推断快得多——但刷新的是速度与成本，不是混沌的可预报上限）；数学（AlphaGeometry 神经网络提辅助线 + 符号引擎严格验证，IMO 几何 30 题解 25 题近金牌；AlphaProof+AlphaGeometry 2 达 IMO 银牌；AlphaTensor 把矩阵乘法当游戏玩出超人类已知最优算法；Lean 形式化数学加速验证）；天文物理（引力波初筛、Kepler-90i 系外行星、LHC 触发决策、RL 控制托卡马克等离子体）。
    • 科研范式之变：AI 从单点工具变成"研究助理"——Google AI Co-Scientist（多智能体假设锦标赛，部分候选已体外实验验证）与 ERA（LLM+树搜索写专家级实验软件）2026 年同日登 Nature；Sakana AI Scientist 端到端做小课题；机器人实验室（利物浦 mobile robot chemist）补上实验闭环。新循环：AI 发现 + 人类解释 + 实验验证——人类负责"该不该做、意味着什么"，AI 负责"能不能做、怎么做出来"。
    • 硬挑战：关联 vs 因果（冰淇淋与溺水的共同原因陷阱）；可解释性（能预测蛋白质结构却说不出折叠的物理机制——"预测而非证明"的学科还算不算科学，是 AI 时代深刻的科学哲学命题）；数据质量与外推（分布外会胡说八道）；物理约束（守恒律要写进模型结构）；复现与出处（模型版本/提示词/随机种子都要留脚印）；双重用途（设计蛋白质可做药也可被滥用——加速器需要刹车）。

    现实产品形态

    • 编程智能体（程序员被冲击最深，因为代码有清晰文件、明确测试、可执行反馈——Git/单元测试/编译器/CI 恰好给了智能体清晰的"行动-反馈"闭环）：三类形态——命令行（Claude Code CLI、Codex CLI，住在项目目录里）、AI IDE（Cursor、Windsurf、GitHub Copilot，AI 在光标旁边）、端到端工程智能体（从 GitHub Issue 自主完成全流程 PR，对边界清晰可验证的小任务可靠）。适合边界清晰、成功有客观判据的任务（补测试、修小 bug、批量改格式、API 迁移）；"重构得更优雅"这类判据模糊的活需要人类眼睛盯着。风险是自信式错误（为了让测试通过而修改测试本身）；对程序员它不是替代品，而是"速度极快、知识广博、偶尔犯低级错误的初级同事"。vibe coding 降低门槛，但"能跑出来不等于能维护，能演示不等于能上线"。
    • 浏览器与电脑操作智能体（Computer Use、Project Mariner、Operator→ChatGPT agent）：挑战是把"看屏幕"和"操作"结合得可靠——关键不是能不能点按钮，而是该点的时候点、不该点的时候停手（看见蓝色按钮得知道那是"提交"还是"同意把银行卡交给陌生网站"）。
    • 通用任务智能体（Manus、AutoGPT/BabyAGI 先驱）：高层目标自主拆解执行，从"概念烟花"走向"可交付一点成果的工具"。
    • 开源与本地优先：记忆可见（存成用户能打开的文件）、权限可控、可离线运行、可审计——"用户未必只需要最强的助手，也需要真正属于自己的助手"。
    • 企业智能体（Salesforce Agentforce、Microsoft 365 Copilot、智能自动化编排 AI agents/RPA/人工审批）：逐步改写流程清晰、可检查、重复性强的工作。

    经验与常见坑

    • 智能体失败最常见根因不是模型不聪明，而是任务定义、环境接口、状态表示没设计清楚。
    • 伪成功（流程完整但没真完成）是智能体特有且最危险的失败——必须显式验证点、可检查完成条件、人工抽检。
    • 工具一多错误面变大：接口模糊会被模型放大成系统性错误；ACI 防呆优于事后修补。
    • 自我反思若无可信反馈源（测试、执行结果、外部检索），只是"把错误从漂亮包装盒换到另一个漂亮包装盒"。
    • 幻觉在行动中放大：LLM 幻觉是一段错误文字，智能体幻觉是直接执行错误动作（发错邮件、误删文件、引入不存在的 API）——从"说错"到"做错"，链条被极大缩短。
    • 提示注入：恶意指令藏在数据里（网页、邮件、PDF、搜索结果、工具返回）诱导智能体做有害事——原理同 SQL 注入（把代码藏进数据），但自然语言无法严格分离指令与数据，是根本性架构问题，"请不要被骗"的提示词解决不了。多层防御：外部内容默认低权限、工具权限分层（读文件≠删文件、查余额≠转账）、敏感操作人工确认、沙箱执行、日志审计。安全的智能体不是胆子小，而是知道什么时候该问一句："老板，这个我真要点吗？"
    • 授权与问责：智能体造成损害时责任如何在使用者/开发者/平台/组织间分配尚无清晰答案；"何时需要人介入"的边界随自主性提升而日益模糊。
    • 可靠性的指数衰减：每步成功率 95%，20 步整体仅约 36%，50 步约 8%；要让 20 步任务整体达 90%，每步须 99.5% 以上。"单步很强"不等于"长任务可靠"。对策（并行使用）：每步加验证器、关键步骤人工确认、冗余（不同方法做两遍比对）、强弱模型分工、可回滚设计（改文件先备份、发邮件先生成草稿、执行先沙箱）。
    • 构建有效 Agent 三原则：保持简单（直接 API 调用优于复杂框架，每层抽象都是调试盲区）；保持透明（显示规划步骤与决策轨迹，黑箱里的错误无法定位）；设计好 ACI（从 Agent 视角设计接口、主动防呆，即制造业的 Poka-yoke 思路——模糊接口会被模型放大成系统性错误）。模型选型：绝大多数 Agent 需要支持思考（Reasoning）的模型，只有单步简单任务可例外；不要只看排行榜，要在自己任务上评估。安全从第一行代码就要考虑，是架构问题而非上线前补丁。
    • 多智能体角色越多不等于越强——协调成本、责任模糊、局部最优、瓶颈单点都会吃掉收益；先问"它让系统更清楚了吗"。
    • 评测均值会掩盖高风险低频切片的退化；回归集必须保留低频高风险任务。
    • 具身机器人演示 ≠ 交付：看视频先问"失败样本在哪里"；每步 99% 的 100 步任务整体仅 36.6%。
    • AI for Science 的输出是候选假设而非科学结论——因果分析、实验验证、可解释性缺一不可。

    ⚠️ 时效性说明

    • 产品与模型（Devin、Claude Code、Operator/ChatGPT agent、RT 系列、π0/π0.5、Helix、AlphaFold 3、Evo 2、AI Co-Scientist 等）为 2026 年前后状态，迭代极快，选型前查最新。
    • 人形机器人成本数字多为媒体估算或厂商目标，非官方成交价；Optimus 量产数字属目标口径。
    • "机器人基础模型""GPT-R 时刻"仍是愿景；具身智能与 AGI 的关系（是否必要条件）是开放争论。
