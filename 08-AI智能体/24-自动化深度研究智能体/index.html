    自动化深度研究智能体

    更新于 2026-11-03

    一句话定义：一个基于 HelloAgents 框架的深度研究助手——用「TODO 驱动的研究范式」把开放的研究主题自动拆解为子任务，多轮搜索、总结并生成带引用的结构化研究报告。

    深度研究是典型的「知识密集型」智能体应用，难点在于信息不断发散、事实快速更新、用户对引用来源要求高。与单轮问答的搜索引擎不同，它需要三种核心能力：问题剖析（把开放主题拆成可检索的查询）、多轮信息采集（多搜索 API 挖掘资料并去重整合）、反思与总结（识别知识空白、决定是否继续检索、生成结构化总结）。

    它解决的是传统研究方式的三大痛点：信息过载（逐个点开搜索结果）、缺少结构（信息碎片化）、重复劳动（每次新主题都重复"搜索→阅读→总结"流程）。核心价值：把 1-2 小时的研究压缩到 5-10 分钟，流程系统化不遗漏，所有来源可追溯，且可通过配置扩展新搜索引擎与数据源。

    核心原理：TODO 驱动的研究范式

    将"研究"这一复杂任务转化为「规划 → 执行 → 整合」三阶段流程：

    1. 规划（Planning）：TODO Planner 把主题分解为 3-5 个子任务（太少覆盖不全、太多冗余），每个子任务含 title（标题）、intent（研究意图）、query（搜索查询，可用英文以获得更好结果）。输入包含当前日期以获取新信息。分解策略通常从基础概念入手，再到技术现状、实际应用、发展趋势，必要时做对比分析。
    2. 执行（Execution）：对每个子任务依次执行——搜索（max_results: 5）→ 总结 Agent 提取核心观点、保留关键数据（数字/日期/名称）、为每个观点加 [1] 式来源引用 → NoteTool 落盘保存总结与来源。
    3. 报告（Reporting）：Report Writer 整合所有子任务总结，按逻辑顺序组织，消除重复，输出五部分结构：标题、概述、各子任务详细分析、总结、参考文献（按子任务分组）。

    对比传统"单次搜索→人工翻链接"，TODO 范式的优势：可控性强（每个子任务目标明确）、质量可靠（专门 Agent 把关）、易调试（可单测子任务）、可扩展（增删子任务灵活）。

    好的规划有四条标准：覆盖全面、逻辑清晰、查询精准、数量适中（3-5 个）。

    核心概念

    系统架构（前后端分离，四层）

    层 技术 职责
    前端层 Vue3 + TypeScript 全屏模态对话框 UI、Markdown 结果可视化
    后端层 FastAPI API 路由（/research/stream，SSE）
    智能体层 HelloAgents 3 个专门 Agent + 2 个核心工具（SearchTool、NoteTool）
    外部服务层 搜索引擎 + LLM 提供检索与推理能力

    数据流转：用户输入主题 → 前端 SSE 连接 /research/stream → FastAPI 创建研究状态 → 规划 Agent 拆 3 个子任务 → 逐个执行（搜索→总结→记笔记）→ 报告 Agent 整合 → SSE 流式推送进度与结果 → 前端实时更新任务状态、进度条、日志、报告。

    三个专门 Agent（职责单一，顺序协作）

    Agent 职责 Prompt 关键设计
    TODO Planner（研究规划专家） 拆解主题为 3-5 个子任务 注入当前日期；强制 JSON 输出；给示例；约束数量与逻辑关系
    Task Summarizer（任务总结专家） 总结搜索结果、提取关键信息 注入任务标题/意图/查询上下文；要求核心观点+关键数据+来源引用
    Report Writer（报告撰写专家） 整合总结生成最终报告 规定五段式结构；要求按逻辑排序、合并重复、保留全部引用

    三者为顺序协作：线性流程、输入输出明确（每个 Agent 的输入来自上一个的输出）、无并发。核心协调器 DeepResearchAgent.run() 按"规划→循环执行→报告"调度三者并通过 _emit_event 向前端推送进度。

    ToolAwareSimpleAgent 的设计要点：在 SimpleAgent 基础上增加 tool_call_listener 回调，重写 _execute_tool_call——解析参数、调用父类执行、再通知监听器。用途：调试（看调了什么工具什么参数）、日志、行为分析、前端实时进度展示。三个 Agent 共用同一监听器，工具调用事件经 SSE 推到前端。

    工具系统集成

    • SearchTool：在基础版（Tavily、SerpApi）上扩展出 DuckDuckGo、Perplexity、SearXNG，并新增 Advanced 模式（组合多引擎）。通过 .env 的 SEARCH_API 配置切换引擎，无需改代码。统一返回 results（标题/URL/摘要）、backend、answer（仅 Perplexity）、notices。
    • NoteTool：持久化研究进度到 workspace 目录，每个笔记是 Markdown 文件（文件名为任务 ID），支持中断后从上次进度继续、事后审计。
    • ToolRegistry：统一注册与管理工具。工具调用流程：Agent 生成 [TOOL_CALL:工具名:{参数}] 指令 → 注册表解析指令 → 按名查找工具 → 调用 run → 结果格式化为字符串返回给 Agent。
    workspace/
├── notes/          # 1.md、2.md… 每个子任务一份笔记
└── reports/
    └── final_report.md

    四个核心服务（Agent 与工具之间的桥梁）

    服务 职责 关键实现点
    PlanningService 构建规划 Prompt → 调规划 Agent → 解析 JSON → 验证字段 用正则 \[.*\] 从含杂文本的响应中提取 JSON 数组，失败再尝试整体解析；逐条校验 title/intent/query 必需字段
    SummarizationService 格式化搜索结果 → 调总结 Agent → 提取来源 URL 搜索结果格式化为 [序号] 标题 + URL + 摘要
    ReportingService 格式化子任务总结 → 调报告 Agent → 整理引用 统一格式含任务序号、标题、意图、总结、来源列表
    SearchService 按配置调度搜索引擎 → 去重 → 限 Token → 错误降级 → 缓存 URL 去重；每来源约 2000 token（1 token ≈ 4 字符）截断；失败返回空列表不中断；查询+引擎名 MD5 做文件缓存（cache/search/），省钱省时

    SearchService 特意不让 Agent 直接调用工具，而是经中间层返回搜索结果，让 Agent 更专注于处理信息本身。

    # JSON 提取的健壮解析模式（规划服务核心）
def _extract_tasks(self, response: str) -> List[dict]:
    json_match = re.search(r'\[.*\]', response, re.DOTALL)  # 先提取 JSON 数组
    if json_match:
        return json.loads(json_match.group(0))
    return json.loads(response)  # 兜底：整体解析

    经验与常见坑

    • LLM 返回的 JSON 不干净：可能在前后夹带说明文字或缺引号逗号，必须做正则提取 + 多策略解析 + 字段验证三层防御。
    • 搜索结果要去重限长：重复 URL 和超长摘要既浪费 token 又稀释总结质量。
    • 搜索要容错降级：单次搜索失败返回空列表继续流程，不因外部服务抖动中断整个研究。
    • 工具调用可观测性：给 Agent 加监听回调是低成本高收益的设计，调试、日志、前端进度展示一份数据三处复用。
    • 搜索结果缓存：以查询+参数+引擎生成 MD5 键落盘，重复研究主题时显著降本提速。

    前端交互设计（概要）

    • 全屏模态对话框：沉浸式、主页面与研究页分离、ESC 可关、响应式（平板 95vw、手机全屏）。组件含顶部栏（主题+关闭）、进度区（进度条+文字）、内容区（loading/Markdown）、底部栏（状态）。
    • SSE 实时进度：POST /api/research 返回 text/event-stream，服务器按阶段推送事件（progress 百分比与文案、plan 任务列表、task_summary 各任务总结、report 最终报告、error、completed）；前端用 EventSource 监听并按 type 分发更新 UI。规划约占进度 10%，执行占 10-80%，报告 90%，完成 100%。
    • Markdown 可视化：marked 库（开启 breaks、gfm）转 HTML 渲染，参考文献按任务分组展示链接。

    ⚠️ 时效性说明

    • 文中基于 2024 年前后的搜索引擎生态（Tavily、SerpApi、DuckDuckGo、Perplexity、SearXNG）与 Vue3 + FastAPI 技术栈，API 细节可能已变化。
    • Token 估算用"1 token ≈ 4 字符"是粗略近似，仅适合限长用途。
    • 实现范式采用"前后端分离 + SSE + 多 Agent 顺序流水线"；如今部分深度研究能力（如内置 Web Search 的推理模型、Deep Research 类产品）可由模型侧直接提供，自建系统的价值更多在于流程可控与来源可审计。
