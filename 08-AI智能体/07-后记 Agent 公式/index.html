    后记：Agent 公式

    来源：bojieli《AI Agent 入门课》后记（更新于 2026-11-03）

    一句话定义：Agent = LLM + 上下文 + 工具——全书的统一公式；后记用它收束全书结构，并提出 Agent 技术的"两朵乌云"（实时交互、持续学习）与"模型-Harness 共同演进飞轮"两个前瞻判断。

    公式的结构

    公式三层理解：实现层、直觉层（大脑/眼睛/手脚）、学术层（策略/观察空间/动作空间）。全书十章即公式三根支柱的展开与组合：

    • 上下文（第二、三章）——"Agent 看到什么"：上下文工程决定单次会话中模型眼前的世界；用户记忆与知识库把单次会话扩展为跨会话的长期积累。
    • 工具（第四、五章）——"Agent 能做什么"：工具定义能力边界；Coding Agent 被单独展开，因为代码是通用性最强的工具——能创造新工具的工具。
    • 模型（第六、七章）——"大脑本身"：评估把 Agent 表现变成可比较的信号，后训练把信号变成模型能力——一个度量智能、一个放大智能。

    第八至十章是三根支柱的组合投向应用：自我进化（不改权重积累经验、创造工具）、多模态与实时交互（感知行动从文本扩展到视觉/语音/物理世界）、多 Agent 协作（并非公式之外的新东西——上下文是否共享是"隔离优于压缩"在架构层的表达，"Agent 互为工具"来自协作工具设计，"新信息"判据呼应评估的核心思想）。

    两朵乌云

    类比 1900 年开尔文的"物理学上空的两朵乌云"（后来变成相对论与量子力学），今天 Agent 天空也有两朵：

    乌云一：实时、流式地与环境交互

    今天绝大多数 Agent 仍是按轮次（turn-by-turn）的"请求-应答"：你说完一句，它想一整段，再一次性吐出。但真实世界不会停下来等它想完——话会被打断、画面持续变化、邮件不断到达。一个真正"活着"的 Agent 应能边听边想、边说边想，在话说到一半时就开始规划，在没人吩咐时主动发现"这封邮件该处理了"。

    两条并行推进的路： 1. 架构上快慢分离：实时与智能几乎是正交的两轴，单一模型难以兼顾——前台快模型维持对话节奏，后台慢模型负责深度思考。 2. 把推理本身做快：decode 速度足够高时，轮次等待短到近乎消失，turn-by-turn 与"实时"的界限随之模糊。例：小米 MiMo 把 1T 参数模型在单个 8 卡节点推过 1000 token/s；Taalas HC1 把 80 亿参数模型整体固化进芯片达约 17000 token/s、响应低于 100 毫秒（代价是模型更新需重新流片）。每秒上千字时，"想完再说"和"边想边说"的体验差距被抹平。

    乌云二：从交互中持续积累经验

    今天的模型像"记性极好、却学不会新东西的天才"：训练时背熟人类知识，上岗后几乎不再成长——任务结束，踩过的坑、试出的窍门大多随上下文丢掉。这是不是真问题，取决于两种针锋相对的假设：

    • 小世界假设：足够大的模型（几万亿参数）装得下物理世界几乎所有重要通用知识，学一次就够。佐证：AI 唯独在编程上最强，不是代码特殊，而是编程是人类最开放的领域（海量开源代码可学）；绝大多数行业没有公开数据。按此观点，前沿实验室正把各行各业的专业能力"蒸馏"进同一个大模型，瓶颈只在数据。
    • 大世界假设：属于具体用户、具体公司的知识（你公司的代码规范、团队做 PPT 的口味、某客户的脾气）不在任何训练语料里且时时在变——只能上岗后持续学习，无法出厂配齐。这正是记忆与自我进化在摸索的方向。

    更进一步，AI 已开始自我进化（"AI for AI"、"AI for Science"）：前沿没有尽头、没有标准答案、没有可背诵的语料，Agent 只能从自己实验的成败里自主学习。模型最强的能力，终将不是记住，而是学习与适应。

    模型与 Agent 的共同演进飞轮

    Harness 里层层叠叠的兜底逻辑（多级上下文压缩、失败数千次才熔断的重试、悲观默认"不安全"的权限判断）——每段看似丑陋的"屎山"，记录的都是模型此刻还做不稳的地方。飞轮：用户提出真实难题 → 应用层用 harness 补上模型暂时做不好的事 → 这些补救沉淀为下一轮训练的信号 → 模型内化后对应 harness 代码删掉。两朵乌云正是靠这条自我强化的飞轮一点点推散。

    "模型会不会吃掉 Harness"的完整答案：会，一层一层地吃，但永远不会完结。三个理由：训练以月计，模型等得起、业务等不起；模型无法内化真实业务中所有约束与偏好，总有一层最新边界需要外部逻辑兜底；每代模型打开新的能力前沿，而前沿恰是模型最做不稳的地方。Harness 不消失，只是随模型向新前沿迁移——《苦涩的教训》的 Agent 时代读法：通用方法终将胜出，但"终将"二字里的每一段路，都是 Harness 铺出来的。

    飞轮的最快转法是同时握住两端：Anthropic 用 Claude Code 让自家模型与自家 harness 互相喂养——模型知道 harness 会怎样调用它，harness 清楚模型边界在哪。不换模型只改 harness 可把准确率从 52.8% 提到 66.5%，说明 harness 今日杠杆之大，也说明其杠杆恰恰来自模型还没走到那一步。这条飞轮本身是时代最深的护城河：真实业务、反馈数据与模型迭代咬合得越紧，外部越难追上。

    对实践者的启示： - 造模型：护城河是让真实场景的反馈尽快回流训练。 - 在模型之上造应用：harness 是短期最锋利的技术杠杆，但模型每内化一层约束就抹平一批只靠 harness 建立的优势；应用层长久的护城河在技术之外——独占数据、渠道、用户信任、网络效应、必须人机协作的复杂场景。把 harness 用来争取时间，把这段时间用来构筑技术之外的壁垒。

    经验与常见坑

    • 不必焦虑框架过时：具体 API、产品、榜单几个月就翻篇，但"看到什么、能做什么、如何验证做得对不对"三个问题不会过时——它们描述的是智能系统与世界交互的基本方式，而非某个模型的用法。
    • 读懂和做出来之间隔着一条只能靠双手跨过的河——书中的实验要亲手跑一遍。

    ⚠️ 时效性说明

    • 文中推理速度数字（小米 MiMo 1000 token/s、Taalas HC1 约 17000 token/s）为 2026 年报道值，硬件与推理引擎迭代极快。
    • "小世界/大世界假设"之争是开放问题，文中立场为作者观点。
