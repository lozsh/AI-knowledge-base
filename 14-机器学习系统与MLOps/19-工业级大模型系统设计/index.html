    AI应用 大模型 机器学习系统

    工业级大模型系统设计：策略建模、离线/在线系统与 AI 中台

    更新于 2026-11-03

    一句话概括：从推荐/广告系统继承的工业级 AI 系统方法论——策略建模做骨架、离线系统做弹药库、在线系统做冲锋队，企业侧再沉淀为 AI 中台。

    核心概念

    三大误区（先破后立）

    1. 把 LangChain/AutoGPT 当工业级 LLM 系统——它们是原型验证工具；工业级需要离线+近线+在线多套系统配合供给；
    2. 把 Embedding 检索奉为圭臬——它只是字面匹配的变种，文档切片破坏语义，无工业架构支撑会被索引膨胀拖垮；
    3. 无视开源模型内容质量——真领域模型需要定制训练+分布式框架+强化学习，API"微调"只是浅层补丁。

    系统总骨架：两次转化

    工业级 AI 系统（以搜索/推荐/广告 AIRC 为设计范式来源，AIGC 与其架构同构——都是"为用户交付内容"，AIGC 只是把"分发"升级为"生成"）： - 第一次转化：业务目标 → 数学问题（策略建模，产品+算法）； - 第二次转化：数学问题 → 工程问题（系统构建，算法+架构）。 三大工作块：策略建模、数据工程、模型工程。

    策略建模四件套

    1. 指标建模：先定北极星指标（电商为 GMV），按转化漏斗拆解（曝光→点击→加购→付款），期望收益 = 点击率×加购率×付款率×客单价；
    2. 召回（Recall）：低复杂度算法快速排除"错误答案"。三路：关键词召回（倒排索引）、用户画像召回、向量召回（对比学习+图神经网络）；坑：任何召回策略都可能流失最优结果（如夫妻共用账号使性别策略反作用）；
    3. 排序（Ranking）：用用户/场景/物品全景特征精确打分；分层为粗排→精排→重排（越靠前算法越快、模型越简单）；规律：被淘汰的精排模型随算力提升下沉为粗排主流；
    4. 控制与博弈：流量调控用 PID/强化学习；广告双边市场 SSP（卖方）vs DSP（买方）经 Ad Exchange 拍卖，卖方设动态底价防"捡漏"。 外加风控：内容安全（机审高召回"宁可错杀"+人审确认）+ 反作弊（在线规则拦 80% + 离线算法挖长周期团伙，对应二八定律）。

    核心原理

    数据与特征工程

    • 特征工程本质：对数据做微观/宏观投影——特征不变，变的是观察维度。微观手段：离散化、非线性变换、归一化（"特征中最重要的是公平公正"）、特征交叉。
    • 类别特征必须 one-hot 独热编码：枚举值直接给模型会引入虚假序关系（未知>女>男）；"无证据前先假设类别间无线性关系，关系交给模型挖掘"。
    • 数据分主体/客体/环境三类（用户/物品/场景）。核心资产：
    • DMP（数据管理平台）：管第一/二/三方数据，两大能力——身份对齐（多设备多账号识别同一人）与 Look-alike 人群扩展；
    • 知识图谱（KG）：物品侧"实体-关系-实体"三元组，构建三步：知识抽取→知识融合（实体对齐/消歧）→知识加工（推理补全）；
    • 实时特征（如"最近 30 分钟点击数"）：价值在时间维度的区分性——画像与物料更新慢，无实时特征则模型输入长期不变。
    • 图 embedding 演进：DeepWalk（随机游走生成序列+Word2Vec）→ GraphSAGE（端到端邻域聚合），思想与 Transformer 位置编码相通。

    模型工程：三大门派

    • 符号主义（知识图谱）、连接主义（深度学习）、行为主义（强化学习/控制论）——生产系统博采众长。
    • 监督学习两步：建立模型（选表达式）+求解参数（拟合）；梯度下降 = mini-batch 算梯度沿负梯度更新。
    • PID 控制器三路：比例（立即反馈）+积分（消除静态误差）+微分（抑制偏差扩大）；适合延迟响应的限流场景；工业新趋势是切向强化学习。
    • 关键认知：排序分本质是系统的目标函数，通过因子（质量分、PID 输出作为控制因子而非硬剔除）控制各业务指标消长；多因子打分本质是混合专家（MoE）思想。

    离线系统（弹药库）

    决定在线服务上限，是 AI 系统"第一颗扣子"。全量数据流： 埋点日志上报（加密防篡改）→ 反作弊清洗（在线规则如动作间隔<100ms 判非人类 + 离线 look-alike 挖作弊设备）→ 样本生成（曝光×点击日志拼接出 CTR 样本 + 特征投影）→ 训练（PyTorch/TF）→ 离线验证（最近 N 天真实样本，达准入门槛才上线）→ 模型发布（热替换在线模型文件）。

    存储索引三件套： - 倒排索引：MySQL 持久化 → 全量导出建索引（开源首选 ElasticSearch）；增量靠解析 MySQL binlog（工具 canal）； - 向量索引：预计算物品/用户向量入向量引擎，在线只查最近邻； - 实时特征：Redis 等内存 KV；知识图谱存 neo4j。

    在线系统（冲锋队）

    消费离线系统的存储索引与模型服务，直接扛流量。要点： - 多因子打分 = MoE 式专家协作（各"XX率"预测模型 + PID 控制因子）； - RTB 实时竞价：DSP 把"点击出价×预估点击率"换算成展示价格再乘盈利系数留抽成；进阶玩法是预测对手报价动态调整盈利系数； - 卖方用动态底价+智能轮空+竞价预估（Bid Landscape Forecasting）博弈。

    企业 AI 中台（自下而上模块划分）

    开发框架/运维管理 → 数据管理（收集、少样本标注、标注管理）→ 训练管理（集成预训练/SFT/指令微调；≥1B 参数考虑 DeepSpeed 等分布式；可视化任务）→ 模型管理（模型仓库≈内部 GitLab、优化调参、Agent 管理）→ 模型服务（API 封装、三方 API 计费限速）→ 应用服务（AppKey/AppSecret 鉴权、流控、权限、服务编排）。

    应用侧防护清单：按 QPS 限速、文件大小/格式限制、上传频率限制、token 计量计费对账；GPU 容量估算路径：预期 QPS → 每秒 token 数 → 按实测单卡吞吐 → 推算卡数+余量。

    术语表

    术语 英文 含义
    策略建模 Strategy Modeling 业务目标形式化为数学问题的方法论
    召回/排序 Recall / Ranking 先粗筛后精排的两级漏斗架构
    粗排/精排/重排 Pre-Rank / Rank / Re-Rank 排序三级，速度与精度递变
    数据管理平台 DMP 管理多方数据、身份对齐与人群扩展
    人群扩展 Look-alike 由种子用户挖掘相似人群

    AI 中台 AI Middle Platform 与业务无关的企业级 AI 通用能力平台
    概念漂移 Concept Drift 数据分布随时间变化导致模型退化

    经验与常见坑

    1. 在线增量训练不能替代全量训练（缺离线反作弊），且必须配指标监控+回滚降级预案；
    2. 日志"加密防篡改"不等于"安全"，反作弊要在线规则与离线算法双轨；
    3. 召回策略永远可能流失最优结果，重要场景要多路召回兜底；
    4. PID 直接剔除超投内容不如把 PID 输出作为排序因子——保留超投弹性，优质内容可突破限流；
    5. 少样本冷启动：CV 模型需 3000~5000 张图起步；两条路——数据增广（旋转/翻转/加噪/生成）与元学习；最好在产品内设计收集入口让用户持续供数；
    6. 数据标注智能标注有准确率折扣，目前仍以人工为主，预算要留足；
    7. 长期习惯放用户画像、高频变化放场景特征——特征归错类是常见设计错误。

    ⚠️ 时效性说明

    • canal/ElasticSearch/Redis/neo4j 等选型是成熟稳定答案，长期有效；
    • 策略建模范式源自搜索/推荐/广告，AIGC 时代增加了生成链路与提示引擎，但漏斗式架构（召回→排序→控制）思想仍然通用。
