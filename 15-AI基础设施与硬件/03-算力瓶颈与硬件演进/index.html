    算力瓶颈与硬件演进

    更新于 2026-11-06

    一句话定义：算力瓶颈是限制机器学习系统吞吐的四堵物理墙——功耗墙、内存墙、通信墙、可靠性墙——而硬件演进（加速器光谱、HBM、Tensor Core 与精度阶梯）就是历代芯片绕开或推移这些墙的路线图。

    机器学习系统有超越代码的物理现实：训练算法可以是公开的，但在规模上执行它们的能力被基础设施物理所把守。以 175B 参数模型为贯穿例子：FP16 权重 350GB 装不进任何单卡，训练全状态（权重+梯度+优化器+激活）超过 2TB——"这个模型装不进一颗芯片"这一事实，驱动了从 HBM 总线宽度到多卡互联的每一个约束。

    核心原理

    四面基础设施墙

    墙 表现 典型量级 缓解手段
    功耗墙 数据中心供电上限 ~40MW 设施，PUE 1.1–1.5 液冷、48V 直流配电
    内存墙 HBM 带宽追不上算力 3.35TB/s vs ~2K TFLOP/s HBM 堆叠、片上 SRAM
    通信墙 网络对分带宽 400Gb/s NDR IB 每端口 Fat-tree 拓扑、梯度压缩
    可靠性墙 MTBF 随规模下降 2.5 万卡集群 MTBF ~2 小时 异步 checkpoint、自动恢复

    通用性税与加速器光谱

    CPU 为任意指令序列付出的控制逻辑，对矩阵乘法是纯粹的浪费。裸片面积分配：CPU 算术单元仅约 5–10%，GPU 约 50–60%，TPU 约 70–80%，定制 ASIC >90%。从 CPU→GPU→TPU→ASIC 每一步都在"回收"控制逻辑面积换算术单元：

    特性 CPU GPU (H100) TPU (v5p) 晶圆级 定制 ASIC
    执行模型 指令 SIMT 脉动阵列 数据流 固定数据流
    灵活性 极高 高 中 中高 低
    能效 低 高 很高 高 极端
    • GPU：SIMT 保留可编程性，H100 有 16896 CUDA 核/132 SM；对不规则算子（稀疏注意力、动态路由）退化。
    • TPU：脉动阵列硬接线数据流，免指令取译码开销；须走 XLA 编译，不规则控制流映射差，编译耗时拖慢迭代。频繁改架构的研究团队选 GPU，跑固定架构的规模团队可选 TPU。
    • 定制 ASIC（Tesla Dojo、AWS Trainium）：目标负载上能效可达通用 GPU 的 5–10 倍，但设计周期 2–3 年、NRE 成本 $50–200M。最大风险是架构押错——2017–2020 年 CNN→Transformer 转型让 CNN 专用 ASIC 变成搁浅资产。
    • 晶圆级引擎（Cerebras WSE-3）：整片晶圆不切割，90 万 AI 核、44GB 片上 SRAM、21PB/s 片上带宽，任意两核纳秒级互访——"把集群做成芯片"。代价：缺陷感知路由、23kW 单片供电与工业级液冷。

    TPU 起源：2013 年 Google 测算语音搜索若被日常使用（每天 3 分钟/用户），推理负载将使数据中心容量翻倍——于是 15 个月造出 TPU v1（256×256 脉动阵列，92 TOPS INT8，75W）。

    GPU 架构演进：每代解决上一代的瓶颈

    架构 年份 关键创新 峰值张量吞吐 TDP NVLink
    Volta 2017 首代 Tensor Core 125 TFLOP/s 300W 300 GB/s
    Ampere 2020 多精度、MIG 312 TFLOP/s 400W 600 GB/s
    Hopper 2022 Transformer Engine、FP8 1979 TFLOP/s 700W 900 GB/s
    Blackwell 2024 双 die 芯粒、NVLink5 4500 TFLOP/s (FP8) 1000W 1800 GB/s

    关键物理约束：光刻 reticle limit（单次曝光约 858mm²）逼出芯粒设计——B200 双 die 经 10TB/s die-to-die 链路封装为等效 1600mm² 的逻辑 GPU。注意事项：峰值数字跨精度不可直接比；旗舰更新周期（V100 三年→A100 两年）已快于设施寿命，数据中心设计必须预留换代周期。"硅片彩票"：4nm 制程的微观差异让同批芯片体质不同，同步训练被最慢参与者拖累，一颗低 50MHz 的芯片可拖低整个集群 5–10% 吞吐，需按体质隔离到推理池。

    TPU 演进走 Pod-first 路线：v1 推理 INT8 → v2/v3 加 BF16 训练（1024 chip pod）→ v4 光路交换机 OCS 可重构拓扑 → v5p（459 TFLOP/s BF16，95GB HBM2e，ICI 1200GB/s）。GPU 是单芯片吞吐竞赛，TPU 是仓储级计算机竞赛。

    内存墙与 HBM

    内存墙（Wulf & McKee 1995）：处理器性能年增 60% 而 DRAM 仅年增 7%，三十年后 ML 推理是其最极端体现。175B 模型自回归解码时，每个 token 都要流过全部 350GB 权重——H100 算力上只需 0.14ms，内存搬运要 42.1ms，99.7% 的时间在等数据。这就是聊天机器人词与词之间可感知停顿的物理原因。

    HBM 的物理原理：不做更快的引脚，而是改变拓扑——多层 DRAM 垂直堆叠，用硅通孔（TSV）垂直互连，1024 位宽总线（对比 DDR5 的 64 位），信号路径从厘米级 PCB 走线缩到微米级（缩短 1000 倍）。结果：带宽 ~3.35TB/s（DDR5 约 200GB/s 的 16 倍）、能耗 ~2pJ/bit（DDR5 约 20pJ/bit）。代价：$10–15/GB（DDR5 约 $3/GB），12 层堆叠良率链低、产能扩产需 12–18 个月——HBM 供货是集群扩建的节奏决定者。

    代际 HBM2e (A100) HBM3 (H100) HBM3e (B200) HBM4（规划）
    带宽 ~2.0 TB/s ~3.3 TB/s ~8.0 TB/s 12–16 TB/s
    容量 40–80 GB 80–96 GB 192 GB 288GB+
    接口宽度 1024-bit 1024-bit 1024-bit 2048-bit

    容量决定模型装不装得下，带宽决定跑多快，两者不可混谈：70B FP16（141GB）在 192GB/2.04TB/s 的卡上 69.2ms/token，在 80GB/3.35TB/s 的卡上（须 INT8 量化到 71GB）21ms/token——小容量快带宽反而赢 3.3 倍。⚠️ 常见误区：HBM 没有"解决"内存墙，只是移动了它——每代 Tensor Core 增速快于 HBM 带宽增速，脊点持续上升（V100 139 → A100 153 → H100 295 FLOP/byte），越来越多的算子落入访存受限区。

    Token 延迟物理账（Llama-3 70B，141GB FP16 权重）：计算 0.14ms vs 内存 42.1ms。推论：H200 与 H100 算力相同但带宽 1.4 倍，解码就快 1.4 倍——解码瓶颈是内存接口而非算术逻辑。万亿参数模型（FP16 约 2TB）即使 16TB/s 带宽，batch=1 也要 125ms/token，必须量化+张量并行。

    Roofline 诊断

    可达性能 = \(\min(R_{peak},\ BW \times I)\)，脊点 \(I_{ridge} = R_{peak}/BW\)（\(R_{peak}\) 为峰值算力，\(BW\) 为显存带宽，\(I\) 为算术强度，\(I_{ridge}\) 为脊点强度）。H100 FP16 脊点 ~295 FLOP/byte：

    • LLM 解码（batch=1）：算术强度 \(I\) 约 1，深访存受限，可达吞吐约峰值的 0.34%——加算力无用，只有加带宽有用。
    • LLM prefill（长上下文）：算术强度约 100–500，跨脊点。
    • LLM 训练（batch=2048）：算术强度约 2048，计算受限——加 TFLOP/s 直接有效。
    • CNN 大 batch 训练：算术强度约 50–200，近/超脊点。

    这解释了为什么训练和推理常用不同代硬件：训练看峰值 FLOP/s/美元，推理看带宽/美元。

    Tensor Core 与精度阶梯

    Tensor Core 单指令做 Y=A×B+C 小块矩阵乘（H100 上 528 个，贡献 989 TFLOP/s，是 CUDA 核吞吐的 ~15 倍）；TPU MXU 是脉动阵列版。只有能分解成 tile 矩阵乘的算子（线性层、注意力分数、卷积）能触发；LayerNorm/softmax/逐元素激活回落到 CUDA 核，每 FLOP 慢 10–30 倍。

    格式 位宽 H100 峰值 用途
    FP32 32 ~67 主权重、loss 计算
    TF32 19 494 训练默认
    BF16/FP16 16 989 训练/微调
    FP8 (E4M3/E5M2) 8 1979 前向权重/反向梯度
    INT8 / INT4 8/4 1979 / 3958 量化推理

    Transformer Engine 按层动态选 FP8/FP16，每张量 scaling 因子动态更新：E4M3（范围小精度高）用于前向，E5M2（范围大精度低）用于反向梯度。基础设施含义：万卡集群从 BF16 转 FP8 训练 ≈ 凭空多一倍算力密度。⚠️ 注意峰值跨精度不可比；容量规划用持续吞吐不用峰值——MFU 40–50% 算好的大规模训练，>50% 是优秀。

    能量账

    读一个 FP16 操作数自 HBM 约 64pJ，一次 FP16 乘加约 1pJ——数据搬运是计算能耗的 64 倍（片外 DRAM 则 320 倍）。175B 单 token：搬权重约 11.2J，计算仅约 0.175J。万卡集群每卡 400–500W 花在内存子系统、仅 150–250W 花在 Tensor Core。并行策略的能耗也不同：NVLink 约 5pJ/bit，InfiniBand 约 15–20pJ/bit。

    功耗墙与 TDP

    电力从电网到晶体管逐级损耗：变压器 ~5%、UPS/PDU ~3%、PSU ~3%、VRM ~5%，累计约 20%。PUE = 设施总功耗/IT 设备功耗（优秀 1.1，行业均值 1.3，老旧 1.5+）。万卡集群（10MW）年电费约 $6–9M。

    TDP 轨迹即后 Dennard Scaling 时代：V100 300W → A100 400W → H100 700W → B200 1000W，年增约 18%。H100 814mm² 裸片散热 700W = 86W/cm² 热流密度，是电炉灶面的 8.6 倍。热管理细节：导热界面材料（TIM）退化 5% 就引发降频——这是"灰故障"（不报错、只变慢），可通过监控恒定负载下结温上升趋势提前发现。功耗管理：clock gating、DVFS、power capping（H100 限 600W 换 15% 省电）。冷却必须按 TDP 峰值设计，不能按 70–85% 的平均值——欠设计的冷却让 MFU 静默损失 10–20%。

    负载-硬件匹配决策表

    按瓶颈选硬件类别：计算受限的负载看峰值算力与卡间带宽，访存受限的负载看带宽单价，容量受限的负载看容量单价。

    工作负载 约束 关键指标 推荐类别
    LLM 训练 (>100B) 计算 峰值 TFLOP/s、NVLink 带宽 H100/B200、TPU v5p
    LLM 推理 (batch=1) 内存带宽 GB/s / 美元 A100/H100
    LLM 推理（batched） 计算+带宽 两者 H100/B200
    推荐系统（embedding） 内存容量 GB / 美元 CPU DRAM + GPU 混合
    研究/原型 灵活性 软件生态 GPU（CUDA），避免 ASIC

    推荐系统案例：TB 级 embedding 表放 CPU DRAM（$3–5/GB），稠密层上 GPU（HBM $10–15/GB）——Meta Grand Teton 即此设计。MoE 增加路由约束（Mixtral 8x7B 总参 46.7B 每 token 仅激活 12.9B），AllToAll 通信和负载均衡决定理论节省能否兑现。

    推移墙壁的技术

    • CXL：PCIe 物理层上的缓存一致互联，把内存容量"外移"成可池化资源。适合放 Adam 优化器态等冷数据；但 CXL 路径 64GB/s vs HBM 3.35TB/s（52 倍差），是容量层级不是 HBM 替代品。
    • 晶圆级：把芯片间通信墙"内移"到消失，换来容量与注入带宽新墙（44GB 片上 vs 350GB 权重 → 靠 MemoryX 1.2TB/s 权重流）。
    • 先进封装（CoWoS 2.5D、SoIC 3D）：压缩 die 间距，换来机柜功耗密度新墙。共同主题：迁移瓶颈而非消灭瓶颈。

    经验与常见坑

    • 更多 GPU ≠ 更快训练：通信开销随规模增长，1024→2048 卡成本翻倍、时间只降 30–40%；超过 2000–4000 卡边际收益趋零（对固定模型规模）。采购前先剖析当前规模下计算/通信/空闲的比例。
    • 不要按峰值 FLOP/s 采购：batch=1 推理算术强度 \(I\) 约 1 FLOP/byte，B200 的 4.6 倍算力峰值只兑现 2.4 倍解码提速（带宽比）——为用不上的算力付费。
    • GPU 小时不等价：H100 GPU 小时 = 6.3 个 A100 GPU 小时 = 15.8 个 V100 GPU 小时（按 TFLOP 计）。比"每有效 TFLOP 小时成本"，不是每小时租金。
    • 网络升级先诊断瓶颈：计算 20s + 通信 2s 的负载，网络翻倍只快 4.5%。Roofline 对整个集群同样适用。
    • 数据加载要提前规划：每 GPU 4–8 个 CPU 加载核、训练数据放本地 NVMe、加载与计算流水线化——部署后才发现 GPU 饿死是常见事故。

    ⚠️ 时效性说明

    H100/B200/TPU v5p 参数、HBM4 规划值与价格数据为 2024–2025 年的公开快照；芯片代际与互联带宽迭代极快，引用前应核对最新规格。
