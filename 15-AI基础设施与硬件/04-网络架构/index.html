    网络架构：ML 集群的同步骨架（Network Fabrics）

    来源：《机器学习系统》教材第 3 章（更新于 2026-11-03）

    一句话定义：ML 集群的网络 fabric 不是辅助设施，而是"梯度总线"——决定千卡集群是一台同步机器还是一队互相等待的闲置硅片；决定有用算力的不是端口速率，而是对分带宽。

    设想 175B 模型分布在 1024 张 GPU 上：每步训练要做 350GB 梯度的 AllReduce，fabric 中任何一条慢链路都会让其余 1023 张卡干等。节点内 NVLink（450GB/s 单向）到节点间 InfiniBand（50GB/s）之间约 9 倍的带宽悬崖，是网络设计的中心挑战。ML 流量与传统数据中心流量完全相反（见下），因此传统网络假设几乎全部失效。

    维度 传统数据中心假设 ML 现实
    流量模式 异步、随机、多对多 同步、周期性集合通信
    流类型 数百万短小"老鼠流" 少量巨大长寿"大象流"（一条 AllReduce 可达 350GB）
    性能指标 平均吞吐、流间公平 尾延迟、全局同步时间
    丢包容忍 容忍（TCP 重传） 不容忍（一个丢包卡住全体）
    拥塞 局部独立事件 全局相关（incast）

    核心原理：五层模型

    从线缆到集群，每层约束因果相连：

    1. L1 线缆与链路：PAM4/FEC 决定不可压缩的延迟下限与集群几何。
    2. L2 传输：RDMA/GPUDirect、InfiniBand vs RoCE、α-β 性能模型。
    3. L3 交换与拓扑：fat-tree、rail-optimized、torus、对分带宽。
    4. L4 fabric 行为：PFC、DCQCN/HPCC 拥塞控制、incast、自适应路由。
    5. L5 集群设计：SuperPOD、Grand Teton、虚拟化与多租户。

    三种基本集合通信模式由 fabric 支撑：AllReduce（梯度求和，同步训练的心跳）、AllGather（收集模型分片重建全量）、AllToAll（最苛刻，每卡向每卡发不同数据，MoE 专家并行必需）。

    L1：线缆与链路物理

    • PAM4 调制：4 电平编码 2 bit/符号，让 400G/800G 成为可能；代价是电压间隙缩为 NRZ 的 1/3，必须配前向纠错（FEC，RS(544,514) 系）——每链路约 100ns 处理延迟。三跳 fat-tree 单向累积 300–600ns FEC"物理税"，构成集合通信的硬延迟下限（α 项）。⚠️ 常见误区：加倍每符号位数不是免费提速，PAM4 链路本质比 NRZ 延迟更高。
    • 介质选择：DAC 无源铜缆（~3m、~$50、延迟最低，机柜内）；AOC 有源光缆（3–30m、~$500，机架间）；可插拔光模块（>30m、最贵，网络核心）。距离就是钱：万卡集群仅 spine 层约 2 万条光链路，$500/条 + 20W/条 = $1000 万线缆 + 400kW 持续功耗。这解释了为什么机柜要塞到 70–100kW——尽量用便宜铜缆。
    • SerDes 与链路预算：SerDes 是 fabric 最大功耗者。1024 卡集群维持全对分带宽约需 3000 条高速链路，每 400G 端口约 25W，仅互联就 75kW——约 10.5% 的电力用于"搬比特"而非计算。链路预算（dB）决定可达距离：800G 铜缆只剩 1–2 米，机柜直径和出柜光化都是物理强制。

    L2：传输层与性能模型

    RDMA 与 GPUDirect

    TCP/IP 在 400G 时代架构性失效：内核协议栈的中断和内存拷贝会吃满整机内存带宽，需几十个 CPU 核才能填满一条链路（"CPU 墙"）。RDMA 把传输卸载到网卡，端到端延迟从内核 TCP 的 50–100µs 降到 1–2µs（25–50 倍）。GPUDirect RDMA 让网卡直读 GPU HBM，省掉 GPU→主机内存→NIC 的反弹路径：175B 模型每步消除 700GB 冗余拷贝。

    ⚠️ 关键脆弱性：RDMA 没有 TCP 的选择性重传，丢一个包触发 Go-Back-N——1GB 传输丢一个帧可能重传尾部 100MB，同步训练中一个丢包让全集群停数百毫秒。RDMA 必须跑在无损 fabric 上。

    InfiniBand vs RoCE

    InfiniBand RoCE (RDMA over Converged Ethernet)
    无损性 硬件信用流控，原生无损 靠 PFC+ECN 近似，可被配置破坏
    运维负担 Subnet Manager、虚拟 lanes PFC 看门狗、拥塞调优、路由设计
    典型场景 专用训练集群（尾延迟可预期） 多厂商以太网舰队（Meta/Google 路线）

    α-β 模型

    传输时间 T(n) = α + n/β（α=固定启动延迟，β=持续带宽）。NDR IB：α≈1.5µs、β≈50GB/s，交叉点 n* = α·β ≈ 75KB：

    • 小消息（4KB 流水线控制消息）：IB 1.58µs vs 以太网 5.32µs——3.4 倍差距纯由 α 决定，加带宽无用，只能减跳数。
    • 大消息（350MB 梯度分片）：IB 7.0ms vs 以太网 28ms——4 倍差距纯由 β 决定，加带宽直接见效。

    推论：梯度是 MB–GB 级，训练通信几乎总在带宽主导区；但流水线并行和分布式协调的小消息在延迟主导区，升链速收益趋零。AllReduce 瓶颈阈值测算：1024 卡 H100 训 1.5B 模型，Ring AllReduce 通信占步时 70.6%；70B 参数（280GB 梯度）时纯数据并行通信彻底压倒计算——超过数十亿参数就必须用张量/流水线并行切分模型，不能只靠数据并行。

    L3：交换与拓扑

    对分带宽（Bisection Bandwidth）：把集群切成两半的最小割容量，是 all-to-all 通信的最坏吞吐上限。注意区别于"聚合带宽"——星型拓扑聚合带宽高但对分带宽受中央交换机背板限制。1024 卡 1:1 无阻塞 fat-tree 的对分带宽 25.6TB/s；4:1 收敛后只剩 6.4TB/s，AllReduce 慢 4 倍——在 $3 亿的超算上（训练 30% 时间通信）这个"省钱"浪费约 $1.42 亿闲置算力。对 ML 训练，超订阅是假节约。

    Fat-tree（Clos）：每层上行容量=下行容量即无阻塞。radix-k 交换机：两层支撑 k²/2 台主机（k=64 时 2048 卡）、三层 k³/4（65536 台）。代价：O(N log N) 交换机与密集布线，4096 卡规模交换硬件 $20–100M。

    Rail-optimized：按 GPU 槽位分 rail——所有节点的 GPU 0 接 Rail 0 交换机、GPU 1 接 Rail 1……数据并行 AllReduce 天然是同 rank 通信（GPU 0 只和别的节点的 GPU 0 同步），被物理硬隔离到单交换机、单跳完成（标准 fat-tree 要 leaf-spine-leaf 3 跳）。延迟 1.8µs→0.6µs，3 倍红利，可把扩展效率从 80% 拉到 95%。代价：跨 rank 流量（MoE 专家路由、不对齐 rail 的流水线交接）需跨 rail 桥接，大集群常用 rail 叶 + fat-tree spine 的混合。SuperPOD 和 Meta Grand Teton 都用此设计。

    替代拓扑： - Dragonfly：高 radix 全互联"组"+组间全局光链路，线缆省 ~50%，但组间带宽仅注入率的 25–50%——作业跨组即 2–4 倍降速，必须用拓扑感知调度器。 - Torus（3D 环面）：直连六邻居，交换硬件最少、局部带宽足，但全局通信要走 O(N^(1/3)) 跳。Google TPU pod 采用（数据/流水线并行都是近邻通信）；MoE 的 AllToAll 在 torus 上会拥塞降速 2–4 倍。

    拓扑（1024 卡） 对分带宽 成本/Gb/s
    Fat-tree 25.6 TB/s $3.0
    Dragonfly 20.0 $4.0
    Rail-opt 12.8 $2.0
    Torus 3D 8.0 $1.5

    ToR 与故障域：ToR 交换机聚合一机柜（4 节点 32 卡），也是最小故障域——ToR 挂了 32 卡瞬间脱离训练作业。高 radix（64 口）下 32 口下行+32 口上行=1:1 订阅保机柜级无阻塞。

    L4：fabric 行为（拥塞与路由）

    BSP 弱链效应：Bulk Synchronous Parallel 下全集群在最慢参与者处设栅栏——1024 卡中一张卡慢 10%，每步浪费约 102 个 GPU-step。$3/GPU 小时下，5% 的 straggler 差距在 $5000 万训练中浪费约 $250 万。尾延迟（P99）才是训练 fabric 的核心指标，不是平均吞吐。⚠️ BSP 并非不如异步：异步因 stale 梯度噪声常需更多总步数，实践上 BSP+straggler 缓解通常墙钟时间更短。

    PFC（优先级流控）与它的危险：RoCE 靠 PFC 在缓冲溢出前 PAUSE 上游实现无损。但 PAUSE 会级联传播——一个慢接收端可在 10–50ms 内让 PAUSE 传 3–5 跳，冻结数千对无关 GPU 的流量（"拥塞扩散"/victim flows）。微软 2016 年 PFC 死锁事故：ARP/MAC 映射不完整导致洪泛+PAUSE 成环，重启服务器都无法清除，最终靠"禁止广播/多播进入无损类+ARP 不完整时丢包而非洪泛"的架构性修复。概率账：4096 卡 RoCE 集群 2.4 万个收发器，即使单件日故障率仅 0.001%，当日至少一次"PFC 风暴"的概率约 21.8%——规模化后"罕见"成为周级常态，必须自动化处理。

    主动拥塞控制： - DCQCN：ECN 标记→接收端回 CNP→发送端乘性降速。部署广，但 ECN 阈值/NIC 固件构成难调的权衡面（Meta 2024 报告甚至选择不用 DCQCN，靠 PFC+上层集合控制）。 - HPCC：交换机在包头附加精确 INT 遥测（队列深度、利用率、时间戳），发送端一个 RTT 内算出精确可用速率，尾延迟方差显著降低；代价是需要可编程交换 ASIC。

    自适应路由 vs ECMP：ECMP 按流哈希选路，对大象流是灾难——8 条流哈希到 4 条路可能 4:0:2:2 分布，最慢链路决定步时。自适应路由按实时队列深度选口：IB 做包级 spraying（硬件保证按序），以太网用 flowlet（间歇重路由避免乱序）。MoE 的 64×64 AllToAll 流量矩阵（4096 条并发流）没有自适应路由必出 straggler。

    Incast：多对一突发——AllReduce reduce 阶段 256 个发送端各 50GB/s 同时涌向一个 400G（50GB/s）端口，瞬时 256 倍超载，32MB 缓冲约 2.5µs 溢出。⚠️ incast 在 BSP 训练中是每层反向传播结束时的确定性事件（每步发生数百次），不是边缘案例。缓解三板斧：分层错峰（梯度桶边产生边 AllReduce）、限制单口扇入的集合算法（层级/同 rail 归约）、QoS 分级。

    L5：集群设计案例

    • NVIDIA DGX SuperPOD：NDR IB + rail-optimized fat-tree + 硬件自适应路由。32 节点 Scalable Unit（256 卡）注入带宽 12.8TB/s；机柜内 DAC 铜缆、spine 光缆；IB 原生信用流控免 PFC 脆弱性。
    • Meta Grand Teton（24,576 H100 × 2 套）：一套 RoCE/Arista 以太网、一套 Quantum-2 IB，都用于 Llama 3 训练。用以太网的动机是运营规模与供应链韧性（多厂商交换机+复用前端运维体系）；代价是接受 PFC/ECN 调优的运维复杂度与小消息延迟劣于 IB。两大生态正在收敛（Spectrum-4 以太网加入 IB 式自适应路由）。
    • 虚拟化与多租户：SR-IOV 把物理 NIC 拆成多个 VF（独立队列/DMA），虚拟化开销可低至裸机的几个百分点；VF 是可分配资源，须与 GPU 一起做放置规划。虚拟 lanes/Traffic Class（IB 16 条逻辑通道）+ ETS 保证梯度流量不被邻居的 checkpoint 写爆——注意 QoS 配置的 VF 也是硬上限，软件优化无法突破。

    监控与调试

    网络问题是"沉默浪费"：一条降级光模块让带宽降 10%，每次迭代只慢 2–3%，30 天×1024 卡悄悄烧掉 1.5–2.2 万 GPU 小时（$4.5–6.6 万）而没有任何告警。三层可观测性必须跨层关联：

    1. 物理层：FEC 错误、SymbolErrorCounter、LinkDownedCounter（链路抖动）、PortXmitDiscards（无损 fabric 中应恒为零）。常见隐患：QSFP 线缆协商降速（400G→200G）或 4 lane 降 2 lane——链路"up"但带宽减半。
    2. 传输层：ib_write_bw 做全对带宽矩阵热力图找冷点；ib_write_lat 验证延迟（NDR 直连应 <2µs，>5µs 说明拥塞，>100µs 说明 RDMA 回落到 TCP 模拟——灾难性配置错误）。⚠️ iperf 测 TCP 会封顶在 20–40Gb/s，不能用于验证 RDMA 路径。
    3. 应用层：nccl-tests 验证实际集合拓扑的 AllReduce 带宽。

    排查顺序（从应用症状到物理根因）：GPU 利用率（dcgmi/nvidia-smi；先排除数据加载饿死）→ NCCL_DEBUG=INFO 看传输选择与回退 → ib_write_bw 点对点定位劣化链路 → PFC/ECN 计数器看拥塞 → 符号错误/CRC 找坏光模块。

    经验与常见坑

    • 链路速率 ≠ fabric 速率：全局 AllReduce 受最窄对分割限制。10KB 控制消息从 200G 升 400G 只快 10.5%（1.90→1.70µs）——延迟主导区升带宽是白花钱。
    • InfiniBand 不是"快以太网"：架构差异（内核旁路、硬件流控、信用拥塞控制）而非速率差异；选型是系统架构决策，不是带宽数字比大小。
    • 无损以太网 ≠ IB 那么可靠：PFC 风暴可让"无损"变成多日瘫痪；IB 信用机制天然免疫此类级联。
    • 别因"流量大多本地"接受超订阅：Web 流量随机可复用，BSP 训练 AllReduce 时全员同时满速注入。
    • 自适应路由不能无中生有带宽：调度器把作业跨超订阅组放置，自适应路由只能均衡不能突破组间瓶颈——拓扑感知放置与自适应路由互补，缺一不可。
    • 网络故障常表现为慢性变慢而非报错：PFC/ECN 计数器渐增是光模块劣化或路由失衡的前兆，必须设告警。

    推移天花板的技术

    • UEC（Ultra Ethernet）：包级 spraying+灵活排序+新拥塞控制，让以太网获得 HPC 行为而不继承 PFC 脆弱性。
    • 更高速率与扁平化：XDR IB 800G/端口、800GbE/1.6TbE、102.4Tb/s 交换芯片——端口密度提高让三层拓扑压成两层，少一跳 FEC 与交换延迟。
    • 共封装光学（CPO）：光引擎移入交换芯片封装，电路径厘米→毫米。51.2T 交换机光学功耗 2.56kW→1.28kW；千台交换机省 1.28MW ≈ 1800 张 H100 的电力。若节点间带宽逼近 NVLink 量级，张量并行跨 2–4 节点的限制将松动。新挑战：激光器温漂需主动热管理、光子与 CMOS 封装工艺兼容性。
    • 资源解耦（CXL 内存池化/可组合架构）：节点边界软化成"可组合的同步骨架"——但跨池访问仍付同样的 α-β 成本，是搬迁瓶颈而非消灭瓶颈。
