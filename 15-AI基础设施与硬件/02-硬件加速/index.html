    硬件加速（Hardware Acceleration）

    来源：《机器学习系统》教材第 11 章（更新于 2026-11-03）

    一句话定义：硬件加速是用针对张量运算特化的领域专用芯片替代通用处理器逻辑，用可编程性换取计算密度和能效——其本质不是"算得更快"，而是"每个有效运算搬动更少的数据"。

    现代计算的中心意外是：算术近乎免费，而搬运数据昂贵。取一个主存数据的时间里，处理器本可以做上千次计算——这就是"内存墙"，它由光速和电子移动的物理代价决定，不是等待修复的工程缺陷。专用加速器存在的意义正是隐藏、摊销、最小化数据搬运成本。由此推出两个工程结论：(1) 若一个操作本来就是访存受限（memory bound），减少计算量不会变快，因为瓶颈从来不是计算；(2) 选硬件不能只比峰值 FLOP/s，要看工作负载的访存模式是否与硬件设计匹配。

    核心原理

    加速的基本定律：Amdahl 定律

    加速只作用于可并行部分 p，总加速比被串行部分封顶：

    Speedup = 1 / ((1-p) + G_accel/p)
    • 可并行部分 p：矩阵乘法（通常占 ML 工作负载 90–99%）。
    • 串行部分 1−p：数据加载、Python 开销、kernel 启动延迟。

    若数据加载占 10%（p=0.9），即使加速器无限快，总加速也只有 10 倍。H100 上的实例：ResNet-50 推理（p=0.95、G=247×）端到端仅 18.6×；GPT-2 自回归生成（p=0.80）仅 4.9×。所以 LLM 推理优化的重点是通过 batching、投机解码等压缩串行比例，而非堆硬件速度。

    能量层级：为什么数据搬运是主要成本

    Horowitz 能量数据（数量级参考，随工艺节点变化）：

    操作 能量（pJ）
    DRAM 读取（64 位） ~640
    SRAM 读取（8KB） ~5
    FP32 乘法 3.7
    FP32 加法 0.9
    INT8 加法 0.03

    从 DRAM 取数比片上 SRAM 贵约 128 倍，比一次 INT8 加法贵约 2 万倍。这解释了为什么加速器架构的所有设计（脉动阵列、Tensor Core、分级存储）都在做同一件事：让数据靠近计算。

    算术强度与 Roofline 模型

    算术强度 I = 计算量 O / 访存量 D_vol（FLOP/byte）。可达性能：

    R_attain = min(R_peak, BW × I)

    分界点是脊点（ridge point）I_ridge = R_peak / BW：

    • A100：312 TFLOP/s ÷ 2.04 TB/s ≈ 153 FLOP/byte
    • V100 ≈ 139，H100 ≈ 295（脊点持续上升——芯片越新，越难喂饱）

    典型操作的归属：大 batch 稠密 MatMul（~204–341）、充分复用的 Conv2D（50–200，可越过脊点）偏计算受限；Attention Softmax（2–5）、LayerNorm（1–2）、Embedding 查找（<1）严重访存受限。同一个算子的强度不是固定的：朴素实现反复从 DRAM 重取操作数则强度低，分块（tiling）复用 SRAM 则强度高。

    两个经典推算： - batch=1 的 GPT-2 推理：每生成一个 token 要搬全部 3GB 权重、只算约 3 GFLOP，I≈1 FLOP/byte，利用率上限约 0.7%——这就是 KV cache 和量化的存在理由。 - batch 从 1→256 时，稠密层算术强度约从 1 升到 204.8 FLOP/byte，从访存受限跨入计算受限——这就是推理服务做 batching 的根本原因。

    硬软件协同设计（Co-design）

    刻意打破硬件/软件抽象层，让算法约束直接塑造硅片设计、硬件能力直接塑造算法形式。例：INT8 量化带来数倍加速，不是因为"8 位在抽象上更快"，而是 Tensor Core 数据通路对低精度运算 packing 更密。协同设计是持续反馈环：Tensor Core 先为 FP16 矩阵乘设计，再按负载需求加了 TF32/INT8，再按结构化剪枝研究扩展出稀疏 2:4 支持。

    关键概念

    AI 计算三原语

    神经网络无论何种层，最终分解为三类可特化的计算模式：

    1. 向量运算（一对一：激活、归一化）→ SIMD/SIMT 单元。向量访存（load）摊销开销，融合乘加（FMA）一条指令并行算 8–16 对数据。
    2. 矩阵运算（多对多：层变换、注意力、卷积）→ Tensor Core / 脉动阵列。一条指令处理整个 16×16 矩阵块；卷积经 im2col 也变成矩阵乘。注意力 Q×Kᵀ 在标量处理器上约需 268ms， tiled Tensor Core 路径 <0.5ms。
    3. 特殊函数单元 SFU（非线性：ReLU、sigmoid、exp、sqrt）→ 定制电路。Piece-wise 近似 1–2 周期，查表+插值 2–4 周期，固定迭代牛顿法 4–8 周期。

    Tensor Core 有"契约"：只对特定精度（FP16/BF16/TF32/INT8）和对齐维度（8/16 的倍数）触发，不满足就静默回退到慢 16 倍的 CUDA Core。这就是为什么模型常用 512 而不是 500 这样的维度。

    SIMT 与执行模型

    • SIMD：一条指令对多个数据元素做同样操作（Arm SVE 可变向量长度）。
    • SIMT：GPU 每个 lightweight 线程处理一个元素，按 warp（32 线程锁步）调度；风险是 warp divergence——线程分支不同则串行化，吞吐可掉一半，所以 ML kernel 用无分支谓词操作。
    • Tensor Core：SIMD/SIMT 之上的矩阵块原语。
    • 脉动阵列（systolic array）：TPU 式设计，数据像心跳一样脉冲式流过 PE 网格，操作数在邻居间传递、一个权重复用整列。能量账：向量单元每 op 约 4 次 DRAM 访问（~2561 pJ），128×128 脉动阵列每 op 约 0.016 次（~11 pJ）——能效差两个数量级。代价是对不规则负载僵硬，且矩阵必须够大才能填满阵列。
    • Tiling（分块）是连接计算图与硅片的桥梁：4096×4096 矩阵乘必须切成 1024 个 128×128 tile，从 HBM 取入 SRAM 再"脉动"进阵列。层宽不是 tile 尺寸的倍数时要交"边缘税"（127 个单元闲着等 1 个）。

    N:M 结构化稀疏

    非结构化剪枝减参数但不提速（访存变乱）。N:M 约束强制每连续 M 个值恰好 N 个非零（NVIDIA 2:4 = 50% 稀疏），硬件只存非零值+紧凑元数据，推理时按元数据选取激活——本质是"不加载零"而非"算零更快"，配合微调可拿最高 2× 张量吞吐。

    数据流（Dataflow）三大策略

    决定哪个操作数固定在本地、哪个流过阵列——这是芯片设计时的永久承诺，决定了硬件偏爱哪类模型：

    策略 固定项 最小化 适用负载
    Weight-stationary 权重 权重读流量 CNN（滤波器小且高度复用）
    Output-stationary 部分和 累加写流量 全连接层、注意力（高扇入）
    Input-stationary 输入激活 激活读流量 Transformer（同 token 跨多头复用）

    Eyeriss 的 row-stationary 是卷积专用的混合体。没有全能策略：早期 TPU 偏 weight-stationary，但 LLM 小 batch 推理时权重每个 token 只读一次、复用极低，架构被迫向 output-stationary 或混合 dataflow 演化。

    内存层级与带宽断层

    层级 延迟 容量 用途
    寄存器 ~1 周期 极小 立即计算的操作数
    L1/L2（SRAM） 1–10ns KB–MB 激活/权重块缓存
    Scratchpad/共享内存 5–20ns MB 软件管理的中间计算（FlashAttention 的关键）
    HBM ~100ns GB 大模型参数与激活
    片外 DRAM 50–150ns GB–TB 装不进 HBM 的权重
    SSD 100µs–1ms TB checkpoint、预训练模型

    节点内带宽断层（"越远离芯片越慢"）：

    HBM (3350 GB/s) ≫ NVLink (900 GB/s) ≫ PCIe (64 GB/s) ≫ 网络 (50 GB/s)

    所有训练数据要经过的 PCIe 是"数据加载瓶颈"；跨节点用 InfiniBand/RDMA。优化手段：DMA 异步传输（算 batch n 时搬 batch n+1，页锁定内存+异步拷贝）、Unified Memory（编程简单但页迁移导致延迟尖刺，生产多用显式 DMA）。为什么必须有片上 SRAM：2GHz 时钟下一个周期 500ps，而 DRAM 访问+协议开销 100+ 周期——物理上不可能一拍取回，光速就是延迟下限。

    不同模型的内存压力画像

    模型 权重 激活复用 访存模式 主要瓶颈
    MLP/稠密 大、稠密 低 规则顺序流 带宽（流式）
    CNN 小、高度复用 高 空间局部性 特征图搬运
    Transformer 大；MoE/剪枝后稀疏 低–中 规则 GEMM + KV/注意力流量 容量+带宽

    注意力的 S×S 分数矩阵随序列长度平方增长，是 KV cache 瓶颈与 FlashAttention（分块流过 SRAM、不物化全矩阵，收益来自减少 HBM 往返而非减少 FLOP）的直接动因。

    分类/类型：专用化演进与芯片形态

    五波专用化（每波都是"瓶颈→专用→集成回通用平台"的循环）：1980s 浮点/信号处理（Intel 8087 协处理器，最高 100× 增益，后集成进 486DX）；1990s 图形（GeForce 256 硬件 T&L → 可编程着色器）；2000s 媒体编码/网络处理（H.264 硬件编解码、IXP2800——线速包处理逼出的"计算贴近内存"布局正是 ML 加速器的雏形）；2010s 深度学习张量运算（TPU v1、Tensor Core）；2020s 应用专用加速（AI 引擎、晶圆级芯片）。

    TPUv1 vs K80 效率冲击（2015）：TPUv1 砍掉缓存/分支预测/乱序执行，填满 256×256 脉动阵列做 8 位矩阵乘，推理快 15–30×、每瓦性能好 30–80×。起源是"TPU 容量悬崖"：2013 年 Google 测算语音搜索若被日常使用，推理负载将使其数据中心数量翻倍，无资本方案可吸收——15 个月造出 TPU。教训：单一负载跨过舰队级经济阈值时，专用芯片从可选变为必选。

    Systems Gap：模型算力需求每年约 6×（Scaling Laws），GPU 供给约 1.7×/年（Huang's Law），缺口每年扩大 3–4×，只能靠并行与协同设计弥合。摩尔定律与 Dennard Scaling（约 2005 年后失效，"暗硅"问题：热约束下只能同时点亮 30–50% 晶体管）双双失效，是专用化的根本推手。

    训练芯片 vs 推断芯片：训练要双向梯度流+大激活内存，堆 FLOP/s 和带宽；推断只前向、可用 INT8/INT4、优先确定性和单请求延迟。数据中心芯片用带宽（TB/s 级 HBM）对抗内存墙，边缘芯片用贴近（寄存器/scratchpad）对抗内存墙。

    成本参考（约值，随行情浮动）：V100 ~$10k（125 TFLOP/s），A100 ~$15k（312 TFLOP/s FP16，$48/TFLOP/s），H100 ~$25–30k（TF32 494 TFLOP/s），TPUv4 ~$29/TFLOP/s，Gaudi2 ~$14/TFLOP/s。对访存受限的 Transformer 负载，带宽/美元比峰值 FLOP/s 更可靠。

    编译器与运行时

    ML 编译五阶段（代表系统：XLA、TVM、TensorRT、MLIR）：

    1. 图优化：算子融合（Conv2D+BN+ReLU → 单 kernel，消灭中间 HBM 写读）、消除冗余计算、调整布局。对低强度算子，融合可带来 2–4× 甚至 10× 提速。
    2. kernel 选择：从 cuDNN/cuBLAS/oneDNN 等库里按规则/代价模型/剖析选最优实现；选错（如给 GEMM 配了非 Tensor Core kernel）可损失一个数量级。
    3. 内存规划：张量布局匹配硬件、buffer 复用、tiling 让计算装进片上内存。
    4. 计算调度：任务切分、执行序优化、计算与传输重叠。
    5. 代码生成：必须发射矩阵专用指令（PTX mma.sync、AMX tile 指令），否则矩阵引擎全程闲置。

    编译的局限是静态：假设的 batch、内存状态与生产不符。运行时（Runtime）补动态三件事——动态 kernel 执行（按实际序列长度/显存调整 tiling）、运行时 kernel 选择（按当前 batch/精度状态选变体）、kernel 调度（保持 SM 占用率、预取中间数据）。典型生产落差：A100 SXM（400W）与 A100 PCIe（300W）散热包络不同，实验室基准的峰值在生产静默丢失。

    多芯片扩展与异构 SoC

    • 扩展边界逐级外推：芯粒（package 内）→ 节点内多卡（数据/模型并行，NVLink 域）→ 集群 fabric → 晶圆级集成（Cerebras，反方向把计算收回一个器件）。
    • 扩展的新约束：梯度同步是串行分数——AllReduce 每 step 要交换与参数量成正比的梯度载荷（千亿参数即数百 GB），不重叠通信时 8 卡只有约 7.5× 加速。通信本质上是"多了一层的内存层级"。
    • 异构 SoC（手机/车机/IoT）：CPU+GPU+DSP+NPU 共享内存。分配原则按算子特性：卷积主干→NPU，NMS 这类分支密集后处理→CPU，全帧像素合成→GPU。unsupported 算子回退到 CPU/GPU 会吃掉 NPU 能效优势。电源/热管理用协调 DVFS、热降频、模型降档；汽车场景额外要求确定性延迟与功能安全（时间触发调度、安全/非安全负载的时间隔离）。

    经验与常见坑

    • 峰值 FLOP/s 是营销数字：实际性能 = 峰值 × 利用率，利用率由 Roofline 决定。Transformer 训练实际 sustain 常只有 40–60%，推荐系统稀疏负载可低到 3–10%。容量规划按持续吞吐，不按峰值。
    • 精度要对口：H100 FP16 Tensor 约 1000 TFLOP/s，FP32 CUDA Core 约 67 TFLOP/s，同芯片差 15 倍。估算训练时间时峰值常数必须匹配实际发射的精度，报 MFU 要注明精度。
    • 小 batch 推理别用训练卡：batch=1–4 时大家都访存受限，便宜的 T4（脊点约 203 FLOP/byte）可能比 H100 更划算。
    • 专用硬件不总是更快：softmax（AI≈2–5）在 A100 上只有 3–10 TFLOP/s（3% 利用率），这类负载上通用 CPU 相对差距反而小。
    • 扩展不线性：GPU 数量翻倍 ≠ 时间减半，通信、负载不均、同步栅都在吃收益。
    • 厂商锁定有长期成本：手写 CUDA/TensorRT kernel 迁移代价高昂，应隔离在硬件抽象层后，保住可替换性。
    • 可持续性也是选型指标：10 亿推理/天的舰队，CPU（0.01 TFLOP/s/W）换 NPU（2 TFLOP/s/W）每年可省约 374 吨 CO₂。
