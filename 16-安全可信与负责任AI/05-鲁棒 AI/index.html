    鲁棒 AI

    更新于 2026-11-03

    一句话定义：鲁棒 AI = 使模型预测在分布偏移、对抗扰动、硬件/软件故障下仍保持有界、可恢复行为的可测量系统属性——它对抗的不是代码 bug，而是"输入、数据分布、硬件不再匹配训练条件时系统依然全速输出错误答案"的静默失败。

    传统软件大声失败：异常崩溃进程、类型错误中断编译、断言终止执行——失败可见所以可修复。ML 系统静默失败：面对分布外输入仍以满置信度输出；被攻击时输出的错误预测与正常预测难以区分；分布漂移下延迟和可用率稳定、精度悄悄流失。等到业务指标显出问题，伤害已累积数周；等到攻击被发现，可能已影响成千上万个决策。鲁棒工程的目标就是把不可见变成可见：让系统知道自己何时在能力范围之外、抵抗操纵、优雅降级，而不是自信地给出错误答案。

    鲁棒性的定义与三支柱

    形式化：鲁棒性用最坏情况保证度量（认证鲁棒分类器证明在指定扰动集内预测不会改变），区别于 i.i.d. 测试集上的平均精度——一个 95% 测试精度的模型可以在人眼不可见的扰动下完全失效（ε=8/255 的 PGD 强攻击常把非鲁棒模型精度打到近零）。⚠️ 常见误区：鲁棒性不能事后加监控补上——它主要由训练决定，没有对抗训练的模型无法靠推理期过滤获得认证鲁棒性，因为漏洞在学到的决策边界里。

    三支柱框架（各自证据与防御族不同）：

    支柱 证据信号 防御族
    环境偏移（数据漂移/概念漂移/域移） 输入/标签分布相对参考连续移动 监控、重校准、重训练
    输入级攻击（对抗样本/投毒/提示注入） 梯度对齐扰动、异常训练样本 对抗训练、认证、输入消毒
    系统级故障（位翻转/SDC/依赖失败/数值错误） 与发布/ECC 计数/内存压力相关 故障检测隔离恢复（另见容错）

    软件故障会伪装成另外两类——这是诊断难点。三种信号区分：①变化边界：真实环境偏移连续、影响整个人群；管线故障呈阶跃不连续、与某次发布/依赖升级/模式变更同步，且会一起移动现实世界不会一起移动的特征。②固定输入可复现性（最有判别力）：回放保存的黄金输入集——偏移和对抗是输入分布的属性，回放结果应复现历史正确输出；硬件/数值故障是计算的属性，同一输入会得出不同答案。③跨层相关：真攻击与输入空间异常（查询模式）相关；伪装的软件故障与系统信号（发布、ECC 计数器、内存告警）相关。

    真实鲁棒性失败

    • Google Photos "大猩猩"事件（2015）：把黑人照片标为"gorillas"——模型与评估管线都未暴露切片级失败。临时修复是直接删除 gorilla/chimp/monkey 标签，多年后仍未恢复——事故压力下的临时缓解往往比它本要过渡的修复活得更久。教训：鲁棒性不是聚合精度，需要切片评估、有害标签测试、安全回退。
    • 静默数据污染（SDC）：Meta 报告每百万台机器每天 6–8 台经历 SDC——比软错误预测高数量级。案例：压缩文件解压前做大小校验，故障 CPU 让 pow 返回 0 → 合法文件大小为 0 → 跳过解压 → 数据库静默缺行。分布式训练中 SDC 更致命：被污染的梯度/激活会扰动优化器状态影响后续步骤，修复常需回滚到最后干净 checkpoint 重启——爆炸半径随同步与 checkpoint 设计增长。Jeff Dean 在 MLSys 2024 强调：大规模训练中硬件错误是常态，一颗坏芯片的错误输出可污染整个训练。
    • Tesla Autopilot（2016）：74mph 行驶中，Mobileye 相机未能把白色拖车侧面与明亮天空区分开，雷达为避免误刹把高挂拖车当静止物过滤——两个传感器都拿到有效数据，融合逻辑把它丢了。
    • Uber 自动驾驶（2018）：感知系统提前 6 秒检测到行人，但分类在"未知物体/车辆/自行车"间反复切换，每次切换重置轨迹预测历史，直到撞前 1.3 秒才预测到碰撞路径——缺乏持久目标跟踪。
    • 嵌入式先例：火星极地着陆者（1999，过早的触地检测关掉发动机）；波音 787 FAA 指令——连续供电 248 天后四个发电机控制单元会同时进入安全模式断掉全部交流电——运行时间本身成了风险因子。安全关键领域（SIL 3/4、ASIL D 要求危险失败率 <10⁻⁸/小时）与 ML 的根本张力：标准要求确定性失效分析，神经网络是随机的，穷举测试不可行。

    硬件故障 × ML 的量化：单个权重指数位翻转（IEEE 754）使值乘以 2^(±2^k)——0.001 变成 10¹⁹，饱和下游神经元、污染整个前向传播。ResNet-50 一个关键权重位翻转可让 ImageNet top-1 从 76% 掉到 11%。V100 HBM2 以 900GB/s 运行 ≈ 每秒处理 7.2×10¹² bit，基础错误率 10⁻¹⁷/bit ≈ 每设备 0.26 错误/小时；集群级 Pr(≥1)=1−(1−p)^N——每设备 10⁻⁴/小时时，1 万台设备 1 小时内至少一次静默错误的概率 63%，约 3 万台时超 95%。

    环境偏移

    偏移类型

    • 协变量偏移：p(x) 变、p(y|x) 不变。白天训练的感知模型夜间部署精度可降 15–30%；雨雪雾使目标检测 mAP 降约 10–25%。
    • 标签偏移：p(y) 变。新冠期间医院病例构成快速变化，诊断模型需重校准阈值而图像特征含义未变。
    • 概念漂移：p(y|x) 本身变了——决策边界错了而非输入分布变了。⚠️ 结构性更贵：数据漂移补新数据即可，概念漂移必须对近期样本重新标注。⚠️ 检测更难：p(x) 可能完全不变，特征统计监控（PSI/KL）完全沉默——只能靠预测 vs 真值的反馈回路确认。
    • 伪相关/捷径学习：世界没变但模型学错了——靠"草地"认"牛"，牛在沙滩上就失效。ERM 鼓励捷径因为统计上更容易；Group DRO（最小化最坏组损失）显式缓解。

    漂移检测的量化工具

    • PSI（总体稳定性指数）：PSI = Σ(pᵢ−qᵢ)·ln(pᵢ/qᵢ)。阈值惯例（信货行业传统，非统计保证）：<0.1 忽略；0.1–0.2 轻微、查根因；0.2–0.25 中等、考虑重训；≥0.25 重大、需重训。连续特征用 10–20 箱、每箱至少 5% 观测、空箱平滑 ε=10⁻⁸。
    • KL / JS 散度：KL 不对称（基线→当前），JS 有界 [0, ln2] 更好选阈值。KL<0.05 忽略、0.05–0.1 中等、≥0.1 显著。
    • 显著性检验：两样本 KS 检验（D_{n,m} > c(α)√((n+m)/nm)，c(0.05)≈1.36）；类别特征用卡方；多特征同时监控需 Bonferroni/FDR 校正。
    • 快速判别：均值偏移 0.05、σ=0.3、n=1000 → 标准误 0.009 → 偏移 5.3 个标准误，p<0.001——统计显著 ≠ 立即重训，是"确认的漂移告警、未确认的模型回归"，先调查、加密监控、关联性能指标。

    重训决策框架（三级）

    1. 自动监控：高重要性特征 PSI>0.1、连续特征 KL>0.05、KS p<0.01（校正后）即告警；
    2. 性能关联：降精度 >3% 且伴随漂移 → 重训；有漂移但性能稳 → 继续监控查来源；性能降但无漂移 → 查概念漂移或标签偏移；
    3. 行动规则：关键特征 PSI>0.25 且精度降 >5%、或概念漂移确认/合规要求 → 立即重训；PSI 0.1–0.25 且性能稳定、或漂移局限在非预测特征/可能是季节性 → 先调查；全特征 PSI<0.1 且性能正常 → 继续监控。

    工作示例（欺诈模型，六个月生产）：国家特征 PSI=0.065（主要贡献来自"其他"桶增长 0.047）→ 忽略；交易额 KL=0.052 → 中等；KS 检验 p<0.001 统计显著 → 综合决策：加密监控频率（月改周），而非立即重训。

    生成式 AI 的鲁棒性

    LLM 把失败面从"分类错误"移到语义可靠性：流畅但无事实依据的输出，系统看起来依然健康。不确定性量化（UQ）让系统知道自己在猜：输出分布熵监控（平坦分布→高不确定性→转人工/拒答）；token 级 log-prob 定位"自信→猜测"的转折段；自一致性（同一问题多次采样，五次答案互相矛盾即视为不稳定并抑制）。RAG 场景的鲁棒性取决于检索质量——检索噪声可让模型忽略参数知识转而传播上下文错误，需重排与上下文校验。提示注入同样是鲁棒性失败：能被轻易说服无视行为约束的模型，就是没能在对抗输入下维持输出不变量。输出护栏（轻量分类器扫描政策违规/毒性/逻辑错误）是最后一道验证。

    输入级攻击

    对抗攻击谱系

    FGSM（单步，x_adv = x + ε·sign(∇ₓL)，便宜所以是对抗训练的主力）→ PGD（多步迭代+投影回范数球，白盒鲁棒性标准基准）→ JSMA（Jacobian 找最有影响力特征、小扰动定向）→ C&W（优化最小扰动，破解过防御蒸馏等早期防御——鲁棒性声明必须对优化型攻击评估，不能只测 FGSM/PGD）→ EAD（弹性 net 稀疏扰动）。黑盒靠可迁移性（替身模型离线构造、转移攻击目标 API）；物理世界攻击（贴纸/对抗补丁/3D 物体）必须穿过摄像头、光照、距离、压缩——鲁棒性要对着部署的传感器回路评估，不能只测数字图像。

    数据投毒

    对抗攻击骗一个训练好的模型（推理时）；投毒让模型从一开始就学错（训练时）。四类目标：可用性攻击（标签翻转，整体报废）、目标攻击（特定输入出错，聚合指标看不出）、后门攻击（隐藏触发器，干净精度正常）、子群体攻击（特定人群降级，公平敏感场景最危险）。机制：标签修改 → 特征腐蚀（不可察觉扰动/触发模式）→ 生成式批量制造。进入路径：网络爬取、众包标注、用户提交、在线学习反馈回路（Tay：24 小时内被协调用户带偏）、联邦聚合（单个恶意客户端毒化全局模型）、车队学习（路面贴纸照片被收进训练集就从推理时攻击变成了训练时投毒）。

    Nightshade：投毒的防御性使用——艺术家给作品加人眼不可见的扰动，Stable Diffusion 仅混入 300 张毒图就开始"car→牛"的概念级错乱，且毒化概念会级联到相关概念（truck/bus/train）。典型的双刃剑：保护创作者的工具同样可破坏合法训练管线。

    对抗防御：一份预算清单

    防御是对特定威胁模型的预算化响应——保证越强，干净精度/训练算力/推理延迟/覆盖面代价越高。工作流四步：定义威胁模型（扰动预算、攻击者知识、攻击时机）→ 选预算花在哪（训练/认证/输入检测/服务护栏）→ 双向度量权衡 → 用比设计时更强的攻击做评估。

    • 对抗训练的代价（robustness tax）：ResNet-50 标准 ImageNet top-1 76%，ε=8/255 对抗训练后干净精度 ~50%——26 个百分点的干净精度税。PGD 式训练每 batch 要跑多步内层攻击，训练时间 3–10×（优化实现可重用梯度降低）。原则 18 的推论：许多场景用外部护栏（输入过滤、输出校验）比把鲁棒性训进权重更划算。
    • 认证防御（随机平滑）：g(x) = argmax_c Pr(f(x+δ)=c)，δ~N(0,σ²I)；认证半径 R = σ/2·(Φ⁻¹(p_A)−Φ⁻¹(p_B))。给数学保证但推理需大量噪声采样估计概率——只能用于异步审计或高风险安全联锁，进不了实时服务路径。
    • 检测：统计检验（KS/Anderson-Darling 比较输入分布 vs 基线——⚠️ 对抗扰动常保持边际分布只破坏联合结构，单变量检验会漏，需 MMD/嵌入空间度量）；特征挤压（降色彩精度/中值滤波后再比对预测，分歧大即异常）；不确定性信号（贝叶斯神经网络/集成不一致性/MC dropout——50 次 2ms 前向 = 100ms/请求，适合批打分不适合实时）。
    • 按威胁模型选防御：图像分类（逃逸）→ 对抗训练/随机平滑；推荐系统（投毒）→ 鲁棒矩阵分解/训练分布修剪离群；欺诈检测（漂移）→ 持续监控 + KS 统计自动重训触发，而非静态加固。

    数据投毒防御：保护训练供应链

    四层按序：

    1. 溯源与访问控制：最小权限原则——推理容器不应访问训练数据、训练任务不应触达生产库、模型不应有超出所需 API 的网络权限。注册表别名（staging/production）只允许窄集审计过的自动评估服务晋升。
    2. 异常检测与消毒：廉价闸门（Z-score、Tukey、原始特征 Mahalanobis 距离）抓统计离群；高维/多模态数据在预训练编码器的嵌入空间做 Mahalanobis/聚类（毒样本在原始特征上平凡、在语义空间是孤立点）；自编码器重构误差；谱签名——后门触发器必须强到压过自然特征，因而在激活协方差矩阵的主奇异向量上留下可检测痕迹，投影去除即可净化而无需知道触发器本身；影响函数（I(z, z_test) ≈ −∇θL·H⁻¹·∇θL，LiSSA 近似）定位"哪个训练样本导致这个错误预测"，但逆 Hessian O(P³) 太贵，只适合粗粒度归因。
    3. 鲁棒目标：Huber/Tukey/截尾均值损失压制离群样本的梯度贡献（平方损失下 100× 误差贡献 10000× 损失）；ℓ₁/ℓ₂ 正则；minimax/分布式鲁棒优化（Madry 形式化：min_θ max_{‖δ‖≤ε} L）；数据增强与随机子采样聚合。
    4. 表示级防御（SSL）：对比学习（SimCLR）/掩码建模（BERT/MAE）减少对单一监督捷径的依赖，预训练表示在部署分布偏离时迁移更好——但它不是鲁棒性保证，SSL 也能学到脆弱捷径，且预训练计算成本前置。

    运维铁律：把训练语料当供应链管理，而不是被动数据集——认证来源 → 消毒可疑数据 → 限制存活离群的影响 → 保留血缘使事故可回溯到被污染的源批次。

    经验与常见坑

    • 对抗样本不是学术玩具：物理补丁/贴纸攻击在受控设置下可裸眼可见地骗过视觉模型，且防御成本真实（PGD 训练数倍训练开销）。
    • 测试集通过 ≠ 鲁棒性：i.i.d. 测试集无法度量对真实偏移的韧性；95% 精度的模型可在关键边缘用例上 100% 脆弱。
    • 分布偏移监控不是可选项：模型常在置信度依旧很高时静默退化。
    • 别等攻击者控制训练管线才防投毒：干净标签投毒只需往公开数据集/爬取源注入，<1% 的污染比例就足以植入潜伏后门——投毒量小不能作为防御理由。
    • 对抗训练不是万能解：鲁棒性严格绑定训练时的威胁模型——防 ℓ∞ 的模型对 ℓ2/几何攻击可能是零保护。
    • 软件故障不能因为"模型是对的"就忽略：事故复盘的中心常是管线与数据问题，而非模型架构或对抗攻击；加固模型的同时必须测管线（schema 校验、预处理 parity、特征新鲜度、回滚演练）。
