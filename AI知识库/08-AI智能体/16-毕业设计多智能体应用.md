# 毕业设计：构建属于你的多智能体应用

<p class="note-date">更新于 2026-11-03</p>

**一句话定义**：HelloAgents 教程的收官章节——指导学习者把前 15 章所学的智能体范式、工具系统、记忆机制、通信协议等知识整合为一个完整的多智能体应用，并以开源协作（GitHub PR）方式提交到社区共创仓库。

毕业设计的核心价值在于综合应用：看教程不等于会做，真正的挑战是把知识落到实际问题上——如何设计完整系统、如何处理边界情况与异常。目标是让学习者独立设计实现一个完整智能体应用、熟练使用 HelloAgents 框架、掌握 Git/GitHub 协作、学会写清晰的项目文档，最终获得一个可展示的技术作品。

## 关键概念

### 提交形式与要求

以开源项目形式提交到 Hello-Agents 仓库的 `Co-creation-projects` 目录：

- **命名**：`{GitHub用户名}-{项目名称}`，如 `jjyaoao-CodeReviewAgent`。
- **内容**：可运行的 Jupyter Notebook（`.ipynb`）或 Python 脚本；完整依赖列表 `requirements.txt`；清晰 README；可选演示视频/截图/数据集。
- **提交方式**：GitHub Pull Request，社区 review 通过后合并。

### 选题指南

选题三原则：解决真实问题（不为技术而技术）、有限时间资源内可完成、能清晰展示技术能力。五个推荐方向：

| 方向 | 示例选题 |
|---|---|
| 生产力工具 | 智能代码审查、文档生成器、会议助手（纪要+行动项）、邮件助手 |
| 学习辅助 | 学习伙伴（推资源+出题）、论文助手（查文献+总结）、编程导师、语言学习 |
| 创意娱乐 | 故事生成器、有个性的游戏 NPC、音乐推荐、菜谱助手 |
| 数据分析 | 数据分析师（分析+可视化+报告）、股票分析、舆情监控、竞品分析 |
| 生活服务 | 健康助手、理财助手、购物比价、自然语言智能家居控制 |

**示例选题（CodeReviewAgent）**：人工代码审查耗时易漏、静态分析工具不懂语义，因此做一个理解代码语义的智能审查助手。核心功能五项：代码质量分析（风格/命名/注释）、潜在 bug 检测（逻辑错误/边界条件/资源泄漏）、性能优化建议、安全漏洞扫描（SQL 注入/XSS）、最佳实践推荐。预期成果：可运行 Notebook，支持 Python/JavaScript 等主流语言，输出结构化 Markdown 审查报告。

### 开发环境与工作流

1. **环境**：Python 3.10+（`pip install "hello-agents[all]"`）、Git（配置用户信息 + SSH 密钥）、Jupyter（推荐 JupyterLab）。
2. **Fork 工作流**：Fork 官方仓库 → 克隆自己的 Fork → `git remote add upstream` 加上游便于同步更新 → 建开发分支 `feature/项目名称`。
3. **项目目录**：在 `Co-creation-projects/` 下建自己的项目文件夹，推荐结构：README.md、requirements.txt、main.ipynb，可选 data/、outputs/、src/（agents/、tools/、utils/）。
4. **README 模板要点**：一句话描述、项目简介（解决什么问题/特色功能/适用场景）、核心功能清单、技术栈（框架 + 智能体范式如 ReAct/Plan-and-Solve + 工具与 API）、快速开始（环境要求/装依赖/配 API 密钥/运行）、使用示例、项目亮点、性能评估（准确率/响应时间）、未来计划、许可证、作者、致谢。
5. **Notebook 结构建议**（7 部分）：项目介绍 → 环境配置（装依赖、加载 .env）→ 工具定义（继承 BaseTool，写 name/description/run）→ 智能体构建（HelloAgentsLLM + SimpleAgent + add_tool）→ 功能演示（基础 + 复杂场景）→ 性能评估（可选）→ 总结与展望（功能/挑战/改进）。

```python
# 自定义工具与智能体的最小模式（骨架）
class CustomTool(BaseTool):
    name = "tool_name"
    description = "工具描述"
    def run(self, query: str) -> str:
        ...  # 工具逻辑
        return "结果"

agent = SimpleAgent(name="智能体", llm=HelloAgentsLLM(), system_prompt="系统提示词")
agent.add_tool(CustomTool())
```

### 提交前自检清单

代码能跑无报错；README 完整；requirements.txt 齐全；有使用示例；注释适当；输出符合预期；处理常见异常；结构清晰命名规范；大文件已妥善处理。

### 大文件处理（避免主仓库膨胀）

硬性限制：项目总大小不超过 5MB，禁止直接提交视频、大型数据集、模型文件。三种方案：

1. **外部链接（推荐）**：大文件传外部平台，README 给下载链接。数据集 → 百度网盘/Google Drive/Kaggle/HuggingFace Datasets；视频 → B 站/YouTube；模型 → HuggingFace Models/ModelScope；图片 → GitHub Issues/图床。
2. **独立资源仓库**：资源多时建 `项目名-resources` 仓库，README 说明克隆与放置方法。
3. **示例数据**：主仓库只放小规模示例数据（如 100 条），完整数据集外链下载后解压到 data/。配套 `.gitignore` 忽略大文件。

### Pull Request 流程

- **Git 提交**：`git status` 检查 → `git add` → 按 Conventional Commits 提交（`feat: 添加XXX毕业设计项目`）→ `git push origin feature/项目名称`。提交类型规范：feat（新功能/项目）、fix（修 bug）、docs、style、refactor、test、chore。
- **PR 设置**：Base 为官方仓库 main 分支，Head 为自己 Fork 的 feature 分支。
- **PR 标题统一格式**：`[毕业设计] 项目名称 - 简短描述`。
- **PR 描述模板**：项目信息（名称/作者/类型）、简介（2-3 句）、核心功能清单、技术亮点（用了什么范式/实现了什么/优化了什么）、演示效果（截图/GIF）、自检清单、其他说明。
- **响应 Review**：看评论 → 按建议改代码 → 提交更新（`fix: 根据review意见修改XXX`）→ 在 GitHub 回复 reviewer 说明修改。

## 示例项目：CodeReviewAgent 完整解剖

作者 @jjyaoao，路径 `Co-creation-projects/jjyaoao-CodeReviewAgent/`。结构：README.md、requirements.txt、main.ipynb（快速演示+完整功能）、.env.example、.gitignore、data/sample_code.py、outputs/review_report.md。

核心实现模式（单智能体 + 多工具）：

1. **自定义工具继承 Tool 基类**，实现 `run(parameters)` 与 `get_parameters()`：
   - `CodeAnalysisTool`：用 Python `ast` 模块做静态分析——统计函数/类数量、代码行数、函数与类名列表；语法错误捕获返回提示。
   - `StyleCheckTool`：规则式 PEP 8 检查——行超 79 字符、缩进非 4 的倍数等问题。
2. **ToolRegistry 注册工具**，SimpleAgent 挂上注册表；系统提示词规定工作流：先用 code_analysis 分析结构 → 再用 style_check 查风格 → 基于结果写含结构分析/风格问题/潜在 bug/性能建议/最佳实践的 Markdown 报告。
3. **运行**：读入示例代码 → `agent.run("请审查以下Python代码: ...")` → 结果落盘 `outputs/review_report.md`。

设计启示：LLM 负责语义理解与报告撰写，确定性检查交给传统工具（ast/规则），工具结果作为 Agent 的客观依据——这是"智能体 + 传统工具链"的典型分工，比纯 LLM 判断更可靠。

## 经验与常见坑

- **别为大而全**：选题优先真实、小而完整；小的原创作品同样被收录，自己动手的都值得珍惜。
- **提交前跑一遍自检清单**：能跑、文档全、依赖全、有示例，四项缺一不可，否则 review 来回拉扯。
- **API 密钥不进仓库**：用 `.env` + `.env.example` 模式，`.gitignore` 排除 `.env`。
- **PR 标题与 commit 信息守规范**：标题 `[毕业设计] 项目名 - 描述`、commit 用 feat/fix 等类型前缀，便于社区管理检索。
- **大文件是主仓库杀手**：5MB 红线，视频/数据集/模型一律外链或独立仓库。
