# Agent 的自我进化

<p class="note-date">更新于 2026-11-03</p>

**一句话定义**：Agent 的自我进化（Self-Evolution）即外部化学习——不改模型参数，把经验从临时上下文中提炼、压缩、结构化，沉淀为可持久化、可检索、可复用的外部资源（知识库、Skill、工具），包含"从经验中沉淀知识"与"主动发现和创造工具"两个维度。

即使最前沿的模型，面对特定企业的退款流程、某运营商的话术、冷门 API 的调用方式仍像新员工两眼一黑。改模型权重的更新周期以周计，而现实中新 API 上线、需求持续变化——Agent 需要更轻量、更即时的进化机制。它与后训练互补：后训练解决"如何让模型更聪明"，自我进化解决"如何让 Agent 更能干"。

## 核心原理

### 学习为什么不会自动发生

关键在注意力机制：上下文学习的内部机制更像**检索**而非推理——擅长"第 37 个笼子里是什么猫"式的一步命中，不擅长"100 个笼子里共有多少只黑猫"式的归纳统计（后者需要遍历记录、维护状态，本质是思考）。把原始经验一股脑堆进上下文，模型能"记得"却不会自动"提炼"成可复用规律；且上下文越长噪声越多、注意力被稀释（上下文腐化），无限上下文反而让检索质量持续下滑。Karpathy 的洞察可反读：模型"记性差"是特性而非缺陷，它逼着我们**主动、显式地做知识提炼**。一句话：学习不会自动发生，必须被显式设计出来。

### 三种学习范式的分工

- **后训练**：RL 固化到参数，成功率高、延迟低、跨任务通用，但成本高周期长。
- **上下文学习（ICL）**：提示词内示范做临时适应，快但会话结束即消失。
- **外部化学习**：沉淀到模型之外的文件/知识库/工具，持久、可解释、可随时修正。

协同而非竞争：事实性知识交给 RAG 与外部化存储，稳定行为与格式交给后训练，当下临时信息交给上下文学习。

### 外部化学习的循环与三种产物

循环：完成任务 → 提炼经验（总结·压缩·结构化）→ 存入外部系统 → 检索复用，形成跨会话的正向积累。

| 产物形态 | 承载内容 | 示例 | 使用方式 |
|---|---|---|---|
| 知识库条目 | 事实和规则 | "该银行要求提供开户行地址" | 语义搜索或 grep 检索 |
| 专用代码工具 | 可重复的操作流程 | "查询账户余额的 API 调用序列" | 固化为代码、参数化调用 |
| Skill 文档 | 复杂但常变的工作策略 | "处理保险理赔的最佳实践" | 自然语言文档、按需加载 |

经验法则：纯事实存知识库；经常用且参数复杂的写成代码；经常变且涉及策略判断的写成 Skill 文档。知识载体多用 Markdown + 文件系统而非人工知识图谱——自然语言是模型最擅长处理的格式，能随模型能力持续扩展。

## 从经验中学习

### 经验学习机制分层

| 层面 | 机制 | 解决什么问题 |
|---|---|---|
| 知识提炼 | 策略摘要、工作流录制、失败反思 | 从成功与失败经验中提取可复用知识 |
| 知识组织 | Skills、睡眠整合 | 知识结构化存储和索引 |
| 知识应用 | 系统提示词优化 | 知识注入行为模式 |
| 工程支撑 | 跨会话续跑 | 长任务持续执行 |

### 策略摘要（Strategy Summary）

把一次成功解题过程浓缩为结构化经验笔记（用了什么方法、踩了什么坑、关键步骤），向量化入库；新任务先语义检索最相似的成功案例，作为"成功范例"注入系统提示词。判断标准是**可迁移性**：只对某次特定输入有效的修正不应进入长期记忆。代表：GAIA 基准上的 gaia-experience 项目（AWorld 框架）。

### 工作流录制与回放

类似 Excel 宏录制：首次用多模态 LLM 走"观察-思考-行动"完成操作，同时录制结构化步骤（操作类型、目标元素 XPath、参数、执行后验证信息）；成功后生成语义标签，存为参数化工作流。回放阶段按语义相似度匹配工作流，用 Playwright 等待机制 + 轻量 LLM 提取实际参数直接执行，无视觉思考——速度提升数倍、成本大降。某步失败（元素找不到/超时）即标记工作流"可能过时"，回退学习模式重学。

两个最脆弱环节的严格版处理（PreAct 思路）：
1. **何时敢信回放**：把成功操作序列编译成带"验证谓词"（回放前必须在真实屏幕上成立的界面模式）的状态机程序，"先看清、再动手"；谓词不成立就交还完整 Agent 重来。命中缓存的重复任务可快 8.5–13 倍。
2. **别把坏程序存进去**：编译完成后立即重置环境从头回放验证"真的做成了"才准入库——防止"流程走完但没把事办成"的假成功程序污染库。原则：**流程记忆也要有验证闸门，自我改进的循环才不会腐坏**。

### 从失败中学习

失败经验信息量甚至更大（一次失败明确排除一条路径）。两种形态：**错误模式库**（什么情况下用什么方法会失败、失败信号是什么）与**负面规则**（"不要用打电话方式办理该运营商退订"）。代表工作 Reflexion（2023）：任务失败后用自然语言反思原因，存入情景记忆（episodic memory），下次同类任务作为额外上下文读取——全程不改参数，是"不改权重的进化"的经典范例。

### Skills：领域知识的结构化外部化

Skill 是"岗位操作手册"：用人类可读文本承载知识，更新快（不重训）、可审查（人类能直接修改）、可迁移（换模型/系统可用）。Anthropic 的 Skill Creator 是"能创造其他 Skills 的元能力"——Agent 通过对话理解场景、分析可复用资源，生成含 scripts/references/assets 和 SKILL.md 的完整 Skill 包，实现"不仅能用 Skill，还能造 Skill"的自举循环。Claude Code 的 CLAUDE.md 机制同理：首次接触代码仓库主动通读并生成项目指南，持续引用更新。

### 睡眠学习：用户记忆的自主进化

类比人类睡眠期记忆整合：零散经验在离线被重组、去冗余、与已有知识融合。整理对象主要是**用户记忆**（"你是谁、偏好、习惯"）而非共享知识库（后者由离线管道批量灌入、少变动）。

- **Claude Code**：记忆存为带 frontmatter 的 Markdown 小文件（一条事实一文件），MEMORY.md 索引导航。后台周期性整合，双重门控（时间间隔 + 新会话数量）触发独立子 Agent 执行四阶段：定向（读索引了解全貌）→ 采集（搜值得持久化的新信息、检测矛盾）→ 整合（合并进已有主题文件、相对日期转绝对、删除被证伪事实）→ 修剪与索引。关键设计：整合异步后台完成不干扰交互；分布式锁防并发重复；权限限定在记忆目录内。没有定期整合，记忆库会退化为低信噪比的信息堆积。
- **Hermes**（Nous Research）：常驻进程（daemon）跨会话自主进化。四层记忆：提示词记忆（MEMORY.md/USER.md，刻意限几千字符逼 Agent 取舍）、会话检索（SQLite FTS5 全文索引，检索片段先 LLM 摘要再注入）、技能库（渐进式披露，默认只加载名字与摘要）、用户建模层。工具调用超 5 次、从错误中恢复、收到用户纠正、跑通非显然工作流等条件触发经验固化为技能，优先以 patch 增量更新。

### 系统提示词的自动优化

Karpathy 提出"系统提示学习"（System Prompt Learning）：LLM 像《记忆碎片》主角，每次醒来不记得之前的事，而我们没给它记录本。系统提示词（如 Claude 的约 1.7 万词）里已含大量人工编写的问题解决策略（如数字母时先给每个字母编号），这类知识应由系统自动从边界案例中学习沉淀。与 RL 的关键差异在**反馈通道的信息量**：RL 只有一个标量结果奖励（对/错，1 比特），自然语言复盘是一整段描述——同样一次失败，系统提示学习吸收的信息远多。其本质是通过**边界情况**让规则边界更清晰（"用户不满意政策"算不算超出能力范围？）。可从单个失败案例立即学，数据效率高且完全可解释。

实现方式：
- **Coding Agent 生成 diff + 人工审核**：读现有提示词、生成精确代码级修改、保证一致性，人类专家终审。适合在线、逐案例演进、高风险场景。
- **自动化框架**：DSPy（提示词当作可优化参数，评估集上自动搜索示例与措辞）；OPRO（LLM 自当优化器，基于历史提示词与得分迭代改写）；GEPA（对失败轨迹做自然语言反思进化提示词，维护帕累托前沿保留互补候选，多项任务超过 GRPO 微调且采样少 1-2 个数量级）。适合离线批量优化。实践可互补：框架做初始优化，diff 方案做上线后持续演进。

### 长任务的跨会话续跑

工程支撑层：把状态写到模型之外。长任务拆成两个角色——Initializer Agent（运行一次，生成 feature-list.json、初始化脚本、初始 git commit、progress.json）+ Coding Agent（每轮从进度文件和 git log 恢复现场，实现一个功能、跑测试、更新 passes 字段、提交后退出）。关键约束：进度放文件而非上下文；清单用 JSON 而非 Markdown（结构化更稳定）；全部 passes 才算完成。任务超过半小时，崩溃恢复是必选项。

## 从工具使用者到工具创造者

### 预定义工具集的根本局限

封闭领域预定义十几个工具或许够用；但通用 Agent 面对的问题：现实所需工具几乎无限无法预枚举；相似工具接口常与需求不匹配；大量服务不是 Agent 友好接口，适配一个就要一次人工开发。预定义范式把 Agent 能力边界锁死在人类工程师的预见上。转变方向：**最小预定义，最大自我进化**（Alita 论文）——给少量基础工具作为与世界交互的起点，自我进化机制提供无限扩展潜力，把全球开源生态变成可用资源池。

### 自主寻找与创造工具的流程

需求识别 → 工具搜索（开放世界找现成库）→ 代码封装 → 工具注册（纳入库可复用）。无现成方案时从头编写：关键差异在**代码的去向**——传统 Agent 的代码执行是一次性的（跑完丢弃），自我进化范式下代码被创造为可复用的模块化工具持久入库，行为确定、可测试，不依赖临时上下文。MCP 是发现和调用工具的标准协议（"工具市场的通信规范"）。典型案例：Alita 面对需要"YouTube 字幕提取"的任务，经 MCP 头脑风暴识别缺口 → Web Agent 搜索到 youtube-transcript-api → Manager Agent 读 README 理解 API → 封装为 MCP 工具执行并入库复用。

### Voyager：开放世界持续学习的蓝图

NVIDIA 的 Minecraft Agent，三大要素：
1. **自动课程生成器**：按当前状态提出"最近发展区"内的下一目标（不太简单也不太难）。
2. **技能库**：成功经验提炼为可执行代码持久存储，层次化可组合（"制作木镐"调用"砍树""制作木板"）；新任务检索组合已有技能，不必每次从头让 LLM 思考。
3. **迭代提示机制**：失败时收集环境反馈、错误消息、自验证结果整合进提示，迭代直到稳定。

效果：显著更快解锁木/石/铁/钻石科技树，独特物品数为基线 3.3 倍。本质是外部化学习实现从"临时适应"到"永久积累"的跨越。

### 三层能力的持续积累

- **工具层**：新工具基于已有工具构建，层次化体系（有"查股价"后可建"投资组合分析"）。
- **知识层**：哪些库适合哪类任务、哪些 API 免 key、哪些库有兼容性问题——沉淀为启发式规则或案例库。
- **策略层**：元学习——自我进化能力本身在进化。短期靠系统提示词与 Skill 沉淀元经验，长期稳定后可由 RL 固化到权重（外部化学习与后训练的接力分工）。

## 经验与常见坑

- **供应链攻击**：自动搜索安装开源库可能中恶意 PyPI/npm 包。缓解：沙盒运行、自动安全扫描。
- **能力漂移**：长期无监督运行中，积累的策略与工具可能偏离设计者意图。缓解：工具类型白名单、限制工具库增长、定期人工审核。
- **工具质量退化**：未经充分测试的自动生成工具，bug 会通过复用传播——一个有 bug 的工具被反复调用，危害远大于一次性推理错误。
- **记忆与经验投毒**：任务中接触的网页/工具输出可能含注入指令，未经审查就沉淀为长期记忆，攻击从一次性变持久性（受害的是"知识"本身，比会话内提示注入更隐蔽难清除）。三层防御：写入前审查与来源标记；经验与指令通道隔离（检索出的经验以"参考资料"而非"命令"身份注入）；检索时注入模式扫描。知识保鲜与投毒防御是同一枚硬币的两面，都要求经验库具备来源追溯与淘汰机制。
- 评估自我进化要用特殊设计的数据集：任务描述只说目标不暗示工具名（"获取某视频字幕"而非"用 youtube-transcript-api"），分层验证任务正确性、发现有效性、创造质量（LLM-as-a-Judge 按 Rubric）、复用能力。
