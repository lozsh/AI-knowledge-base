# AI 智能体：现状综述（2026）

<p class="note-date">更新于 2026-11-06</p>

**一句话定义**：截至 2026 年末，智能体已从论文概念变成三大类商品化产品——编码智能体、通用助理、垂直智能体，并由 MCP/A2A/AG-UI 三个协议分层打通"智能体—工具—智能体—用户"的连接，但企业落地成功率低、评测基准加速失效，仍是格局中最突出的两个裂缝。

本篇聚焦"现在的格局"：谁在做、靠什么连、用什么搭、落地到什么程度、怎么衡量。各技术点的原理与构建方法见同目录其他笔记。

## 时间线：从协议发布到智能体普及

- **2024 年 11 月**：Anthropic 发布 Model Context Protocol（MCP，首个规格版本 2024-11-05），为"智能体—工具/数据"连接立标准。
- **2025 年 2 月**：Claude Code 以命令行工具形态发布研究预览；GitHub Copilot 推出 agent mode（2 月 6 日），编码智能体赛道开赛。
- **2025 年 3–4 月**：OpenAI 发布 Agents SDK（Swarm 实验框架的生产化升级）；VS Code agent mode 向全体用户开放并接入 MCP；Google 发布 A2A 协议；OpenAI 开源 Codex CLI（4 月 16 日）。
- **2025 年 5 月**：OpenAI Codex 云端智能体上线研究预览（codex-1，基于 o3 优化）；Claude Code 随 Claude 4 正式 GA（5 月 22 日）。
- **2025 年 8 月**：MIT NANDA 发布《The GenAI Divide》报告，称约 95% 的企业生成式 AI 试点对损益表没有可衡量影响。
- **2025 年 9 月**：Scale AI 发布 SWE-bench Pro，将评测拉向企业级长时程任务。
- **2025 年 10–11 月**：Cursor 发布自研编码模型 Composer（10 月 29 日）；Claude Code 网页版上线（10 月 20 日）；Anthropic 发布 Claude Opus 4.5（11 月 24 日），宣称 SWE-bench Verified 达 80.9% 的业界最优。
- **2026 年上半年**：Codex 桌面应用发布（2 月，路透报道称月活开发者超百万）、周活用户突破 200 万并推出 Windows 版与安全审查智能体 Codex Security；Claude Code Security 上线（2 月）；MCP 发布 2026-07-28 版规格，将协议层改为无状态，并把 Tasks 等长时任务能力移入可选扩展。
- **2026 年年中至今**：Codex 应用并入 ChatGPT 桌面端（7 月 9 日）；A2A 于 8 月加入 Linux Foundation 旗下的 Agentic AI 基金会；跨会话记忆巩固（如 Claude 的 "Dreaming" 研究预览，5 月）成为长时程智能体的新竞争点。

## 产品格局

### 编码智能体：竞争最激烈的赛道

编码是智能体最先跑通"可验证反馈闭环"的领域，也因此成为三大巨头正面交锋的主战场。格局的关键事实：

| 产品 | 所属 | 形态 | 关键节点 |
|---|---|---|---|
| Claude Code | Anthropic | CLI / IDE 插件 / 网页 / SDK / Managed Agents | 2025-02 预览，2025-05 GA；被微软、谷歌内部采用 |
| Codex | OpenAI | CLI / 云端 / 桌面 / 并入 ChatGPT | 2025-04 CLI，2025-05 云端；2026-03 周活超 200 万 |
| Cursor | Anysphere | IDE 优先 | 2025-10 发布自研 MoE 编码模型 Composer，主打 4 倍生成速度 |
| GitHub Copilot | 微软 | IDE 内 agent mode + MCP | 2025-02 预览、04 全量开放，靠既有装机量渗透 |

三条路线的分化值得注意：Anthropic 与 OpenAI 都把编码智能体做成了"全家桶"（CLI + 云端 + IDE + SDK），Cursor 则走"模型自研 + IDE 深度体验"路线。安全子场景（Claude Code Security、Codex Security）在 2026 年率先独立成产品，说明编码智能体已深入到足够细分的环节。社会层面，2025–2026 年冬假期间"vibe coding"（非程序员用自然语言驱动编码智能体做出应用）破圈，把编码智能体从开发者工具变成了大众产品。

### 通用助理与深度研究

以 ChatGPT、Claude、Gemini 为代表的通用助理全部完成"聊天→执行"的转型：浏览网页、操作文件、跑深度研究、执行多步骤任务。深度研究（Deep Research）是通用助理智能体化的样板品类：OpenAI 于 2025 年 2 月 3 日首发，智能体自主浏览 5–30 分钟产出带引用的报告；2026 年 2 月升级到 GPT-5.2 底座并支持连接 MCP 服务器，检索能力第一次以协议方式对外开放。通用助理是编码智能体之外的第二增长极，其特点是任务面宽但单任务成功率低于垂直智能体。

### 垂直智能体

客服、销售、安全运营、数据分析等垂直场景由初创公司与云厂商共同填补。MIT 报告的一个关键数据：外购专业化厂商方案的成功率约 67%，而企业自建的成功率只有前者的约三分之一——"买胜于建"是当前企业智能体市场的普遍经验。垂直赛道同时也暴露了智能体的双刃剑属性：2025 年 8 月 Anthropic 披露有犯罪组织利用 Claude Code 实施勒索攻击，11 月披露某组织用其自动化了八到九成的攻击流程——自动化能力一旦外溢，垂直智能体本身就是攻击面。

## 协议生态

协议是 2025–2026 年智能体格局中变化最大的一层，形成了清晰的分层：

| 协议 | 发起方 | 解决的连接 | 现状 |
|---|---|---|---|
| MCP | Anthropic | 智能体 ↔ 工具与数据 | 事实标准；官方 SDK 覆盖十余种语言（C# 与微软、Go 与谷歌合作维护）；Claude、ChatGPT、VS Code、Cursor 等主流客户端全部支持；由 Linux Foundation 托管 |
| A2A | Google | 智能体 ↔ 智能体 | Linux Foundation 项目，技术指导委员会含 AWS、思科、谷歌、IBM、微软、Salesforce、SAP、ServiceNow 八家公司；2026-08 加入 Agentic AI 基金会；提供 Python/JS/Java/.NET/Go/Rust SDK |
| AG-UI | CopilotKit | 智能体 ↔ 用户界面 | 事件式双向流协议，与 LangChain、CrewAI 联合推出，微软、谷歌 ADK、AWS 等框架提供第一方集成 |

三个关键判断：其一，MCP 的"AI 界 USB-C"定位已经兑现——Agent Skills（Anthropic 2025 年 12 月）、MCP Apps 等围绕 MCP 长出的扩展表明它正在从"连接工具"扩展为"承载能力分发"的生态底座；其二，A2A 与 MCP 是互补而非竞争（工具连接 vs 智能体协作），双协议栈成为企业设计的默认假设；其三，协议之争已从"谁的协议"变成"基金会治理"，卡位基本完成，下一轮竞争在注册中心（Registry）、鉴权扩展等企业化能力上。

## 框架格局

| 框架 | 定位 | 现状要点 |
|---|---|---|
| LangGraph | 图结构编排 | 已过 1.0 里程碑（当前 1.x），与 LangChain 平台组成全家桶，是开源编排层使用最广的选择之一 |
| OpenAI Agents SDK | 模型厂官方轻量框架 | Swarm 的生产化升级：Agents、Handoffs、Guardrails、会话、追踪、MCP 集成内置 |
| Claude Agent SDK | Harness 即库 | 直接把 Claude Code 的智能体循环、内置工具、权限、会话、子智能体暴露为 Python/TypeScript 库；另有 Anthropic 托管沙箱运行的 Managed Agents |
| Microsoft Agent Framework | 企业 .NET/Python 生态 | AutoGen 与 Semantic Kernel 两套开源框架合并的产物，AG-UI 官方集成名单成员 |
| CrewAI 等 | 角色协作 | 面向多智能体编排的轻量选择，AG-UI 首批合作方 |

格局主线是**收敛**：研究型框架（Swarm、AutoGen 一代）让位于三条稳定的供给——模型厂官方 SDK（绑定自家模型与 Harness 优势）、图编排框架（复杂流程与平台化）、以及"把自家旗舰智能体开放为库"的新路线（Claude Agent SDK）。厂商把"能打赢自己产品的智能体"整套开放出来，是 2025–2026 年框架市场最重要的新变量。

## 企业落地现状

MIT NANDA《The GenAI Divide》（2025-08）给出的现状诊断：约 95% 的试点对损益表无可衡量影响，但瓶颈不是模型而是**组织的学习缺口**——通用工具在个人层面好用，却接不进企业工作流。其他要点：预算错配（过半生成式 AI 支出流向销售营销，而 ROI 最强的是后台自动化）；影子 AI 普遍存在；员工侧冲击集中在客服与行政岗位，且更多表现为岗位空缺冻结而非裁员。编码智能体是明显的例外赛道：三大产品的高频使用数据、安全细分产品的出现和巨头互相采用（微软、谷歌内部使用 Claude Code）都表明该场景已越过"试点"阶段。

落地路径上，2025–2026 年沉淀出三条被反复验证的经验：**买胜于建**（外购专业化方案成功率远高于自建）；**一线授权胜于中心实验室**（成功案例多由懂业务的线经理推动，而非集中的 AI 部门）；**深度集成胜于通用工具**（能嵌入工作流并随使用适应的工具才有留存）。这三条共同指向一个结论：智能体落地的瓶颈在组织与技术栈的接口处，不在模型能力本身。

## 评测现状与局限

- **SWE-bench Verified**：事实上的编码智能体标杆，但已逼近饱和——Claude Opus 4.5 的 80.9% 意味着剩余提升空间有限，且其对"人类用时"的估计方式（未含熟悉代码库的时间）使任务难度被系统性低估。
- **SWE-bench Pro**（2025-09，1,865 题、41 个活跃仓库）：把评测推向企业级长时程任务与防污染设计，前沿模型成绩显著回落，暴露了 Verified 分数与真实工程能力之间的缺口。
- **GAIA**（2023-11）：通用助理基准，人类基线 92% 对当时 GPT-4 + 插件的 15%；此后差距大幅收窄，但与 SWE-bench 同样面临天花板问题。
- **METR 时间视界**（2025-03）：改用"能完成多长的任务"度量智能体，发现 50% 可靠度下的任务时长约每 7 个月翻倍；2026-01 发布修订版 Time Horizon 1.1。

评测的共同困境：基准饱和速度快于新基准的构建速度、榜单分数与生产环境成功率脱节、长时程与真实工作流的评测方法尚未定型。选型时榜单分数只能作参考下限，不能作验收标准。

从 2025–2026 年的公开实践可以提炼三条经验：一是**任务时长比任务分数更有预测力**——METR 式"能独立完成多长的任务"比单题正确率更接近生产表现；二是**组合评测优于单一基准**——编码（SWE-bench 系）、通用助理（GAIA 系）、终端操作、长时程各取其一，按业务场景加权；三是**私有评测集不可省略**——公开基准污染风险随知名度上升，SWE-bench Pro 的 held-out 与商业集设计就是为了对冲这一点。

## 趋势判断

1. **协议栈固化，应用层重新洗牌**：MCP/A2A/AG-UI 的分层基本落定，竞争回到"谁把智能体体验做得最好"，协议红利从先发者转向能在注册中心、鉴权、合规上做深的企业化玩家。
2. **长时程任务成为下一个主战场**：METR 的翻倍曲线、跨会话记忆巩固、异步运行（后台/托管智能体）共同指向"以小时和天为单位"的任务，这要求 Harness 在记忆、断点续跑、成本控制上整体升级。
3. **多智能体协作从演示走向工程**：子智能体模式（Claude Agent SDK 内建）与 A2A 协议正在把"多智能体"从论文概念变成可调试、可治理的工程结构，但编排复杂度的成本仍常被低估。
4. **安全与治理成为产品力**：编码智能体被用于攻击的公开事件、以及两大厂商同步推出安全审查智能体，标志着"智能体安全"从研究议题变成产品线。
5. **智能体经济仍在探索**：按任务计费、智能体间支付等设想有大量试验，但尚未出现被广泛接受的结算基础设施——目前智能体商业模式仍以订阅和 API 用量为主。
