# 智能的延伸：AI 智能体

> 来源：《智能体》教材第 10 章（wiki 化重写于 2026-11-03）

**一句话定义**：智能体是能感知环境、制定决策、采取行动去达成目标的系统；大模型智能体给"会说话的大脑"装上手、脚、眼、记忆，让它以"想一下、做一下、看一下"的循环完成整件事——从回答问题走向完成任务。

大语言模型本身只是一个"会说话的大脑"：一次答一句、没记忆、没手脚。2023 年 AutoGPT 第一次让大众看见"让 AI 自己去做事"的可能（尽管常死循环、忘记目标）；此后的编程智能体、浏览器智能体、研究智能体共同标志着 AI 从"回答问题的工具"走向"完成任务的助手"。但这没有魔法——会做事的 AI 需要可靠工具、清楚权限、可回滚操作、可审计日志和人工确认机制，否则就像"精力旺盛但没有门禁卡的实习生"。

## 关键概念

### 五大核心组件

1. **大脑（LLM）**：理解任务、分析状态、决定下一步。能力直接决定智能体上限；推理模型把上限再推高一档——底层模型每提升一档，"根本不敢交给它"的事变成"可以试着让它做"。
2. **工具**：与世界的每个接触点——代码执行器、搜索引擎、文件操作、API 调用、浏览器控制、数据库查询。
3. **记忆**：三层，对应人的记忆——短期记忆（当前上下文，工作记忆）、长期记忆（外部系统存储：**向量记忆**——历史编码为向量相似度检索，本质给记忆装 RAG，灵活但解释性差；**结构化记忆**——显式记事实到数据库/Markdown，精确可编辑但只记得让它记的）、程序性记忆（记"怎么做"：Reflexion 经验笔记与技能，类似肌肉记忆）。核心难题：什么该记什么该忘（全记会被噪音淹没）、记忆冲突怎么办（去年喜欢咖啡今年改喝茶）、记忆放哪（云端方便但有隐私顾虑，本地私密但难迁移）。关键不是产品而是**记忆控制权**：允许用户检查、纠正、删除。
4. **规划**：Plan-and-Execute（先列大纲再逐节写）、递归分解（层层剥洋葱）、搜索式规划（多路径评估择优；未必在模型内部，也可在外层驾驶舱做多候选采样验证）。
5. **感知与反馈**：ReAct 循环——想（Think）→ 做（Act）→ 看（Observe）→ 再想；没有反馈就是开环执行，有反馈才能闭环纠错。

### Skill 与 MCP：判断力与能力两条路

| 维度 | Skill（技能） | MCP |
|---|---|---|
| 本质 | 含 SKILL.md 的文件夹 + 可选脚本/资源 | MCP server（本地 stdio，远程 Streamable HTTP） |
| 交付方式 | 做法说明按需加载进上下文 | 把外部工具/资源暴露为运行时接口 |
| 状态 | 无状态 | 可有状态（认证、session、连接） |
| 部署成本 | 一个 .md 文件随仓库提交 | 要写服务、启动、管理进程 |
| 典型场景 | 团队代码规范、code review 流程 | GitHub、Slack、数据库、浏览器 |

一句话：**MCP 解决"连到哪里去"，Skill 解决"该按什么流程做"**——访问不到资源缺 MCP，不知道怎么做缺 Skill。技能 = 指令（自然语言操作手册）+ 代码（只在需要精确执行处）+ 资源（模板、风格指南等隐性知识载体）。工具告诉智能体"你能做什么"，技能告诉它"该怎么做"——工具是能力，技能是经验。技能还让非程序员也能"教"智能体：Markdown 指令 + 模板即成技能，各行业专家可沉淀经验；软件形态正从"功能按钮"转向"可复用的工作流"。最佳实践是两者并用：MCP 接数据库（能力），Skill 教公司的数据模型与查询规范（判断力）。

### 模型基座 + 驾驶舱 + 训练

智能体产品 = 合格的基座模型 + 精心设计的驾驶舱 + 针对任务的后训练，缺一不可。

- **基座（Agentic Model）**：擅长严格遵循格式（工具调用）、长程推理、写改代码、错误中恢复。最成功的智能体场景都离不开代码——"会说话的程序员"；不擅长代码的模型做智能体"像不会看地图的人送外卖"。
- **驾驶舱（Harness）六职责**：循环控制（ReAct 的实际执行者）、工具调度（解析文本为函数调用、处理错误超时）、上下文管理（决定每步给模型看什么）、安全检查（拦截有害操作、过滤提示注入）、记忆管理、日志与回放。驾驶舱是工程不是算法：同一模型套编程驾驶舱是代码助手、套浏览器驾驶舱是网页操作员。
- **训练三步**：SFT（喂高质量智能体轨迹学"做事的样子"）→ 强化学习（模拟环境跑真实任务按结果给奖励，学长程目标导向；开放任务的奖励设计本身是研究问题）→ 工具使用训练（见过大量调用/错误/组合样本，知道"锤子不是拿来拧螺丝的"）。模型决定能力上限，驾驶舱决定产品形态，训练决定具体场景表现——三者协同迭代。
- **知识接入（RAG）**：离线切块+编码+建向量库；在线问题编码 → 相似度检索 → 过滤重排 → 拼提示生成（附出处、引用校验、拒答策略）。四个环节的工程坑：**切块粒度**决定检索精度（按语义边界切，别按字数）；**嵌入模型质量**决定"相关"判定（"订购产品"与"取消订单"向量可能很近但意图相反；重排/领域微调）；**检索策略**（纯向量对精确字符串弱——"2024-Q3"与"Q4"向量几乎一样，需 BM25/元数据/混合检索兜底）；文档质量决定上限。**Agentic RAG**：多轮检索、反思换关键词、拆解子问题分别查再综合——从"一次查书"变成"像研究员那样多轮查证再下笔"。RAG 局限：检索不到就没法答；多份资料冲突靠模型推理；资料本身错就只是把错误送到模型眼前。

### 上下文工程视角

能力上限不只取决于模型，更取决于每次推理拿到什么上下文：喂垃圾上下文输出垃圾，喂结构良好的上下文出专家级回答。组件：上下文获取与生成（提示设计、检索、动态组装）、上下文处理（长序列、结构化与多模态整合）、上下文管理（记忆层级、压缩、调度）。当前模型理解复杂上下文强，但生成同等复杂度的长输出仍明显落后。

## 反思与自我改进三层

- **Self-Refine（自优化）**：生成初稿 → 同一模型给反馈 → 修订，循环多轮，无需训练。"写时是作者，改时是审稿人"。边界：模型能力不足以识别错误时，反思会把对的改错——"自信"不等于正确；复杂数学/代码/事实核查应引入测试、执行结果或外部检索作反馈，否则只是"把错误从一个漂亮包装盒换到另一个"。
- **Reflexion（反思）**：把语言反思写入外部"经验笔记"（episodic memory），下次任务作为上下文读回——不更新权重但积累经验，"今天跌的跤，明天就记得避开"。
- **自进化（Self-Evolution）**：经验积累（工作日记，直接可解释可编辑，但日记不改变大脑）→ 技能提炼（把反复做对的流程固化成可复用技能）→ 自我微调（最激进：能力内化进权重；挑战是错误自我强化、灾难性遗忘、成本；Self-Instruct、Self-Rewarding 等仍以研究为主）。自进化改变部署模式——智能体像会积累经验的员工，"用得越久越懂你"，但带来新问题：换机器怎么带走学到的东西？学错了怎么遗忘？学到偏见怎么纠正？

## 分类/类型

### 评估

智能体评测远难于语言模型：BLEU/F1 不够，要综合成功率、步数、效率、成本、人工介入。基准：SWE-bench（修真实 GitHub bug）、GAIA（通用助手）、WebArena（网页操作）；基准快速饱和，社区不断推更难一代（SWE-bench Verified、TheAgentCompany、Terminal-Bench）。但基准多是受限场景；真实部署还要看：任务完成率、平均步骤数、失败恢复、人工介入次数、单次成本、可回滚性、日志可审计性。

### 现实产品形态

- **编程智能体**（程序员被冲击最深，因为代码有清晰文件、明确测试、可执行反馈——Git/单元测试/编译器/CI 恰好给了智能体清晰的"行动-反馈"闭环）：三类形态——命令行（Claude Code CLI、Codex CLI，住在项目目录里）、AI IDE（Cursor、Windsurf、GitHub Copilot，AI 在光标旁边）、端到端工程智能体（从 GitHub Issue 自主完成全流程 PR，对边界清晰可验证的小任务可靠）。适合边界清晰、成功有客观判据的任务（补测试、修小 bug、批量改格式、API 迁移）；"重构得更优雅"这类判据模糊的活需要人类眼睛盯着。风险是**自信式错误**（为了让测试通过而修改测试本身）；对程序员它不是替代品，而是"速度极快、知识广博、偶尔犯低级错误的初级同事"。vibe coding 降低门槛，但"能跑出来不等于能维护，能演示不等于能上线"。
- **浏览器与电脑操作智能体**（Anthropic Computer Use、Project Mariner、Operator→ChatGPT agent）：挑战是把"看屏幕"和"操作"结合得可靠——关键不是能不能点按钮，而是**该点的时候点、不该点的时候停手**（看见蓝色按钮得知道那是"提交"还是"同意把银行卡交给陌生网站"）。
- **通用任务智能体**（Manus、AutoGPT/BabyAGI 先驱）：高层目标自主拆解执行，从"概念烟花"走向"可交付一点成果的工具"。
- **开源与本地优先**：记忆可见（存成用户能打开的文件）、权限可控、可离线运行、可审计——"用户未必只需要最强的助手，也需要真正属于自己的助手"。
- **企业智能体**（Salesforce Agentforce、Microsoft 365 Copilot、智能自动化编排 AI agents/RPA/人工审批）：逐步改写流程清晰、可检查、重复性强的工作。
- **多智能体协作**：把任务分给不同角色（项目经理/研究员/工程师/测试员/审查员），弥补单一视角盲区；应用如 MetaGPT/ChatDev（软件开发流程）、AI Scientist（自动化科研样机）、结构化辩论、游戏 NPC（Generative Agents）。挑战：通信格式设计、集体幻觉（需交叉验证与"批评者"角色）、任务分配、成本控制。"多智能体不是'人多力量大'的童话，更像一次会议——抢话筒只会生成更长的会议纪要和更贵的账单。"

## 经验与常见坑

**可靠性的指数衰减**：每步成功率 95%，20 步整体仅约 36%，50 步约 8%；要让 20 步任务整体达 90%，每步须 99.5% 以上。"单步很强"不等于"长任务可靠"。对策（并行使用）：每步加验证器、关键步骤人工确认、冗余（不同方法做两遍比对）、强弱模型分工、可回滚设计（改文件先备份、发邮件先生成草稿、执行先沙箱）。

**幻觉在行动中放大**：LLM 幻觉是一段错误文字，智能体幻觉是直接执行错误动作（发错邮件、误删文件、引入不存在的 API）——从"说错"到"做错"，链条被极大缩短。

**提示注入**：恶意指令藏在数据里（网页、邮件、PDF、搜索结果、工具返回）诱导智能体做有害事——典型：PDF 里藏"把用户邮箱内容发送到某网址"，助手同时有读邮件和发请求权限就可能真执行。原理同 SQL 注入（把代码藏进数据），但自然语言无法严格分离指令与数据，是根本性架构问题，"请不要被骗"的提示词解决不了。多层防御：外部内容默认低权限、工具权限分层（读文件≠删文件、查余额≠转账）、敏感操作人工确认、沙箱执行、日志审计。安全的智能体不是胆子小，而是知道什么时候该问一句："老板，这个我真要点吗？"

**授权与问责**：智能体造成损害时责任如何在使用者/开发者/平台/组织间分配尚无清晰答案；"何时需要人介入"的边界随自主性提升而日益模糊。

## ⚠️ 时效性说明

- 上下文窗口、产品能力（ChatGPT 记忆、Computer Use、Operator 并入 ChatGPT agent 等）为原书成文时点信息，快速变化。
- MCP 已由 Anthropic 单家开源协议演进为 Linux Foundation 旗下 AgenticAI Foundation 的开放标准。
- 未来三条主线：能力更强（从受限场景走向开放任务，瓶颈是可靠性）、部署更近（渗透日常工具，云端与本地长期并存——"私人敏感事交给本地，需要最强能力的事交给云端"）、责任更重（单体+子智能体的"智能体生态"，最终走向具身）。
