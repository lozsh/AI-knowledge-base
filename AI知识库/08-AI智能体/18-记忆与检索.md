# 记忆与检索

<p class="note-date">更新于 2026-11-03</p>

**一句话定义**：记忆系统让智能体跨会话存储、检索、整合和遗忘信息；RAG（检索增强生成）在生成前从外部知识库检索相关内容注入上下文——两者分别解决 LLM 的"对话状态遗忘"和"内置知识局限"两大根本缺陷。

基于 LLM 的智能体面临两个根本性局限。**局限一：无状态导致的对话遗忘**——每次 API 调用都是独立计算，模型不自动记住上次对话，导致上下文丢失、个性化缺失、学习能力受限、多轮对话前后矛盾。（注意区分：框架内 SimpleAgent 同一实例的 `_history` 只暂存当前对话，不跨会话持久化，也不能长期检索、遗忘和整合。）**局限二：内置知识静态有限**——训练数据有时间截止点、专业领域深度不足、易幻觉、缺信息来源，RAG 为此而生：生成前先从外部知识库检索最相关的信息作为上下文。

设计上借鉴认知科学的人类记忆层次：感觉记忆（0.5-3 秒，容量大）、工作记忆（15-30 秒，7±2 项）、长期记忆（近乎无限，分程序性记忆/陈述性记忆，后者又分语义记忆——一般知识与概念、情景记忆——个人经历事件）。

## 核心原理

### 记忆系统的架构与工作流程

HelloAgents 将记忆和 RAG 设计为两个独立工具（`memory_tool` 管交互信息，`rag_tool` 检索知识库并可回存重要结果），遵循"封装为标准工具而非新建 Agent 类"的原则。记忆系统四层架构：

- **基础设施层**：MemoryManager（统一调度）、MemoryItem（标准化记忆项）、MemoryConfig、BaseMemory（通用接口）
- **记忆类型层**：WorkingMemory、EpisodicMemory、SemanticMemory、PerceptualMemory
- **存储后端层**：Qdrant（向量）、Neo4j（图）、SQLite（文档）
- **嵌入服务层**：云端 API（DashScope）/ 本地 Transformer / TF-IDF 兜底

认知科学的记忆形成五阶段映射为工程操作：编码→add、存储→各记忆模块、检索→search、整合→consolidate、遗忘→forget。

### 四种记忆类型与评分公式

| 类型 | 定位 | 存储 | 检索评分公式 |
|---|---|---|---|
| 工作记忆 | 当前会话临时上下文，容量 50 条 + TTL 自动清理，纯内存 | 内存 | (TF-IDF 相似度×0.7 + 关键词×0.3) × 时间衰减 × (0.8+重要性×0.4) |
| 情景记忆 | 具体事件与经历，支持时间序列/会话级回顾 | SQLite + Qdrant | (向量相似度×0.8 + 时间近因性×0.2) × (0.8+重要性×0.4) |
| 语义记忆 | 抽象知识、概念、规则；自动提取实体关系建知识图谱 | Qdrant + Neo4j | (向量相似度×0.7 + 图相似度×0.3) × (0.8+重要性×0.4) |
| 感知记忆 | 图像/音频等多模态，支持跨模态检索 | 按模态分离的 Qdrant 集合 | (向量相似度×0.8 + 时间近因性×0.2) × (0.8+重要性×0.4) |

权重设计思想：情景记忆更强调时间近因性（事件的时间相关性重要）；语义记忆更强调图检索（关系推理补充语义匹配，发现概念间隐含关联）；重要性权重限制在 [0.8, 1.2]，避免重要性过度扭曲相似度排序。时间近因性用指数衰减 `exp(-0.1 × age_hours / 24)`，最低保 0.1 基础分——模拟人类遗忘曲线。感知记忆按模态分离存储（text/image/audio 各自独立向量集合），避免维度不匹配。

### MemoryTool 的关键操作

统一入口 `execute(action, **kwargs)`，"统一入口、分发处理"模式。核心操作：

- **add**：添加记忆（四类型可选，importance 默认 0.5）；自动管理会话 ID、推断多模态文件类型、补充时间戳元数据。
- **search**：支持单/复数类型参数，`min_importance`（默认 0.1）过滤低质量记忆。
- **forget**：三种遗忘策略——基于重要性（删低于阈值的）、基于时间（删超龄的）、基于容量（超限时删最不重要的）。
- **consolidate**：记忆固化——把重要性超阈值（默认 0.7）的工作记忆提升为情景记忆、重要情景记忆提升为语义记忆，模拟短期记忆向长期记忆的转化，全自动执行。

MemoryTool（用户接口与参数处理）与 MemoryManager（核心管理逻辑）分层，体现关注点分离；Manager 按配置选择性启用记忆类型，避免不必要的资源消耗。

## RAG 系统

### 基础与发展历程

RAG = 检索（从知识库查相关内容）+ 增强（检索结果融入提示词）+ 生成（输出准确且可溯源的答案）。流程分两大环节：数据准备（提取→分块→向量化→可检索库）与应用（检索→注入 Prompt→生成）。

三阶段演进：

1. **朴素 RAG**（2020-2021）："检索-读取"，TF-IDF/BM25 关键词匹配，文档直接拼接上下文——字面匹配好，不懂语义。
2. **高级 RAG**（2022-2023）：稠密嵌入语义检索；引入查询重写、文档分块、重排序等优化。
3. **模块化 RAG**（2023-）：模块可插拔可组合；混合检索、多查询扩展、假设性文档嵌入；生成侧思维链推理、自我反思与修正。

### HelloAgents 的"五层七步"架构

用户层（RAGTool 统一接口）→ 应用层（问答/搜索/管理）→ 处理层（解析/分块/向量化）→ 存储层（向量库/文档库）→ 基础层（嵌入模型/LLM/数据库）。每层可独立替换（如嵌入从 sentence-transformers 切换到云端 API 不影响上层）。主流程：**任意格式文档 → MarkItDown 转换 → Markdown → 智能分块 → 向量化 → 存储/检索**。

关键设计：

- **MarkItDown 统一转换**：微软开源的通用文档转换工具，把 PDF、Word、Excel、PPT、图片（OCR）、音频（转录）、代码等一律转为 Markdown——为后续基于结构的分块提供统一基础。
- **Markdown 结构感知分块**：标题层次解析（#/##/### 维护 heading_path）→ 段落语义分割 → Token 计算分块（chunk_size/chunk_overlap，重叠保上下文连续）→ 向量化。中英文混合 Token 估算：CJK 字符按 1 token 计，其余按空白分词计。
- **嵌入三级回退**：云端 API → 本地 all-MiniLM-L6-v2 → TF-IDF 兜底，保证各种环境可用。

### 高级检索策略：MQE 与 HyDE

用户查询与文档用词常有差异，导致相关文档检不回。两种互补策略：

- **多查询扩展（MQE）**：同一问题有多种表述，不同表述匹配不同文档。用 LLM 生成语义等价的多样化查询（"如何学 Python"→"Python 入门教程"/"Python 编程指南"），并行检索后合并。擅长用词多样性问题，对模糊查询和专业术语查询效果显著，可提升召回率 30%-50%。
- **假设文档嵌入（HyDE）**："用答案找答案"——问题通常是疑问句、文档是陈述句，语义空间有鸿沟。让 LLM 先生成一段假设性答案，用它的向量去检索真实文档；即使假设答案不完全正确，其关键术语和表述风格也能有效引导检索。擅长弥合语义鸿沟，尤其专业领域查询。

统一扩展检索框架走"扩展-检索-合并"三步：生成扩展查询（MQE 多样化查询 + HyDE 假设文档）→ 各查询并行检索（候选池按 `candidate_pool_multiplier=4` 扩大）→ 去重按最高分合并返回 top-k。选型建议：一般查询启用 MQE；专业领域同时启用 MQE + HyDE；性能敏感场景只用基础检索或仅 MQE。

## 应用案例：智能文档问答助手

基于 Gradio 的 Web 应用（核心类 `PDFLearningAssistant` 封装 RAGTool + MemoryTool），展示两系统有机结合：

- **用户隔离**：MemoryTool 用 `user_id` 隔离记忆空间；RAGTool 用 `rag_namespace`（`pdf_{user_id}`）隔离知识库；`session_id` 追踪单次会话。
- **记忆分工**：加载文档 → 情景记忆（具体事件、importance 0.9）；提问 → 问题入工作记忆、问答交互入情景记忆；学习笔记 → 语义记忆（概念知识，importance 0.8）。
- **检索分工**：文档内容问答走 RAG（MQE + HyDE 高级检索）；"我之前加载过哪些文档"走记忆检索——两者构成可设计"智能路由"的组合。
- **报告生成**：统计会话时长、文档数、提问数、笔记数，连同记忆摘要和 RAG 状态导出 JSON 学习报告。

选型参考（三类嵌入方案对比）：云端 API 准确性高、有成本、需联网；本地 Transformer 离线可部署、速度取决于硬件；TF-IDF 零成本兜底但无语义能力。

## 经验与常见坑

- 框架实例内的对话历史 ≠ 记忆：临时消息列表不跨会话、不可检索、不可整合——真正的记忆需要持久化 + 检索 + 遗忘 + 整合的闭环。
- 重要性权重别设太宽（[0.8, 1.2] 为参考）：权重过大会压过语义相似度，检索结果变成"重要但无关"。
- 分块策略依赖 Markdown 标题结构；处理无标题结构的文档（小说、法律条文）需另设计语义边界分块。
- 跨模态检索需按模态分离向量集合，否则维度不匹配；跨模态对齐需要统一向量空间（CLIP/CLAP 类编码器）。
- "删除"记忆在向量库 + 图库场景不彻底：嵌入缓存、图谱关系都是残留路径，敏感数据清除需专门设计。
- MQE/HyDE 都多花一次 LLM 调用——高召回与低延迟需按场景取舍。
