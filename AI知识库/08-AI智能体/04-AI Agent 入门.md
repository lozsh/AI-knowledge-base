# AI Agent 入门

<p class="note-date">更新于 2026-11-03</p>

**一句话定义**：现代 AI Agent = LLM（大脑）+ 上下文（眼睛）+ 工具（手脚）；要让它从能跑的 Demo 变成可靠的产品，还需在模型之外加上约束、验证、纠正三层工程外壳，即 Harness（Agent = Model + Harness）。

AI Agent 是能自主规划执行步骤、调用工具完成任务、并根据结果不断调整策略的智能系统，区别于"你问一句它答一句"的被动对话。代表形态：Coding Agent（Cursor）、Deep Research 类搜索 Agent、电脑操控（Manus）、手机助手（豆包）、个人办事 Agent（Pine AI）。它们的共同特征：开放式动作空间（生成任意自然语言和代码，而非从固定按钮中选）、行动前内部思考、依据环境反馈持续交互。

## 关键概念

### 核心公式与 RL 对应

| 直觉 | 组件 | RL 学术概念 | 职责 |
|---|---|---|---|
| 大脑 | LLM | 策略（Policy） | 理解意图、思考规划、决定下一步 |
| 眼睛 | 上下文 | 观察空间（Observation Space） | 决策点能看到的一切信息 |
| 手脚 | 工具 | 动作空间（Action Space） | 能做的所有事情的集合 |

### 上下文的五个组成部分（API 视角）

- **系统提示词**（静态）：开发者的"岗位说明书"，定义身份、权限、行为准则；含跨会话用户记忆与动态环境状态。
- **工具定义**（静态）：名称、功能描述、参数格式；与系统提示词构成静态前缀。
- **用户消息**（动态）：可能含 RAG 检索引入的外部知识。
- **模型回复**（动态）：最多含 reasoning（思考链）+ content（回复文本）+ tool_calls（工具调用请求）三部分，一次回复中不必然同时出现。
- **工具执行结果**（动态）：闭环控制的直接依据。

**关键事实：上下文 = 静态前缀 + 轨迹（trajectory，动态消息历史）**。消融实验结论：去掉工具定义 → 完全丧失行动能力；去掉工具结果 → 反复调用同一工具、盲目循环；剥离 reasoning → 前后决策矛盾；去掉历史 → "失忆"、重复执行已完成步骤。

### ReAct 循环与轨迹

循环三环节：想（Reasoning）→ 做（Acting，调用工具）→ 看（Observing），重复至任务完成。轨迹是不断累积的消息历史（user / assistant / tool 角色），每次 LLM 调用都能看到完整轨迹——这带来上下文累积性与结构化可解释性。轨迹数据可用于分析行为模式、沉淀知识库、甚至经强化学习训练更好的模型。示例：多币种收入汇总任务 3 次迭代、4 次工具调用完成（先并行汇率转换，再代码解释器汇总，最后作答）。

### 工具五分类（按互动方向）

1. **感知工具**：访问信息（搜索引擎、文件系统、API/数据库）。
2. **执行工具**：改变世界（代码执行、文件操作、系统命令）。
3. **协作工具**：与其他 Agent 分工、请求人类确认。
4. **事件触发工具**：非 Agent 主动调用，而是外部输入驱动启动（新邮件、定时点、Webhook）。
5. **用户沟通工具**：主动向用户传递进展（消息、语音、邮件）。

**工具调用（Tool Calling / Function Calling）四步**：上下文声明工具 → 模型自主决定是否调用/调哪个/传什么参数 → 工具结果追加到上下文 → 模型决定下一步。设计原则：工具保持通用性（提供 Python 代码解释器优于专用计算器；提供文件读写优于专用日志工具），让 Agent 组合基础能力创造性地解决问题。

### Agent 的三种学习范式

| 范式 | 时点 | 机制 | 特点 | 类比 |
|---|---|---|---|---|
| 后训练（Post-training） | 训练时 | RL 修改模型权重 | 永久通用、成本高更新慢 | 系统性学教科书 |
| 上下文学习（ICL） | 推理时 | 注意力做模式检索式适配 | 快（毫秒）但临时、会话结束即失 | 临场查参考资料 |
| 外部化学习（Externalized） | 运行时 | 固化为知识库 + 可执行工具代码 | 持久、可更新、可验证 | 整理个人笔记本 |

注意：上下文学习本质是模式匹配而非真学习——能套用已见过的模式，不能发现全新规律（零样本 = 没例子也能做；少样本 = 看几个例子就学会）。

### 模型即 Agent 与 Harness

**模型即 Agent（Model as Agent）**：先进模型通过后训练（尤其 RL）把工具调用决策内化为原生能力——何时调用、调哪个、传什么参数由模型自决，无需人工编排。但要分清归属：RL 内化的是**决策策略**（"用不用、怎么用"），工具本身及执行（web_search、代码沙盒）仍在模型之外的基础设施里；编排循环没有消失，只是从客户端移到了服务端。例：Kimi K3（MoE、百万 token 上下文、长链工具调用稳定，200-300 次连续调用不退化）；GPT-5.6（Responses API 内置搜索与代码解释器服务端闭环、自由格式工具调用 `type:"custom"` 省去 JSON 转义、意图澄清机制——先提问确认用户真实需求再动手）。

**Harness（马具隐喻）**：模型是强大但不可预测的马，Harness 是把能力引导为可靠任务执行的工程外壳。完整公式：

```text
Agent = LLM + [上下文 + 工具 + 约束 + 验证 + 纠正] = Model + Harness
```

最小公式是 Demo 视角，扩展公式是生产视角。三层保障：
- **约束（Constrain）**：行为边界。核心原则"故障安全默认值"——能力默认关闭，显式开放（类似手机 App 权限）。
- **验证（Verify）**：自动判断操作对错。核心原则"输入隔离"——安全检查只看结构化数据而非模型自由文本（防提示注入）。
- **纠正（Correct）**：失败时自动修正/回退。核心原则"确认无法恢复前不暴露中间态"——先静默重试，连续失败熔断转人工。

例：上下文嵌入退款政策属"上下文"；校验退款金额不超订单金额属"约束"；API 超时自动重试属"纠正"。Claude Code 的 Harness 绝大部分代码是约束/验证/纠正（流程状态管理、多层上下文压缩、权限分类、熔断器、错误恢复），工具本身只占一小部分。

**与苦涩的教训的关系**：方向认同（模型会持续"吃掉"Harness——工具调用、长程规划已从外部编排变成原生能力），节奏务实（训练以月计，模型无法一次内化所有业务约束；模型此刻的能力边界就是 Harness 此刻的价值——模型做不稳的先补上，模型每内化一层就卸下一层）。

### 工程范式演进

软件工程 → 提示工程（优化指令）→ 上下文工程（系统性管理模型能看到的一切）→ Harness 工程（模型所在系统的全部基础设施）→ Loop 工程（跨轮次持续自主运转：谁发现下一件事、何时验证、何时算完成）。层层包含而非替代。模型能力趋同后，竞争优势转移到模型之外的工程实践：LangChain 用 Harness 改进（自动检查执行结果、检测重复循环、优化思考策略）把 Terminal Bench 2.0 成绩从 52.8% 提到 66.5%，模型未变。

## 分类/类型

### 编排模式：工作流 vs 自主 Agent

| | 工作流（Workflow） | 自主 Agent（Autonomous） |
|---|---|---|
| 执行路径 | 代码预定义，确定性 | Agent 根据环境反馈实时决定 |
| 优势 | 严格流程控制（如"付款前不能预订"代码强制）、攻击面限制在单节点 | 灵活应对开放式问题、步骤数不可预测 |
| 局限 | 遇预设外情况无法变通 | 成本高、有复合错误风险 |

选择原则"从简单到复杂"：先优化单次 LLM 调用 → 固定子任务用工作流 → 需要动态决策才用自主 Agent。自主 Agent 本质是"在循环中使用工具的 LLM"，必须有明确停止条件（任务完成/无工具调用返回/最大轮次/错误超限）。实践常混合：合规关键流程走工作流，灵活部分走自主（n8n 可在同一系统中混用两种节点）。

### 主流框架速览

OpenAI Agents SDK（轻量原型）、Claude Agent SDK（生产级自主任务）、LangChain/LangGraph（复杂链式与多步工作流）、n8n（可视化低代码）、Dify（企业 RAG/知识库）、CrewAI（角色化多 Agent）、OpenClaw（自托管全能个人 Agent）。选型关键不在框架复杂度，而在能否以最小抽象层让你专注业务逻辑。

### 护栏三位置

- **输入侧**：相关性分类器、安全分类器（越狱 = 用户自己绕过限制；提示注入 = 攻击者借外部数据间接操纵，二者不同）、内容审核、规则保护（黑名单/长度限制/正则）。
- **执行侧**：工具风险评级（按可逆性、权限等级、财务影响分低/中/高，高风险需人工确认）。
- **输出侧**：PII 过滤、品牌一致性验证。

工业实践：Anthropic Constitutional Classifiers——用自然语言"宪法"生成合成数据训练分类器；上下文联合判断（提问与回答放一起检查）；两级筛查（轻量探针读内部激活全量初筛，可疑才交强分类器复审）。

**人工干预（Human in the loop）**触发条件：超过失败阈值（重试/操作次数上限）；高风险操作（取消订单、大额退款等敏感不可逆操作）。

## 经验与常见坑

- 构建有效 Agent 三原则（Anthropic 经验）：**保持简单**（直接 API 调用优于复杂框架，每层抽象都是调试盲区）；**保持透明**（显示规划步骤与决策轨迹，黑箱里的错误无法定位）；**设计好 ACI**（Agent-Computer Interface，从 Agent 视角设计接口、主动防呆，即制造业的 Poka-yoke 思路——模糊接口会被模型放大成系统性错误）。
- 模型选型：绝大多数 Agent 需要支持思考（Reasoning）的模型，只有单步简单任务可例外；不要只看排行榜，要在自己任务上评估；另关注输出 token 速度（多轮推理时直接决定端到端延迟）与多模态能力。
- 安全从第一行代码就要考虑，是架构问题而非上线前补丁。
