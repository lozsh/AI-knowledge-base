# 初识智能体

> 来源：Datawhale hello-agents 教程第一章（wiki 化重写于 2026-11-03）

**一句话定义**：智能体（Agent）是任何能够通过传感器感知环境、并通过执行器自主采取行动以达成特定目标的实体；大语言模型（LLM）的出现让"决策核心"从人工编写的规则升级为通用推理引擎。

智能体是人工智能的核心概念之一。经典定义（Russell & Norvig《人工智能：现代方法》）包含四要素：**环境**（智能体所处的外部世界）、**传感器**（感知输入，如摄像头、API 数据流）、**执行器**（改变环境的手段，如机械臂、代码执行）、**自主性**（基于感知和内部状态独立决策，而非被动执行预设指令）。"感知 → 思考 → 行动 → 观察"的闭环构成一切智能体行为的基础。

LLM 驱动的新范式改变了智能体的构建方法：传统智能体的能力来自工程师的显式编程，行为确定且有边界；LLM 智能体通过海量数据预训练获得隐式世界模型和涌现能力，可直接处理高层级、模糊的自然语言指令（如"规划一次厦门之旅"），自主完成规划、工具调用与动态修正。核心转变在于：从开发专用自动化工具，转向引导一个通用"大脑"去规划、行动和学习。

## 关键概念

### 传统智能体的演进阶梯

| 类型 | 决策核心 | 回答的问题 | 典型例子 |
|---|---|---|---|
| 简单反射智能体 | 条件-动作规则 | 现在感知到什么就做什么 | 自动恒温器 |
| 基于模型的反射智能体 | 内部世界模型 | 世界现在是什么样？ | 隧道中维持对前车位置的估计 |
| 基于目标的智能体 | 目标 + 搜索/规划 | 我该做什么才能达成目标？ | GPS 导航（A* 算法规划路径） |
| 基于效用的智能体 | 效用函数最大化 | 哪种行为结果最令人满意？ | 同时权衡时间、油耗、拥堵的路线选择 |
| 学习型智能体 | 学习元件修正性能元件 | 如何从经验中变得更好？ | AlphaGo Zero 自我对弈 |

### 三个互补的分类维度

1. **按内部决策架构**：即上表的演进阶梯；学习能力是可叠加于任何类型的元能力。
2. **按时间与反应性**：
   - *反应式（Reactive）*：即时响应、低延迟、低成本，但"短视"，易陷入局部最优（安全气囊、高频交易）。
   - *规划式（Deliberative）*：行动前系统探索未来可能性，有战略远见，但时间与计算成本高（棋手式思考）。
   - *混合式（Hybrid）*：分层架构（底层快速反应 + 高层审慎规划），或 LLM 智能体的"思考-行动-观察"循环——把长期任务分解为一系列"规划-反应"微循环。
3. **按知识表示**：
   - *符号主义 AI*：智能源于符号的逻辑操作，透明可解释，但规则难穷尽（知识获取瓶颈）。
   - *亚符号主义/连接主义*：知识内隐分布于神经网络，模式识别强、对噪声鲁棒，但是黑箱且可能幻觉。
   - *神经符号主义*：融合两者。卡尼曼《思考，快与慢》的双系统理论是绝佳类比——系统 1（快速直觉）对应神经网络，系统 2（慢速审慎推理）对应符号推理。LLM 智能体是当前最佳实践：内核是神经网络，工作时却生成结构化的中间符号（思想、计划、API 调用）。

## 核心原理

### 任务环境：PEAS 模型

用四个维度规约一个任务环境：**性能度量**（Performance）、**环境**（Environment）、**执行器**（Actuators）、**传感器**（Sensors）。

LLM 智能体所处的数字环境通常具有以下特性（以旅行助手为例）：

- **部分可观察**：只能通过 API 看到部分数据 → 需要记忆与探索能力。
- **随机性**：两次相邻的票价查询结果可能不同 → 需处理不确定性。
- **多智能体**：其他用户、脚本、航司调价系统都是环境中的"行动者"。
- **序贯且动态**：当前动作影响未来，且环境在决策期间自身也在变化。

### 智能体循环（Agent Loop）

1. **感知（Perception）**：接收观察（用户指令或上一步行动的反馈）。
2. **思考（Thought）**：LLM 驱动的内部推理，细分为*规划*（分解/调整任务）与*工具选择*（挑选工具并确定参数）。
3. **行动（Action）**：调用工具（代码解释器、搜索 API 等），改变环境状态。
4. **观察（Observation）**：环境反馈新状态，回到第 1 步。

### Thought-Action-Observation 交互协议

工程上通过结构化文本规范 LLM 的每次输出：

```text
Thought: 用户想知道北京的天气。我需要调用天气查询工具。
Action: get_weather("北京")
（外部解析器捕获指令并执行）
Observation: 北京当前天气为晴，气温25摄氏度，微风。
```

要点：`Action` 字段是对外部世界的指令，由解析器执行；工具返回的原始数据（JSON）需封装成简洁自然语言作为 `Observation`，再喂回下一轮循环。

## 最小可行实现（关键模式）

用约百行 Python 可实现一个真实 LLM 驱动的旅行助手（查天气 → 按天气推荐景点），四个组件：

1. **指令模板（system prompt）**：声明角色、可用工具清单、严格的 Thought/Action 输出格式、`Finish[最终答案]` 结束标记。
2. **工具函数**：如 `get_weather(city)`（调 wttr.in API）、`get_attraction(city, weather)`（调 Tavily 搜索），注册进一个 `available_tools` 字典。
3. **LLM 客户端**：兼容 OpenAI 接口规范（OpenAI/Azure/Ollama/vLLM 均可），只需 API_KEY + BASE_URL + MODEL_ID。
4. **主循环**：拼接历史 prompt → 调 LLM → 正则解析 `Action` → 截断多余输出 → 执行工具或判定 `Finish` → 把 `Observation` 追加回历史，循环直至完成（设最大轮数上限，防止死循环）。

一次成功运行通常三轮循环收敛：查天气 → 按天气搜景点 → Finish 汇总。该案例演示了智能体的四项基本能力：**任务分解、工具调用、上下文理解、结果合成**。

## 应用协作模式

- **作为开发者工具**：增强而非取代开发者。代表：GitHub Copilot（编辑器内补全 + Chat）、Claude Code（终端全流程编码，支持 headless 自动化）、Cursor（AI 原生编辑器，强调理解整个代码库）、Trae（轻量快速原型）。
- **作为自主协作者**：从"命令-执行"变为"目标-委托"。架构范式：
  1. *单智能体自主循环*（BabyAGI、AutoGPT）：思考-规划-执行-反思闭环自我迭代。
  2. *多智能体协作*：角色扮演式对话（CAMEL）、组织化工作流/SOP（MetaGPT、CrewAI）、灵活对话网络（AutoGen、AgentScope）。
  3. *高级控制流架构*（LangGraph）：把执行过程建模为状态图，支持循环、分支、回溯、人工介入。

### Workflow 与 Agent 的差异

| | Workflow | Agent |
|---|---|---|
| 本质 | 预先定义的静态流程图 | 目标导向的自主系统 |
| 决策 | 条件分支全部人工预先设定 | LLM 基于实时信息动态推理 |
| 典型例子 | 报销审批流（金额 < 500 走经理，> 500 加签财务总监） | 旅行助手（无"if 晴天 then 颐和园"的硬编码，雨天会自主改推博物馆） |

一句话：Workflow 是让 AI 按部就班执行指令，Agent 是赋予 AI 自由度去自主达成目标。

## ⚠️ 时效性说明

- 文中列举的编程工具与多智能体框架（Copilot、Claude Code、Cursor、Trae、AutoGPT、CrewAI、MetaGPT 等）迭代极快，产品能力描述反映成文时点，选用前应查最新状态。
- 自动 AutoGPT 类"单智能体自主循环"范式实践中暴露出循环失控、成本失控等问题，业界已更多转向受控工作流 + 有限自主性的混合设计。

## 经验与常见坑

- 主循环必须设最大迭代次数，否则解析失败或任务无进展时智能体会无限循环、烧钱。
- LLM 可能一次输出多对 Thought-Action，解析前需截断只保留第一对。
- 工具返回的原始 JSON 含大量冗余，直接塞给 LLM 浪费上下文且干扰推理，应封装为简洁自然语言的 Observation。
- Action 解析要容忍格式偏差：解析不到 Action 时应把错误信息作为 Observation 反馈给模型，让其自我修正。
