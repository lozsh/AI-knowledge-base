# 混合精度与多模型训练

<p class="note-date">更新于 2026-11-06</p>

**一句话定义**：精度工程与多模型共存是并行策略之外的另两件武器——FP8/混合精度把每个字节的价值翻倍（缩载荷而不改并行轴），RLHF 基础设施则把一次训练升级为四个模型的协同调度，两者的共同账本都是"内存与带宽"。

## FP8 与混合精度

FP8 是分布式杠杆：字节数减半直接缩 $T_{\text{comm}}$（通信时间），对通信受限的大模型训练是直接红利。两种格式分工——**E4M3**（±448，前向权重/激活）与 **E5M2**（±57344，反向梯度，范围大精度粗）。

### 动态 scaling 与三精度方案

核心挑战是**动态 scaling**：每张量乘 scale 因子再转 FP8，按运行最大绝对值动态调整；三精度方案（FP32 主权重 + FP8 GEMM + FP16 累加）可在合适负载上逼近 FP16 训练质量。FP8 改变载荷大小，不改变并行轴——它与[分布式训练](08-%E5%88%86%E5%B8%83%E5%BC%8F%E8%AE%AD%E7%BB%83.md)中的数据/张量/流水线并行正交，可以叠加。

## 多模型训练：RLHF 基础设施

### 四模型协同与内存账

PPO 式 RLHF 要四个模型协同：policy（训练态，70B 全套状态 1120GB）、reference（推理态，140GB，供 KL 惩罚）、reward（推理态 13B 约 26GB）、value（训练态 critic）。总静态内存约 1494GB，加 KV cache 与激活，**单个 RLHF 实例实际最少 64–128 卡**。

核心矛盾是**不对称性**：policy/value 需要完整反向，reference/reward 是嵌在训练循环里的推理服务；自回归生成阶段是带宽受限的（每 token 一次全模型前向），batch 256×1024 token 的 GQA KV cache 就要 85.9GB。系统按"时间多路复用"切换：生成阶段像推理系统，训练阶段回到 3D 并行。

### DPO 的基础设施红利

去掉 reward/value 模型和生成阶段，四模型变两模型，静态内存 1494→1260GB（value 为 policy 级时降幅近 48%），有效 MFU（模型算力利用率）从 15–25% 升到 40–55%——**PPO vs DPO 不只是建模偏好，也是基础设施约束**。代价：DPO 用静态偏好对，失去在线探索能力。

### 序列长度方差问题

RLHF 数据 10–50 倍长度方差，固定 padding 浪费 88% 计算是常态；缓解靠序列打包（拼接+注意力掩码）与按 token 数自适应 microbatch，但引入 DP worker 间负载不均——所有 worker 每步须处理相同 token 数以保梯度一致性。

## 经验与常见坑

- **FP8 格式不能混用**：前向权重/激活走 E4M3（±448），反向梯度走 E5M2（±57344）——把梯度塞进 E4M3 直接溢出，把前向压成 E5M2 则精度太粗。
- **scale 因子必须动态调**：FP8 依赖按运行最大绝对值动态调整的 scale，静态 scale 在数值分布漂移时要么溢出要么下溢损失精度。
- **FP8 不是免费午餐**：三精度方案（FP32 主权重 + FP8 GEMM + FP16 累加）只在合适负载上逼近 FP16 质量——迁移前要在目标模型上验证收敛，不能默认无损。
- **RLHF 内存账只算 policy 会差一个量级**：四模型静态内存约 1494GB，还不含 KV cache 与激活；按单模型训练的直觉做容量规划必然翻车。
- **生成阶段与训练阶段的拓扑需求不同**：自回归生成是带宽受限的（每 token 一次全模型前向），用训练态 3D 并行的配置跑生成会大量闲置；时间多路复用要求系统在两种形态间切换。
- **序列打包不是白捡的**：序列打包与按 token 数自适应 microbatch 解决 88% 的 padding 浪费，但引入 DP worker 间负载不均——所有 worker 每步必须处理相同 token 数，否则梯度不一致。
- **DPO 省的是基础设施不是能力**：四模型变两模型、MFU 从 15–25% 升到 40–55%，但用静态偏好对换掉了在线探索能力——建模取舍与基础设施取舍要分开评估。

## ⚠️ 时效性说明

FP8 的硬件原生支持范围、scaling 策略与配套库（如 Transformer Engine）随代际与版本快速演进；RLHF 栈里 PPO/DPO 及其后续变体、四模型协同的拆分方式也在迭代。持久的变量是两条账本本身：载荷字节决定通信与显存，多模型共存的内存与调度账决定集群规模。
