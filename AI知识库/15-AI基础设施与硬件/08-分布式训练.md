# 分布式训练

<p class="note-date">更新于 2026-11-06</p>

**一句话定义**：分布式训练是把一个优化循环切分到数千加速器上并保持数学等价的约束满足问题——三种并行（数据并行/张量并行/流水线并行）各解一个约束（吞吐/单层内存/深度），组合成 3D 并行以匹配集群的带宽层级。

前置的硬件层级、网络 fabric 和存储管线就绪后，剩下的挑战是算法性的：切分训练作业而不破坏"一次连贯优化"的语义。触发分布式的三个信号：(1) 内存耗尽——混合精度 Adam 下 80GB 卡在约 5B 参数（不含激活）就到顶；(2) 训练时长不可接受——GPT-3 即便装得下也要数月，日历本身就是系统约束；(3) 数据集达 TB 级——单机不再是大吞吐的自然单位。

## 核心原理：舰队定律与扩展效率

**舰队定律**：一步训练的时间由可并行计算、通信、同步三项与重叠抵消决定（公式与推导见[分布式 ML 原则](07-%E5%88%86%E5%B8%83%E5%BC%8F%20ML%20%E5%8E%9F%E5%88%99.md)）。关键比值 $\rho = T_{\text{comm}}(N)\big/\left(T_{\text{compute}}/N\right)$（$N$ 为卡数，$T_{\text{comm}}$ 为 $N$ 卡时的通信时间，$T_{\text{compute}}$ 为单卡计算时间）判定状态：计算受限（理想态，大 batch 稠密模型）vs 通信受限（LLM/DLRM 常态，梯度同步打满网络）。

**扩展效率**：$\eta_{\text{scaling}} = T_1/(N\times T_N)$（$T_1$ 为单卡耗时，$T_N$ 为 $N$ 卡耗时）。$\eta=0.5$ 意味着万卡集群只干了 5 千卡的活。经验规律：2–32 卡线性区效率 85–95%；64–256 卡通信受限区 60–80%；512 卡以上协调开销主导，只剩 40–60%。

175B 模型的实例：ring AllReduce 350GB 梯度、50GB/s IB、75% 重叠 → 暴露通信约 3.5s，计算项 2.1s，**纯数据并行效率仅 37.5%**。修复手段不是调参而是换组合：加张量并行（NVLink 域内通信）+ 流水线并行 + 拓扑感知放置。

**扩展墙与经济区间**：通信/计算比随 $N$ 恶化。175B 例子的成本高效区约 1024–4096 卡（效率 >70%），8192 卡以上效率跌破 50%——花 8000 张卡的钱干 4000 张卡的活。模型越大越容易扩展（计算增量超线性增长、通信只线性增长）："贵的工作负载恰好是最能用上集群的"，是大规模基础设施的良性循环。

**扩展的能量税**：单 GPU 内搬字节 1–2pJ/bit，NVLink 5–10pJ/bit，IB 交换 20–50pJ/bit。万卡集群 NVLink 包络 ~9PB/s @ 7.5pJ/bit ≈ 540kW，IB 包络 ~140kW——重叠通信之外，减少不必要的搬运直接省电。

**收敛理论**（BSP 下）：同步数据并行 SGD 收敛率 $O(1/\sqrt{NbK})$（$N$ 为卡数、$b$ 为单卡 batch、$K$ 为总步数），方差下限随 $N$ 线性下降。**梯度陈旧度 $\tau_{\text{stale}}$**（worker 允许使用多少步之前的过期梯度）决定协议代价：

| 模型 | 陈旧度 | 收敛 | 特点 |
|---|---|---|---|
| BSP | 0 | $O(1/\sqrt{NbK})$，等价单机大 batch | 最慢 worker 决定步时；最终训练/复现 |
| SSP | $\le s$ | $+\ O(s^2\eta^2L^2/(Nb))$ 惩罚 | 有界陈旧，超参搜索/异构集群 |
| ASP | $\infty$ | $+\ O(\bar{\tau}_{\text{stale}}^2\eta^2L^2)$，并行方差缩减消失 | 最大吞吐；需学习率衰减/梯度裁剪补偿 |

**学习率缩放规则**：线性规则 $\eta_{\text{large}} = k\cdot\eta_{\text{base}}$（$\eta_{\text{base}}$ 为基线学习率、$k$ 为全局 batch 扩大倍数；Goyal 2017，配 warmup；对 ResNet-50/ImageNet batch 8192 验证）；超过临界 batch 后用平方根规则；极端 batch（32K–1M）用 LARS/LAMB 逐层自适应。**临界 batch size $B^{*}$**：梯度噪声尺度 $\text{tr}(\Sigma)/\|\nabla L\|^2$ 估计，$B<B^{*}$ 线性扩展、$B>B^{*}$ 收益递减。ImageNet 约 8K–16K，BERT-Large 约 32K–65K——新模型要实测，不能照抄。

一小时的 ImageNet 战役（FAIR 2017）：256 卡训 ResNet-50，朴素放大 batch 使优化崩溃，靠"线性缩放规则+渐进 warmup"救回，确立 batch 8192 的大 batch 配方——**集群、通信调度、batch、学习率必须当一个系统调**。

## 核心概念：数据并行

每卡完整模型副本 + 独立数据分片，AllReduce 平均梯度。数学基础是期望的线性性：等局部 batch 下，平均局部梯度 ≡ 合并大 batch 的梯度。五阶段：数据切分（DistributedSampler 按秩确定性分区、不可重叠，否则梯度有偏）→ 前向/反向（完全并行，零通信）→ 梯度同步（AllReduce，10–40% 步时）→ 参数更新（各卡独立应用相同更新，无需中心服务器）。

**同步拓扑**：Ring AllReduce 带宽最优（每卡 $2(N-1)/N \times M$ 字节，$M$ 为每卡需同步的梯度体积；NCCL/DDP 默认）；Parameter Server 中心瓶颈（DistBelief 时代遗留，但对稀疏负载仍是正解）；All-to-All mesh 链路数平方增长，8 节点以上不实用。

**三堵墙**：内存墙（每卡全副本：175B > 1TB/卡）、带宽墙（AllReduce 可吃掉 LLM 步时 50%+）、batch 陷阱（全局 batch $= N\times B_{\text{local}}$，$B_{\text{local}}$ 为单卡 batch，撞临界 batch）。

**GPT-2 扩展实例**：单节点 8 卡 NVLink 效率 99.4%；跨 4 节点 10GbE 扩展到 32 卡，通信占步时 72.1%、效率仅 27.9%。**梯度累积反转结论**：在慢网络上做 4 步累积（通信降到 0.08%）比扩展到 32 卡省 86.7% 成本——网络慢时不要 scale out，在带宽富集的节点内 scale batch。

**ZeRO/FSDP 分片数据并行**：混合精度 Adam 每参数 16 字节（2 权重+2 梯度+12 优化器），7B 模型全状态 112GB，80GB 卡 OOM。分档：

| ZeRO 阶段 | 切分对象 | 内存缩减 | 通信代价 |
|---|---|---|---|
| ZeRO-1 | 优化器状态 | ~4× | 无（同 DDP） |
| ZeRO-2 | +梯度 | ~8× | ReduceScatter 替代 AllReduce |
| ZeRO-3/FSDP | +参数 | ~N（线性） | 每层前 AllGather（重分片则正反向各一次）+ ReduceScatter |

ZeRO-3 在 64 卡下每卡仅 1.75GB 状态。代价：满分片 FSDP 每步约 $3N_L$（$N_L$ 为层数）次集合通信（vs DDP 的 1 次），通信量约 $3M_{\text{state}}$ vs $2M_{\text{state}}$（$M_{\text{state}}$ 为单卡需传输的完整状态体积），实测 10–25% 开销。**容量是用带宽买的**：模型装得下时 DDP 更快（7B 模型实例 DDP 145 vs FSDP 118 样本/秒），只有内存压力真实存在时才值得。

## 核心概念：模型并行

当 ZeRO-3 也救不了：175B 静态状态 2800GB，ZeRO-3 64 卡每卡仍 43.8GB，加激活 ~50GB 超 80GB——**必须切模型本身**。模型并行的第一收益是容量不是速度，调度不好利用率可以低于单卡。

**流水线并行**：按层切阶段，microbatch 流水填满。气泡分数 $= (p-1)/(m+p-1)$（$p$ 为流水线阶段数，$m$ 为 microbatch 数）：p=8、m=32 时约 18%；p=16、m=16 时 48%——**要 m≫p 才能把气泡压到 10% 以下**，代价是激活内存。通信量仅阶段边界激活（约 200MB/边界），**可容忍 IB 带宽，是跨节点扩展深度的主力**。调度演进：GPipe（全前向再全反向）→ PipeDream（异步+权重暂存）→ **1F1B**（一前一后交错，激活驻留从 $O(m\times p)$ 降到 $O(p)$，才让大 m 可行）→ 零气泡调度（把 W kernel 即权重梯度计算挪去填气泡，B kernel 只算激活梯度走关键路径；气泡可趋近零，代价是激活驻留更久）。

**张量并行**：切单层内的矩阵。Megatron 式"列并行+行并行"配对：QKV 投影列切（前向无通信）→ 输出投影行切（一次 AllReduce 合并），每 transformer 块恰好 2 次 AllReduce（注意力后、FFN 后）。代价：每块每方向都通信，通信量对 activation payload（S=2048、d=4096、B=4、FP16 约 67MB/AllReduce，96 层全 step 约 51GB）。**9 倍带宽悬崖锁死它**：NVLink 900GB/s 下每 AllReduce 0.1–0.5ms，IB 50GB/s 下 2–10ms——96 层跨 IB 就是每步 200–960ms 纯同步，MFU（模型算力利用率）崩到个位数。实践中 TP≤8（节点内），Llama 3 405B 也是 TP=8。扩展：序列维度也可切——Ring Attention 让每卡只持 S/N 的 KV 状态、K/V 块沿环流转，把上下文长度扩展 N 倍（百万 token 级），通信与计算重叠可完全隐藏。

**参数服务器与 embedding 分片**：稠密模型上 PS 是瓶颈（incast），4–8 卡以上 AllReduce 胜出；但推荐系统（DLRM，10TB+ embedding 表、每 batch 只触 0.001% 的行）天然稀疏——Sparse Pull/Push 只搬被触碰的行，TorchRec 等把热 embedding 放 GPU、冷的放 CPU PS，形成参数的分层内存。

**专家并行（MoE）**：门控选 top-1/top-2 专家 → All-to-All dispatch → 专家计算 → All-to-All combine。容量与计算解耦（万亿参数 MoE 每 token 只激活约 10B）。每 MoE 层 2 次 All-to-All（如 67MB×2），考验对分带宽而非单链路。⚠️ 自然语言路由天然偏斜：热专家可收 3–5 倍流量。控制手段：capacity factor C=1.25–1.5（超限 token 走残连接丢弃）+ 辅助负载均衡损失（权重 0.01–0.1）。

## 3D 并行与层级感知

$N_{\text{total}} = d \times p \times t$（$d$ 为数据并行度、$p$ 为流水线并行度、$t$ 为张量并行度）。**带宽匹配铁律**：通信最频繁的 TP 锁在 NVLink 域内；点对点的 PP 跨节点走 IB；一次性且可重叠的 DP 同步跨全集群。三配置对比（1024 卡训 175B）：

| 配置 | 通信位置 | 效率 |
|---|---|---|
| 纯 DP-1024 | 350GB AllReduce 全走 IB | ~37.5% |
| TP-8 + DP-128 | TP 走 NVLink，DP 分片 43.75GB 走 IB | 54.5%（重叠后 75–85%） |
| TP-8 + PP-4 + DP-32 | PP 通信量最小，DP 更小 | 更优（气泡 ~9%） |

内存预算实例：TP=8、PP=16 下每卡静态 13.7–19.1GB（简化/完整 Adam 口径），留出激活空间。方向联动：任意一维变化把压力推给另外两维——TP×PP×DP 是紧耦合系统而非三个独立旋钮。自动设计空间搜索（约束网格搜索最大化 MFU）可在秒级给出 TP=8/PP=8/DP=128 这类配置，并揭示"PP 深了反而降 MFU"（气泡）。

**MFU 进化史**（利用率天花板在 40–46%）：GPT-3 21.3%（2020）→ MT-NLG 30.2% → Gopher 32.5% → PaLM 46.2%（2022）→ Llama 3 405B：8192 卡 43.0% vs 16384 卡 41.0%——**扩展税是实测的**，卡数翻倍 MFU 反降。

## 经验与常见坑

- **线性加速不可求**：梯度同步本质串行，1000 卡达到 500× 已是 exceptional，通信重的负载 100–200× 才是常态。按线性扩展做预算必然延期超支。
- **MFU 与扩展效率是相乘的**：单机 50% MFU × 1024 卡 50% 扩展效率 = 25% 有效吞吐（256 卡当量）。容量规划要同时报两者，追踪乘积（goodput）。
- **小集群超参不能直接迁移**：8 卡调好的学习率乘上 GPU 数跳到大 batch，可能掉精度。warmup、LARS/LAMB、逐项实验不可省。
- **加卡前先建模通信**：超过临界 batch 后加倍 GPU 只加倍成本、几乎不加速收敛。1024 卡 18h/$45k 可能不如 512 卡 19h/$22k。
- **并行策略不能用小模型外推**：1B 模型通信占 33% 步时，70B 模型只占 7%——小模型上"流水线气泡让 PP 永远更慢"的结论在大模型上会反转。要么目标规模实测，要么用解析模型（计算 O(n²)–O(n³) vs 通信 O(n)）。
- **扩展效率不是硬件常数**：它是负载通信比、并行策略、网络拓扑、软件栈四者的联合属性。用厂商 hero benchmark 做容量规划是错的。
- **梯度累积不是免费的**：驻留梯度缓冲（7B FP16 仍 14GB）、优化器延迟放大 K 倍、FP16 累加数百步可能溢出发散（实战案例：16 步累积在 step 1200 loss spike，改 4 步恢复）。累积是拿通信频率换更新延迟、内存驻留与数值风险。
- **checkpoint 间隔按 Young-Daly 定**（$\tau_{\text{opt}}=\sqrt{2\,T_{\text{write}}\cdot\text{MTBF}}$，$T_{\text{write}}$ 为写一次 checkpoint 的耗时，推导见[分布式 ML 原则](07-%E5%88%86%E5%B8%83%E5%BC%8F%20ML%20%E5%8E%9F%E5%88%99.md)与[容错](11-%E5%AE%B9%E9%94%99.md)）：1024 卡（集群 MTBF 48.8h）+5 分钟写入 → 最优约 2.9 小时（总税 5.8%）；"保险起见"每 15 分钟存一次税升到 33.6%，每天多烧约 $13,638。
- **内存容量不唯一决定策略**：175B/64 卡的例子里 PP-8 比 TP 组合高 23% 吞吐——要 profile 通信模式与气泡，不是只看权重装不装得下。
