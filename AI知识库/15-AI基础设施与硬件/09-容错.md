# 容错（Fault Tolerance）

<p class="note-date">更新于 2026-11-03</p>

**一句话定义**：容错是让分布式执行在组件故障、降级、消失时继续产生有效进展的系统属性——大规模下故障不是要消灭的例外，而是每几小时一次的常态，工程目标从"防止故障"转为"让恢复自动、快速、无感"。

万卡集群跑三个月的大模型训练：GPU 每几小时坏一块，同步训练下任何一台卡住都让全集群停下。同步是吞吐的来源也是脆弱的来源——集体通信把成千设备绑成一台机器，也意味着一个停滞设备能停住整个机队。容错的四件事：检测故障、checkpoint 保存可恢复状态、重启或弹性重塑作业、把硬件轮换当作正常执行路径。ML 的有利特性：SGD 容忍某些误差、checkpoint 大小大但可预测、恢复目标只需近似。

## 核心原理：必然故障的数学

**故障率与 MTBF 缩放**：单组件故障率 λ（单位 FIT = 每十亿设备小时一次故障；5 万小时 MTBF 的 GPU = 20,000 FIT）。串联系统（任一坏则全坏）故障率相加、可靠度相乘：

```
MTBF_system = MTBF_component / N
```

万卡集群（单卡 5 万小时）GPU-only MTBF 仅 5 小时；加上 PCIe、电源、网络域后更低——完整级联计算（10,000 H100 + PCIe 20 万小时 + 电源 10 万小时/8 + 网络 15 万小时/8）得 **系统 MTBF 3.69 小时，约 6.5 次故障/天，一周训练约 45 次故障**。

实测验证（不是纸面定律）：Meta RSC 研究投影 16,384 卡作业 MTTF 1.8 小时；Llama 3 训练实测 54 天 419 次故障 ≈ 3.1 小时 MTTF。**16K 卡规模的故障节奏就是 2–3 小时一次。**

"9 个 9"的乘法陷阱：单卡 99.99% 可用性，万卡集群全健康的概率 = 0.9999^10000 ≈ **37%**。可靠性按乘法复合，不按平均。

**Young-Daly 定律**（最优 checkpoint 间隔）：

$$\tau_{\text{opt}} = \sqrt{2 \cdot T_{\text{write}} \cdot \text{MTBF}_{\text{system}}}$$

平衡两类浪费：写开销（T_write/τ，随间隔变长而降）与重做损失（τ/2·MTBF，随间隔变长而升），总和最小处即最优。本篇集群实例：MTBF 3.69h、3.7TB checkpoint @100GB/s 写 37 秒 → **τ_opt ≈ 16.5 分钟，总浪费约 7.5%**；每小时存一次浪费 14.6%。平方根关系是好消息：MTBF 减半只让最优间隔缩 √2≈1.4 倍——集群翻倍不需要翻倍 checkpoint 带宽。

⚠️ 公式假设的失效模式：故障非指数（浴盆曲线）、T_write 非常数（波动 2–3 倍）、恢复时间常是写入的 3–5 倍（调度+加载+预热）、相关故障违反独立假设、短训练不适用。重启时间应计入总浪费与恢复 SLO 预算，但不能不加推导地塞进 T_write。

**可用性架构**：串联系统率相加；并联冗余（活跃副本）可靠度 = 1−∏(1−Rᵢ)。**ECC 是前提不是选项**：1024 卡×80GB HBM 按 ~250 FIT/Mbit，无保护时约每 20 秒一次未纠正损坏——ECC 把软错误率砍两个数量级，残余多 bit 逃逸就是 SDC 问题。

**故障词汇**：fault（底层缺陷/事件）→ error（被破坏的状态）→ failure（系统必须应对的外显行为）。

## 关键概念：故障分类学

| 类别 | 表现 | 危险 | 检测/恢复 |
|---|---|---|---|
| 瞬态（Transient） | 微秒-毫秒，一次即逝（宇宙射线 SEU、电压波动、热节流） | **静默损坏**：梯度悄悄变错，无报错 | ECC/校验和/梯度范数监控；重试或回滚 |
| 永久（Permanent） | 不可逆（stuck-at、器件死亡、电迁移） | **可重复性**：重试同设备复现同样错误 | 心跳超时；换硬件+checkpoint 恢复 |
| 间歇（Intermittent） | 时有时无（焊点裂纹热开合、老化、电压边缘） | **歧义性**：本轮过验证下轮出错 | 遥测趋势分析；降频/隔离/排水 |

**SDC（静默数据损坏）**是 ML 最阴险的故障类：nanometer 工艺下硬件本质是概率性的——宇宙射线 SEU（万卡规模是统计必然）与"边缘芯片"制造方差（只在特定电压/温度组合翻转，如 backward pass 的剧烈 dV/dt）。真实案例：Meta 曾有硬件故障让合法文件解压时被报告为"size zero"（系统没崩但数据被静默删除）；Google 报告 TPU pod 的 SDC 表现为 inexplicable 的梯度范数尖峰——指数位一个 bit 翻转就能把 10⁻⁵ 变成 10²⁰。检测窗口：损坏发生在微秒级，发现可能要数小时到数周。Google 的系统级缓解：热备容量 + 梯度范数/loss 监控触发抽走可疑芯片——**把可靠性从组件（不可信）搬到系统（验证结果）**。

**浴盆曲线**：早期故障期（制造缺陷，数天-数周）→ 有效期（常数故障率，指数模型适用）→ 耗损期（电迁移、热循环疲劳、TIM 退化）。运营推论：新集群头几周故障率高；burn-in 测试（85–125°C、24–168 小时加压）在生产前筛掉早期故障；新修节点先派短任务/推理服务，不直接上数月预训练；预测性维护（温度趋势、ECC 计数增长）针对耗损期。

**故障影响因模型而异**：70B LLM 训练 2–4 周、checkpoint 数百 GB、每损失 24 小时约 $2–5M；DLRM 是连续训练+embedding 新鲜度=收入（恢复时间比 checkpoint 开销更重要，优先级反转让"最小化恢复时间"压过"最小化保存开销"）；视觉模型 checkpoint 1–2GB 可高频保存；科学计算要额外保存模拟器/搜索前沿状态。

**经济框架**：C_total = C_compute + E[N_failures]×C_per-failure + C_ft。投资准则：容错的边际成本 < 边际减少的故障损失。小规模训练最小容错即可；千卡以上故障每日多次，频繁 checkpoint+自动恢复+弹性训练是正 ROI。

## Checkpointing

必须保存的完整状态：模型参数、**优化器状态（不是权重，是 checkpoint 大小主导项）**、训练进度（curriculum/数据位置）、随机种子与学习率调度。175B 模型仅 Adam 优化器态就 2.1TB（完整 FP32 口径 3.7TB）。

**同步 vs 异步**：同步保证全局一致（所有 worker 同一 step）但"stop-the-world"——万卡停 2 分钟 ≈ 333 GPU 小时 ≈ $1,000/次，每小时存一次即 $24,000/天耗在等 I/O。异步三阶段：GPU→CPU 内存快照（32GB/s PCIe）→ 后台写本地 NVMe（训练立即恢复）→ 后台 NVMe→共享存储。Meta OPT-175B 实战：同步 checkpoint 曾吃掉 12% 有效训练时间，改异步后降到 <3%。

**协调模式**：
- **集中式**：worker 发状态给 coordinator 汇总写入——coordinator 是吞吐瓶颈+单点故障，数十 worker 以内可用。
- **分布式**：六步协议（广播 checkpoint ID → 栅栏对齐 → 各写 shard → 确认 → 写元数据 → 广播完成）。元数据完整=有效 checkpoint，可检测不完整与垃圾回收。⚠️ 基础协议有正确性 bug：coordinator 在部分确认后崩溃会留下"worker 以为成功、系统无有效 checkpoint"——生产用**两阶段提交**（先写 staging、coordinator 原子 rename 提交，失败则回滚 staged 写）。
- **一致性谱系**：严格同步（最强、栅栏最贵——万卡总有慢 worker，栅栏是主要成本）→ 有界异步（worker 相差 ≤k 步，生产实际使用的模式，恢复取最早一致切面）→ 最终一致（最省但恢复逻辑复杂）。
- **分片 checkpoint**：ZeRO-3/FSDP 下每 worker 只写自己的 shard——175B/1024 worker 每个只写 3.6GB（秒级完成），对比单点写 3.7TB。代价：恢复需要所有 shard 齐全且一致，任一 shard 存储损坏即整个 checkpoint 报废；换 worker 数恢复需 reshard。

**分层存储**（详见[05-数据存储](05-数据存储.md)）：本地 NVMe 快恢复（5–10GB/s/节点）→ PFS 中速+持久 → 对象存储慢但灾备。恢复读速度决定 T_load。

**诊断实例**：70B 模型 checkpoint 要 10 分钟而非预期的 2 分钟——逐层诊断：基础设施层（700GB 状态 / 10Gbps NFS = 1.25GB/s → 理论下限 9.3 分钟，带宽不足是物理事实）；分布层（64 节点并发共享 10Gbps，每节点摊 20MB/s）；治理层（30% 开销使 2 周变 2.6 周、多花 $500K）。修复必须跨层组合：装本地 NVMe + 三阶段异步化 → 训练影响从 30% 降到 <1%。

## 故障检测与恢复

**恢复时间分解**：

```
T_recovery = T_detect + T_restart + T_load + T_warmup
```

175B/1024 卡实例：60s 检测 + 3min 重启 + 37s 加载 + 2min 预热 ≈ **6.6 分钟/次**。1024 卡（MTBF 49h）每天丢约 3 分钟（0.2%）；万卡每天约 32 分钟（2.2%，≈5,293 GPU 小时/天）。

**检测机制（多层）**：
1. 心跳：T_timeout = H + kσ_d（k=3–5）。难点：区分"真死"与"在写大 checkpoint 的慢节点"——调太紧 checkpoint 触发误杀，调太松全集群干等。
2. 集合通信超时：NCCL 传输/RAS 超时参数——冻结的 GPU 会让所有 rank 无限等待。
3. 编排器探针：K8s/SLURM liveness/readiness，抓应用心跳抓不到的死锁。
4. **loss 尖峰检测**：SDC 的签名——loss 瞬间跳 10–100 倍或塌成 NaN，且无超参变更。发现后立即暂停、用 checksum/回放定位坏 rank、排水节点、从健康 checkpoint 重启。

生产实测检测延迟：进程崩溃 5–30s；GPU 挂起 30–120s（要区分慢 kernel）；网络分区 60–180s（要区分拥塞）；**SDC 数分钟到数小时（只能靠统计异常）**。成熟做法是多阶段检测：快超时触发调查、慢确认触发恢复。

**恢复六步**：SIGTERM 广播（DDP 下一 worker 失效即 communicator 失效，须全拆）→ 资源回收（坏节点标 draining、从备池要替换）→ 作业重启 → 加载 checkpoint 分片 → 状态同步（ncclCommInitRank 重建 communicator、验证同 step）→ 训练恢复（dataloader 快进到正确 batch）。**恢复验证**常被忽略：验证参数形状/dtype、跑几步看 loss 是否接续、验证梯度统计——loss 立即发散说明 checkpoint 本身可能坏了，须回退更早快照。

**冷重启 vs 热重启**：冷重启全杀全载（简单、对相关故障/SDC 安全）；热重启存活 worker 保留显存中的权重与优化器态、只换坏节点，99.9% 集群的 T_load/T_warmup 趋零，恢复从分钟级到 30–90 秒。代价：动态成员管理的软件复杂度（CUDA 内存泄漏、communicator 重建死锁）。**成熟部署：热重启为快路径、冷重启为安全网。**

**自动化流水线**（万卡必须无人值守）：健康监控 daemon（GPU 遥测+应用指标）→ 故障分类器（Xid 48 双 bit ECC=致命 / 瞬时拥塞 / 热节流）→ 动作选择（进程挂起→容器重启；硬件错误→排水换节点；网络分区→暂停等待保住内存态）→ 验证（金丝雀 batch 确认 loss）。将 MTTR 从人工的 30–60 分钟压到 10 分钟内。**分类是关键**：所有故障都当冷重启会在瞬时问题上浪费算力，把硬件故障当瞬时会放任损坏的计算继续。

**Straggler vs 故障**：straggler 是还正确但慢的 worker（热节流、线缆劣化、OS 后台进程、I/O 拥塞）——不触发超时，静默拖垮全局效率。BSP 下步时 = max(各 rank) + T_comm：1024 卡集群一台卡降速 50%，**0.1% 的硬件让全集群吞吐掉 50%，每小时浪费 $1,536**。数学结论：**严重 straggler 按硬故障处理更优**——盈亏平衡点：降速超过 T_recovery/MTBF_system 就该杀。缓解谱：backup worker（冗余计算先到先用）、有界陈旧、动态负载再平衡、预测性替换（遥测趋势）。

## 弹性恢复（Elastic Recovery）

打破"必须恢复原 GPU 数"的假设：1024 卡作业丢 8 卡，与其全集群闲置等修复，不如以 1016 卡继续（99.2% 容量）。**把硬故障变成吞吐降级而非全停**。需要协调的自适应：batch size 调整（少 worker 则每卡多吃样本或缩全局 batch）、学习率重校准（线性规则或保守的平方根恢复策略 η∝√(N_new/N_base)）、**梯度累积替代学习率调整**（worker 减半则累积步数加倍，有效 batch 不变、无学习率风险）、数据加载器再分配（必须原子完成，静默失败=样本丢失或重复=训练分布损坏）、状态 resharding（ZeRO/FSDP 分片迁移或从 checkpoint 重切）。

**Spot 抢占即故障类**：竞价实例被回收对框架而言与硬件故障无异；弹性恢复让每秒 $0.6 的 spot 容量可用（vs $3 的按需）——偶尔的重塑停顿换来数倍成本优势。

框架支持：TorchElastic（rendezvous 机制处理成员变更、自动 rank 重排，batch/学习率语义留给用户）、DeepSpeed（checkpoint 为中心+Universal Checkpointing 跨并行拓扑可移植）、Ray Train（actor 监督+checkpoint 重试）、Horovod Elastic（elastic state API）。共同边界：**框架自动处理成员/分组重建，batch 数学、学习率与数据覆盖不变量仍归训练脚本负责**。

**恢复状态不变量按负载定制**：LLM 要保优化器精度+curriculum 位置+数据调度位置；推荐系统优先 embedding 新鲜度（增量/tiered/版本化 checkpoint）；视觉要增强种子、shuffle 顺序、BN 统计量、渐进 resize 调度；科学计算把模型+模拟器+搜索前沿+随机状态当一个一致性单元。共同模式：**恢复正确性比权重恢复宽**——权重对了但 curriculum 位置错了照样是错误的恢复。

## 服务端容错

训练容忍分钟级恢复，**服务要求毫秒级**——完全不同的方法论。

- **无状态 vs 有状态**：无状态（图像分类、单轮问答）故障=重试即可，毫秒级负载均衡切换；有状态（多轮对话 KV cache、流式语音上下文、推荐会话）故障=质量性状态丢失，需要 session 亲和路由、状态 checkpointing、状态复制、优雅降级，failover 秒级。
- **冗余数学**：A_system = 1−(1−A_single)^k。99% 单副本（年停 3.65 天）→ 双副本 99.99%（52.6 分钟）→ 三副本 99.9999%（31.5 秒）。⚠️ 独立性假设常被共享电源/网络/软件 bug 打破。
- **复制策略**：active-active（利用率高，副本挂了幸存者瞬时加压）vs active-passive（确定性 failover， standby 闲置）vs 地理复制（防区域故障、付跨区延迟）。
- **健康检查**：liveness（活着吗）与 readiness（能接流量吗）分开——活着的死锁进程要靠 readiness 摘除。
- **降级三板斧**：模型回退（主模型挂→轻量模型/缓存/热门推荐兜底）、特征回退（特征服务不可用→默认特征值）、负载卸载（牺牲部分请求保整体）。三态循环（健康/降级/恢复）防止系统在降级态卡死。Netflix 混沌工程训诫：**从不演练的回退路径只是文档，不是容错**。

## 经验与常见坑

- **硬件故障不是主要矛盾**：ML 作业长活、有状态、对控制面小错敏感——软件 bug、配置错误、资源耗尽往往占事故大头。错误的 checkpoint 路径能让恢复不可能、集合库版本不匹配能让全 rank 挂起。重金堆硬件冗余却忽视软件防御（输入校验、渐进发布、配置管理）是常见错配。
- **checkpoint 间隔靠直觉定必错**：1000 卡、MTBF 4h、写 5 分钟 → 最优 49 分钟（直觉"每小时"碰巧接近）；写变 15 分钟 → 最优 85 分钟（"每 15 分钟求保险"反而多花数倍）。直觉值常偏 2–3 倍。
- **MTBF 是种群统计不是单卡预言**：5 万小时 MTTF 的 GPU 可能 200 小时就坏。它可靠预测的只有聚合故障率（万卡 ≈ 每 5 小时一次）。预测哪张卡下一个坏是范畴错误。
- **故障是相关的**：共享电源/交换机/软件 bug/冷却让独立假设失效——相关故障同时改变频率与爆炸半径。用多样性缓解：不同供电、不同网络路径、金丝雀发布。
- **不是所有故障都该全量重启**：瞬态→重试/暂停（内存态还有效）；永久→checkpoint-restart 换硬件；**静默损坏→回滚到更早的 checkpoint 而非最新的**（需要保留 checkpoint 历史）；资源耗尽→先重配置再重启（否则立即再崩）。误分类白烧算力。
- **checkpoint 要验证一致性**：rank 间 step 不齐、部分写、优化器态与权重不同拍、in-flight 梯度——生产必须验证 shard 齐全、迭代号一致、优化器态匹配。恢复时才发现 checkpoint 坏了就只剩更早的回退点。
- **容错路径必须常练**：没崩过=恢复逻辑从没跑过=bug 期末兑现。混沌工程（随机杀 GPU、注入分区、打挂主模型）把"应该能用"变成"已知能用"。
- **弹性训练不替代 checkpointing**：状态一致性、最小可行规模、软件 bug 仍在、退化累积后还是要 restart——两者互补。
- **开销百分比不是物理常数**："气泡 10%/checkpoint 5%/恢复 3%"是工程目标，不是容量计划的固定行项目。每项都是可优化的决策。
- **加卡有可靠性版收益递减**：每张卡都抬升聚合故障率、抬高恢复/重放期望时间。存在一个规模点，之后故障+恢复损失吃掉新增并行收益、墙钟时间不降反升。合并模型：goodput = MFU × 扩展效率 × (1−故障开销)。
- **有 ECC ≠ 没有 SDC**：ECC 管单 bit，多 bit 逃逸与逻辑路径损坏仍会发生。"loss spike 是坏 batch"、NaN 归咎学习率、正确超参却不收敛——都可能是 bit 翻转。检测靠冗余计算、梯度 checksum、分布监控。
- **观测三支柱**：Metrics（症状：p99 从 45ms 跳 800ms）、Traces（定位：feature-service span 700ms 而 inference 正常）、Logs（根因：缓存连接超时→缓存击穿打挂数据库）。级联故障诊断实例指向修复：缓存熔断+默认 embedding 兜底。**训练失败签名**：平滑下降=正常；突刺+梯度范数 100×=数据损坏/爆炸；平台期=死优化器/学习率；NaN 震荡=数值溢出。

## 案例研究

- **Meta OPT-175B**（992 A100、两个月）：约 90 次硬件/稳定性驱动的人工重启、100+ 台主机轮换（约每天 2 台宕机）；train-log 新鲜度监控（15 分钟阈值后放宽到 1 小时）；同步 checkpoint 12% 开销改异步 <3%；loss spike 处理=回滚+降学习率（最终约为 GPT-3 学习率的 2/3）；最终维持约 147 TFLOP/s/A100（近 FP16 峰值 50%）。
- **Google TPUv4 pod**（4096 chip=64 个 4×4×4 cube）：策略是**切片抽象而非在线修复**——OCS 光路交换把健康 cube 拼成逻辑 slice，故障时不修补运行中的拓扑而是抢占作业、重构等形新 slice（libtpunet+healthd 监测，健康 cube 替换）。99.98% 系统可用性。教训：紧耦合高带宽系统，修补运行拓扑常是徒劳，**原子故障单元之上重组**更高效。
- **Netflix 混沌工程**：主动注入故障验证稳态；ML 服务的回退层级（主模型→轻模型→缓存→热门兜底）必须被演练。
- **微软 DeepSpeed**：分片框架的容错=checkpoint+shard 恢复原语交给调度器组合，不是单体重启脚本；Universal Checkpointing 提供跨拓扑可移植性。

三条普适原则：**检测速度决定恢复成本；故障的原子单元要匹配架构耦合度；容错是光谱不是二值**。

## ⚠️ 时效性说明

MTBF 常数（GPU 5 万小时等）、Meta/Google 实测数据、框架（TorchElastic/DeepSpeed/Ray/Horovod）能力矩阵为原书 2024–2025 年快照；运维者应以自己集群的实测故障率替换规划常数。
