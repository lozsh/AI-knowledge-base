# 向量检索与嵌入：从 ANN 算法到向量数据库

/> 来源：公开课程资料自学整理（更新于 2026-11-03）
> 一句话概括：语义检索 = 嵌入模型把文本映射为高维向量 + 近似最近邻（ANN）索引 + 向量数据库的工程化封装；传统检索专栏的 LSH/乘积量化是这一切的算法底座。

## 核心概念

- **嵌入（Embedding）**：把文本/图像/音频映射为高维稠密向量，向量在语义空间中充当"坐标"。语义相近的对象在向量空间中彼此邻近，语义相异的相距较远。每个维度对应文本的某种隐含特征。
- **向量检索（Vector Retrieval）**：把查询也转成向量，通过计算相似度找出最相近的文档向量。它匹配的是**语义**而非字面——这是与传统关键词检索的本质区别。
- **向量空间模型（Vector Space Model）**：传统做法是把文档表成"关键词 × TF-IDF 权重"的稀疏高维向量；现代做法是用嵌入模型生成稠密向量。两者都把检索问题转化为高维空间中"找最近邻的点"。
- **近似最近邻检索（ANN）**：高维空间精确找最近邻代价不可接受（k-d 树在十几维尚可，维度上百后退化到接近遍历），因此放弃精确性换取速度，"非精准换高效"。

## 关键方法/原理

### ANN 索引的三条技术路线

1. **哈希路线：局部敏感哈希（LSH）**
   - 设计思想：让**相似的数据哈希后哈希值也相近**（普通哈希恰恰相反，一字之差哈希值天差地别）。
   - 随机超平面法：随机生成 n 个超平面把空间切分，点在超平面哪一侧记 1/0，得到 n 位哈希码；两点哈希码相同（或海明距离小）则大概率相近。
   - **SimHash**（Google，64 位）：用普通哈希函数对每个关键词生成 64 位哈希，0 换 -1 后乘关键词权重，按位累加，最后正负号定 1/0。保留关键词权重信息且实现简单。相似判定用**海明距离**（Google 取 <3）。
   - 检索加速用**抽屉原理分段**：64 位切 4 段，海明距离 ≤3 时至少一段完全相同，按段建 4 个倒排索引，查相似只需查 4 个段索引再精判海明距离。
   - 局限：粒度粗、更适合**字面相似**而非语义相似。
2. **量化路线：乘积量化（PQ）**
   - **量化** = 把空间划成多个区域，用区域编码代替精确坐标；**乘积** = 高维空间视为多个低维子空间的乘积。
   - 做法：1024 维 float 向量（4KB）切成 4 段各 256 维，每段用 K-means 聚成 256 类，每段向量用它所属聚类 ID（1 字节）表示——整向量压到 4 字节，**压缩比 1/1024**。
   - 距离计算查表化：查询向量每段先与 256 个聚类中心算距离生成距离表（每查询只算一次），与样本的距离 = 4 次查表 + 合并，代价从高维计算降为常数级。
   - 与倒排索引结合即 **IVF-PQ**：先对全量向量 K-means 聚成 1024 类、以聚类 ID 建倒排索引，类内向量再减去类中心后做 PQ 压缩；查询时只遍历最近的（或次近的）几个聚类。
3. **图路线：HNSW（层次可导航小世界图）**
   - 多层图结构，相似向量互连，查询从顶层稀疏图逐层下降快速缩小范围。现代向量数据库的主流索引。

配套的聚类基础：K-means 的优化目标是**类内点到类中心距离均值总和最短**；迭代"分配→更新中心"直至收敛。比 LSH 更灵活，保留向量高维度以精确计算距离。

### 相似度度量

| 度量 | 含义 | 适用 |
|---|---|---|
| 余弦相似度 | 向量夹角，不受模长影响 | **文本语义检索首选**（RAG 默认） |
| 欧氏距离（L2） | 空间直线距离 | 密集特征的聚类/分类，图像 |
| 内积（点积） | 常与余弦等价（归一化后） | 推荐召回 |
| 曼哈顿距离（L1） | 坐标差绝对值之和 | 稀疏数据 |

工程要点：嵌入向量做**归一化**（normalize）后，余弦相似度与内积等价，计算更简单准确。

### 嵌入模型的选择

- 演进脉络：word2vec/GloVe/fastText（静态词向量）→ BERT/RoBERTa 等 Transformer（**上下文敏感**，同一个词在不同语境向量不同）→ 专用检索嵌入模型。
- 选型评估维度：领域适用性、检索精度、支持语言、**最大 token 数**（512 已满足多数分块场景）、**嵌入维度**（维度低→推理快存储省；维度高→保留细节）、模型大小与延迟。
- 参考 **MTEB / C-MTEB 榜单**：RAG 场景按 **Retrieval Average（检索平均值）**列排序，而非综合分。榜单只是初筛——**实验至关重要**：选多个高分模型在自己的业务数据集上测。
- 中文知名开源模型：智源 **BGE 系列**（bge-small/large-zh-v1.5 等，C-MTEB 表现出色）；工程上常用 SentenceTransformers 加载。

### 向量数据库

- 定位：专为**生产场景的向量嵌入管理**构建的数据库，对比纯索引工具（Faiss 只是不带存储管理的库）：数据增删改管理、**元数据存储与过滤**、可扩展性（分布式/无服务器）、实时更新、备份恢复、生态集成（LangChain/LlamaIndex）、数据安全与多租户。
- 工作流程：数据处理与向量化 → 向量存储 → 向量索引（HNSW/PQ/LSH 等结构，本质是"预处理"）→ ANN 相似性搜索（速度与准确性权衡）→ 取回原始数据并后处理。
- 四类选型（按开源/商用 × 专用/通用）：
  - 开源专用：Chroma（轻量开箱即用，适合快速开发）、Qdrant、Milvus（企业级高性能/可扩展）、Vespa、LanceDB、Marqo
  - 开源通用（带向量插件）：PostgreSQL(pgvector)、OpenSearch、ClickHouse、Cassandra
  - 商用专用：Pinecone（全托管免运维）、Weaviate
  - 商用通用：Elasticsearch、Redis、SingleStore
  - FAISS：极致性能、但无持久化与数据管理，适合实验/内存场景。
- 经验：原型选 Chroma/Qdrant；企业级大规模选 Milvus/Zilliz；已有 PG/ES 的团队直接用插件（pgvector/ES 向量字段）避免引入新组件。

## 经验与常见坑

- k-d 树只适合低维（十几维）；文本/图像 embedding 几百上千维，必须用 LSH/PQ/HNSW 类 ANN。
- LSH 只能抓**字面相似**：讲"随机超平面"和讲"SimHash"的两篇文章字面迥异、语义相同，LSH 抓不到——语义相似必须靠学习型嵌入。
- SimHash 分段数由海明距离阈值决定：距离 ≤3 时 64 位切 4 段（3 个差异位最多落在 3 段，必有一段全同）；阈值变了分段数要跟着按抽屉原理重算。
- 嵌入模型的最大 token 数决定分块上限：超长 chunk 会被截断，尾部信息静默丢失。
- 向量检索的弱项恰是关键词检索的强项：**精确匹配**（订单号、产品名、人名）、**超短查询**（缩写 RAG/LLM）、**低频关键词条**——这是混合检索存在的理由（详见 04 篇）。（RAG快速弉

## ⚠️ 时效性说明

- LSH 在现代向量数据库中已较少作为主力索引（HNSW/IVF 系为主），但其"分桶换速度"思想仍是面试与原理理解的必备。
- 嵌入模型型号迭代极快（BGE 系列为 2024 年时点推荐），选型时以当年 MTEB/C-MTEB 榜单为准；文中"512 token 足够"的结论对应当时的分块实践，长上下文嵌入模型出现后需重新评估。
- 向量数据库格局变化快，列名以 2024 年为快照。
