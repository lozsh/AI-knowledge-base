# 提示词设计方法论：从结构化提问到场景落地

<p class="note-date">更新于 2026-11-05</p>
> 一句话概括：模型 = 概率 + 模式 + 关键词权重，理解这个根因就能推导出全部提示词技巧——结构化提问解决输入质量，人设与参数化解决复用，Few-shot/CoT 解决推理，负面限定解决定制化，迭代与 Debug 解决不确定性，场景模板解决落地。

## 核心概念

- **根因推导链**：模型按概率和关键词权重工作，"不要"常被忽略甚至反向触发；输出质量主要取决于输入质量（prompt 是用户唯一可控的发力点，数据+算法+算力都不可控）。
- **两大法则**：**把 AI 当人**——平等沟通、相信并引导其逐步推理，而不是当搜索框用；**结构化写法**——本质是把模型的创造性限制在业务场景范围内。
- **提示词是一切应用的基础**：提示词是对大模型的"进一步训练"，一个提示词就是一个接口，定义输入输出契约。
- **图灵思维**：先定位模型边界，边界内求最优解，不硬闯禁区。幻觉、知识截止、上下文限制都是边界，各有应对策略而非硬扛。
- **提示词通用公式**：定义角色 + 背景信息 + 任务目标 + 输出要求；本质都是给模型充足上下文，让它推断你想要什么。
- **推理模型的打法反转**：自带思维链的推理模型（o 系、DeepSeek-R1 路线）不需要"角色扮演+少样本+CoT 指令"堆料，回归朴素——真诚、清晰、直接地表达真实意图，套话和过度包装反而稀释意图。

## 关键方法/原理

### 1. 交互五原则
1. **写清晰指令，一步到位**：明确任务、输出格式、约束。清晰指令下弱模型也能高质量完成；反例是笼统一句就指望好结果。
2. **提供参考资料**：模型知识冻结于训练时刻，把数据放进上下文"查字典"才准确可信（最简形态的 RAG）。不供数据问数据类问题 → 幻觉。
3. **分而治之**：大目标拆成有序小步骤，任务越具体越有的放矢。"写份报告"这种指令输出必然散漫。
4. **思考、再思考**：追问"还有哪些因素/不足/切入点"促周全。**注意：反思类技巧对模型规模有下限**，小模型做二阶反思会崩坏成复读。
5. **用外部工具增强**：模型只决定调什么、消化结果，执行交给真实 API；不该让模型硬答实时信息。

### 2. 结构化提问（输入质量）
- 提问 5 要素：**主题 + 数量 + 细节 + 方式 + 格式**。
- 3 步提需求法：① 明确需求并按 P0/P1/P2 优先级拆分；② 补背景信息（主体/受众、领域、AI 可能不懂的概念、材料数据）；③ 补细节约束（DO & DON'TS + 示例、数量字数、风格、输出格式）。
- 通用模板：`主题+目的 / 背景信息 / 步骤 / 要求 / 材料`。
- 坏 prompt 两个极端：缺背景的简陋提问 vs 拥挤无结构的大段描述。**指令冲突（前后矛盾）比信息少更致命**，是长 prompt 的头号杀手。

### 3. 3 步人设法（3W）
1. **WHO 立人设**："你是一位 xx 领域的 xx 角色"，可投喾示例/知识库。
2. **HOW 列要求**：需求 ≥3 项就加"步骤"激活慢思维；规避项用示例引导，而非干说"不要"。
3. **WHAT 下指令**：一句清晰具体的需求放模板**末尾**（古腾堡法则——结尾是"最终视觉区"，权重最高）；人设部分才能长期复用，主题可替换。

### 4. 参数化沟通（复用）
- 四组件：功能指令（`/xx` 区分指令与描述）、变量（赋值驱动 1 到 N 复用）、默认值（回复"1"走默认，高容错）、初始化 + `/help`（首屏偏好菜单防迷失）。
- 3W 的参数化变体：Who = import 角色；How = 模块（"/xx 模块：做什么？有哪些要求？"，规则可写 if 条件分支）；What = run 调用。
- 配套技巧：指令/变量用简短英文命名（`tail` 优于"后缀"）；暗号触发任务隔离"沟通"与"执行"；一个会话一个人设，一个会话只跑一个分支。

### 5. Few-shot、思维链与思考框架
- 效果阶梯：Zero-shot → One-shot（精度大幅提升）→ Few-shot → One-Shot CoT（示例里带推理步骤）。无示例时用"请一步一步思考"（Zero-Shot CoT）激活慢思维；示例求质不求量，2-3 个精品示例通常够用。
- 思考框架谱系（可组合；RAG、工具调用、ReAct 广义上都是思考框架）：

| 框架 | 做法 | 注意点 |
|---|---|---|
| Few-shot | 给示例 | 示例须覆盖全部类别，否则偏科 |
| CoT | 规定输出结构"重述问题→分步骤→答案" | 结构化约束比口头"一步步想"有效 |
| Self-Consistency | 高温度多候选 + 投票 | 开销 ×N |
| 辩论/自我反思 | 解题→质疑→综合，每步换角色 | 受模型规模下限约束 |
| APE | 把提示词当优化对象自动搜索 | 易过拟合 |

### 6. 推理模型的专用打法
- **通用公式（万能模板）**：`我要（做）____，要给____用，希望达到____效果，但担心____问题。`四要素 = 任务 + 背景 + 目标 + **负面限定**（担心的"内心戏"）。例："做北京到日本的旅游攻略，给爸妈用，希望他们开心玩 20 天，但担心他们玩得太累、腿腰不好"——模型会自动输出带每日步数限制、备选休息安排的细致方案。**"担心什么"往往比"要什么"更决定输出质量。**
- 七个技巧：① **真诚+直接**（必杀技），说清真实场景别包装——"把这份调研报告总结包装成周报给老板看，老板很看重数据"比"你是资深分析师，按格式写 500 字周报"效果更好；② 通用公式（上）；③ **说人话**——回答太官方/学术时加一句"说人话"；④ **反向施压**——利用思维链让它更卖力："列出 10 个反对理由再给方案""这个回答你满意吗？请复盘至少 10 轮"；⑤ **善于模仿**——约束式写文案效果一般，给范文或指定模仿某人的语气命中率高得多；⑥ **锐评句式**——"______，笑死"触发犀利点评（适合初稿自我审视）；⑦ **激发深度思考**——结尾加"加入你的批判性思考""回答之前先自己复盘"。
- **坑：蒸馏小模型 ≠ 满血版**。本地跑的 1.5B–8B 蒸馏模型复杂推理远弱于 671B 满血版，效果差先查模型版本再怀疑提示词。

### 7. 否定处理（控制）
- 三策略：① 否定转肯定（说"改成什么"）；② 侧重肯定 + 附否定；③ 示例调教让它"抄作业"。
- 进阶：加判断分支（"如果…否则…"、"回 1 保持默认"）；上下文成对约束（"用高效方式"+"避免多余依赖库"成对出现，比孤立"不要"更精准）。英文 "Do not" 比中文"不要"更稳。

### 8. 迭代改进（不确定性管理）
- 迭代循环：盘点需求设计初始 prompt → 源头观察校正（编辑原 prompt 修错漏、重新生成做多组对比）→ 过程迭代（**方向没偏才持续沟通，偏离就回源头改**）。
- 判断标准：调整后能跑通且基本符合预期 → 继续聊；否则改源头——因为初始 prompt 影响权重最大。
- **提示词当程序、修改当 Debug**：先给模型"画像"（如"讨好型客服"），再在对应分区（Goals/Skills/Workflow）中定位调整；一版提示词改 20+ 次是正常的。
- **用词即代码**：最隐蔽的 Bug 是双方对同一个词的理解不一致——让模型输出"你对某词的理解"当作 log 来对齐。
- 优化三原则：根据输出调整、删冗余、去冲突。
- 小技巧："从 XX 部分继续"精确续写；报错直接复制"报错：<信息>"交回 AI 修；抓大放小搁置非核心需求。

### 9. 多步提示与任务分解
- **生成单元测试四步：解释 → 规划 → 执行 → 检查**。单步直接写会漏边界；先让模型解释代码（注入 CoT），再按"好测试准则清单"规划场景（准则是关键杠杆），执行时累积前两轮全部消息 + 严格输出模板，最后程序静态校验语法、失败重生成。
- **自然语言转 SQL 三段式**：完整 schema（程序化从库拉取，不靠猜）+ 问题 + 硬约束"只输出 SQL"。弱模型多表 JOIN 需显式标注外键。
- 可迁移公式：**结构化上下文注入 + 输出格式硬约束 + 真实环境执行验证**。
- 底线：期望值（ground truth）不能交给 AI 生成，正确性必须人管。

### 10. 生产化要点
- **模板化**：用 `"""` 分隔指令与变量；输出加自定义分隔符（如 `$$$start$$$`）便于程序提取。
- **多平台适配**：同一提示词在不同模型上行为不同，分隔符要选不会撞车的（如 `__start__`）并专门限定。
- **收窄职责反而效果更好**：判题提示词删掉题干与答案、只留输出比对，效果大增；逻辑严谨场景用总结能力，宽松场景才用生成能力。
- **成本**：简化输入可省约 50% token；缓存策略避免重复调用（系统级成本优化见[应用选型与成本](../07-%E5%A4%A7%E8%AF%AD%E8%A8%80%E6%A8%A1%E5%9E%8B/14-%E5%A4%A7%E6%A8%A1%E5%9E%8B%E5%BA%94%E7%94%A8%E9%80%89%E5%9E%8B%E4%B8%89%E5%B1%82%E6%A1%86%E6%9E%B6.md)）。

### 11. 边界应对策略
| 边界 | 应对 |
|---|---|
| 幻觉 | 所有结果必须验证；换不同 prompt 测答案一致性交叉验证；创作场景可反向利用幻觉；学术引用逐条核实 |
| 知识截止 | 新概念附加解释（"AI 绘图工具 Midjourney"式注释）；要求给出处但须逐个验证 |
| 上下文限制 | 长文摘要套娃或分块输入（中途只回 OK）；固定"生成点"接近上限就编辑重提防断片 |
| 中英差异 | 关键术语中英混打；否定用英文更稳 |
| 精确计算 | 分工给工具/代码执行环境，模型只出思路和代码 |

## 附录：落地场景速查

场景提示词的共同结构是"**领域要素填空**"：把领域方法论拆成提示词组件（目标 + 特殊要求 + 输出格式），换主题即复用。以下为高频场景的要素范式，可直接套用。

### 办公与职场
- **PPT 五分钟流**：模型生成大纲 → 专业工具（Kimi 类 PPT 功能、Xmind 思维导图：先出 Markdown 大纲再导入）套模板 → 细节调整。多工具组合优于单模型硬扛。
- **会议纪要**：提取时间/地点/参会人/决议事项/责任部门/完成时限六要素，分条列项，删讨论留结论；或按决策/待办/风险三类分栏。
- **英文跟进邮件**：进度 + 关键节点 + 请求配合 + 期待回复。
- **简历深度优化**：STAR 法则重构工作经历（每段 3 个量化指标）+ 技能栏细分项 + 按 JD 调整关键词密度 + ATS 兼容性检测。
- **合同审核**：知识产权/违约责任/保密条款逐条检查并标风险。
- **人力资源**：岗位 + 能力 + 测试示例 → 输出胜任力测试考题。

### 体制内公文（要素化模板）
- 通知类："你作为[单位][职务]，起草关于[主题]的通知，需包含[要素1][2][3]，语言简洁无形容词，符合《党政机关公文格式》。"
- 请示类："以[单位]名义向[上级]提交[事项]请示，说明[背景][请求内容][方案建议]，结尾用'妥否，请批示'。"
- 调研报告："[基本情况]-[主要问题]-[对策建议]"结构，数据注明来源，问题按紧迫性排序，建议注明责任单位。

### 编程开发
生成代码（"用 Python 写[X]脚本，实现[X]功能并加异常处理"）、API 对接（含身份验证与错误重试）、代码审查（"检查 5 个潜在问题，按安全性/性能/可读性分类"）、DEBUG（附错误日志要两种修复方案）、算法优化（指出复杂度改进方向并解释思路）、并发（防数据竞争死锁）、数据库迁移（支持清洗转换、确保无丢失）、单元测试（覆盖核心功能与边界，断言验证）。

### 数据分析
数据洞察（找 3 个增长机会 + 2 个风险）、市场预测（未来 6 个月 3 个趋势）、财报解读（2 个关键问题 + 1 个改进建议，通俗语言）、用户画像（3 个关键特征）、定价策略、客户流失（3 个原因 + 2 个挽留策略）、数据质量评估（准确性/完整性/一致性）、可视化设计（指定要突出的维度）。

### 教育与学术
- **教学设计**：技能 + 教学目标 + 工作流，按主题/目标/课时/学情生成课程大纲草案；**分层习题**按布鲁姆认知分类标注难度（A/B/C 三级）。
- **论文全流程八步**：锁定选题 → 大纲 → 文献综述 → 按大纲扩写 → 研究方法设计 → 数据分析与讨论 → 撰写 → 润色与查重。
- **学术八件套**：文献速读（近 3 年 5 篇高被引、规范引用格式）、论文速读（300 字总结 + 3 创新点 + 2 缺陷）、润色重写、学术翻译（术语准确）、学术辩论（正反各 3 证据表格对比）、综述撰写、研究假设设计（3 个可验证假设 + 实验方案）。⚠️ 文献类输出模型可能编造条目，引用必须逐条人工核实。
- **作业辅导（家长版五步法）**：知识点锚定 → 分步教学引导 → 互动练习 → 错误分析 → 能力拓展；把"我不懂教学、快失去耐心"的处境写进背景，让模型输出带情绪管理提示的辅导方案。

### 内容与商业
- **新媒体**：爆款标题（10 个、语气词+悬念）、短视频脚本（开场悬念+中段反转+结尾行动号召+3 个特写镜头）、公众号深度文（3 个分论点各配 1 案例）、种草笔记（身份视角、3 场景 3 痛点）、SEO 文章（关键词密度 + H2/H3 标签）。
- **电商**：直播话术（憋单 + 价格锚点 + 互动留人）、详情页转化（痛点爆破 + 信任体系 + 证言）、跨境文案（目标市场人群 + 规避文化禁忌 + 植入 SEO 关键词）、舆情监测（目标 + 情感分析 + 追踪要求）。
- **批量海报**：先统一制式生成文案信息，再按各工具差异替换标题/标语/图片——提示词驱动的"模板 + 变量"生产模式。

### 去 AI 味提示词组
降 AI（过渡词替换为最基础常用词、删文末总结）、保持主题一致性（段落递进、衔接清晰）、简化结构（短句、每句一个核心意思）、润色（风格介于书面与口语间、非日常词汇替换）、转换语气（按正式/说服/非正式场景调）、增加细节、调整节奏句式、突出核心删冗余。

### 生活服务
旅行规划（景点/美食/交通/住宿，避免过度安排——把"担心玩太累"写进负面限定）、菜谱（指定食材做低卡料理含营养数据）、购物决策（多维度打分对比）、健身/学习计划、家庭财务管理（把收入结构与开支约束写进背景生成分配规划）。命理玄学类属娱乐向用法，模型输出不具备事实性保证。

## 经验与常见坑

- **GPT 能解决的问题 ≠ 你以为它能解决的问题**：最贵的坑是意识不到它能做。从自身需求找结合点，正反馈驱动。
- **给推理模型堆角色扮演和示例常常适得其反**：过度包装的提示词不如一句真实意图——这是推理模型与传统生成模型最大的打法差异。
- **忘写"担心的负面限定"**：只说要什么不说怕什么，输出往往是泛泛的通用方案。
- 慢来比较快：先试探再深入，提问能力决定迭代次数；不期望一步到位。模板要吃透要点灵活调整，不要生硬完形填空。
- 概念试探法：不确定模型懂不懂某概念，先新开会话试探，懂就不写进 prompt（省 token）。
- 反思/辩论类高级技巧在小型模型上会失效甚至劣化——技巧与模型能力要匹配。
- 提示词对词义的理解偏差是最隐蔽的 Bug，让模型复述定义是对齐手段。
- 严格限定输出职责（删掉不必要的输入信息）通常提升而非降低效果。
- 单步直出的复杂任务结果漏边界，几乎总要拆成"解释→规划→执行→检查"。
- 局部不稳定属正常，不影响核心功能就迭代一次即可；Prompt 资产化：高频模板/人设存成可快速调用的库，持续迭代、过时下架。公式化提示词可固化为团队标准件，换参数即复用。
- 提示词效果随模型版本变化，昨天有效的写法明天可能失效，必须持续实测；跨模型不可直接复用。

## ⚠️ 时效性说明

方法论骨架（结构化提问、人设、few-shot、迭代、负面限定）长期有效，但具体参数已大幅过时：⚠️ 上下文"约 4000 汉字"、知识截止 2021、"GPT 数学运算差、无联网"等局限叙述均已被后续模型推翻（长上下文、联网检索、推理模型内置 CoT 已普及）；DAN 越狱类玄学 prompt 已失效；推理模型使手工 "step by step" 的价值下降。推理模型打法部分基于 2025 年初 DeepSeek-R1 爆发期的观察，其后各家推理模型持续迭代（更长思维链、工具调用、多模态），具体通道与价格以当期官方信息为准（详见[DeepSeek 推理模型、蒸馏与部署选型](../12-%E6%A8%A1%E5%9E%8B%E8%AE%AD%E7%BB%83%E4%B8%8E%E4%BC%98%E5%8C%96/09-DeepSeek%E6%8E%A8%E7%90%86%E6%A8%A1%E5%9E%8B%E3%80%81%E8%92%B8%E9%A6%8F%E4%B8%8E%E9%83%A8%E7%BD%B2%E9%80%89%E5%9E%8B.md)）。"反思类技巧的规模下限"等结论基于 2024 年前后的模型水平，随模型迭代边界会移动。
