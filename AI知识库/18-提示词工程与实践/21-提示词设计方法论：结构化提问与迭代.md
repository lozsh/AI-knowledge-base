# 提示词设计方法论：结构化提问、人设与参数化

<p class="note-date">更新于 2026-11-03</p>
> 一句话概括：模型 = 概率 + 模式 + 关键词权重，理解这个根因就能推导出全部提示词技巧——结构化提问解决输入质量，人设与参数化解决复用，Few-shot/CoT 解决推理，否定转肯定解决控制，源头迭代解决不确定性。

## 核心概念

- **根因推导链**：模型按概率和关键词权重工作，"不要"常被忽略甚至反向触发；输出质量主要取决于输入质量（prompt 是用户唯一可控的发力点，数据+算法+算力都不可控）。
- **图灵思维**：先定位模型边界，边界内求最优解，不硬闯禁区。幻觉、知识截止、上下文限制都是边界，各有应对策略而非硬扛。
- **提示词通用公式**：定义角色 + 背景信息 + 任务目标 + 输出要求；本质都是给模型充足上下文，让它推断你想要什么。

## 关键方法/原理

### 1. 结构化提问（输入质量）
- 提问 5 要素：**主题 + 数量 + 细节 + 方式 + 格式**。
- 3 步提需求法：① 明确需求并按 P0/P1/P2 优先级拆分；② 补背景信息（主体/受众、领域、AI 可能不懂的概念、材料数据）；③ 补细节约束（DO & DON'TS + 示例、数量字数、风格、输出格式）。
- 通用模板：`主题+目的 / 背景信息 / 步骤 / 要求 / 材料`。
- 坏 prompt 两个极端：缺背景的简陋提问 vs 拥挤无结构的大段描述。**指令冲突（前后矛盾）比信息少更致命**，是长 prompt 的头号杀手。

### 2. 3 步人设法（3W）
1. **WHO 立人设**："你是一位 xx 领域的 xx 角色"，可投喾示例/知识库。
2. **HOW 列要求**：需求 ≥3 项就加"步骤"激活慢思维；规避项用示例引导，而非干说"不要"。
3. **WHAT 下指令**：一句清晰具体的需求放模板**末尾**（古腾堡法则——结尾是"最终视觉区"，权重最高）；人设部分才能长期复用，主题可替换。

### 3. 参数化沟通（复用）
- 四组件：功能指令（`/xx` 区分指令与描述）、变量（赋值驱动 1 到 N 复用）、默认值（回复"1"走默认，高容错）、初始化 + `/help`（首屏偏好菜单防迷失）。
- 3W 的参数化变体：Who = import 角色；How = 模块（"/xx 模块：做什么？有哪些要求？"，规则可写 if 条件分支）；What = run 调用。
- 配套技巧：指令/变量用简短英文命名（`tail` 优于"后缀"）；暗号触发任务隔离"沟通"与"执行"；一个会话一个人设，一个会话只跑一个分支。

### 4. Few-shot 与思维链
- 效果阶梯：Zero-shot → One-shot（精度大幅提升）→ Few-shot → One-Shot CoT（示例里带推理步骤）。
- 无示例时用"请一步一步思考"（Zero-Shot CoT）激活慢思维。示例求质不求量，2-3 个精品示例通常够用。

### 5. 否定处理（控制）
- 三策略：① 否定转肯定（说"改成什么"）；② 侧重肯定 + 附否定；③ 示例调教让它"抄作业"。
- 进阶：加判断分支（"如果…否则…"、"回 1 保持默认"）；上下文成对约束（"用高效方式"+"避免多余依赖库"成对出现，比孤立"不要"更精准）。英文 "Do not" 比中文"不要"更稳。

### 6. 迭代改进（不确定性管理）
- 迭代循环：盘点需求设计初始 prompt → 源头观察校正（编辑原 prompt 修错漏、重新生成做多组对比）→ 过程迭代（**方向没偏才持续沟通，偏离就回源头改**）。
- 判断标准：调整后能跑通且基本符合预期 → 继续聊；否则改源头——因为初始 prompt 影响权重最大。
- 优化三原则：根据输出调整、删冗余、去冲突。
- 小技巧："从 XX 部分继续"精确续写；报错直接复制"报错：<信息>"交回 AI 修；抓大放小搁置非核心需求。

### 7. 边界应对策略
| 边界 | 应对 |
|---|---|
| 幻觉 | 所有结果必须验证；换不同 prompt 测答案一致性交叉验证；创作场景可反向利用幻觉 |
| 知识截止 | 新概念附加解释（"AI 绘图工具 Midjourney"式注释）；要求给出处但须逐个验证 |
| 上下文限制 | 长文摘要套娃或分块输入（中途只回 OK）；固定"生成点"接近上限就编辑重提防断片 |
| 中英差异 | 关键术语中英混打；否定用英文更稳 |
| 精确计算 | 分工给工具/代码执行环境，模型只出思路和代码 |

## 术语表

| 术语 | 英文 | 含义 |
|---|---|---|
| 零样本/单样本/少样本 | Zero/One/Few-Shot | 不给例子/给 1 个/给多个示例引导输出 |
| 思维链 | CoT (Chain of Thought) | 显式推理步骤，提升推理任务正确率 |
| 人设 | Persona/Role | 用角色定义为模型提供行为框架 |
| 参数化提示词 | Parameterized Prompt | 用变量和指令把 prompt 做成可复用模板 |
| 指令集 | Instruction Set | 人设+变量+任务+规则的组合，可按分支调用 |
| 慢思维 | Slow Thinking | 通过"一步步思考"触发的显式推理模式 |

## 经验与常见坑

- **GPT 能解决的问题 ≠ 你以为它能解决的问题**：最贵的坑是意识不到它能做。从自身需求找结合点，正反馈驱动。
- 慢来比较快：先试探再深入，提问能力决定迭代次数；不期望一步到位。
- 模板要吃透要点灵活调整，不要生硬完形填空；"写最少的 prompt，拿最好的结果"。
- 概念试探法：不确定模型懂不懂某概念，先新开会话试探，懂就不写进 prompt（省 token）。
- 局部不稳定属正常，不影响核心功能就迭代一次即可，别追求完美。
- Prompt 资产化：把高频模板/人设存成可快速调用的库（输入法自定义短语等），持续迭代、过时下架。
- 提示词效果随模型版本变化，昨天有效的写法明天可能失效，必须持续实测（两门课共同的铁律）。

## ⚠️ 时效性说明

方法论骨架（结构化提问、人设、few-shot、迭代）长期有效，但具体参数已大幅过时：⚠️ 上下文"约 4000 汉字"、知识截止 2021、"GPT 数学运算差、无联网"等局限叙述均已被后续模型推翻（长上下文、联网检索、推理模型内置 CoT 已普及）；DAN 越狱、"谢谢❤️"玄学 prompt 已失效；推理模型使手工 "step by step" 的价值下降。课程基于 ChatGPT 网页版对话场景，2026 年的 API/IDE 场景下系统提示词与开发者消息分层已取代部分技巧。
