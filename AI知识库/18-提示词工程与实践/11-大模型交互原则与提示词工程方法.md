# 大模型交互五原则与提示词工程方法

/> 来源：公开课程资料自学整理（整理于 2026-11-03）
> 一句话概括：与大模型交互的五条基本原则 + 思考框架引导推理 + 结构化提示词写法与"提示词即程序、修改即 Debug"的迭代方法。

## 核心概念

提示词工程的两个定位：
- 提示词是**一切应用的基础**——它是对大模型的"进一步训练"，一个提示词就是一个接口，定义输入输出契约。
- 两大法则：**把 AI 当人**（平等沟通、相信并引导其逐步推理，而不是当搜索框）；**结构化写法**——本质是把模型的创造性限制在业务场景范围内。

## 关键方法/模式

### 交互五大基本原则
1. **写清晰指令，一步到位**：明确任务、输出格式、约束。清晰指令下弱模型也能高质量完成；反例是笼统一句就指望好结果。
2. **提供参考资料**：模型知识冻结于训练时刻，把数据放进上下文"查字典"才准确可信（最简形态的 RAG）。不供数据问数据类问题 → 幻觉。
3. **分而治之**：大目标拆成有序小步骤，任务越具体越有的放矢。"写份报告"这种指令输出必然散漫。
4. **思考、再思考**：追问"还有哪些因素/不足/切入点"促周全。**注意：反思类技巧对模型规模有下限**，小模型做二阶反思会崩坏成复读。
5. **用外部工具增强**：模型只决定调什么、消化结果，执行交给真实 API；不该让模型硬答实时信息。

### 思考框架（引导推理的提示词模式）
| 框架 | 做法 | 注意点 |
|---|---|---|
| Few-shot | 给示例 | 示例须覆盖全部类别，否则偏科 |
| CoT | 规定输出结构"重述问题→分步骤→答案" | 结构化约束比口头"一步步想"有效 |
| Self-Consistency | 高温度多候选 + 投票 | 开销 ×N |
| 辩论/自我反思 | 解题→质疑→综合，每步换角色 | 同样受模型规模下限约束 |
| APE | 把提示词当优化对象自动搜索 | 易过拟合 |

框架可组合；RAG、工具调用、ReAct 广义上都是"思考框架"。

### 结构化提示词写法
经典骨架：Role / Profile / Goals / Rules / Skills / Workflow / Constraints / Initialization。

### 提示词迭代方法（比框架更重要）
- 把提示词**当程序、修改当 Debug**：先给模型"画像"（如"讨好型客服"），再在 Goals/Skills/Workflow 中定位调整。
- 用词即代码：最大 Bug 是双方对词的理解不一致 → 让模型输出"你对某词的理解"当作 log 来对齐。
- 一版提示词改 20+ 次是正常的。

### 生产化提示词的四个实战挑战
1. **模板化**：用 `"""` 分隔指令与变量；输出加自定义分隔符（如 `$$$start$$$`）便于程序提取。
2. **多平台适配**：同一提示词在不同模型上行为不同，分隔符要选不会撞车的（如 `__start__`）并专门限定。
3. **成本**：简化输入可省约 50% token；缓存策略避免重复调用。
4. **幻觉**：**收窄职责反而效果更好**——判题提示词删掉题干与答案、只留输出比对，效果大增；逻辑严谨场景用总结能力，宽松场景才用生成能力。

### 多步提示/任务分解模式
- **生成单元测试四步：解释 → 规划 → 执行 → 检查**。单步直接写会漏边界；先让模型解释代码（注入 CoT），再按"好测试准则清单"规划场景（准则是关键杠杆），执行时累积前两轮全部消息 + 严格输出模板，最后程序静态校验语法、失败重生成。
- **自然语言转 SQL 三段式**：完整 schema（程序化从库拉取，不靠猜）+ 问题 + 硬约束"只输出 SQL"。弱模型多表 JOIN 需显式标注外键。
- 可迁移公式：**结构化上下文注入 + 输出格式硬约束 + 真实环境执行验证**。
- 底线：期望值（ground truth）不能交给 AI 生成，正确性必须人管。

## 术语表

| 术语 | 含义 |
|---|---|
| Few-shot | 在提示词中给少量输入输出示例引导行为 |
| CoT（思维链） | 引导模型输出中间推理步骤再给答案 |
| Self-Consistency | 多次采样候选答案后投票取一致结果 |
| APE | 自动提示词工程，把提示词当优化变量搜索 |
| 结构化提示词 | 按 Role/Goals/Rules/Workflow 等分区组织的提示词模板 |
| 幻觉 | 模型编造不存在的事实 |

## 经验与常见坑

- 反思/辩论类高级技巧在小型模型上会失效甚至劣化——技巧与模型能力要匹配。
- 单步直出的复杂任务结果漏边界，几乎总要拆成"解释→规划→执行→检查"。
- 提示词对词义的理解偏差是最隐蔽的 Bug，让模型复述定义是对齐手段。
- 严格限定输出职责（删掉不必要的输入信息）通常提升而非降低效果。

## ⚠️ 时效性说明

原则与模式长期有效；"反思类技巧的规模下限"等结论基于 2024 年前后的模型水平，随模型迭代边界会移动。
