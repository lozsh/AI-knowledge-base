# 低成本领域模型路线与 MoE 架构

<p class="note-date">核对更新于 2026-11-13</p>
> 一句话概括：小团队做大模型的标准动作——Self-Instruct 数据无中生有 + LoRA 低算力微调；大模型侧用 MoE 稀疏激活延续 Scaling Law，后训练用 GRPO 把"好提示词"固化成稳定能力。

## 核心概念

### 领域模型路线（以 Alpaca 为范式）
开源"羊驼系"回答了两个根本问题：**训练数据从何来、算力从何来**。
- Alpaca：LLaMA-7B + **175 条**人工种子指令 → Self-Instruct 扩到 **52K** 指令（text-davinci-003 生成），API 成本 **<$500**；LoRA 微调后指定任务可达 SOTA。
- 衍生：Vicuna-13B（ShareGPT 对话数据，$300 成本媲美 ChatGPT）、Guanaco（多语言）。
- 模型工程两大任务：微调（1→10）与从零构建（0→1）；领域模型多数方法源自 Alpaca 路线。

### MoE（混合专家模型）= 稀疏激活 + 分而治之
动机：Scaling Law 有效，但参数到数千亿~万亿级后**推理成为瓶颈**（单卡装不下、跨卡交互拉高时延与成本）。
- 一些架构（如 DeepSeekMoE）在 MoE 层使用**路由专家（Routed Experts）**与**共享专家（Shared Experts）**；共享专家并非所有 MoE 的必备构件；token 经 **Gate 门控**打分，Top-K 只激活最相关专家；共享专家承载跨任务共通知识，减少路由专家冗余（类比：大厅排队 → 专业柜台 + 调度中心）；
- **负载均衡**是命门：路由失衡导致热门专家过载、冷门专家欠训练伤泛化。DeepSeek V3 方案：引入按负载规则更新的**路由偏置（bias）**；训练步后根据专家过载/欠载调节，而非把它简单说成普通梯度学习参数。偏置只用于专家选择，混合权重仍用原 affinity；论文仍保留小系数序列级均衡损失；
- 两大收益：专业性提升表现、单请求实际计算量降低省推理成本；让有限算力下继续吃 Scaling Law 红利，是开源模型（V3→R1）能与头部闭源模型分庭抗礼的架构基础。
- 趋势判断：多模态、MoE、模型小型化是三大长期方向；GPT-4 是否采用 MoE 在公开报告中未获确认，不能把业界推测写成已证实结构。

## 核心原理

### Self-Instruct：数据无中生有四步
1. **种子数据**：每任务 1 指令 + 1 示例（唯一人工环节，175 条即可）；
2. **生成新指令**：每轮随机取 8 个上下文任务（6 人工 + 2 机器生成）提高多样性；
3. **分类任务特殊处理**：分类用**输出优先**（先生成标签再生成输入，避免类别偏斜）；非分类用输入优先；
4. **过滤**：与已有指令 ROUGE-L 重叠 ≥0.7 丢弃、排除含"图片/图表"类指令、去重。
本质是模型反演；数据质量上限 = 教师模型知识上限，突破法 = 低质量大规模原始语料 + LLM 提炼少量高质量语料。

### LoRA：低秩适配概要

LoRA 的核心假设是预训练模型适应下游任务只需较低的**内在维度**：冻结原权重 W₀，侧通道增量 ΔW = **BA**（r ≪ 维度），训练量与显存大幅下降（某些实验的 adapter checkpoint 可大幅缩小；完整推理仍要加载基座权重，adapter 大小不是总模型显存）。本领域小团队的典型用法：对 Self-attention 四矩阵做 LoRA、冻结 MLP，PEFT 库加载，单张消费级显卡即可在数小时内完成 Alpaca 级复现——低秩假设推导、初始化细节与超参配置详见[大模型训练流程实践](03-%E5%A4%A7%E6%A8%A1%E5%9E%8B%E8%AE%AD%E7%BB%83%E6%B5%81%E7%A8%8B%E5%AE%9E%E8%B7%B5.md)。

### 全量微调基准配置（可复算）
4×A100 80G，FSDP `full_shard`，3 epochs，lr 2e-5，cosine 调度，bf16/tf32——7B 级模型的通用起点。

### 后训练闭环：把提示语的偶然收益固化为技能
预训练"偶然捡到"的有效提示语（如 "Let's think step by step"）有随机性；**后训练目标 = 提升目标分布上的稳定行为，不能保证任意场景都触发正确技能**：
- **指令微调对齐**：收集真实场景指令数据（问答/任务规划/信息检索），专家标注校验；**多任务联合训练**——每类"好用"提示词视为一种任务，让模型提炼共同语义特征与推理路径；
- **强化学习对齐**：奖励体系对逻辑性/准确性/指令契合度打分；模拟场景与虚拟用户多轮交互试错；引入真实用户在线实验数据；
- **GRPO（Group Relative Policy Optimization）**：轻量化 RL 对齐的代表——同一问题采样一组输出，根据组内奖励构造相对优势并更新策略，省去单独价值模型；不是让参考模型直接评选最佳答案。奖励可来自规则或奖励模型，参考策略用于适用目标中的 KL 约束。R1 的表现很大程度受益于 V3 的高效推理调度 + 此类轻量 RL。PPO/GRPO/DPO 的机制对比与选型详见[模型后训练](06-%E6%A8%A1%E5%9E%8B%E5%90%8E%E8%AE%AD%E7%BB%83.md)。

## 术语表

| 术语 | 英文 | 含义 |
|---|---|---|
| 混合专家 | MoE（Mixture of Experts） | 门控稀疏激活多个专家子网络 |
| 稀疏激活 | Sparse Activation | 每 token 只激活部分参数 |
| 路由/共享专家 | Routed / Shared Experts | 按需激活的专家 / 全 token 共用的专家 |
| 内在维度 | Intrinsic Dimension | 微调所需低维子空间假设（LoRA 理论根基） |
| 低秩适配 | LoRA | 冻结权重、训练低秩增量 BA |
| PEFT | Parameter-Efficient Fine-Tuning | HF 参数高效微调工具库 |
| Self-Instruct | — | 用 LLM 自举扩增指令数据的方法 |
| GRPO | Group Relative Policy Optimization | 免价值模型的组内相对比较强化学习 |

## 经验与常见坑

1. Self-Instruct 的 ROUGE-L 去重阈值（0.7）与"输出优先"分类任务处理是数据质量的关键细节，漏掉会指令同质化；
2. 批量解码一次生成 20 条指令可摊薄生成成本；每指令只生成 1 个实例即可；
3. LoRA 有推理侧额外开销（合并前多一次 BA 计算），延迟敏感场景要合并权重或权衡；
4. 大模型参数大、单次训练成本高、合规责任重，不宜无验证地直接在线改权重；更新方式取决于算力、数据与风险。MoE 也不自动带来安全的实时学习，需要版本、回归与回滚；
5. MoE 负载均衡做不好，效果反而不如同算力稠密模型——盯专家利用率指标；
6. 离线准入测试集要包含常识、逻辑推理、对抗、内容安全四类样本，缺一类上线就是事故源；
7. 风控双轨：在线风控管越狱与内容安全，离线风控管训练数据投毒。

## ⚠️ 时效性说明

- Alpaca/Vicuna 等 2023 年模型数字（$500、52K 指令）是方法佐证而非当前最优；
- DeepSeek V3 的负载均衡 bias 与 GRPO 为本节概要解读，论文细节（如 MTP、MLA 注意力机制）以 DeepSeek 官方论文为准。

## 总参数、激活参数与显存分别算

[Mixtral 原论文](https://arxiv.org/abs/2401.04088)报告总参数约 47B、单 Token 激活约 13B；[DeepSeek-V3 报告](https://arxiv.org/html/2412.19437v1)为 671B/37B。激活参数描述本 Token 的计算路径，不是只需保存这部分权重。一批 Token 可能访问所有专家，部署还涉及权重放置、KV Cache、路由通信、负载均衡和量化开销。

在模型内部路由专家也不等于多智能体投票：专家通常是网络子模块，不是各自独立读完整任务的聊天机器人。

LoRA 降低可训练参数、梯度与优化器状态开销，不会自动删掉基座。参数比例由秩、目标矩阵和层数决定；QLoRA 还涉及量化基座、适配器与计算精度，不能把“4 位权重”当作整个训练状态都只用 4 位。
