# 大模型训练系统：分布式训练、微调与对齐

/> 来源：公开课程资料自学整理（更新于 2026-11-03）
> 一句话概括：预训练五步流程、显存账怎么算、DeepSpeed 三种并行怎么切、LoRA 微调参数怎么选、RLHF 对齐三阶段——大模型训练的工程全景。

## 核心概念

### 训练五步流程（预训练与普通训练同构）
初始化参数 → 前向传播 → 计算损失 → 反向传播（链式法则）→ 更新参数（w ← w - η·∂L/∂w）。

- **初始化**：随机初始化（正态 N(0, 1/√n)，He 初始化配 ReLU、Xavier/Glorot）、正交初始化（RNN/深网，保持梯度独立）；常数初始化不推荐（神经元同质）；偏置常初始化为 0 或 0.01；
- **损失**：语言模型用交叉熵；二元交叉熵 L = -(1/N)Σ[y·log ŷ + (1-y)·log(1-ŷ)]；
- **优化器**：Adam、AdaGrad、RMSProp；学习率过大不稳定、过小陷局部最优。

### 显存账（训练前必算）
| 构成 | 说明 |
|---|---|
| 参数 | FP16 训练 2 字节/参数 |
| 梯度 | FP16 2 字节/参数 |
| 优化器状态 | Adam 的动量+二阶矩，约 12 字节/参数（FP32） |
| 激活值 | 随 batch 和序列长度增长，可梯度检查点换算力 |

锚点：1.2 亿参数 FP32 权重约 460MB；6B 模型 FP16 推理约 13GB；PyTorch DDP（纯数据并行）约 14 亿参数就 OOM。

## 关键方法/原理

### 分布式训练：3D 并行（DeepSpeed）
微软 DeepSpeed 四大块：训练、推理、压缩、研究。训练侧 3D 并行：
1. **数据并行**：各卡持完整模型、切数据。**ZeRO 系列**切分模型状态与梯度，消除冗余——ZeRO-2 可将内存降至 1/8，ZeRO-3 单卡可训 130 亿参数（DDP 只能约 14 亿）；
2. **模型（张量）并行**：把单层权重矩阵切片到多卡，用于模型超单卡显存（如 3100GB 的模型 vs 80GB 的卡）；
3. **管道（流水线）并行**：模型按层分阶段，微批次流水填充。

选型直觉：数据并行解决"数据太大"，模型/管道并行解决"模型太大"，ZeRO 解决"数据并行的显存冗余"。

### 微调：LoRA 与能力增强三方案
- 模型能力增强三方案：**微调**（闭卷考试，学知识+推理，成本中）、**外挂知识库/RAG**（开卷，知识准确、随时更新）、**API 外挂**（开卷，扩展信息源）。可叠加；选型口诀：**RAG 解决知识问题，微调解决推理/逻辑/风格问题**。
- **LoRA 原理**：冻结原模型，只训练注入的低秩增量矩阵；关键参数 **r（秩）** 决定可训练参数规模。实例：6B 模型 trainable params 仅 1.9M；微调显存约 23G，推理约 12G。
- 数据格式：JSON Lines，每行 `{"conversations":[{"role":"user",...},{"role":"assistant",...}]}`；需 train/dev 拆分，几十条 dev 即可。

### 全量+增量训练的"三级火箭"（工业实践）
1. 一级：全量样本（如一年数据）训练，算力大，约每周一次；
2. 二级：一级模型 + 最近一天样本做短期增量，每日一次；
3. 三级：上线后 24h 内增量数据实时喂给在线模型。
关键约束：**在线增量缺少离线反作弊参与，不能替代全量训练**；需配合指标监控，指标大幅波动即回滚降级为非增量模式。

### 对齐（Alignment）：RLHF 三阶段
对齐三原则：**有用（Helpful）、诚实（Honest）、无害（Harmless）**。起点：InstructGPT 用 1.3B 参数做到了比 175B GPT-3 更符合人类意图。

1. **SFT 监督微调**：人工编写/标注示范问答对，教会基本指令遵循；
2. **奖励模型 RM**：标注者对同一 prompt 的多个输出**排序**（只排序不写答案，标注效率大幅提升），用 Learning to Rank 建模偏序关系（损失 = 拉开好/坏答案的 reward 差距）；
3. **PPO 强化学习**：以 RM 打分为信号优化 SFT 模型；PPO 的核心是**限制新旧策略差异幅度**，渐进式更新保训练稳定。

演进谱系：GPT-3 → code-davinci-002（代码训练）→ text-davinci-002（SFT）→ ChatGPT（RLHF）。

### 模型评测
- 三要素：数据集、测评维度、基准测试。常用数据集：MMLU、C-Eval（13948 道多选、52 学科）、GSM8K、MATH、HumanEval、MBPP、BBH；综合基准：OpenCompass（12 个一级维度）、CLUE/SuperClue。
- few-shot vs zero-shot：预训练模型 few-shot 通常更好；指令微调后 zero-shot 可能反超。few-shot 面向开发者（ICL），zero-shot 面向用户。
- SOTA = 当前最优；**坑：厂商榜单普遍夸大，以第三方评测为准**。

## 术语表

| 术语 | 英文 | 含义 |
|---|---|---|
| ZeRO | Zero Redundancy Optimizer | 切分优化器状态/梯度/参数消除数据并行冗余 |
| 3D 并行 | 3D Parallelism | 数据并行×张量并行×流水线并行组合 |
| LoRA | Low-Rank Adaptation | 冻结原模型，训练低秩增量矩阵的参数高效微调 |
| SFT | Supervised Fine-Tuning | 人工标注问答对的监督微调 |
| RLHF | RL from Human Feedback | 以人类偏好排序训练奖励模型再 PPO 优化 |
| PPO | Proximal Policy Optimization | 限制策略更新幅度的强化学习算法 |
| 对齐税 | Alignment Tax | 对齐某方面能力时牺牲其他能力的代价 |
| 梯度检查点 | Gradient Checkpointing | 重算激活换显存的时间换空间手段 |
| 概念漂移 | Concept Drift | 数据分布随时间变化导致模型退化 |

## 经验与常见坑

1. **微调轮数不是越多越好**：小数据多轮必过拟合，低轮数权重可能优于高轮数；盯 loss、grad_norm（过大=梯度爆炸/过小=梯度消失）、learning_rate、epoch 四个监控指标；
2. 微调数据少于验证集切片数会数组越界（如 val_dataset.select(range(50))）；
3. 训练集远好于验证集 = 过拟合，用 dropout、增数据、正则化、early stopping 缓解；数据划分常 80/20；
4. 对齐的坑：对齐税（混入部分原始预训练数据做对数似然训练缓解）、英语文化偏向、"漏网之鱼"需输入/输出过滤器双重拦截；模型"自己吃自己"的合成数据近亲繁殖风险；
5. RLHF 不是 OpenAI 首创，胜在恰当时机的完整工程化；
6. LangChain/AutoGPT 等是原型验证工具，性能稳定性不能直接上生产；工业训练需离线+近线+在线多套系统配合；
7. 长任务训练可靠性靠透明检查点（translucent checkpoints）+硬件级恢复（CRIU），故障重启是常态而非异常。
