# 低成本领域模型路线与 MoE 架构

/> 来源：公开课程资料自学整理（整理于 2026-11-03）
> 一句话概括：小团队做大模型的标准动作——Self-Instruct 数据无中生有 + LoRA 低算力微调；大模型侧用 MoE 稀疏激活延续 Scaling Law，后训练用 GRPO 把"好提示词"固化成稳定能力。

## 核心概念

### 领域模型路线（以 Alpaca 为范式）
开源"羊驼系"回答了两个根本问题：**训练数据从何来、算力从何来**。
- Alpaca：LLaMA-7B + **175 条**人工种子指令 → Self-Instruct 扩到 **52K** 指令（text-davinci-003 生成），API 成本 **<$500**；LoRA 微调后指定任务可达 SOTA。
- 衍生：Vicuna-13B（ShareGPT 对话数据，$300 成本媲美 ChatGPT）、Guanaco（多语言）。
- 模型工程两大任务：微调（1→10）与从零构建（0→1）；领域模型多数方法源自 Alpaca 路线。

### MoE（混合专家模型）= 稀疏激活 + 分而治之
动机：Scaling Law 有效，但参数到数千亿~万亿级后**推理成为瓶颈**（单卡装不下、跨卡交互拉高时延与成本）。
- 每层含**路由专家（Routed Experts）**与**共享专家（Shared Experts）**；token 经 **Gate 门控**打分，Top-K 只激活最相关专家；共享专家承载跨任务共通知识，减少路由专家冗余（类比：大厅排队 → 专业柜台 + 调度中心）；
- **负载均衡**是命门：路由失衡导致热门专家过载、冷门专家欠训练伤泛化。DeepSeek V3 方案：门控网络引入**可学习偏置项（bias）**，自适应调低高频专家、给低频专家机会，替代传统辅助损失式均衡；
- 两大收益：专业性提升表现、单请求实际计算量降低省推理成本；让有限算力下继续吃 Scaling Law 红利，是开源模型（V3→R1）能与头部闭源模型分庭抗礼的架构基础。
- 趋势判断：多模态、MoE、模型小型化是三大长期方向；GPT-4 即 MoE（业界推测+谷歌研究印证）。

## 关键方法/原理

### Self-Instruct：数据无中生有四步
1. **种子数据**：每任务 1 指令 + 1 示例（唯一人工环节，175 条即可）；
2. **生成新指令**：每轮随机取 8 个上下文任务（6 人工 + 2 机器生成）提高多样性；
3. **分类任务特殊处理**：分类用**输出优先**（先生成标签再生成输入，避免类别偏斜）；非分类用输入优先；
4. **过滤**：与已有指令 ROUGE-L 重叠 ≥0.7 丢弃、排除含"图片/图表"类指令、去重。
本质是模型反演；数据质量上限 = 教师模型知识上限，突破法 = 低质量大规模原始语料 + LLM 提炼少量高质量语料。

### LoRA：低秩适配的精确机制
- 核心假设：预训练模型适应下游任务只需较低的**内在维度（intrinsic dimension）**，模型过度参数化；
- 机制：冻结 W₀，侧通道 ΔW = **BA**（B: d×r 升维，A: r×k 降维，r ≪ min(d,k)），前向 h = (W₀+BA)x；**A 随机高斯初始化、B 零矩阵初始化**（训练开始侧通道为零）；任务切换 = 减去 BA 换 B'A'；
- 关键数字：GPT-3 175B 训练显存 1.2TB → 350GB（省 2/3，因不存冻结参数的优化器状态）；r=4 只调 wq/wv 时 checkpoint 350GB → **35MB**（万倍压缩）；训练提速 25%；
- 实践配置：常只对 Self-attention 四矩阵（wq/wk/wv/wo）做 LoRA、冻结 MLP；HuggingFace **PEFT + bitsandbytes** 8bit 量化加载；典型超参 lora_r=8、alpha=16、dropout=0.05、target_modules=[q_proj, v_proj]、lr 1e-4；
- 算力对照：Alpaca 全量微调 8×A100 80G×3 小时 vs LoRA 单张 RTX 4090×5 小时，效果相当。

### 全量微调基准配置（可复算）
4×A100 80G，FSDP full_shard，3 epochs，lr 2e-5，cosine 调度，bf16/tf32——7B 级模型的通用起点。

### 后训练闭环：把提示语的偶然收益固化为技能
预训练"偶然捡到"的有效提示语（如 "Let's think step by step"）有随机性；**后训练目标 = 把它固化成任何场景稳定触发的技能**：
- **指令微调对齐**：收集真实场景指令数据（问答/任务规划/信息检索），专家标注校验；**多任务联合训练**——每类"好用"提示词视为一种任务，让模型提炼共同语义特征与推理路径；
- **强化学习对齐**：奖励体系对逻辑性/准确性/指令契合度打分；模拟场景与虚拟用户多轮交互试错；引入真实用户在线实验数据；
- **GRPO（Group Relative Policy Optimization）**：传统 RLHF 需策略模型+参考模型+奖励模型+**额外训练的价值模型**，成本高；GRPO 只训一个策略模型，一次生成 N 个候选输出，由**冻结的参考模型+奖励模型**直接评估选优——省去价值模型，流程轻量化。R1 的表现很大程度受益于 V3 的高效推理调度 + 此类轻量 RL。

## 术语表

| 术语 | 英文 | 含义 |
|---|---|---|
| 混合专家 | MoE（Mixture of Experts） | 门控稀疏激活多个专家子网络 |
| 稀疏激活 | Sparse Activation | 每 token 只激活部分参数 |
| 路由/共享专家 | Routed / Shared Experts | 按需激活的专家 / 全 token 共用的专家 |
| 内在维度 | Intrinsic Dimension | 微调所需低维子空间假设（LoRA 理论根基） |
| 低秩适配 | LoRA | 冻结权重、训练低秩增量 BA |
| PEFT | Parameter-Efficient Fine-Tuning | HF 参数高效微调工具库 |
| Self-Instruct | — | 用 LLM 自举扩增指令数据的方法 |
| GRPO | Group Relative Policy Optimization | 免价值模型的组内相对比较强化学习 |

## 经验与常见坑

1. Self-Instruct 的 ROUGE-L 去重阈值（0.7）与"输出优先"分类任务处理是数据质量的关键细节，漏掉会指令同质化；
2. 批量解码一次生成 20 条指令可摊薄生成成本；每指令只生成 1 个实例即可；
3. LoRA 有推理侧额外开销（合并前多一次 BA 计算），延迟敏感场景要合并权重或权衡；
4. 大模型参数大、单次训练成本高、合规责任重，**不能做流式在线实时训练**；MoE 下的小专家模型才可在局部用"三级火箭"保实时性；
5. MoE 负载均衡做不好，效果反而不如同算力稠密模型——盯专家利用率指标；
6. 离线准入测试集要包含常识、逻辑推理、对抗、内容安全四类样本，缺一类上线就是事故源；
7. 风控双轨：在线风控管越狱与内容安全，离线风控管训练数据投毒。
