# 网络架构

> 来源：《机器学习系统》教材第 6 章"Network Architectures"（更新于 2026-11-03）

**一句话定义**：选择神经网络架构不是建模决策，而是与物理规律的契约——CNN 承诺空间局部计算、Transformer 承诺平方级注意力内存、推荐模型承诺占满内存的巨大嵌入表；这些物理后果贯穿整个系统栈，且实践中不可逆（数据管道、训练设施、服务系统、监控面板都围绕架构搭建，换架构等于全部重建）。**架构不是模型做什么，而是硬件必须做什么。**

> **War Story：Netflix 没有上线的集成模型**：Netflix Prize（2006 年，百万美元悬赏把评分预测 RMSE 提升 10%）。2009 年 BellKor's Pragmatic Chaos 团队以 10.06% 改进夺冠——把一百多个组件模型混合成一个集成。但离线指标提升后，**胜出架构因部署成本太高而从未上线**：工程代价不被额外精度证明合理，且产品本身已从评分制 DVD 推荐转向流媒体个性化。教训：架构选择必须以运行成本评判，不只是静态基准上的准确率——参数更多的网络可能输给算力/内存预算匹配系统的更简单网络。

## 核心原理：归纳偏置——全章的统一概念

**归纳偏置（inductive bias）**：内建于模型架构的结构约束，通过编码领域假设（空间局部性、时序依赖）缩小假设空间，使模型能从有限数据泛化。

三个关键点：

1. **意义**：归纳偏置直接降低泛化所需的数据量。CNN 的局部性偏置把假设空间从 O(N²_pix)（全连接）压到 O(N_pix·K²)（局部滤波器，K≪N_pix）：224×224 图像上一个 3×3 核比等效稠密连接少约 5575 倍参数，内存与所需数据同步缩减；
2. **与正则化的区别**：正则化在训练时**惩罚**复杂假设（L1/L2），归纳偏置在架构设计时**消灭**整类假设——CNN 无论如何训练都无法表示任意非局部函数；
3. **常见误区**："归纳偏置越强越好"是错的——强局部性偏置（CNN）擅长空间数据，却无法表示语言中的长程依赖；Transformer 恰以缺乏空间偏置（代价是 O(S²) 内存）换来灵活长程连接。

**五大架构家族与系统瓶颈**（瓶颈列即决策列）：

| 架构 | 数据类型 | 核心创新 | 系统瓶颈 |
|---|---|---|---|
| MLP | 表格/无结构 | 稠密连接 | 内存带宽 |
| CNN | 空间（图像） | 局部滤波器+权重共享 | 计算吞吐 |
| RNN | 序列（时序） | 循环状态 | 顺序依赖 |
| Transformer | 关系（语言） | 动态注意力 | 内存容量（S²） |
| DLRM | 类别（推荐） | 嵌入表 | 内存容量（TB+） |

## 关键概念：灯塔模型与算术强度谱

五个"灯塔模型"各自隔离一种系统瓶颈（类比用 MIPS 处理器教流水线——不是最快，而是最清晰）：

| 模型 | 领域 | 参数 | 单次推断 | 内存 | 瓶颈 | 角色 |
|---|---|---|---|---|---|---|
| ResNet-50 | 视觉 | 25.6M | 4.1 GFLOP | 102.4 MB | **计算** | 稠密视觉吞吐基准 |
| GPT-2 XL | 语言 | 1.5B | ~3 GFLOP/token | 6 GB | **内存带宽** | 逐 token 服务的 LLM 原型 |
| DLRM | 推荐 | 25B | 低 | 100 GB | **内存容量** | 嵌入表与容量规划 |
| MobileNetV2 | 边缘视觉 | 3.5M | 300 MFLOP | 14 MB | **延迟** | 深度可分离卷积 |
| KWS (DS-CNN) | 音频 | 200K | 20 MFLOP | 800 KB | **功耗** | 常开 TinyML 功耗预算 |

**算术强度（I = FLOP/byte）决定模型的"天然硬件家园"**：

- ResNet-50 约 **~40 FLOP/byte**（深层瓶颈层可达 100–200+）：卷积权重在空间维度上大量复用 → 计算受限 → 亲和 GPU/TPU 的 ALU；
- GPT-2 推断约 **~0.5 FLOP/byte**（约 80 倍差距）：自回归每生成一个 token 只做一次矩阵-**向量**乘，却要把全部 6 GB 权重从 HBM 搬一遍 → 永远"饿"数据 → 内存带宽是唯一重要的指标。这就是 LLM 推断**带宽受限而非计算受限**的根本原因；
- MobileNet 居中：深度可分离卷积降低总计算但相对搬运更多数据——适配手机硬件，却会"饿死"为稠密计算优化的数据中心 GPU。

结论：选 Transformer 不是因为它抽象地"更好"，而是项目付得起其低算术强度意味着的带宽压力，换取关系建模的灵活性。

## 分类/类型：逐族剖析

### MLP：稠密模式处理

归纳偏置 = **无先验结构**，任意输入可关联任意输出。理论上由通用近似定理（UAT）保障：足够宽 + 非线性激活的 MLP 可逼近紧集上任意连续函数。

**可学习性鸿沟（representation ≠ learnability）**：UAT 保证"能表示"，不保证"能学到"。三个鸿沟来源：① **样本复杂度**——MLP 把 784 像素当独立特征，学空间相关性需要指数级样本，CNN 的局部性偏置把它降到多项式级；② **参数效率**——逼近 sin(x₁)+…+sin(x_d) 类函数，MLP 可能需要 O(exp(d)) 神经元，独立处理各维的架构只需 O(d)；③ **优化难度**——即使最优权重存在，梯度下降未必找得到，专用架构的对称性缩小了搜索空间。（背景假设：流形假设——高维数据实际占据低维流形，如"合法猫图"只是 65536 维像素空间中一个小的结构化区域。）

**MNIST 对照实验**（表示力相同，可学习性悬殊）：

| | MLP (784→4096→4096→10) | CNN (Conv-Pool-Conv-Pool-FC) |
|---|---|---|
| 参数 | ~20M | ~421K（**47 倍更少**） |
| 精度 | ~97–98% | ~99%（同样 6 万训练样本） |
| 部署含义 | 边缘不可行 | 内存/训练/推断全面胜出 |

**计算映射**：h⁽ˡ⁾ = f(h⁽ˡ⁻¹⁾W⁽ˡ⁾ + b⁽ˡ⁾)，一行 `matmul(X, W) + b` 的框架调用底下是嵌套循环（样本→输出神经元→输入累加），由 BLAS/cuBLAS 分发到优化内核，可达峰值吞吐的 80–95%。**系统瓶颈是数据搬运**：每个权重每次前向只用一次，无复用机会；批量=1 时算术强度约 0.5 FLOP/byte——**全连接层几乎总是内存带宽受限**，这解释了为何全连接层在推断负载中常是性能瓶颈。另一个关键数字：一次 MAC 本身约 1 pJ，但从片外 DRAM 取操作数约 200 pJ——**200 倍的能耗差使数据搬运而非算术成为 ML 系统的主导约束**。

### CNN：空间模式处理

两个空间先验：**局部连接**（邻近像素更相关）+ **权重共享**（同一特征可出现在任何位置，平移等变性）。参数效应：3×3×64×64 卷积层约 3.7 万参数，与输入分辨率无关；等效全连接（224²×64→64）需约 2 亿参数——**约 5500 倍差距**。极端对比：100 万像素图像的 5×5 单通道检测器，全连接 100 万权重 vs 卷积 25 权重（4 万倍）。

**平移等变 vs 平移不变（容易混淆，必须分清）**：

- **等变**：f(T(x)) = T(f(x))——输入平移多少，特征图平移多少，位置信息保留（数学证明：卷积+换元即得）。垂直边缘检测器的例子：边缘从第 3 列移到第 5 列，响应峰值也移到第 5 列——网络"知道边缘在哪"，不只是"存在边缘"；
- **不变**：f(T(x)) = f(x)——输出不变，位置信息丢弃（如全局平均池化）。

任务决定在何处引入不变性：**目标检测**需要全程等变（框坐标要跟踪物体位置）；**分类**只需最后不变；**分割**需要等变到输出层（逐像素标签对齐输入位置）。卷积本身不产生不变性——是池化层**刻意丢弃**精确位置数据。注意工程中的等变并不完美：非对称 padding、跨步下采样、按位置统计的 BatchNorm 都会破坏严格等变性，实践中接受这些偏离。

**计算映射**：滑窗七层嵌套循环在硬件上通常经 **im2col** 变换（把输入图块重排成矩阵列）转为单个 GEMM，用内存冗余（复制重叠像素）换取计算规整性。每个 3×3 滤波器权重在 224×224 特征图上被复用 50,176 次——高复用使卷积**计算受限**，优化策略是缓存滤波器、流水化特征图、SIMD/Tensor Core 并行。

> ⚠️ **常见误区：FLOPs = 速度**。"MobileNetV2 的 FLOPs 是 ResNet-50 的 1/13.7，所以快 13.7 倍"是错的。在数据中心 GPU 上（峰值算力超出带宽 10–20 倍），MobileNetV2 的低算术强度让硬件喂不饱、内核启动开销主导，**往往比 ResNet-50 还慢**；在算力带宽大致平衡的手机 CPU 上才成立。FLOPs 度量工作量，吞吐量取决于工作与硬件的匹配。

**深度可分离卷积**（MobileNet 系/DS-CNN）：把标准卷积（O(N·K²·C_in·C_out)）分解为逐通道深度卷积 + 1×1 点卷积，3×3 核下 FLOPs 降 8–9 倍，参数与 FLOPs 约降 1/K² 倍。KWS（关键词唤醒，"Hey Siri"级）把它推到极端：微控制器、毫瓦功耗、KB 级内存，逼出 INT8/INT4 极限量化。

### RNN：序列模式处理

时序归纳偏置：顺序重要、过去影响现在。隐状态 h_t = f(W_hh·h_{t−1} + W_hx·x_t + b) 把历史压缩进固定大小状态。

**双刃剑**：

- 优势：推断内存 **O(1)**，与序列长度无关（10000 token 与 10 token 一样）——这在 O(S²) 注意力内存不可承受的流式场景（微控制器上的关键词唤醒）仍是**系统上正确的选择**，"RNN 已死"是误区；
- 代价 1（延迟）：h_t 必须等 h_{t−1} 完成——O(S) 关键路径在每个时间步强制屏障同步，时间维度无法并行，GPU 利用率典型只有 **30–50%**（对比计算受限架构的 80–90%）；
- 代价 2（训练）：BPTT 要存所有时间步的激活（O(S·d_hidden)）；梯度是 S 个雅可比矩阵的连乘 ∏∂h_t/∂h_{t−1}，指数级消失或爆炸——门控（LSTM/GRU）是缓解手段。

### 注意力：动态处理

RNN 把长程依赖压缩进瓶颈状态（"The cat, which…, was sleeping"中 cat 与 sleeping 的主谓关系被中间词冲淡），注意力直接**保留所有 token 表示并计算相关性分数**：任意两个位置 O(1) 深度连通，内容依赖的动态路由。

**代价是二次方内存**：相似度矩阵 O(S²)——4096 token、16 位分数下，仅注意力矩阵就是每层每头 33.6 MB。**上下文翻倍，注意力内存翻四倍**——这是硬物理约束，也是 FlashAttention（重算而非存注意力矩阵）和稀疏注意力变体存在的理由。常见误区："注意力是可随意套用的通用加权方案"——不，二次方内存是硬约束。

### Transformer：并行序列处理

自注意力公式：

$$\text{SelfAttention}(X) = \text{softmax}\left(\frac{(XW_Q)(XW_K)^\top}{\sqrt{d_k}}\right)XW_V$$

- **除以 √d_k 的目的**：防止点积过大把 softmax 推入梯度极小的饱和区；
- **多头注意力**：并行多组 Q/K/V 投影，各关注输入的不同方面；
- **系统的收益是并行**：RNN 处理 S 个 token 执行 S 个顺序步骤，Transformer 全部 S 个位置 O(1) 深度完成，序列维完全并行、饱和所有计算单元。代价是 O(S²) 注意力内存；
- **常见误区："Transformer 有无限上下文"**——上下文被两个内存成本封顶：训练/prefill 的注意力分数矩阵，以及**自回归服务时累积的 KV cache**（历史 token 的 key/value 向量）——长上下文时 KV cache 可与模型权重等量齐观，所以 KV cache 压缩是活跃的工程方向。

**Transformer 不是新发明，而是对既有积木的精妙重组**：MLP 的稠密投影 + ResNet 的残差路径 + 归一化的激活稳定 + 注意力的动态门控。RNN→Transformer 的转变是从"顺序状态管理"到"并行状态管理"的决定性工程转移。

### DLRM：稀疏架构（推荐系统）

50 毫秒内从百万级目录中选几条推荐。核心挑战是**高基数类别特征**：数十亿 User ID、百万级 Item ID——原始 ID 无几何意义（用户 1042 不比 1043 "更近"），必须经**嵌入表**映射为稠密向量。DLRM 结构：稀疏嵌入查表 → 交互层收集嵌入向量并与稠密特征组合 → 顶层 MLP 输出点击率。

**两种计算模式压榨不同硬件子系统**：稠密部分是标准 GEMM（Tensor Core 高效处理）；稀疏嵌入查表是**随机访问**——嵌入表可达 TB 级，超出单加速器内存，系统必须先决定表放在哪（容量受限 regime）。DLRM 是"典范随机访问负载"。

## 共享积木：跨架构的工程原语

| 积木 | 诞生于 | 解决的问题 | 现已用于 |
|---|---|---|---|
| 稠密矩阵乘（GEMM） | MLP | 通用函数逼近 | **所有架构**（Transformer 的前馈层内核） |
| 参数共享 | CNN | 空间效率 | Transformer（共享投影）、RNN（跨时间复用） |
| 跳跃连接 | ResNet | 深度下的梯度流 | Transformer、DenseNet、U-Net、现代深网络 |
| 归一化 | CNN（BatchNorm）→ LayerNorm | 激活稳定 | 几乎所有现代架构（Transformer 用 LayerNorm：不依赖批统计，架构无关） |
| 门控/路由 | RNN（LSTM） | 信号路由 | 注意力、MoE |

**残差连接为什么有效（雅可比视角）**：普通 N 层网络梯度 = ∏J_ℓ，若谱半径 ρ(J_ℓ)<1 指数消失、>1 指数爆炸——把数百个矩阵平衡在"混沌边缘"数值上不可能。残差块 y = F(x)+x 的雅可比 J = I + ∂F/∂x，N 层梯度 = ∏(F'ᵢ+I)——**恒等项保证即使残差分支梯度消失，直接通路永远畅通**，这是能训练 152 层（乃至 1000 层）网络的数学根源。

**跨架构原语对照**：

| 原语 | MLP | CNN | RNN | Transformer |
|---|---|---|---|---|
| 计算 | 稠密 GEMM | 卷积 | 顺序 GEMM | GEMM + 注意力 |
| 内存访问 | 顺序 | 跨步 | 顺序+状态 | 分块 QKV 流 |
| 数据搬运 | 广播 | 滑窗 | 时序广播 | Gather+Reduce |
| 并行度 | 高 | 高 | 低（时间依赖） | 高（位置并行） |

工程启示：GEMM 分块与混合精度惠及所有架构；跳跃连接的内存管理适用于任何残差网络；注意力专属优化只帮 Transformer——**区分可移植优化与架构专属优化**。

## 架构选择框架与误区

**四步审视法**：每个架构按四要素评估——针对什么数据模式、执行什么计算、诱导什么硬件映射、暴露什么瓶颈。评估的是"跑起来花多少代价"，不只是"能学到什么"。

误区清单：

- ❌ "FLOPs 少 = 快"（见上文 MobileNet 案例）；
- ❌ "更深的网络总更准"——深度与宽度的机制不同，且都受内存/带宽约束；
- ❌ "Transformer 有无限上下文"——被注意力矩阵和 KV cache 双重封顶；
- ❌ "RNN 已经过时"——O(1) 状态在流式边缘场景仍不可替代；
- ❌ "更归纳偏置总更好"——偏置与数据结构错配即负资产；
- 架构选择是**不可逆的工程承诺**：为架构搭建的数据管道、训练设施、服务系统、监控面板，决定了早期决策在更好替代出现后仍长期存续。
