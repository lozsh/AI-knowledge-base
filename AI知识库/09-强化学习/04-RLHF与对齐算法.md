# RLHF 与对齐算法：奖励建模、PPO 微调与 DPO

<p class="note-date">更新于 2026-11-03</p>

**一句话定义**：RLHF（Reinforcement Learning from Human Feedback，人类反馈强化学习）通过"人类排序偏好 → 训练奖励模型 → 用 PPO 微调语言模型"三步，把主观模糊的人类价值观变成可优化的奖励信号，是 ChatGPT 区别于 GPT-3 的最核心突破；DPO 则用一次数学变换把这条流水线简化成监督学习。

## 概述

预训练赋予模型海量知识，但对齐（alignment）让模型与人类价值观一致——SFT 实现指令对齐（会读题解题），RLHF 实现更深层的价值观对齐（安全、有用、无害）。ChatGPT 技术报告中的三阶段训练，后两阶段（训练 RM + PPO 训练）就是 RLHF。

为什么需要 RL 而不是继续监督学习？因为**"好的回答"没有标准答案**：人类只能告诉你"A 比 B 好"，无法给出每个问题的标准回复；奖励信号稀疏、主观、只说好坏不说对错——这正是强化学习（而非监督学习）擅长处理的那类信号。可以把 LLM 比作学生：Pretrain 教基础知识，SFT 教读题解题，RLHF 则是真正的刷题练习——人类当老师批改，强化正确的解题方式。

## 核心原理

### 第一步：收集偏好数据——为什么是排序而不是打分

关键洞察：**偏好比绝对评分可靠**。让标注员给回答打 1-10 分，不同人的标准极不一致（同一个回答，有人给 7 有人给 4）；但两两比较"A 和 B 哪个好"，一致性高得多。标量打分会放大标注者之间的价值观差异，让模型难以拟合；排名数据天然消除了绝对刻度。

数据形态即一对：`prompt + chosen（人类偏好的回答）+ rejected（被拒绝的回答）`。

### 第二步：训练奖励模型（RM）——学"排序"而非"打分"

RM 本质是一个文本回归模型：LLM 架构（或 BERT 架构）把 `(prompt, 回答)` 编码后，接一层输出**标量奖励**——和文本分类模型结构完全一致，只是取隐藏层输出而非分类概率。

训练用 **Bradley-Terry 模型**（统计学处理配对比较的经典方法）：把模型对两个回答的标量分差转化为"人类会选 chosen 的概率"，用负对数似然训练：

$$\mathcal{L}_{\text{RM}} = -\log \sigma\big(r_\phi(x, y_{\text{chosen}}) - r_\phi(x, y_{\text{rejected}})\big)$$

直觉：对人类选中的给高分、没选中的给低分，**分差越大代表模型越确信人类的偏好**。注意训练的是排序能力，绝对分值本身没有意义。

工程细节：RM 与最终 LLM 大小常不同（OpenAI 用 6B 的 RM 配 175B 的 LLM）；RM 可以从 SFT 后的模型初始化，也可以用偏好数据从头训，孰优尚无定论。

### 第三步：PPO 微调——四模型流水线

语言模型作为策略：输出一个动作 = 生成一整段回答；奖励 = RM 对这段话的打分。PPO 训练时要同时维护**四个模型**（两两成对，从 SFT 模型和 RM 分别初始化）：

| 模型 | 初始化 | 是否更新 | 职责 |
|---|---|---|---|
| Actor Model | SFT 后的 LLM | ✅ | 被训练的策略，生成回答 |
| Ref Model | SFT 后的 LLM | ❌ 冻结 | 提供 KL 约束的参照分布 |
| Reward Model | 第一步的 RM | ❌ 冻结 | 给回答打标量分 |
| Critic Model | 第一步的 RM | ✅ | 预测累积奖励（价值估计），供 PPO 算优势 |

流程：输入 prompt → Actor 与 Ref 各生成回答 → 计算两者分布的 KL 散度 → Actor 回答分别送入 RM（得标量分）和 Critic（得逐位置累积奖励估计）→ 合成最终奖励并计算 actor loss / critic loss → 分别更新两个可训练模型。

**KL 惩罚是防崩绳**：最终奖励中扣掉与 Ref 模型的 KL 散度（乘权重 β），惩罚新模型偏离 SFT 起点太远。为什么要拴：不拴的话，策略会一路滑向"奖励模型最喜欢"的输出分布，把 Pretrain/SFT 赋予的语言能力和知识全丢掉（reward hacking 的结构性诱因，见下）。综合目标即：

$$J(\theta) = \mathbb{E}_{x,\,y\sim\pi_\theta}\big[r_\phi(x,y)\big] - \beta\, D_{KL}\big(\pi_\theta \| \pi_{\text{ref}}\big)$$

**代价**：四模型并存使显存数倍于 SFT——RM 和 LLM 各 7B 时，PPO 全程约需 240G 显存（4 张 80G A100，每卡约 60G）。高门槛正是后来 DPO、GRPO 等简化方案的动力。

### RLHF 的三大实际病症

1. **奖励作弊（reward hacking）**：模型找到 RM 的漏洞而非真正满足人类——RM 偏好长回答就一味拉长，RM 偏好某些词就堆砌。因为 RM 只是人类偏好的近似，优化压力必然挤向近似误差的缝隙。缓解：迭代更新 RM、KL 约束、偏好数据持续补充。
2. **模式塌陷（mode collapse）**：RL 使输出集中到少数"安全"模式，千篇一律一个腔调，丢失预训练的多样性。对抗：奖励中加多样性项。
3. **训练不稳定**：PPO 本身就不算稳，在千亿参数上更难伺候——RM 质量、KL 权重、采样策略、超参互相纠缠。RLHF 不像拧一个旋钮，**更像同时调十几个水龙头，一个没拧好浴室先成游泳池**。

另一个根本局限：人类偏好本身有偏差、噪声和矛盾，RLHF 最终对齐的是**标注员群体的平均偏好**，未必是"真正的好"。

### DPO：把 RL 问题变回监督学习

**动机**：RLHF 流程复杂、训练慢、四模型显存爆炸。DPO（Direct Preference Optimization, 2023）证明：带 KL 约束的偏好优化目标存在闭式解——最优奖励可以用策略与参考策略的概率比直接写出：

$$r(x,y) = \beta \log \frac{\pi_\theta(y|x)}{\pi_{\text{ref}}(y|x)} + \text{const}$$

把这个等价关系代回 Bradley-Terry 目标，奖励模型被**消元**，得到直接关于 $\pi_\theta$（被训练策略）的分类式损失：

$$\mathcal{L}_{\text{DPO}} = -\mathbb{E}\Big[\log \sigma\Big(\beta \log \tfrac{\pi_\theta(y_c|x)}{\pi_{\text{ref}}(y_c|x)} - \beta \log \tfrac{\pi_\theta(y_r|x)}{\pi_{\text{ref}}(y_r|x)}\Big)\Big]$$

效果：**不需要训练 RM，不需要 PPO 采样循环**，只需两个 LLM（训练的 $\pi_\theta$ + 冻结的 $\pi_{\text{ref}}$（参考策略，还可离线预计算），训练形式接近加权交叉熵，简单稳定得多，因此成为开源社区做偏好对齐的常用工具。

**定位要摆正**：DPO 不是"RLHF 已过时"的证据。需要复杂交互、工具使用、长程任务时，显式 RL（在线采样、试错、多步信用分配）仍不可替代；DPO 更像一把轻便的瑞士军刀，不是万能施工队。

### 后续演化一览

- **GRPO**（DeepSeek）：砍掉 Critic，用同一 prompt 下多个回答的**相对排名**估计优势，省一个价值模型的显存与训练——R1 路线的关键组件，详见 [Agentic-RL](05-Agentic-RL.md)。
- **RLAIF**：用强 AI 模型（如 GPT-4）替代人类标注员做偏好排序，效果接近甚至超过 RLHF，成本大降。
- **可验证奖励（RLVR）**：数学题对错、代码是否通过测试等客观信号替代 RM，是 o1/R1 式推理模型的核心训练信号，也是当前最重要的方向。

## 关键概念

| 概念 | 英文 | 一句话解释 |
|---|---|---|
| 对齐 | Alignment | 让模型行为与人类价值观/意图一致 |
| 偏好数据 | Preference Data | prompt + chosen/rejected 的成对比较数据，比绝对评分可靠 |
| 奖励模型 | Reward Model (RM) | 拟合人类偏好的打分器，学排序不学绝对分 |
| Bradley-Terry 模型 | Bradley-Terry Model | 把标量分差转成配对胜率的统计模型，RM 训练的理论基础 |
| KL 约束 | KL Penalty | 惩罚偏离参考模型，防能力丢失与 reward hacking 的安全绳 |
| 四模型流水线 | — | Actor/Ref/RM/Critic 同时在线的 PPO 训练形态，显存门槛极高 |
| 奖励作弊 | Reward Hacking | 模型钻 RM 近似误差的空子，得高分而不解决真问题 |
| 模式塌陷 | Mode Collapse | 输出收敛到少数安全模式，失去多样性 |
| DPO | Direct Preference Optimization | 奖励闭式重参数化后，跳过 RM 与 RL 直接用偏好数据做监督训练 |
| RLAIF | RL from AI Feedback | 用 AI 替代人类标注偏好，降低数据成本 |

## 经验与常见坑

- **别用标量打分数据训 RM**：标注者尺度不统一会把噪声放大成训练目标的一部分；坚持成对比较 + BT 损失。
- **KL 权重 β 是核心平衡点**：太大模型不敢动（等于没训），太小会漂移崩坏、能力遗忘。它是 RLHF 调参里最值得盯的旋钮之一。
- **RM 打分只看相对高低**：跨 prompt 比较绝对分值没有意义；评估对齐效果要用独立基准，不能只看 RM 分上涨——RM 分上涨可能正是 reward hacking。
- **DPO 数据质量要求更高**：没有在线采样和 RM 兜底，chosen/rejected 的质量直接决定上限；偏好对里的噪声会被监督学习直接学进去。
- **SFT 是前提不是可选项**：没有 SFT 打底的指令遵循能力，RLHF 的探索空间里几乎没有"好回答"可强化（参见[模型后训练](../12-%E6%A8%A1%E5%9E%8B%E8%AE%AD%E7%BB%83%E4%B8%8E%E4%BC%98%E5%8C%96/06-%E6%A8%A1%E5%9E%8B%E5%90%8E%E8%AE%AD%E7%BB%83.md)的"SFT 与 RL 的本质区别"）。
- **把 R1 的成功全归功于 GRPO，就像把一道好菜全归功于锅铲**：数据、验证器、采样、训练工程和底座模型同样重要。

## ⚠️ 时效性说明

RLHF 三步框架（InstructGPT, 2022）与 DPO（2023）已是工业稳定实践，原理部分无过时风险。但该领域演进极快：GRPO 之后已有 DAPO、GSPO 等新变体；RLVR（可验证奖励）在推理模型训练中的占比迅速上升；RM 训练与偏好数据的最佳实践（如过程奖励模型 PRM）仍在快速迭代。选型时以当年主流开源配方为准。
