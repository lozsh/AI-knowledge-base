# Agentic-RL：用强化学习训练大模型智能体

<p class="note-date">更新于 2026-11-03</p>

**一句话定义**：Agentic RL 是把大语言模型（LLM）当作可学习的策略，嵌入智能体的"感知-决策-执行"循环中，用强化学习优化多步任务（推理、工具使用、长期规划）表现的训练范式。

传统监督学习训练智能体有三个核心局限：数据质量完全决定上限（模型只能模仿训练数据）；缺乏探索能力（只能被动学习人类给的路径）；难以优化长期目标（无法精确优化多步推理的中间过程）。强化学习让智能体自主生成多个候选答案并根据结果获得奖励，从而学会哪些推理路径更优，甚至发现比人类标注更好的解法。

本文以 HelloAgents 框架（集成 Hugging Face TRL 库、Qwen3-0.6B 模型）为载体讲解，本文保留其方法论与关键公式，省略具体工程代码细节。

## 核心原理

### LLM 训练全景：预训练 + 后训练

一个强大的 LLM 通常经历两个阶段：

**预训练（Pretraining）**：在海量文本（数 TB 级）上做自监督的因果语言建模（下一个词预测），目标函数为负对数似然：

$$\mathcal{L}_{pretrain} = -\sum_{t=1}^{T} \log P(x_t \mid x_1, \dots, x_{t-1}; \theta)$$

学到语法、语义、世界知识和基础推理能力，但模型只会"预测下一个词"，不会遵循指令、对话或对齐人类偏好。

**后训练（Post-training）**三步：
1. **监督微调（SFT）**：用 (prompt, completion) 对训练，目标仍是最大化正确输出的概率 $\mathcal{L}_{SFT} = -\sum_i \log P(y_i \mid x_i; \theta)$。数据量小、人工标注、快速见效，学任务格式和基本能力。
2. **奖励建模（RM）**：用偏好对比数据（同一问题的两个回答，一个 chosen、一个 rejected）训练评分模型：$\mathcal{L}_{RM} = -\mathbb{E}[\log \sigma(r_\phi(x, y_w) - r_\phi(x, y_l))]$，让好回答得分更高。
3. **强化学习微调**：最经典用 PPO，最大化奖励同时用 KL 散度约束不偏离参考模型（SFT 模型）太远：$J_{PPO} = \mathbb{E}_{x,y \sim \pi_\theta}[r_\phi(x,y)] - \beta \cdot D_{KL}(\pi_\theta \| \pi_{ref})$。

为降低人工标注成本，**RLAIF**（Reinforcement Learning from AI Feedback）用强大的 AI 模型（如 GPT-4）替代人类标注员做评分排序，实验表明效果接近甚至超过 RLHF，成本大幅降低。

### Agentic RL vs PBRFT：MDP 视角的对比

传统的基于偏好的强化微调（PBRFT）优化单轮对话质量；Agentic RL 优化多步序贯决策。在 MDP 五元组 $(S, A, P, R, \gamma)$ 下两者的对比（记号：$s_t$ 为 $t$ 时刻的状态即已累积的上下文，$a_t$ 为第 $t$ 步动作，$o_t$ 为第 $t$ 步观察即环境/工具返回，$T$ 为一条轨迹的总步数）：

| 维度 | PBRFT（单轮对话） | Agentic RL（智能体任务） |
|---|---|---|
| 状态 | $s_0$ = prompt（初始提示），不变化 | $s_t = (\text{prompt}, o_1, \dots, o_t)$，随行动演化 |
| 行动 | 仅文本生成 | 文本生成 + 工具调用 + 环境操作 |
| 转移 | 无状态转移（$T=1$） | $s_{t+1} \sim P(s_{t+1} \mid s_t, a_t)$，$T \gg 1$ |
| 奖励 | 单步 $r(s_0, y)$，由奖励模型给出 | 多步累积 $\sum_t \gamma^t r(s_t, a_t)$，可稀疏/密集/混合 |
| 目标 | 最大化单步期望奖励 | 最大化完整轨迹的累积折扣奖励 |

例：分析 GitHub 仓库代码质量的智能体任务中，调用 API、读取文件、分析代码、生成报告每步都可获得部分奖励（+0.1/+0.1/+0.2/+0.6），总奖励 1.0。这是思维方式的转变——从"生成更好的单个回答"到"完成复杂任务"，LLM 从"对话助手"进化为"自主智能体"。

### Agentic RL 的六大核心能力

1. **推理（Reasoning）**：推理任务可建模为序列决策（生成推理链 c 与答案 a），奖励常设计为答案正确 +1 否则 0；RL 让模型发现训练数据中没有的推理路径，学会何时深思考、何时快答。
2. **工具使用（Tool Use）**：行动空间扩展为 {思考, 工具调用 (`tool_name`, `arguments`)}，学会何时用工具、选哪个、如何组合。
3. **记忆（Memory）**：学习记忆管理策略——什么值得记、何时更新、何时删除，超越静态 RAG 检索。
4. **规划（Planning）**：超越线性 CoT，学会动态规划行动序列、权衡短期与长期收益，愿意执行看似"绕路"的信息收集步骤。
5. **自我改进（Self-Improvement）**：自我反思、识别错误、分析失败原因并调整策略。
6. **感知（Perception）**：多模态理解与视觉推理、视觉工具使用。

## 关键概念

### GSM8K：数学推理训练的标准任务

数学推理是训练 LLM 推理能力的理想任务：答案客观可自动评估（不需要人工或复杂奖励模型）、需要分步推导、可泛化。**GSM8K** 是小学数学应用题数据集（7,473 训练 / 1,319 测试，2-8 步推理），三种数据格式：

| 格式 | 用途 | 内容 |
|---|---|---|
| 原始 | 人类阅读 | question + answer（含步骤标记 `<<48/2=24>>`、`#### 72`） |
| SFT | 监督微调 | prompt + 完整解答作为 completion（含对话模板标记） |
| RL | 强化学习 | `prompt + ground_truth`（只有最终答案），模型自己生成推理过程 |

RL 格式只给最终答案的设计，迫使模型学会自主推理而非记忆答案。

### 奖励函数设计

奖励函数定义"什么是好行为"。好的奖励函数应：清楚定义成功、能提供梯度信号、方差不过大、易调整组合。三种基础类型（均只在答案正确时生效，避免模型为降惩罚/刷步骤牺牲正确性）：

1. **准确率奖励（AccuracyReward）**：正确 +1，错误 0。简单直接但稀疏，无法区分"接近正确"与"完全错误"。工程要点：答案提取（找 "Final Answer:" 后的数字 / `####` 标记 / 最后一个数字）与数值比较（72.0 = 72、单位转换、格式差异）。
2. **长度惩罚（LengthPenaltyReward）**：$r = r_{acc} - \alpha \cdot \max(0, l - l_{target})$，鼓励简洁、控制推理成本；惩罚系数需仔细调，过强会抑制详细推理。
3. **步骤奖励（StepReward）**：$r = r_{acc} + \beta \cdot s$（s 为检测到的推理步骤数，β 默认 0.1），鼓励可解释推理；可能导致为刷步骤生成冗余内容。

常见组合：准确率 + 长度惩罚（问答系统）、准确率 + 步骤奖励（教育场景）、三者平衡（全面优化），需调权重避免某一目标过度主导。

### LoRA：参数高效微调

全量微调 0.6B 模型需约 12GB 显存（FP16），更大模型在消费级 GPU 上几乎不可行。**LoRA** 的核心假设：微调的参数变化 ΔW 可用低秩矩阵分解表示：

$$\Delta W = BA, \quad h = Wx + BAx$$

其中 W ∈ ℝ^{d×k} 冻结，只训练 B ∈ ℝ^{d×r}、A ∈ ℝ^{r×k}，r ≪ min(d, k)。例：d=k=4096、r=8 时参数量从约 1677 万降到约 6.5 万，减少 256 倍。优势是省显存、训练快、易部署、防过拟合；效果通常略逊于全量微调。

关键超参数：**`rank`**（$r$，典型 4-64，越大表达越强）、**`alpha`**（缩放因子，常设为 rank 的 2 倍）、**`target_modules`**（通常选注意力的 `q/k/v/o_proj`，可扩展 MLP 层）。

### GRPO：为 LLM 设计的 PPO 简化版

PPO 在 LLM 训练中的问题：需要额外训练价值模型（Value Model）估计优势函数；要同时维护四个模型（Policy、Reference、Value、Reward），工程复杂且显存占用高；易出现奖励崩塌或策略退化。

**GRPO（Group Relative Policy Optimization，出自 DeepSeekMath）**的核心：去掉 Value Model，用**组内相对奖励**代替绝对奖励估计优势：

$$J_{GRPO}(\theta) = \mathbb{E}\left[\frac{\pi_\theta(a|s)}{\pi_{ref}(a|s)} \cdot (r(s,a) - \bar{r}_{group})\right] - \beta \cdot D_{KL}(\pi_\theta \| \pi_{ref})$$

训练循环五步：① 每个问题用当前策略生成 N 个答案构成"组"→ ② 计算每个答案的奖励 → ③ 减去组内平均得相对奖励（降低方差）→ ④ 带 KL 惩罚更新策略 → ⑤ 重复。KL 散度按 token 计算后求和，防止"遗忘"SFT 阶段学到的知识。

关键参数与经验值：

| 参数 | 作用 | 建议值 |
|---|---|---|
| `num_generations` | 每题生成几个答案（组大小） | 4-8 |
| `max_new_tokens` | 单个答案最大长度 | 256-512 |
| `temperature` | 采样随机性 | 0.7-1.0（保持探索） |
| `learning_rate` | GRPO 学习率应比 SFT 小 | 1e-5 ~ 5e-5 |
| `kl_coef`（$\beta$） | KL 惩罚：太小偏离太远，太大限制学习 | 0.05-0.1 |
| `clip_range` | 策略比率裁剪（同 PPO 的 ε） | 0.2 |

### SFT 是 RL 的前提

预训练模型解决数学问题时输出冗长、无结构、没有明确答案（"Maybe I should use a calculator? Or maybe I can just estimate..."），无法提取答案、无法计算奖励。SFT 后模型输出结构清晰（Step 1 → Step 2 → Final Answer），强化学习才有有效的奖励信号。**SFT 是基础，RL 是提升：没有 SFT 基础，RL 很难成功；没有 RL 优化，模型只能模仿训练数据。**

## 分类/类型：评估指标体系

- **准确性指标**：准确率（正确答案比例，简单但区分不出"接近正确"）；Top-K 准确率（K 次采样中至少一次正确，反映模型潜力）；数值误差（区分接近/完全错误）。
- **效率指标**：平均生成长度（token 成本）；推理步骤数（2-5 步合适，过多说明冗余）；推理时间。
- **质量指标**：格式正确率（含 Step/Final Answer 标记）；推理连贯性（需人工或评估模型）；可解释性。

**错误四分类**：计算错误（步骤对但算错数）、推理错误（逻辑顺序错）、理解错误（没读懂问题）、格式错误。示例分析中计算错误占比最高（42%）、格式错误最少（5%，说明 SFT 有效）；按难度分组看，简单题（1-2 步）准确率约 78%，困难题（5+ 步）仅约 32%，说明多步推理能力仍是瓶颈。

## 经验与常见坑

**训练监控三个关键指标**：损失应逐渐下降（不降→学习率太小或数据有问题；先降后升→学习率太大或过拟合）；梯度范数应在 0.1-10（>100 梯度爆炸，<0.01 梯度消失）；学习率按 warmup 策略变化。GRPO 额外监控：平均奖励应上升、KL 散度保持在 0.01-0.1、准确率应提升。

**GRPO 常见故障排查**：
- 奖励不上升 → 学习率太小 / KL 惩罚太大 / 奖励函数不合理 / SFT 基础太差；对策：增大学习率、减小 `kl_coef`、重训 SFT。
- KL 散度爆炸（>0.5）、输出格式混乱 → 学习率太大或奖励函数过激；对策：降学习率、增 `kl_coef`、梯度裁剪。
- 准确率升但质量降 → 奖励只看准确率或 KL 太小；对策：组合奖励、增 `kl_coef`、减少轮数。
- 显存 OOM → GRPO 需同时生成多个答案并存储参考模型输出，比 SFT 占用高；对策：减 `num_generations`、`batch_size`、`max_new_tokens`，用梯度检查点与混合精度。

**训练流程经验**：从小规模开始（100-1000 样本快速迭代验证流程，再扩到全量）；训练前做数据质量检查（字段完整性、空值、重复）；数据增强（改写问题、相似问题生成）注意别引入噪声。

**超参数调优三法**：网格搜索（简单但组合爆炸）、随机搜索（对数均匀采样学习率，更高效）、贝叶斯优化（Optuna 等库，样本效率最高）。

**分布式训练选型**：单机多卡（2-8 卡）用 DDP；大模型（>7B）用 DeepSpeed ZeRO-2/ZeRO-3；多节点集群用 ZeRO-3 + Offload（优化器状态/参数卸载到 CPU）。注意总 batch size = 单卡 batch × 卡数 × 梯度累积步数，学习率按平方根线性缩放规则调整。

**部署**：LoRA 权重先 merge 回基础模型再上线；可用 8-bit 量化加速推理；用 FastAPI 等封装推理服务。

## ⚠️ 时效性说明

- 实验基于 HelloAgents 0.2.5 + TRL + Qwen3-0.6B（2025 年前后），API 细节、显存数字与"Qwen3-0.6B SFT 后 GSM8K 40-50%、GRPO 后 60-70%"的参考值随版本变化，具体以框架当前文档为准。
- GRPO 之后，面向 LLM 的 RL 算法仍在快速演进（DAPO、GSPO 等变种及多轮 Agent RL），"去掉 Value Model、用组内相对奖励"的思想仍是主流路线之一。
- 本文对 Agentic RL 的讨论以离线训练 + 单轮工具调用为主；真正的多步在线 Agent RL（长程任务、环境探索）是仍在发展的方向。
