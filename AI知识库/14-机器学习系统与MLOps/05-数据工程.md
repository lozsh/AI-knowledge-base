# 数据工程（Data Engineering）

<p class="note-date">更新于 2026-11-03</p>

**一句话定义**：数据工程是从源头到模型管理数据全生命周期的**基础设施层**（获取、转换、存储、治理）——本质是"数据集编译"而非"数据清理"。

## 概述：为什么数据是真正的源代码

传统软件中程序员编写逻辑、数据是输入；机器学习中程序员编写的是"从数据中提取逻辑的优化程序"，因此**改变数据就改变系统行为**，即使一行传统代码都没改：

- 微妙的标注不一致 → 产生微妙行为不一致的模型；
- 缺少边缘案例 → 在边缘案例上失败；
- 反映历史偏见 → 延续这些偏见。

没有任何架构、超参数或训练技巧能恢复从未存在的信息（∇），或纠正从一开始就植入的错误。与静止的源代码不同，数据是**活的**：它捕获的分布随世界变化，即使内容未动，也会静默使模型学到的行为失效。行业调查显示数据工作消耗 ML 项目努力的 60%–80%（CrowdFlower 2016）——不是因为乏味，而是因为它最重要。

**定义（定义 4.1）**：数据工程 = 从源头到模型管理数据生命周期的基础设施层，包括获取、转换、存储和治理。
1. 关键功能：确保**训练-服务一致性**，通过模型与原始数据的解耦防止静默降级；在铁律中它控制字节移动 D_vol，数据集质量决定数据是否仍代表目标分布。
2. 区别：数据科学专注于推理和洞察，数据工程解决**数据管道的可扩展性与可靠性**。
3. 常见误区：数据工程 ≠ "数据清理"，而是**数据集编译**——把有噪的原始观测编译为模型消费的干净训练集。

## 核心原理：数据集编译（编译器类比）

| 编译器概念 | 数据管道对应物 |
|---|---|
| 多级表示转换（tokens→AST→IR→机器码） | 原始观测 → 训练就绪张量的多阶段转换 |
| 死代码消除 | 过滤损坏记录、异常值、不相关特征 |
| 循环展开 | 数据增强（旋转图像、音高偏移、注入噪声） |
| 公共子表达式消除 | 去重（重复记录会偏置梯度估计、浪费计算） |
| 类型检查 | 模式验证（schema validation，严格类型与范围检查） |

工程推论：数据集必须版本控制、单元测试（质量检查）和调试；重新训练 = 重新编译。

**编译强制分区间的信任边界**：训练集塑造参数；验证集塑造模型/管道选择；测试集只在选择完成后估计泛化。**泄漏**的形式：重复示例跨分割、同一源记录的增强变体落在分割两侧、同用户/同家庭记录同时出现在训练与测试、用未来观测计算时间衍生特征。说话人无关、时间感知的分割是测量部署人群性能的前提，不是簿记细节。

## 数据物理学

### 数据引力（Data Gravity）

移动成本是数据量与带宽的函数：`T = D_vol / BW`。10 Gbps 链路移动 1 PB ≈ 9.3 天。

**纸巾估算**：1 PB 从美东数据中心移到美西加速器——专用 100 Gb/s 线路 ≈ 12.5 GB/s → 80,000 秒 ≈ 22 小时；按 $0.09/GB 出口费 ≈ $90,000（2024 AWS 定价基准）。若训练本身不足 22 小时、成本不足 $90,000（约 22,500 TPUv4 小时），则带宽比计算更贵。**经验法则：PB 级数据，代码移向数据；GB 级数据，数据移向代码。** 这解释了 Data Lakehouse（Spark/Presto 直接跑在存储节点上）的兴起；Data Mesh 则从治理角度提出按域去中心化数据所有权。

### 信息熵（Information Entropy）

信息熵是**信号密度**（每字节信息位数）。100 万张相同图像：高引力（TB 存储）、零熵；1 万个多样化边缘案例：低引力、高熵。二者之比给出：

```
数据选择增益 ∝ 信息熵 / 数据引力    （方程 4.1）
```

去重在不降熵的情况下去掉质量，直接增大比值；主动学习添加高熵边缘案例、忽略低熵常见案例——"数据清理"本质是**信噪比工程**。

### 供给问题与"供给税"（Supply Tax）

系统只与其最慢的项一样快。若加速器可处理 1,843 img/s 但存储管道只交付 250 MB/s，昂贵硅片在等待。**供给税** = I/O 等待浪费的墙钟时间，直接拉低铁律中的 η_hw；标准云卷上可超过 77.5%。供给示例中的参考加速器需要约 1.1 GB/s 的传输速率，迫使从传统文件系统转向专用存储架构。

### 能量-运动不变量

移动比特比在其上计算消耗多得多的能量，且随数据离处理器越远乘数越大：

| 操作 | 能量 | 相对成本 |
|---|---|---|
| 32 位浮点 MAC | 3.7 pJ/FLOP | 1× |
| DRAM 访问（32 位） | 640 pJ | 173× |
| 本地 SSD 访问（32 位） | 4,000 pJ | 1,081× |
| 网络传输（32 位） | 40,000 pJ | 10,811× |

推论：**局部性是系统工程的主导杠杆——数据不采取的步骤是最大的节能手段**。对训练数据去重修剪 50% 不只是省磁盘，而是消除训练生命周期中最耗能的阶段；数据选择是系统工程师手中杠杆最高的工具。

## 关键概念：四支柱框架

**数据级联（定义 4.2）**：上游数据质量问题沿收集→标注→特征工程→训练→评估→部署传播并放大为下游模型故障或用户伤害。修复成本随被污染的下游工件数量级联增长（特征表重生成、模型重训、评估重算、部署回滚）。**它不会被普通软件测试捕获**：损坏的数据可以满足模式、通过单元测试、跑出成功的训练作业，同时教给模型错误的信号——防御需要血缘、验证、合约和与模型行为绑定的监控。

**管道丛林示例**：上游团队把 zip_code 从整数改成字符串以支持国际代码，没有数据合约 → 管道静默把 "02139" 转成 2139，前导零丢失 → 模型将其视为全新未知类别、默认"高风险"。这就是**数据合约**（关于模式、单位、允许范围、特征语义的版本化协议）缺失的静默故障。

| 支柱 | 关注点 | 典型权衡 |
|---|---|---|
| 质量 | 准确性与适用性（验证、监控、漂移检测） | 拒绝噪声样本提升正确性但减少覆盖 |
| 可靠性 | 一致性与容错（错误处理、重试、本地缓冲、优雅降级） | 验证开销 vs 吞吐量 |
| 可扩展性 | 分布式规模下继续成立 | 一致性约束 vs 分布式规模 |
| 治理 | 合规与问责（GDPR、同意记录、数据声明/Datasheets、偏见记录） | 性能 vs 隐私；偏差缓解 vs 可用数据量 |

**诊断透镜**：准确率渐降 → 质量（漂移/标注降级）；间歇性管道故障 → 可靠性；硬件充足但训练慢 → 可扩展性；审计合规缺口 → 治理。最阴险的故障跨支柱（如训练与服务用不同特征计算路径）。**生产经验一致显示：数据基础设施故障在数量上远超模型故障**——但从业者本能上总先查模型。

## 分类/案例

### DLRM 推荐灯塔（可扩展性极限）

| 属性 | 值 | 系统含义 |
|---|---|---|
| 数据规模 | 十亿级用户/物品 ID | 嵌入表可达 TB/PB 级 |
| 约束 | 存储容量 | 单机放不下，必须分区 |
| 瓶颈 | 稀疏访问 | 随机查找对带宽的压力超过计算 |

与 ResNet 类视觉模型（算术吞吐受限）、GPT 类语言模型（流式带宽受限）不同，DLRM 受**存储容量 + 稀疏查找带宽**限制，嵌入表分区是一等系统关注。

### KWS 关键词识别案例（资源约束极限）

始终在线的唤醒词检测（"OK Google"/"Alexa"）：模型须适配 SoC 常开岛（几十 KB 量级权重 + 预处理同样受限），几百 MHz 算力，连续聆听功耗目标亚毫瓦，且须覆盖口音/年龄/环境噪声多样性。

**假唤醒目标估算**：容忍每月 1 次假唤醒，1 秒分类窗口全天候 → 每月 24×3600×30 = 2,592,000 个窗口 → 每窗口假阳性率 ≈ 3.9×10⁻⁷，即 99.99996% 的非关键词拒绝率。**"98% 准确率"这类标准指标在此毫无意义**；必须评估每小时错误接受数（FA/Hr）等专项指标。

## 经验与常见坑

- 把数据工程当预处理/清理的附属工作：它是决定系统今天能否工作、明天能否继续工作的"另一种语言编程"。
- 无数据合约的管道丛林：一个上游 schema 变更即可造成下游灾难性静默故障。
- 只优化最显眼的（模型），忽视最昂贵的（数据移动与供给）——供给税可达 77%+。
- 分区边界随意：泄漏让线下指标好看、线上失效。
- 灯塔/极例是可扩展性的试金石：DLRM 与 KWS 分别展示了容量墙与功耗墙下的数据工程。
