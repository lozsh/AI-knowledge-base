# 机器学习系统（部署范式）

<p class="note-date">更新于 2026-11-05</p>

**一句话定义**：光速、热力学和内存物理把 ML 部署划分为云端、边缘、移动、TinyML 四种范式——它们是物理定律的产物而非设计偏好，同一模型在不同范式中需要根本不同的工程。

## 核心原理

### 约束驱动架构

ML 系统工程的定义性洞察：**约束驱动架构**。三个永久的物理边界将世界划分为根本不同的操作区域：

- **光障（光速）**：光纤中光速约 200,000 km/s（真空的 2/3），加州到弗吉尼亚（约 3600 km）往返纯传播就需约 36 ms，任何计算还没开始。亚 10 ms 响应的应用物理上无法使用远程云。
- **功率墙（热力学）**：Dennard 缩放（约 2006 年终结）下 Power ∝ C·V²·f，且 V∝f，故功率随频率立方上升——频率翻倍需约 8 倍功率。缩放终结迫使行业走向并行（多核）和专业化（GPU/TPU）。移动设备 3–5 W 硬热限制，超过即"热节流"降频。
- **存储器墙**：计算能力约每 18 个月翻倍，内存带宽每年仅改善约 20%（比率约 1.33×/年）。数据移动成为大多数 ML 工作负载的主要瓶颈和能量成本。

**部署范式**：一种独特的操作区域，其边界由物理定律而非惯例设定。没有任何法规能让光速更快，也没有任何经济模式能废除热力学。

### 四种部署范式

跨越功率（MW→mW）和内存（TB→KB）各九个数量级：

| 范式 | 位置 | 延迟 | 功率 | 内存 | 最适合 |
|------|------|------|------|------|--------|
| Cloud ML | 数据中心 | 100–500 ms | MW 级 | TB | 训练、复杂推理 |
| Edge ML | 本地服务器 | 10–100 ms | 100 W 级 | GB | 实时推理、隐私 |
| Mobile ML | 智能手机 | 5–50 ms | 3–5 W | GB | 个人 AI、离线 |
| TinyML | 微控制器 | 1–10 ms | mW 级 | KB | 始终在线感知 |

具体硬件锚点：

| 类别 | 示例设备 | 处理器 | 内存 | 功率 |
|------|----------|--------|------|------|
| 云端 | Google TPU v4 Pod | 4096 芯片，1.1 EFLOP/s | 131 TB HBM2 | ~3 MW |
| 边缘 | NVIDIA DGX Spark / Jetson 系列 | 1 PFLOP/s AI | 128 GB | ~200 W（Jetson 7–60 W 视 SKU） |
| 移动 | 旗舰手机 SoC | CPU+GPU+NPU，15–45 TOPS | 8–16 GB | 3–5 W |
| TinyML | ESP32-CAM | 双核 240 MHz，<1 TOPS | 520 KB RAM | 0.05–1.2 W |

## 关键概念

### 铁律与瓶颈原则

铁律将延迟分解为三项（加法形式，适合分析单个任务）：

```
T = Dvol/BW + O/(Rpeak·ηhw) + Llat
    数据移动   计算          固定开销
```

现代加速器用流水线重叠数据移动与计算（算批次 n 时预取批次 n+1），因此吞吐量受最慢环节主导——铁律的和变为最大值（瓶颈原则，适合分析连续任务流）：

```
T_bottleneck = max(Dvol/BW, O/(Rpeak·ηhw), T_network) + Llat
```

推论：若系统受内存限制（Dvol/BW > O/(Rpeak·ηhw)），购买更快的处理器产生恰好 0% 加速——就像所有交通必须过两座桥时，拓宽六车道高速毫无用处。优化前必须先识别主导项。

### 传输的能量：本地 vs 上云

电池设备的决策速算：1 MB 数据经 Wi-Fi/LTE 上传（100 mJ/MB）耗 100 mJ；本地 MobileNetV2 推理（NPU）仅 0.1 mJ。传输比本地处理贵 **1000×**——即使云端推理时间为零，能量墙也使云卸载对始终在线电池设备不可行。机器约束（电池）决定算法选择（TinyML）。

### 工作负载原型

四种反复出现的物理瓶颈（不是模型类别，而是决定哪种工程举措有效的诊断）：

| 原型 | 特征 | 优化方向 |
|------|------|----------|
| 计算兽（Compute Beast） | 每字节做大量计算（大型训练） | 算力、利用率、并行度 |
| 带宽猪（Bandwidth Hog） | 等待密集权重/激活移动（自回归生成） | 更宽总线、数据重用 |
| 稀疏散射（Sparse Scatter） | 不规则表查找、差缓存局部性（推荐嵌入表） | 内存容量、访问延迟 |
| 微小约束（Tiny Constraint） | 每次推理的能量和内存占用决定可行性 | 极致压缩、定点算术 |

五个灯塔模型将其锚定到具体模型：ResNet-50（计算兽，4.1 GFLOP/图，FP32 102.4 MB）、GPT-2/Llama（带宽猪）、DLRM（稀疏散射，嵌入表可超 100 GB）、MobileNetV2（高效计算兽，深度可分离卷积省 13.7× 计算）、关键词识别 KWS（微小约束，约 200K 参数 / 800 KB）。

### 算术强度与屋顶线

判别瓶颈的无量纲量：

- 工作负载算术强度 **I = O / Dvol**（FLOP/字节）
- 硬件平衡点 **B = Rpeak / BW**（FLOP/s ÷ 字节/s）
- I > B → 计算受限；I < B → 内存受限。

同一模型会跨越分界：ResNet-50 在云端 batch=1 时算术强度仅约 80 FLOP/字节，低于加速器平衡点，**内存受限**（内存时间 0.025 ms vs 计算时间 0.013 ms，A100 FP16）；在移动 NPU（INT8，25.6 MB）上同样内存受限且更严重。当批处理提高重用使 I 越过平衡点后才变为计算受限。这解释了为什么减字节（量化、压缩）比堆峰值 FLOP/s 更能改善部署。

### 按范式的主导瓶颈

| 范式 | 主导约束 | 原因 | 优化焦点 |
|------|----------|------|----------|
| 云端训练 | 计算 O/(Rpeak·ηhw) | 内存/网络充足 | 加速器利用率、批量大小 |
| 云端 LLM 推理 | 内存带宽 Dvol/BW | 顺序生成反复移动模型状态 | 增加重用、减少字节 |
| 边缘推理 | 内存带宽 | 本地带宽有限 | 更小模型、更少传输 |
| 移动 | 能量（电池 = ∫Power·dt） | 热节流 | 降精度、占空比循环 |
| TinyML | 模型必须适合片上容量 | KB 级 SRAM | 微小模型、定点算术 |

训练与推理的瓶颈可以互换：训练要吞吐量（大批量、增强），推理要延迟（单样本、新鲜度）。

### 关键延迟数字

决策规则：延迟 > X 的操作不能出现在延迟预算为 X ms 系统的关键路径上。

| 操作 | 延迟 |
|------|------|
| GPU 矩阵乘（单 op）/ L1 缓存命中 | ~1 ns |
| HBM 读取（GPU） | 20–50 ns |
| 同一数据中心 / 同区域 / 跨区域网络 | 0.5 ms / 1–5 ms / 50–150 ms |
| NPU 推理（MobileNetV2） | 5–20 ms |
| LLM 首 token（GPT-4 级） | 200–500 ms |
| 唤醒词检测（TinyML） | ~100 μs |

## 分类/类型：四种范式的定义与权衡

**云端 ML**：以延迟换弹性计算，将算力与数据/用户位置解耦。定义性主张：训练 GPT-3 需 3640 PFLOP-天（约 1 万个 V100 跑 15 天，兆瓦级功率，估计约 460 万美元），地球上没有单机可做。常见误解是"无限计算"——距离惩罚和摄取瓶颈是任何软件优化消除不了的。TCO 速算：ResNet-50 规模视觉服务（1M 推理/天），云端约 35,288 美元/年（GPU+出口+负载均衡+监控），本地 T4 边缘约 21,610 美元/年（其中 DevOps 人力 15,000 美元占主导）；利用率超过约 60% 后边缘更便宜——云端"按需付费"只在低利用率下占优。

**边缘 ML**：把计算放到数据源附近（工厂、零售、医院、基站），优先确定性的 Llat 项和数据主权。常见误解是"云端的小规模复制品"——实际要处理间歇连接、受限功率、异构硬件、车队远程管理（fleet management）。金融、医疗等法规要求数据不出场所时，边缘不是可选项而是强制项。

**移动 ML**：电池供电的个人设备（3–5 W），优先个人 AI 交互与离线智能。核心是功率墙 + 热节流：60 FPS 跑 1 分钟的模型可能随升温降到 15 FPS，性能不可预测。优化手段：高效模型（MobileNet/EfficientNet）、NPU、占空比循环、INT8/FP16 降精度。

**TinyML**：频谱极端——微控制器（数百 KB 到 KB 内存、kHz–MHz 时钟、毫瓦预算、1–10 美元成本），纽扣电池运行数月到数年，始终在线感知。常见误解是"把模型缩小即可"——实际需要根本不同的设计：模型必须适合片上 SRAM、定点算术（非浮点）、禁止动态内存分配、占空比循环。约束层次（评估顺序）：① 内存适配（硬限制）→ ② 延迟预算 → ③ 能耗与电池寿命。案例：智能门铃模型过了内存关（12.5% 占用）却在 ESP32-S3 上以 101 ms 基线延迟没过 50 ms 实时目标——适配的模型仍必须为交互预算继续优化。

## 范式选择与混合架构

按主导约束选择（部署是约束驱动的选择，不是偏好）：

| 约束 | 最适范式 |
|------|----------|
| 延迟 < 10 ms | 边缘 / 移动 / TinyML（光障排除云端） |
| 延迟 10–100 ms | 边缘 / 移动 |
| 延迟 > 100 ms 可接受 | 云端 |
| 隐私 / 数据驻留 | 边缘 / 本地 |
| 无网络连接 | 移动 / TinyML |
| 大规模训练、GPT-4 级推理 | 云端 |
| 单位成本敏感的始终在线感知 | TinyML |

复杂应用通常需要**混合架构**，云端-边缘-设备连续体自然分工：TinyML 做始终在线筛选与唤醒词；移动/边缘做本地决策与隐私筛选；云端做训练、聚合与全局更新。自动驾驶是典型：毫瓦级传感器异常检测（TinyML）+ 300–500 W 主 AI 系统（感知/预测/规划）+ 云端训练与高清地图（光障禁止云端参与实时控制回路）。

**联邦学习**（Konečný et al. 2016）将混合架构系统化为训练方法：数据留在设备上本地训练，只聚合模型更新（梯度）到云端，兼顾隐私与全局模型能力。

## 系统熵：部署为何不是终点

**系统熵** = 数据分布漂移 + 基础设施漂移的复合，使生产系统持续偏离部署时验证过的行为。

- **数据分布漂移**：世界在变而模型固定——用户行为演进、传感器降级、经济模式转移。经验证据表明不重新训练的模型性能每月退化 5–20%，是需要持续监控和再训练的统计必然性。
- **基础设施漂移**：库更新、OS 迁移、依赖变化、硬件更替在代码不变的情况下改变模型行为。

部署是系统开始变陈旧的起点：漂移检测与再训练管道必须设计为核心组件，而非事后补充。

## 经验与常见坑

- **谬误：同一模型可跨范式不加修改地运行。** MobileNet 是为移动专门设计的新结构（深度可分离卷积），不是缩小版 ResNet；GPT-4 级模型 TB 级内存需求根本不适用于边缘。每个范式需要在其约束下重新设计。
- **谬误：范式边界是严格分离的。** 实际边界模糊：手机可混合推理上云；Jetson 用移动级芯片；ESP32-S3 不到 1 美元跑数百 MHz，模糊了 TinyML 与移动的界线。每个范式定义典型中心而非硬边界。
- **谬误：云端与边缘是竞争对手。** 它们互补：边缘无法经济地训练大模型，云端无法提供亚 10 ms 响应，移动无法超越电池算力，TinyML 无法训练复杂模型。非平凡应用需要三四种范式组合。
