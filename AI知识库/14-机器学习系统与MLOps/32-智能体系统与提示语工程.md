# 智能体系统与提示语工程

<p class="note-date">更新于 2026-11-03</p>
> 一句话概括：提示语引擎就是智能体的本体——围绕 ICL 的方法库（选例/排序/思维链）加上"记忆流+反思+规划"三层智能体架构（斯坦福 AI 小镇），构成 LLM 应用的系统工程框架。

## 核心概念

### 提示语引擎 = 智能体本体
与 LLM 交互的唯一方式是 Prompt，所以工业级智能体的核心组件是**提示语引擎（Prompt Engine）**。三大能力：
1. **识别用户意图**（提示语工程 + 指令微调联合设计）；
2. **识别和选择检索结果**（WebGPT 起源）；
3. **压缩有价值信息**（最少 token 保留最多信息——记忆管理本质是长提示词压缩）。

### AIGC 系统建模链路：检索-生成-检索
AIGC 与推荐系统（AIRC）同构——都是"为用户交付内容"，区别是"检索"变"生成"。但生成内容被视作服务者"生成"（无避风港原则），可信与合规是底线：
**用户请求 → 生成推理计划 → 检索外部记忆 → 模型生成 → 用搜索引擎验证可信性/加引用 → 呈现**。

### 多专家模型而非统一大模型
合久必分、分久必合：文生图+内容理解+摘要合一需 ≥100B 参数，拆成三个 80B 专家模型可大幅省推理成本。生成 LLM 四能力：理解引擎加工后的指令（注意其数据分布 ≠ 用户原始输入分布）、任务分类路由到专家模型、涌现能力融合外部信息、基础内容安全过滤。控制模块用强化学习做反馈标注、升降级策略与总算力控制。

### 知识注入两条路
模型工程（微调，参数学习）与提示语工程（ICL，上下文学习）本质都是知识注入。ICL（GPT-3 提出）衍生 Zero-Shot / Few-Shot；提示语工程核心目标 = **基于 ICL 为 LLM 选择合适的 Few-Shot 示例**。

## 关键方法/原理

### ICL 设计四环节与方法库
| 环节 | 方法 | 要点 |
|---|---|---|
| Selecting 选例 | **KATE**（就近法则） | 语义向量距离近的示例更优 |
| | **EPR** | 借鉴 Learning-to-Rank 的 Pairwise 对比学习，用 LLM 自身为示例打分 |
| Ordering 排序 | 全局熵/局部熵排序（ACL'22） | 相比随机排序分别平均提升 13% / 9.6%；高质量示例靠后、靠近问题位置 |
| Reasoning 推理 | **CoT**、**Self-Consistency** | CoT 分步推理；Self-Consistency 采样多条推理路径选最一致答案（"一题多解"验证），最常用 |
| 知识补充 | **Generated Knowledge Prompting** | 先让 LLM 生成相关知识再反哺输入，避免滥用涌现能力省算力 |
| 多轮追问 | **Self-Ask** | 模型自判知识够不够，不足时输出 Follow-up 调外部工具；多智能体/具身场景常用，聊天场景步数不可控少用 |
| 自动化 | **APE** | LLM 生成候选提示模板→打分选优→蒙特卡洛搜索迭代改进 |

另有 **APE（Automatic Prompt Engineering）**：LLM 依示例生成候选提示模板 → 打分选最优 → 迭代搜索语义变体。模型热身 Warmup：训练阶段调 ICL 整体能力，区别于具体任务微调。

### 智能体三层架构（斯坦福 Generative Agents / AI 小镇）
LLM 无状态，一切历史靠外部记忆。25 个智能体小型社会实验的核心设计：

1. **记忆流（Memory Stream）**：记忆对象 = 自然语言描述 + 创建时间戳 + 最近访问时间戳；检索得分 = **时近性 Recency + 相关性 Relevance + 重要性 Importance** 加权求和（实验代码权重约 0.5 / 2 / 3，可未来用 RL 学习）——本质是注意力式的长提示压缩。效果对比：朴素全量塞 prompt 答"我在忙工作"，记忆流答"我在策划情人节派对"。
2. **反思（Reflection）**：每天约 2-3 次（周期+随机触发）；流程 = 生成候选反思问题 → 用问题检索记忆流 → 生成带证据的感悟 → 存回记忆流并连接相关记忆，形成**反思树**（叶=观察事件，越高越抽象）——本质是记忆聚合/提示压缩。
3. **规划（Planning）**：保证行为一致性（否则一天吃两次午饭）。两步：全天粗规划（依据人设+前日摘要生成 5-8 条）→ 递归细节规划（先按小时再细到 5-15 分钟）；**临时规划**：感知到相关人/事时检索记忆并重排后续计划。
4. **环境树**：世界表示为区域/对象树，每个智能体只维护自己的子图（类似战争迷雾）；移动用传统游戏寻路，交互与物体状态变化触发 LLM 决策。

实验涌现数据：市长竞选信息知晓率 4%→32%、派对信息 4%→48%（信息传播）、关系密度 0.167→0.74——多智能体社会会涌现新社会现象。

### 外部记忆的存储与检索
知识表征三路：**倒排索引**（字面关键词）、**嵌入表征**（语义向量；用 SBERT 这类 Bi-Encoder——Cross-Encoder 两两比对推理开销不可接受）、**知识图谱**（结构化+GNN）；工业实践多路召回融合。

向量检索 MIPS/ANN 三类算法：
- 空间划分（KD-Tree、聚类）、空间编码转换（LSH、**PQ** 乘积量化——向量拆成低维子空间各自量化）、邻居图（HNSW、SPTAG）；Faiss 是开源代表。
- 向量库四大挑战：亿级索引精度/效率、高维维度灾难、分布式分片合并、流式在线更新。

### 工具接入
类 OpenAI Function Calling 的微服务注册中心式接入 + **API Bank**：插件向量化入库，按语义相似性匹配插件——"给智能体挑工具"本身也是一个检索问题。

## 经验与常见坑

1. 用户输入分布 ≠ 提示语引擎加工后的分布——指令微调要用引擎加工后的数据训练；
2. ReAct（LangChain/AutoGPT 式）门槛低但极初级，工业级智能体要上记忆流/反思/规划完整架构；
3. 用 GPT-4 标数据注意"模型参数盗窃"式的合规争议；风控要覆盖训练数据投毒、对抗越狱、指令注入三类攻击面（可用 PromptBench 测试）；
4. Self-Ask 多轮步数不可控，聊天场景少用，具身/多智能体博弈场景才用；
5. 示例排序不是小事：熵排序的个位数到两位数提升免费用；
6. 记忆检索权重是超参，按场景调，别照抄小镇默认值；
7. Cross-Encoder 精度高但只能重排小候选集，大规模召回必须 Bi-Encoder。
