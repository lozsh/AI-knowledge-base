# 机器学习系统与 MLOps：现状综述（2026）

<p class="note-date">更新于 2026-11-06</p>

**一句话定义**：MLOps 的经典体系（数据-训练-部署-监控闭环）已趋成熟并平台化，而 LLM 的普及把工程重心推向提示词管理、评估与可观察性三件套（LLMOps），行业正从"部署一个模型"转向"运营一个会写代码、会调用工具的 AI 系统"。

经典 MLOps 体系形成于 2015 年前后的技术债务反思与 2018-2022 年的工具平台化浪潮，其核心假设是"团队训练并部署自己的模型"。2022 年末 ChatGPT 发布后，多数应用团队的模型来源变成了少数基座厂商的 API，"训练"环节被"提示词 + 检索 + 微调 + 评估"取代，MLOps 工具链随之经历了一次重构：评估与可观察性从附属功能上升为核心组件，一批 LLMOps 新生代公司在 2024-2025 年完成平台化。本篇综述截至 2026 年末的格局，侧重"现在什么样"，原理与经典流程参见同目录各篇。

## 时间线：从 MLOps 到 LLMOps

- **2015**：《Hidden Technical Debt in Machine Learning Systems》发表，ML 系统的工程复杂性进入主流视野。
- **2018**：MLflow 由 Databricks 开源，实验追踪与模型注册成为标准化组件。
- **2020-2022**：MLOps 概念普及，Kubeflow、Airflow、特征商店组成经典流水线；各云厂商推出托管 ML 平台。
- **2023**：ChatGPT 引爆 LLM 应用开发；OpenAI 开源 Evals 评估框架；向量数据库与提示词工具爆发。
- **2024-02**：LangChain 发布 LangSmith（评估 + 可观察性 SaaS），标志 LLMOps 平台化起点。
- **2025-03**：CoreWeave 宣布以约 17 亿美元收购 Weights & Biases，GPU 云向上整合 MLOps 工具层。
- **2025-06**：MLflow 3.0 发布，正式引入 GenAI 追踪（tracing）与评估能力，经典 MLOps 工具吸收 LLMOps 功能。
- **2025-10**：LangChain 1.0 发布，框架重心从"链式调用"转向智能体（agent）工程。
- **2025-2026**：评估平台、智能体评估、AI 治理合规工具成为增长最快的品类；"评估驱动开发"成为主流工程方法。

## LLM 时代的新核心：提示词、评估、可观察性

### 提示词管理

提示词从散落在代码里的字符串，演变为有版本、有测试、有灰度发布的资产。主流平台均提供提示词注册表（prompt registry）、Playground 实验、与代码仓库分离的提示词版本管理，以及提示词与模型版本的组合 A/B 测试。随着上下文工程兴起，管理对象也从单条提示词扩展到系统提示词、工具描述、检索上下文模板等整套"上下文资产"。参见 [08-AI智能体/08-上下文工程.md](../08-AI智能体/08-上下文工程.md)。

### 评估：从模型指标到系统评估

LLM 时代评估的最大变化是对象从"模型"变为"应用系统"：输出质量依赖提示词、检索、工具调用、模型四者的组合，传统单指标不再够用。当前评估体系的公认做法包括：

- **LLM-as-a-judge**：用强模型给弱模型的输出打分，配合评审提示词校准与人工抽检对齐；
- **在线评估**：生产流量采样 + 用户反馈信号回流，替代离线基准的滞后性；
- **智能体评估**：按任务完成率、工具调用正确率、多轮轨迹质量评估，而非单点输出质量。

评估能力已成为平台竞争的主战场：LangSmith、Braintrust、Arize、W&B Weave、Langfuse 均以数据集 + 评审器 + 实验对比为核心抽象，Langfuse 的开源仓库在 2026 年获得约 3.7 万 GitHub 星标，反映开源评估/追踪一体化方案的强劲需求。参见 [08-AI智能体/15-Agent 的评估.md](../08-AI%E6%99%BA%E8%83%BD%E4%BD%93/15-Agent%20%E7%9A%84%E8%AF%84%E4%BC%B0.md)。

### 经典 MLOps 与 LLMOps 关注点对照

| 维度 | 经典 MLOps | LLMOps（2026 年主流形态） |
| --- | --- | --- |
| 模型来源 | 自训练为主 | 基座 API + 开源权重微调为主 |
| "代码"主体 | 特征、超参、训练脚本 | 提示词、检索配置、工具描述、智能体流程 |
| 版本管理对象 | 模型权重、特征集 | 提示词版本、评估集、系统配置组合 |
| 质量验证 | 离线指标 + 回归测试 | 评估集 + LLM 评审 + 在线 A/B + 红队测试 |
| 生产监控 | 特征漂移、预测分布 | 调用链追踪、成本/延迟、幻觉率、拒答率 |
| 回滚单位 | 模型版本 | 提示词/模型/检索三元组的组合版本 |

### 可观察性：Tracing 成为一等公民

经典 ML 监控关注特征漂移与预测分布，LLM 应用的核心则是**调用链追踪**：一次请求往往经过检索、多次模型调用、工具执行，调试必须能看到每一步的输入输出、token 消耗、延迟与成本。OpenTelemetry 推进 GenAI 语义约定，使追踪数据可以跨厂商互通；OpenAI Evals 框架（GitHub 约 2 万星）则是评估侧开放生态的代表。可观察性数据同时反哺评估与微调数据集，形成"生产数据 → 评估集 → 后训练"的飞轮。

## 主流平台格局

| 层次 | 代表 | 特点 |
| --- | --- | --- |
| 云厂商平台 | SageMaker AI（AWS）、Vertex AI（Google）、Azure AI Foundry（Microsoft） | 数据湖 + 训练 + 托管推理 + 治理一体化；2024 年末起全部完成 GenAI 化改版 |
| 经典 MLOps 工具 | MLflow、Weights & Biases、Kubeflow、Airflow | 实验追踪/流水线事实标准；MLflow 3.x 补齐 GenAI 能力；W&B 并入 CoreWeave |
| LLMOps 新生代 | LangSmith、Braintrust、Arize（Phoenix）、Langfuse | 评估 + 提示词管理 + 追踪三合一；开源（Langfuse、Phoenix）与 SaaS 并存 |
| 智能体工程框架 | LangChain/LangGraph、Agent 开发套件 | 框架与自家 LLMOps 平台绑定，形成"框架 + 评估 + 部署"组合 |

新生代 LLMOps 平台对比：

| 平台 | 形态 | 差异化定位 |
| --- | --- | --- |
| LangSmith | 闭源 SaaS | 与 LangChain/LangGraph 生态深度绑定，评估 + 追踪 + 提示词管理全家桶 |
| Braintrust | 闭源 SaaS | 面向 AI 产品团队的评估与在线实验，强调产品迭代节奏 |
| Arize（Phoenix） | 开源 SDK + SaaS（Phoenix 开源，约 1.2 万星） | 从 ML 监控起家，主打生产端可观察性与评估打通 |
| Langfuse | 开源 + 云托管（约 3.7 万星） | 自托管友好，开放标准接入，成本敏感团队的主流开源选择 |
| W&B Weave | SaaS（随 W&B 平台） | 经典实验追踪向 GenAI 追踪/评估的自然延伸，训练侧一体化 |

三层格局的关键动态：

- **云厂商**：AWS 于 2024 年末 re:Invent 将 SageMaker 整合为覆盖数据与 AI 的统一平台；Microsoft 于 2024 年 11 月发布 Azure AI Foundry，把模型目录、评估、安全过滤器打包为企业入口；Vertex AI 依托 Gemini 与 TPU 形成模型到芯片的垂直整合。云厂商的打法是"一站式"，但工程团队普遍反馈深度调优仍需专业工具。
- **经典工具**：MLflow 归 Apache 基金会、由 Databricks 主导，3.0 版本把追踪与评估纳入同一数据模型，是开源世界对 LLMOps 的回应；W&B 被算力云商 CoreWeave 收购，暗示工具层与算力层正在垂直整合。Kubeflow 现为 CNCF 孵化项目（2023 年 7 月获基金会投票接受），定位调整为"云原生 AI 平台"。
- **新生代**：LangSmith 依托 LangChain 生态（公司 2024 年完成红杉领投的 2500 万美元 A 轮）；Braintrust、Arize 面向 AI 产品团队的评估与在线实验；Langfuse 以开源 + 自托管路线切入，成为成本敏感团队的主流选择。

## 特征商店与流水线工具的现状

- **特征商店**热度相对峰值回落。开源侧 Feast 仍是主流（GitHub 约 7400 星），商业侧 Tecton、Hopsworks 继续服务金融/风控等实时特征场景；云厂商的特征商店功能多已并入其数据平台（如 Databricks 的 Unity Catalog 特性工程）。LLM 时代"模型输入"从数值特征变成文本与检索结果，RAG 数据管道承接了特征商店的部分投资。
- **流水线编排**仍以 Airflow 为批处理事实标准，Dagster、Prefect 占据数据工程敏捷场景；训练编排则分散在各训练框架与调度器中。
- **整体判断**：经典"特征-训练-部署"流水线工具进入维护型成熟期，增量投资流向数据检索（RAG）管道、评估数据集管理与智能体运行时。经典工作流详见 [04-机器学习工作流.md](04-机器学习工作流.md) 与 [05-数据工程.md](05-数据工程.md)。

## AI 治理与模型风险管理

合规已从可选项变成 MLOps 平台的内置模块，三条主线并行：

1. **欧盟《AI 法案》**：2024 年 8 月生效，2025 年 2 月起禁止"不可接受风险"应用，2025 年 8 月起通用目的模型（GPAI）义务生效，2026 年 8 月起大部分高风险义务适用（部分延至 2027 年）。系统级义务包括技术文档、训练数据摘要、系统性风险评估与事故上报。
2. **国际框架**：NIST《AI 风险管理框架》（AI RMF 1.0，2023 年 1 月）与 ISO/IEC 42001（2023 年 12 月发布）成为企业治理体系的两把标尺，云厂商平台的"模型清单 + 评估报告 + 责任链"功能均按其设计。
3. **金融等强监管行业**：在既有模型风险管理（如美联储 SR 11-7 所确立的模型验证、独立复核、有效性质疑）框架内扩展至 AI 系统，LLM 的不可解释性促使"人审兜底 + 输出监控 + 影子运行"成为落地标配。

平台侧的直接体现：Azure AI Foundry、SageMaker、Vertex AI 均内置模型目录安全评级、内容过滤与评估报告导出；评估平台的"合规证据链"（谁改了提示词、哪个版本上线、依据什么评估结论）成为企业采购的关键卖点。参见 [16-安全可信与负责任AI/03-负责任 AI.md](../16-%E5%AE%89%E5%85%A8%E5%8F%AF%E4%BF%A1%E4%B8%8E%E8%B4%9F%E8%B4%A3%E4%BB%BBAI/03-%E8%B4%9F%E8%B4%A3%E4%BB%BB%20AI.md)。

## 趋势判断

1. **评估驱动开发（EDD）成为主流方法论**：先建评估集再写功能，已成为 LLM 应用团队的通行实践；评估基建（数据集、评审器、回归流水线）的地位相当于传统软件的单元测试。智能体能力提升反而放大了对评估的需求——行为面越宽，越需要系统性验证。
2. **AI 参与软件工程，重塑系统形态**：头部公司披露其新增代码中相当比例由 AI 生成（Google CEO 曾表示超过 30%），GPT-5 等前沿模型在 SWE-bench Verified 上的解决率已达约 75%。代码由 AI 大量生成后，CI/CD 的瓶颈从"写代码"转移到"验证代码"，评估、回滚与可观察性从运维附属品变为工程核心；MLOps 与 DevOps 的边界正在融合为"AI 系统工程"。
3. **平台整合继续**：算力云收购工具层（CoreWeave-W&B）、框架商补平台层（LangChain-LangSmith）、数据平台吞并特征层（Databricks），单一功能的点工具生存空间收窄，"评估 + 追踪 + 提示词"三合一成为入场券。
4. **智能体运行时是新战场**：会话状态管理、工具权限、长任务编排、成本核算成为 2026 年平台竞争的新焦点，经典 MLOps 概念（版本、回滚、灰度）正在被逐一映射到智能体世界。
