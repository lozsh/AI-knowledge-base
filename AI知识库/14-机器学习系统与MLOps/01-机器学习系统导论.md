# 机器学习系统导论

<p class="note-date">更新于 2026-11-03</p>

**一句话定义**：机器学习系统是行为由数据定义、在物理约束（数据移动、算术、延迟、能量）下运行的系统，其工程原理因此与传统软件根本不同——AI 工程就是用确定性的可靠性目标去驯服这种概率性系统。

## 核心原理

### 双重要求（Dual Mandate）

每个机器学习系统必须同时管理两件事：

- **统计不确定性**：模型预测是概率性的，行为由数据而非显式逻辑定义。
- **物理约束**：执行预测需要移动 TB 级数据并执行海量算术运算，通常要在毫秒级完成。

失败边界的区别最为关键：代码错误导致崩溃（"响亮"失败），数据错误导致错误预测（"沉默"失败）。当准确率莫名下降 5 个百分点时，可能是数据偏移、训练中断或未收敛——调试、测试和架构设计都因此改变。

### 软件 1.0 → 软件 2.0

Andrej Karpathy（2017）将这一转变形式化：神经网络权重是新的"源代码"。

| 特征 | 软件 1.0（传统） | 软件 2.0（机器学习） |
|------|------------------|----------------------|
| 源代码 | C++/Python/Java | 训练数据 + 标签 |
| 编译器 | GCC、LLVM | 训练循环（SGD，随机的） |
| 逻辑 | 显式（手写） | 隐式（习得） |
| 失败模式 | 响亮（崩溃） | 沉默（指标退化） |
| 调试 | 追踪执行路径 | 检查数据分布 |

推论："数据即代码"不变量——数据集充当源代码，训练流水线充当编译器，模型权重充当可执行文件。调试 ML 系统意味着调试数据而非 Python 脚本。

### 隐藏技术债务

谷歌里程碑论文（Sculley et al. 2015）证明：成熟 ML 系统中，ML 代码只占整个系统的约 5%，其余是数据收集、验证、特征提取、资源管理、监控和服务基础设施。"机器学习"容易，"机器学习系统"困难。

### 验证差距

传统软件输入空间可枚举，可以写覆盖边界情况的单元测试；ML 系统的输入空间是高维连续的（224×224 RGB 图像有 256^150528 种配置），任何测试集都无法有意义地覆盖：

```
验证差距 = 总输入空间 − 测试集覆盖 ≈ 总输入空间
```

因此有保证的正确性被换成统计可靠性，必须依赖生产中的持续监控。

### 经典范式演进：每代一个瓶颈

AI 七十余年繁荣-萧条周期遵循一致模式：每次寒冬在前一范式遇到系统上限时到来，每次复兴都紧随基础设施工程突破而非算法突破。

| 时代 | 范式 | 瓶颈 | 典型系统 |
|------|------|------|----------|
| 1950s–1970s | 符号 AI | 逻辑瓶颈：规则无法覆盖现实模糊性 | STUDENT（1964）：换一种措辞即失败 |
| 1980s | 专家系统 | 知识瓶颈：提取和维护专家知识比系统价值更贵 | MYCIN（1976）：胜过初级医生，但数千条规则不可维护 |
| 1990s | 统计学习 | 特征工程瓶颈：性能受限于人工预处理创造力 | 朴素贝叶斯垃圾邮件过滤：p(spam\|email) ∝ p(spam)·∏ᵢ p(wordᵢ\|spam)；Viola-Jones 人脸检测 |
| 2012 至今 | 深度学习 | 基础设施瓶颈：计算吞吐量与内存带宽 | AlexNet（2012）：算法（并行矩阵运算）匹配硬件（GPU），top-5 错误率 15.3%，相对改善 41.6% |

相关概念：**苦涩教训**（Rich Sutton）——长期看，利用更多计算的通用方法胜过手工编码专业知识；**数据的不合理有效性**（Halevy et al. 2009）——海量数据喂养的简单模型常胜过少数据的复杂模型；**莫拉维克悖论**——对人类"简单"的感知任务（视觉、语音）恰恰需要最高算力，这推动了加速器浪潮。

## 关键概念

### D·A·M 分类法

任何 ML 系统由三个相互依存的轴组成：**数据**（Data）、**算法**（Algorithm）、**机器**（Machine）。瓶颈在轴之间迁移而非消失：改善一个轴通常把压力暴露到另一个轴。系统习惯是先问"哪个轴现在绑定"，再选择不引发更大下游故障的干预。

### 铁律（Iron Law of ML Systems）

将端到端延迟分解为三项，是整个学科的分析骨架：

```
T ≈ Dvol/BW + O/(Rpeak·ηhw) + Llat
     数据移动    计算          固定开销
```

- Dvol：移动的数据量；BW：内存带宽；O：总运算量；Rpeak：峰值算力；ηhw：硬件利用率；Llat：固定延迟。
- 量纲一致：每项都是秒，不能把 FLOPs 加到字节上。
- 示例（心算）：GPT-3 级模型 ≈3.14×10²³ FLOPs，1024 个加速器（312 TFLOP/s），利用率 45% → 训练约 25 天；利用率提到 60% → 19 天。

配套的**能量税**公式（Horowitz 2014）：

```
Etotal ≈ Dvol × Emove + O × Ecompute   （主导项 = 数据移动）
```

从片外 DRAM 移动一个字节约等于 145× 一个 FP16 运算、约 800× 一个 INT8 运算——最小化数据移动是速度和能效的首要杠杆。

### 经济不变量：计算回报率（RoC）

```
RoC = ΔAccuracy / ΔCompute Cost
```

准确率提升 1% 需要计算量增加 10 倍，可能通不过 RoC 测试。RoC 为负或可忽略时，系统是过度工程化的——"准确率"从研究目标转变为工程预算。

### 五个灯塔模型

作为反复出现的参考工作负载，每个隔离一种瓶颈：

| 灯塔模型 | 系统瓶颈 | 关键工程问题 |
|----------|----------|--------------|
| ResNet-50 | 计算吞吐量 | 我的硬件在做数学还是在等数据？ |
| GPT-2/Llama | 内存带宽（自回归解码逐 token 加载权重） | 我能多快把模型状态移到计算？ |
| DLRM | 内存容量（TB 级嵌入表） | 如何在内存中容纳 TB 级模型？ |
| MobileNetV2 | 延迟和功率 | 能否满足电池的实时约束？ |
| 关键词检测（KWS） | 功率包络 | 能否毫瓦级始终在线推理？ |

### 效率框架：三个维度

纯扩展不可持续（GPT-4 级训练约 250 万加速器-天），效率优化不可选择：

1. **算法效率**：更好的模型设计，每运算产生更多有用行为。
2. **计算效率**：对齐算法逻辑与机器物理，提高硬件利用率。
3. **数据选择**：从有限样本提取更多学习信号，降低总运算量 O。

量化证据：2012–2019 年达到 AlexNet 级 ImageNet 性能所需计算减少约 44.5×（约每 15 个月翻一番，超过摩尔定律）。**效率悖论**：效率增益不会变成成本节约，而是投入更大的模型和实验——效率促进规模，规模又要求效率。

## 定义 AI 工程

AI 工程：设计、部署和维护内在概率性系统，同时满足 D·A·M 三轴约束（数据质量、算法正确性、机器效率）以达到确定性可靠性目标的工程学科。与 ML 研究的区别：研究优化单一目标（验证损失），AI 工程优化部署后变化分布上的多目标约束面（延迟、吞吐量、准确率、成本、公平、鲁棒性）。类比：计算机工程在 1960 年代桥接电气工程与计算机科学而诞生，AI 工程正在桥接算法、软件与硬件。

## ML 系统生命周期

六阶段闭环（非线性管道），两个反馈循环：评估不达标返回数据准备；监控发现性能退化触发重新收集数据。

```
数据收集 → 数据准备 → 模型训练 → 模型评估 → 模型部署 → 模型监控
   ↑                                                              |
   └────────────────── 性能退化 / 需要改进 ←──────────────────────┘
```

工程对象不再只是代码，而是代码、数据、模型行为、部署环境和监控证据的共同演化体。

## 部署频谱

物理约束把世界划分为四种部署范式（详见 [[03-机器学习系统]]）：

| 环境 | 主要约束 | 效率焦点 |
|------|----------|----------|
| 云训练 | 成本、吞吐量 | 分布式效率、硬件利用率 |
| 云推理 | 延迟、每查询成本 | 批处理、模型服务优化 |
| 边缘设备 | 内存、功率 | 更小模型、更低数据移动 |
| 移动 | 电池、热 | 能量高效推理 |
| TinyML | KB 级内存、mW 功率 | 极端压缩、专用架构 |

每个部署决策会级联影响整个系统：边缘/嵌入式选择强制模型压缩、限制更新频率；隐私法规可能把计算推向边缘，训练数据需求又拉向云端。典型混合模式：自动驾驶车辆边缘实时感知 + 云端训练，语音助手本地唤醒词 + 云端复杂 NLP。

## 部署案例研究

- **Waymo**：安全关键延迟 + 数据新鲜度。车载感知模型边缘运行（LiDAR 每秒数百 MB 点云），云端大规模训练，构成高风险混合部署；数据漂移（阳光道路训练、暴雪环境运行）是生死攸关的问题。
- **FarmBeats**（微软精准农业）：约束是网络带宽而非算力，TV 白空间联网 + 边缘处理。
- **AlphaFold**：计算密集型云部署，128 个 TPUv3 核心训练数周，依赖蛋白质数据库的精心策划数据。

## 五支柱框架

ML 系统工程围绕五个工程学科组织（对应失败链条的归属边界）：

1. **数据工程**：数据质量、规模、隐私、漂移、血统。
2. **训练系统**：数据集、框架、优化算法、超参数、分布式协调、成本-质量权衡。
3. **部署基础设施**：训练-服务鸿沟、打包、推理性能、设备约束。
4. **运维与监控**：漂移检测、告警、推出策略、事件响应、持续评估。
5. **伦理与治理**：公平、透明、隐私、安全、文档、问责。

四类挑战（数据、模型、系统、伦理）相互勾连：数据漂移退化模型 → 紧张基础设施 → 放大伦理风险。此外还有推理攻击（从模型预测反推训练数据）等安全威胁，激励差分隐私等防御。

## 经验与常见坑

- **谬误：更好的算法自动产生更好的系统。** 准确率高 1% 但违反延迟要求的模型效用为零；工程化良好的简单模型可胜过缺乏基础设施的复杂架构。
- **陷阱：把 ML 系统当作恰好包含模型的普通软件。** 传统测试验证确定性路径，ML 系统需要监控捕获数据漂移和校准失败；只靠 CI/CD 部署的团队在用户可感知之前不会发现沉默退化。
- **谬误：基准高分 = 生产就绪。** 分布偏移和操作差异会导致部署中大幅退化；需要跨亚组失败分析、漂移监控和匹配真实条件的验证协议。
- **陷阱：孤立优化单个组件。** 阿姆达尔定律支配端到端性能：推理从 45ms 降到 15ms，但预处理 60ms + 后处理 25ms 仍在，总延迟只从 130ms 降到 100ms（23% 而非预期的 67%）。团队常发现 50–70% 的优化努力未改善端到端指标。
- **谬误：部署一次无限期运行。** 退化是统计必然：推荐系统 85% 准确率六个月静默降至 80.2%，代码零改动。监控 + 再训练是操作要求，不是可选项。
- **陷阱：以为 ML 专业能力就够。** 五个学科需要算法、软件、系统、运营的集成专业知识；有效团队整合研究者、软件工程师与运营人员。
