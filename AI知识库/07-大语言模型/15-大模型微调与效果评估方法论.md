# 大模型微调流程与效果评估方法论

<p class="note-date">更新于 2026-11-03</p>
> 一句话概括：微调项目 80% 的工作量在数据工程（可用"数字孪生"造语料），效果评估靠人工测评 + 通用测评 + 私有任务三线并行，奖励模型思路可让评估自动化。

## 核心概念

- **数字孪生造数据**：没有数据是常态，方法是用一条种子数据"造出一类数据"——程序生成字段变种 + 模板生成句式变种。
- **三类评估线**：人工测评（最重要）、通用基准测评（防能力劣化）、私有任务测评（自动相似度比对）。
- **评估专家/奖励模型**：把"判断回答好坏"本身训练成一个模型（RLHF 流程第二步的独立化）。

## 核心原理

### 数字孪生语料生成
- 字段变种：用假数据生成库造虚拟人名/电话/地址，字段可组合出复杂地址。
- 句式变种：用模板引擎造同义句式；同义模板可让大模型批量扩写（要求保留 `{{}}` 参数占位）。
- 数据量经验：单一细化能力千级即可；复杂能力（地址抽取、多轮参数提取）每场景 1000-10000 条；可商用模型需要上百次微调迭代。
- 数据格式设计依据：以模型已有的基础 NLP 能力（分词、实体识别、实体关系）为理论依据设计标注模板，让能力组合泛化出新能力——少量样本即可激发。

### 训练监控与调参（经验值）
- 学习率常见区间 2e-5 ~ 5e-5，批次大小按显存资源定。
- 看 loss 曲线诊断：训练/验证损失同步下降 = 正常；训练降、验证不降 = 过拟合（加 L2 正则，`weight_decay` ≈ 0.01）；双双降但很慢 = 提高学习率。
- 流程纪律：先小量数据验证 pipeline 可跑通，再上全量。

### 三线评估体系
| 评估线 | 做法 | 用途 |
|---|---|---|
| 人工测评 | 把最关心的能力做成问题集 + 期望答案（Excel），程序自动回填模型回答，人工打分；线上新问题持续补充进集子 | 衡量业务目标能力，最重要 |
| 通用测评 | MMLU 等公开基准跑分，与微调前对比 | 防基础能力灾难性遗忘；看相对变化，不纠结绝对分 |
| 私有任务 | 自建评测任务配置 + BLEU 等相似度算法 | 只适合有标准答案的问题；配置文件名与任务名必须一致、数据集须含 train/validation 段 |

### 奖励模型（评估专家）设计
- 三种偏好数据格式按场景选：
  - **KTO**（单条二值：符合/不符合）——客观题、数据质量检查；实践证明二值分类优于打分制。
  - **DPO**（A/B 二选一的倾向性）——主观题。
  - **RLHF 排序**（C>D>A>B 全序）——要求最细，数据成本最高。
- 训练方式：不从零训练，基于小模型微调（如用 8B 级模型做安全/质量判别）。
- 两大难点：偏好数据质量（标注噪声导致标签翻转，需要损失平滑）、奖励函数泛化（靠对比学习）。

### 自动化评估细分
- 客观短文本：先抽取关键答案再比对（可用专做答案抽取的微调模型，准确率可达 90%+）。
- 客观长文本：余弦相似度 / BERTScore。
- 主观题：用更强的大模型当裁判，评分提示词按 准确性/一致性/清晰度/详尽度 分维度打分。
- 核心原则：**评分必须多维细分统计**，才能定位问题反馈到数据与训练调整。

### JSON 原子能力
- 对每个问题分类训练"对话 → JSON 参数抽取"，JSON 是 Agent 对接编程体系的关键接口。
- JSON 解析通过率本身可以作为一种量化评估指标。

## 经验与常见坑

- 微调不是"喂公司文档"：文档知识应走 RAG，微调数据应是"输入-理想输出"行为样本。
- 奖励模型标注数据必须多样，否则准确率崩；正负样本标注时错误数据也要放入正例通道、靠内容字段区分，避免分布偏差。
- 私有评测任务的配置目录、任务名、数据集分段都有硬性约定，报错先查这三处。
- 评估不是上线前一次性动作：训练过程中随时评，上线后持续收集坏例回流语料。

## ⚠️ 时效性说明

TRL、Llama Guard 3、xFinder、MMLU、LM-Evaluation-Harness、P-tuning v2 等为 2024 年前后工具/方法名；KTO/DPO/LoRA 等范式与三线评估体系、数字孪生造数法是耐用方法论。
