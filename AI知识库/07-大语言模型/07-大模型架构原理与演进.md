# 大模型架构原理与技术演进

<p class="note-date">核对更新于 2026-11-16</p>
读完这篇，你能从结构、参数和缓存三个角度核算模型的代价，并解释为什么“参数更多”或“上下文更长”不等于更适合自己的任务。基础计算路径见[大语言模型基础](06-大语言模型基础.md)，这里继续看架构选择与工程取舍。

## 核心概念

### 语言模型两大类
- **掩码语言模型 MLM**（BERT，Encoder Only）：双向看上下文，完形填空式，擅长理解；
- **自回归语言模型 ALM**（GPT，Decoder Only）：用上文预测下文，常以原文后续 Token 提供自监督信号。预训练、指令微调与偏好优化是常见能力形成阶段，但不是每个模型必须遵循的一条固定配方，不能仅靠架构推断生成质量上限。

### 演进主线（为什么走到 Transformer）
1. **RNN**：隐藏状态 $h_t = f(W_{xh} x_t + W_{hh} h_{t-1} + b_h)$（$h_t$ 为 $t$ 时刻的隐藏状态，$W_{xh}$/$W_{hh}$ 为输入/循环权重矩阵），循环结构带"记忆"。两大死穴：串行计算无法并行；梯度消失/爆炸导致无法捕捉长距离依赖。
2. **LSTM/GRU**：用门控缓解梯度问题——LSTM 三门：遗忘门（弃旧）、输入门（写新）、输出门（控输出）；设计规律：Sigmoid 常作门控激活。
3. **Seq2Seq（Encoder-Decoder）**：统一"序列进序列出"范式，编码器把源语言投影到高维语义空间，解码器投影回目标空间。死穴：全部输入压进一个固定长度向量，长句丢信息。
4. **Attention 注意力**：解码器每一步对编码器全部输出"私人定制"一个上下文向量（Query 查询 Key/Value），解决长距离依赖。
5. **Transformer**（2017《Attention Is All You Need》）：彻底去掉递归、只用注意力，靠并行训练效率与效果双赢。
6. **Mamba/SSM**（2023）：线性复杂度挑战者（见下）。

## 核心原理

### Transformer 关键构件
- **自注意力三步**：输入线性变换出 Q/K/V → Query 与 Key 点积并除以 $\sqrt{d_k}$（Key 的维度）缩放（scaled dot-product）→ Softmax 归一化成权重（实现时减 max 防溢出）后加权求和 Value。
- **自注意力与交叉注意力**：Attention 是总称；自注意力的 Q/K/V 来自同一序列表示，交叉注意力的 Q 与 K/V 来自不同表示组。两者都通过匹配与汇集利用信息，不能把 Attention 总称仅解释成输入—输出关联。
- **多头注意力**（原始 Transformer 基础配置为 8 头，现代模型并无统一默认值，每头 $d_{\text{model}}/h$，$d_{\text{model}}$ 为模型隐藏维度）：多组同构注意力并行学不同子空间特征，再拼接+线性变换；它扩展可学习的信息汇集方式，不等于多个模型赛马，也不保证减少初始化随机性。
- **位置编码（Positional Encoding）**：RNN 串行自带顺序信息，内容注意力本身不能完整表达位置，需要位置相关设计；因果方向、位置编码和缓存状态不是同一概念。
- **编码器层结构"1+2+1"**：位置编码 + 自注意力层 + FFN 前馈层，每个子层后接 **Add & Norm**（残差连接给梯度开多通路，承袭 ResNet；层归一化稳定训练）。FFN(x) = max(0, xW₁+b₁)W₂+b₂。
- **解码器多一层 Encoder-Decoder Attention**；自注意力用上三角掩码（mask 填 -inf）阻止看到未来词，保证自回归性。末尾 Linear 映射到词表维度 + Softmax。
- 词向量起点：**Word2Vec** 两种架构——CBOW（上下文预测中心词）与 Skip-Gram（中心词预测上下文，罕见词表现更好）；短板是静态向量无法处理一词多义 → **ELMo** 用双向 LSTM 按上下文动态调整词向量（但两方向独立训练仅拼接，非端到端）。

### 参数量与算力估算（训练前的账）
- 参数量：N ≈ vocab×embed（嵌入层）+ [4×embed²（Q/K/V/输出投影）+ 2×embed×FFN隐藏维] × 层数 + vocab×embed（输出层）。例如 vocab=100000、embed=512、hidden=2048、6 层，在输入/输出权重不共享且忽略偏置、归一化参数的此公式下，约 1.21 亿参数；共享权重或采用门控 FFN/MoE 时需改账。
- **Scaling Law**：C ≈ 6ND（FLOPs ≈ 6×参数量×token 数，Decoder-only 前提）；这是训练计算量近似，不是“三者同比例放大”的定律。经验损失规律要与固定算力下模型规模、训练 Token 的最优分配分开讨论。
- 锚点数字：GPT-3 = 96 层 / 175B 参数 / 570GB 过滤后高质量数据（原始约 45TB）；1.2 亿参数 FP32 原始权重载荷约 480 MB（十进制）或 458 MiB，不包括运行内存。

### 规模规律：训练最优不等于部署最优

[Kaplan 等（2020）](https://arxiv.org/abs/2001.08361)在所测范围内拟合参数、数据、训练计算与交叉熵损失的幂律关系，固定预算下倾向较大模型和较早停止。[Hoffmann 等（2022）](https://arxiv.org/abs/2203.15556)重新研究预算分配，发现其计算最优区间内模型参数和训练 Token 应近似等比例增长。两者不是一条“参数、数据、算力同时乘二”的规则：若 \(C \approx 6ND\)，\(N\) 与 \(D\) 各乘二时 \(C\) 约乘四。

此估算忽略注意力随序列长度增长、稀疏路由、数据质量等因素。部署中大量重复推理时，可能值得多训练较小模型来降低长期成本，不能把训练算力最优配方直接当作服务采购结论。

[涌现指标争议研究（2023）](https://arxiv.org/abs/2304.15004)展示了部分跃升可由非连续评价指标产生；它没有证明所有新能力都不存在。比较候选模型时应看同一任务集的逐题表现、成本、时延与失败分布。

### Mamba / 状态空间模型（SSM）
- 动机：自注意力 O(n²·d) 是长上下文的根本瓶颈；RNN 计算快但遗忘长依赖。
- 线性、时间不变 SSM 的一种表示：状态方程 h'(t) = Ah(t) + Bx(t)；输出方程 y(t) = Ch(t) + Dx(t)。部分早期 SSM 设计使用 HiPPO 初始化，离散化方式依实现而定；不能把这些选择概括为所有 SSM 或 Mamba 的统一配置。
- 线性时间不变 SSM 可在卷积与递推表示之间转换。Mamba 的选择性参数依赖输入，不能直接用固定卷积核概括；它通过硬件感知的选择性扫描实现高效计算，推理保留递推状态。
- **选择性 SSM**（Mamba 创新点）：让 B、C、Δ 依赖输入内容，模型可对信息取舍，弥补"小状态"弱于全量注意力的问题。
- 选择性扫描在序列长度上的计算与状态空间有不同于全量注意力的取舍；信息提取、吞吐和内存收益仍需具体任务测试。混合注意力与 SSM 的架构是另一条路线，产品大小或曾否被会议接受都不能代替生产验证。

## 经验与常见坑

1. 参数规模不能代替同任务评测；数据、训练、架构与部署配置都影响结果，不从不同实验的单一总分推导普遍大小排名；
2. Decoder Only 在完形填空上先天劣势，但在生成任务上反成优势——架构选择看任务范式；
3. 代码语料可能提供形式化与结构化学习信号；增益受数据、模型和任务影响，不以“所有主流模型都如此”概括未知训练配方；
4. U 形曲线警示：某个规模上效果变差不等于方向错误；
5. 少样本示例数量受最大上下文长度约束——这是倒逼"更长上下文"演进的根本动力之一；
6. RNN 系（含 Mamba 这类循环形式）推理快但"小状态"压缩历史，全量注意力保留可查询缓存但更昂贵；保留状态不保证模型正确利用信息——长序列选型是权衡而非替代。

## ⚠️ 时效性说明

- Mamba 的生产验证状态、Q*/具身智能等推测性内容仍在快速变化；
- 涌现门槛经验值（68B/100B）基于 2024 年前观察，后续研究对"涌现是否只是度量假象"有争议，作数量级参考。

## 架构演进速查：从 GPT-1 到 MoE 与长上下文

按关键决策点（而非逐年罗列）看架构演进：

- **2018 GPT**：确立 Decoder-Only + 生成式预训练 + 下游微调的三段范式，此后"预训练"成为行业默认起点。
- **2020 GPT-3**：175B 参数 + 上下文学习（in-context learning），考察了不更新参数的少样本任务表现；规模并非唯一变化因素，不能把所有收益归给参数量。
- **2022 Chinchilla**：修正"只堆参数"的路径——计算最优区间内参数与训练 token 应近似等比增长，$$C \approx 6ND$$，$$N$$ 与 $$D$$ 各乘二时 $$C$$ 约乘四。此后"数据质量/数量"与参数规模并列为第一优先级。
- **2023 Llama 2（2023-07-18，Meta × 微软共同宣布）**：开放权重路线确立。开发者可取得权重并商用（附许可条件），开源生态从此有了可依赖的锚点；架构上 RMSNorm、SwiGLU、RoPE 的组合成为其后开源模型的默认配置。
- **2023-12 Mixtral 8×7B**：稀疏 MoE 进入主流开源。每层 8 个 FFN 专家、每 token 选 2 个按路由权重加权——总参数约 47B，激活约 13B。注意两个常被误解的点：路由器处理的是层内隐藏向量而非"问题分类"；"专家"是内部权重组，不是几个完整聊天机器人投票。MoE 改变"每个 token 计算多少"，不直接改变"要存多少内存"。
- **长上下文**：Llama 2 的 4K → Llama 3 的 8K → 3.1 的 128K，社区微调版（llama3-gradient）曾到 1M 级。主流路径是 RoPE 缩放 + 渐进式长文本继续预训练，而非改动注意力结构；上下文变长直接改变应用设计（一次喂整套资料 vs RAG 切片检索的权衡）。
- **多模态**：Llama 3.2 Vision 的"文本模型 + 视觉适配器"路线（图像编码器经 cross-attention 注入）说明：多模态不必从零训练，接入已有视觉表示是一种可行路线；是否成本最低还需计训练、适配和任务效果。

一条贯穿的规律：**架构的大结构（Decoder-Only Transformer）自 2018 年以来基本稳定，演进发生在注意力的工程化（GQA/MQA）、归一化与激活的替换（RMSNorm/SwiGLU）、位置编码（RoPE）、计算稀疏化（MoE）与训练配方（数据配比 + 后训练）**。读新模型发布时，先找这五个维度相对前代的差异，比记参数量更有解释力。


## 注意力工程与 KV 缓存：长上下文的真实约束

推理瓶颈取决于权重规模、序列、批量、硬件和执行阶段，可能是矩阵计算、权重读取或 KV 访存。先分别测 Prefill 与 Decode，再判断该减少输入、改缓存、调整批量还是更换运行配置。

### KV 缓存为什么吃显存

自回归生成时，已生成 token 的 Key/Value 必须保留供后续注意力查询。常规全量 K/V 载荷约为 `2 × 层数 × KV头数 × 头维度 × 序列长度 × batch × 每元素字节`，2 对应 K 和 V 两份。它不含权重、临时张量或分配开销；滑窗、量化和潜在缓存需另算。序列翻倍、batch 翻倍都会线性放大它——这就是"上下文长度"直接换算成钱的机制，也是长上下文模型推理更贵、更难部署的原因。

### 变体谱系：压缩 KV 的三条路

| 变体 | 做法 | 代价 |
|---|---|---|
| MQA（Multi-Query） | 所有查询头共享 1 组 KV | 常规载荷可按原 KV 头数比例缩小；质量变化需任务评估 |
| GQA（Grouped-Query） | 查询头分组共享 KV（Llama 2 70B/3 全系采用） | 设查询头 h、KV头 g，常规载荷相对多头KV约为 g/h；质量和速度需实测 |
| MLA（Multi-head Latent Attention，DeepSeek V2/V3） | 用潜在表示压缩缓存，具体实现可通过吸收投影等方式避免每步完整展开 | 压缩率更高；实现复杂，配合 RoPE 需专门处理 |

注意：**GQA/MLA 减少的是缓存与带宽，不减少注意力计算量级**；长序列下注意力的平方复杂度仍需稀疏注意力、滑动窗口等手段配合（各家长上下文方案通常是 RoPE 缩放 + 分层/稀疏注意力 + 渐进式续训的组合拳）。

### 读写缓存与提示词缓存

- **Prefill 与 Decode 是两个阶段**：Prefill（处理输入，计算密集，可并行）与 Decode（逐 token 生成，访存密集）。首 Token 时间还包含排队、网络和其他前处理；Decode 吞吐还受批量、权重访存与缓存策略影响——API 定价与性能优化都围绕这两个阶段分别设计。
- **提示词缓存（prompt caching）**：相同前缀（系统提示、长文档）的 KV 只算一次、复用多次，是否命中、保留时长与价格取决于服务，不承诺固定折扣。应用设计应把稳定内容前置、动态内容后置，主动制造可缓存前缀。

选型检查单：问清上下文窗口内的有效利用率（中间信息是否被用上）、并发下的 KV 显存上限、是否支持前缀缓存与计费折扣——这三项比单看"支持 128K"更能预测真实成本。
