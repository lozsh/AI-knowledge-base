# 大语言模型

> 来源：原资料（wiki 化重写于 2026-11-03）

**一句话定义**：大语言模型（Large Language Model，LLM）是参数量达数十亿以上、在数 T token 语料上预训练的语言模型，以**涌现能力、上下文学习、指令遵循、逐步推理**四大能力区别于传统预训练语言模型（PLM），通过 Pretrain → SFT → RLHF 三阶段训练而成。

2022 年底 ChatGPT 刷新 NLP 能力上限后，LLM 开始接替传统 PLM 成为 NLP 主流，基于 LLM 的新研究范式正在刷新 BERT 发扬光大的预训练-微调范式。一般认为 **GPT-3（175B 参数）是 LLM 的开端**，基于 GPT-3 经三阶段训练得到的 ChatGPT 主导了 LLM 时代的到来。广义上，只要模型展现出涌现能力（在复杂任务上远超 BERT/T5 等传统模型的能力与潜力），从十亿级（如 Qwen-1.5B）到千亿级（如 Grok-3 414B）都可称为 LLM。

ChatGPT 发布后一年内涌现了大量 LLM：开源侧有 LLaMA、MOSS、Alpaca/Vicuna、ChatGLM、通义千问、BaiChuan、LLaMA2、Yi、DeepSeek 等；闭源侧有 GPT-4、文心一言、Claude、Bard、星火、混元、Gemini、豆包、Grok 等。

## 核心能力

### 涌现能力（Emergent Abilities）

区分 LLM 与传统 PLM 最显著的特征：**同样的模型架构与预训练任务下，某些能力在小模型中不明显、在大模型中特别突出**——类似物理学的相变，量变引起质变，模型性能随规模增大迅速跃过随机水平。这是业界对 LLM 保持高度热情的核心：尽管 LLM 与通用人工智能（AGI）尚有差距，但涌现能力的存在让人相信随着数据、架构与训练框架的进步，LLM 终能具备 AGI 所需能力。

### 上下文学习（In-context Learning）

由 GPT-3 首次引入：提供自然语言指令或少量任务示例，模型理解上下文即完成任务，**无需额外训练或参数更新**。对比传统 PLM：BERT 类模型（0.5B）微调需 10G+ 显存，且需人工标注 1k~数 10k 训练样本。具备此能力后，NLP 范式从"预训练-微调"转向 **Prompt Engineering**——目前大部分任务通过调整 Prompt 或给 1~5 个示例，GPT-4 即可超过传统 PLM 微调的效果。

### 指令遵循（Instruction Following）

通过**指令微调**（用自然语言描述的多任务数据微调），LLM 能理解并执行**未见过的**指令，无需事先见过具体示例，展现强泛化。ChatGPT 的高热度核心正在于此：写作文、编程序、批改试卷、读报纸皆可。当前的 Agent、Workflow 乃至未来的全能助理，本质都依赖这一能力。

### 逐步推理（Step by Step Reasoning）

多步复杂推理（如数学题）一直是 NLP 难关。LLM 通过**思维链**（Chain-of-Thought，CoT）——在提示中包含中间推理步骤——可解决此类任务。据推测这种能力可能来自对代码的训练。它使 LLM 能处理需要逻辑判断的日常问题，向"可靠智能助理"迈出坚实一步。

## 主要特点

- **多语言支持**：预训练语料本身是多语言的，LLM 天生具备跨语言能力；但英文高质量语料占大头，GPT-4 等英文能力显著强于中文，针对中文优化的国内模型（文心一言、通义千问等）在中文上更优。
- **长文本处理**：传统 PLM 以 512 token 为上限惯例；LLM 训练时即支持 4k/8k/32k，且普遍采用**旋转位置编码 RoPE**（或同样可外推的 AliBi），具备**长度外推**能力——如 InternLM 以 32k 预训练却可处理 200k 上下文。
- **拓展多模态**：为 LLM 增加 Adapter 层与图像编码器，在图文数据上有监督微调，即可获得不错的图文问答甚至生成能力；如何对齐文本与图像表示、辐射更多模态是重要方向。
- **挥之不去的幻觉**：LLM 会根据 Prompt 杜撰虚假信息（如捏造"一本正经"的论文和参考文献）。这是固有缺陷，在医学、金融等强调精准的领域后果严重。Prompt 限制、RAG（检索增强生成）等手段只能削弱、无法根除。

## 三阶段训练

训练完整 LLM 需经过 **Pretrain（预训练）→ SFT（有监督微调）→ RLHF（人类反馈强化学习）**。可类比学生：Pretrain 教基础知识，SFT 教读题解题，RLHF 是真正的刷题练习。

### Pretrain

最核心也是工程量最大的阶段，使用海量无监督文本训练随机初始化的参数；主流 LLM 采用 Decoder-Only 类 GPT 架构（LLaMA 架构），预训练任务沿承 CLM（因果语言模型：给上文预测下一个 token）。

与传统 PLM 的差异在于**体量**：

| 模型 | 层数 | hidden_size | 注意力头数 | 参数量 | 预训练数据量 |
|---|---|---|---|---|---|
| BERT-base | 12 (Encoder) | 768 | 12 | 0.1B | 3B token |
| BERT-large | 24 (Encoder) | 1024 | 16 | 0.3B | 3B token |
| Qwen-1.8B | 24 (Decoder) | 2048 | 16 | 1.8B | 2.2T token |
| LLaMA-7B | 32 (Decoder) | 4096 | 32 | 7B | 1T token |
| GPT-3 | 96 (Decoder) | 12288 | 96 | 175B | 300B token |

**数据量估算——Scaling Law**：OpenAI 提出计算量 C ~ 6ND（N=参数量，D=token 数），实验推出训练 token 数约为参数的 **1.7 倍**（175B 的 GPT-3 配 300B token）；LLaMA 进一步主张 **20 倍** token 最优（同样 175B 可配 3.5T token）。

**算力与分布式训练**：百亿级 LLM 需 1024 张 A100 训一个多月，十亿级也需 256 张 A100 训两三天。分布式训练两大思路：

- **数据并行**：模型单卡放得下但 batch 拉不大、数据太多——模型实例跑在多卡多批数据上，每次前向后汇总梯度、统一更新再同步；每卡参数一致，总 batch = 各卡 batch 之和；
- **模型并行**：模型大到单卡放不下——把模型拆到多卡，每卡存放不同的层或部分。

在两者基础上演化出**张量并行、3D 并行、ZeRO** 等。主流框架：**DeepSpeed**（使用面最广）、Megatron-LM、ColossalAI。DeepSpeed 核心策略是 **ZeRO + CPU-offload**。训练时每卡显存分两类：模型状态（参数+梯度+Adam 状态；混合精度下 1M 参数约需 16M 空间，其中 Adam 占 12M）与剩余状态（激活值、缓存、显存碎片）。ZeRO 三级递进分片：

1. **ZeRO-1**：只分片 Adam 状态参数；
2. **ZeRO-2**：继续分片模型梯度（仅参数每卡一份）；
3. **ZeRO-3**：参数、梯度、Adam 状态全部分片。

分片越多每卡显存越省，但通信开销越大——每卡 GPU 利用率 ZeRO-1 最高、ZeRO-3 最低，需按资源与模型体量动态选择。

**预训练数据**：LLM 知识绝大部分来自预训练，语料需多来源按比例混合——**数据配比是预训练的"核心秘籍"**。主要开源语料：CommonCrawl、C4、Github、Wikipedia 等。LLaMA 配比：

| 数据集 | 占比 | 磁盘大小 |
|---|---|---|
| CommonCrawl | 67.0% | 3.3 TB |
| C4 | 15.0% | 783 GB |
| Github | 4.5% | 328 GB |
| Wikipedia | 4.5% | 83 GB |
| Books | 4.5% | 85 GB |
| ArXiv | 2.5% | 92 GB |
| StackExchange | 2.0% | 78 GB |

⚠️ 中文语料难度更大：高质量语料集中于英文；中文开源预训练数据仅有昆仑天工 SkyPile（150B）、中科闻歌 yayi2（100B）等，与英文差距明显。

**数据清洗流程**（质量往往比体量更重要）：

1. **文档准备**：URL 过滤（滤有害内容）、文档提取（HTML 提纯文本）、语言选择；
2. **语料过滤**：去除低质量/有毒内容。两种方法——基于模型（高质量语料训练分类器）或基于启发式（人工定义质量指标打分）；
3. **语料去重**：大量重复显著损害泛化能力。基于 hash 算文档/跨数据集相似性、超阈值去除；或按子串在序列级精确匹配去重。

实例：RedPajama-1T（按 LLaMA 思路收集清洗）与其筛选去重版 SlimPajama-627B——实验证明 627B 高质量数据效果反而好于 1T 全量。

### SFT（Supervised Fine-Tuning）

预训练赋予能力但不激发：预训练后的 LLM 像"博览群书又不求甚解的书生"，只会顺着接下文，不懂指令含义——因为预训练任务就是 CLM 预测下一个 token。SFT 教它"如何使用知识"。

区别于传统 PLM 对每个下游任务单独微调，LLM 的 SFT 训练的是**通用指令遵循能力**（指令微调）：输入是各种用户指令，拟合输出是期望回复。要点：

- **数据量与覆盖面**：单个任务 500~1000 样本即可有不错的微调效果；但要泛化到多种任务指令，需覆盖多类型指令且数据量较大，表现良好的开源 LLM SFT 数据一般在数 B token 量级；
- **配比**：InstructGPT（ChatGPT 前身）使用来自 API 用户行为的十类指令——文本生成 45.6%、开放域问答 12.4%、头脑风暴 11.2%、聊天 8.4%、文本转写 6.6%、文本总结 4.2%、文本分类 3.5%、其他 3.5%、特定域问答 2.6%、文本抽取 1.9%；
- **数据来源**：人工标注成本极高（ChatGPT 的成功很大程度源于高质量人工标注），罕有企业开源；替代方案是用 ChatGPT/GPT-4 生成指令数据集，如经典开源指令集 **Alpaca**（基于种子 Prompt 让 ChatGPT 扩写指令并生成回复）。

**数据格式**：指令数据集一般含三个键——`instruction`（用户指令）、`input`（补充输入，可空）、`output`（期望回复）。示例：

```json
{"instruction": "将下列文本翻译成英文：", "input": "今天天气真好", "output": "Today is a nice day！"}
```

SFT 通常套用特定模板（LLaMA 格式）：`### Instruction:\n{content}\n\n### Response:\n`，content 为指令与输入的拼接。注意指令微调本质仍是 **CLM 训练**：模型预测的是 input+output 整体，只是 input 部分不计 loss。

**多轮对话**：模型的多轮对话能力**完全来自 SFT**（与预训练无关），需把数据构造成多轮对话格式。对 `<prompt_1><completion_1>...<prompt_3><completion_3>` 有三种构造方式：

1. 只拟合最后一轮回复、前面全作为输入（丢失大量中间信息）；
2. N 轮拆成 N 个样本（大量重复计算）；
3. 一次预测**每一轮**的回复：`[MASK]<completion_1>[MASK]<completion_2>[MASK]<completion_3>`——最优方案。

方式三之所以可行，是因为 CLM 单向注意力从左到右依次拟合，前轮输出的预测不影响后轮。目前绝大部分 LLM 的 SFT 都采用多轮对话形式。

### RLHF（Reinforcement Learning from Human Feedback）

从功能上，LLM 训练可分**预训练**（赋予知识）与**对齐**（alignment，让模型与人类价值观一致，达到安全、有用、无害）两阶段：SFT 对齐指令，RLHF 从更深层次对齐价值观——它被认为是 ChatGPT 相较 GPT-3 的最核心突破。

**第一步：训练 RM（Reward Model，奖励模型）**。RM 拟合人类偏好，对 LLM 的每个回复输出标量奖励，本质是一个文本分类模型（LLM/BERT 架构 + 分类层，取隐藏层输出而非分类输出）。

关键细节：**不直接用文本对应标量奖励训练**——标注者之间有价值观差异，标量数值会放大差异导致难以拟合。因此对同一 prompt 下的不同**回复做排名，再转化为奖励**。训练数据形如：

```json
{"prompt": "问题", "chosen": "符合人类偏好的回答", "rejected": "不符合偏好的回答"}
```

训练时 prompt 分别与 chosen/rejected 拼接前向得到两个标量奖励，通过**最大化两者差异**计算 loss。RM 与最终 LLM 大小可以不同（OpenAI 用 175B LLM + 6B RM）；RM 可由 SFT 后的 LM 初始化，也可用偏好数据从头训练，哪种更好尚无定论。

**第二步：PPO 训练**。PPO（Proximal Policy Optimization，近端策略优化）是最适合 RLHF 的经典 RL 算法（成熟、成本低）。训练时**同时存在四个模型**：

- **Actor Model**（参数更新）与 **Ref Model**（参数冻结），均从 SFT 后的 LLM 初始化；
- **Critic Model**（参数更新）与 **Reward Model**（参数冻结），均从训练好的 RM 初始化。

流程：输入 Prompt → Actor 与 Ref 分别生成回复 → 计算两者输出的 **KL 散度** → Actor 回复再送入两个 RM 打分（Reward Model 输出标量奖励，Critic Model 额外输出从位置 i 到最后的累积奖励）→ 由 KL 散度与打分合成奖励函数（β 控制 KL 散度权重、γ 控制下一步打分权重）→ 分别计算 actor loss 与 critic loss，更新 Actor 与 Critic 参数（两者更新方法不同）。

保留参数冻结的 Ref/Reward Model 的目的：**限制模型更新不过度偏离原模型**，防止丢失 Pretrain 和 SFT 赋予的能力。四模型并行导致显存数倍于 SFT——RM 与 LLM 均为 7B 时，PPO 约需 240G 显存（4 张 80G A100，每卡约 60G），门槛极高。

**DPO 平替**：DPO（Direct Preference Optimization，直接偏好优化）把 RLHF 的强化学习问题**转化为监督学习**直接学习人类偏好——通过奖励函数与最优策略间的映射，证明约束奖励最大化可由单阶段策略训练优化，无需训练 RM、无需强化学习。只需两个 LLM 即可训练，过程远比 PPO 简单，是 RLHF 更易用的平替版本。

## 经验与常见坑

- **SFT 的 loss 掩码**：指令微调仍是对整段 input+output 做 CLM，只是 input 部分不计 loss——实现时漏掩码会让模型"学着复述指令"；
- **多轮对话样本构造**：选"一次预测每轮回复"的方式，另外两种要么丢信息、要么浪费算力；
- **RLHF 显存账**：PPO 四模型同台，显存约是 SFT 的数倍，资源紧张时优先考虑 DPO；
- **数据质量 > 数据体量**：预训练（SlimPajama 627B 胜 RedPajama 1T）与 SFT（高质量人工标注是 ChatGPT 成功关键）两侧都被反复验证。
