# 检索增强生成（RAG）：朴素 RAG、GraphRAG 与评估

/> 来源：公开课程资料自学整理（整理于 2026-11-03）
> 一句话概括：RAG 一体两面——对 AI 搜索是信息整合管线，对智能体是外部记忆；朴素"切片+向量检索"必然丢语义，演进方向是图谱化索引、闭环反馈和体系化评估。

## 核心概念

- **RAG（检索增强生成）**：先从外部知识库检索相关内容，再由大模型据此生成回答，弥补预训练知识的时效与领域缺口。
- **知识冲突规则**：RAG 注入的上下文与预训练知识冲突时，**模型默认优先提示词内容**——所以注入的信息本身必须准确，错误注入 = 错误传播。
- **GraphRAG**：用 LLM 从文本抽取三元组构建知识图谱，结合社区摘要做检索，替代纯切片向量检索。
- **三元组（Triple）**：（主语-谓语-宾语）的结构化知识表示，知识图谱的基本单元。
- **本地搜索 / 全局搜索**：GraphRAG 两种策略——围绕具体实体的局部检索 vs 基于社区摘要回答宏观问题。
- **忠实度（Faithfulness）**：生成内容与检索到的原始信息的一致程度，RAG 评估第一维度。
- **RAG 一体两面**：对 AI 搜索是信息整合，对智能体是外部记忆。

## 关键方法/原理

### 1. 朴素 RAG 五步（基线）
①文档分割（固定长度/按逻辑，平衡 chunk 大小）→ ②嵌入生成（选对模型）→ ③向量存储（Faiss/Milvus/Chroma，HNSW 索引）→ ④检索（查询同模型嵌入，余弦相似度 top-k）→ ⑤生成（检索片段 + 查询拼提示词）。

**为什么准确率低**：切片导致语义碎片化、多义词歧义（"cloud"）、缺乏跨文档全局视角。

### 2. GraphRAG：智能索引
- 构建：LLM 做实体识别（名称/类型/描述）→ 关系识别（实体对 + 关系描述 + 1–10 强度分）→ 统一格式输出三元组（微软 GraphRAG 提示词模板：Goal + Steps + Examples）。
- 社区划分：层次聚类（Leiden 算法）把图谱切成主题社区，每社区生成摘要；**宏观问题直接查摘要**，不逐字检索。
- 适用判断：需要跨文档全局综合、复杂关系推理 → GraphRAG；纯事实点查 → 普通向量检索即可。

### 3. 准确性提升手段
- **来源透明**：用向量库元数据（标题/作者/日期/URL）随生成内容附引用，可验证、可追责。
- **反馈闭环**：用户赞/踩动态调整文档质量分（高/中/低质量集合，检索优先高质量）；高质量历史问答（query-answer）单独成一路召回索引——本质是把用户反馈变成 few-shot 学习。
- **隐式反馈**：用户不点赞踩时，把历史对话喂给 LLM 推断满意度，自动补全反馈标签。
- **AI 搜索四阶段管线**：查询预处理（分词、NER、意图分析）→ 信息检索（BM25 关键词 + 向量 ANN + 外部知识库多路）→ 上下文整合（重排、筛选、可信度验证）→ 生成。

### 4. RAG 评估方法论
- 三维度 LLM 打分（1–10 + 解释）：**忠实度**（生成 vs 检索文档逐句比对）、**倾向性**（是否答非所问/偏离意图）、**上下文一致性**（多轮对话逻辑连贯）。
- **层级评估策略**：用更强的模型（或多角色多步推理）评估较弱模型，破解"运动员兼裁判员"悖论。
- 成本逻辑：评估数据量远小于在线推理量，离线评估可用更大模型。
- 业界成熟框架是 **RAGAS**（忠实度/答案相关性/上下文精确率等指标），课程为自建 prompt 打分。

## 经验与常见坑

- 切片向量检索是 RAG 准确率低的主因之一——先排查 chunk 策略，再怀疑模型。
- 图谱构建中的实体识别不必用大模型：小模型更省资源、更稳定；大推理开销集中在社区划分和全局搜索，需监控性能。
- 静态知识图谱会过时，必须配自动化更新机制。
- 注入上下文即"最高优先级事实"：来源校验是生成前的最后一道闸。
- 用 LLM 评 LLM 有自评悖论：必须更强评更弱，或多角色评单角色，或人类标注 + 在线反馈兜底。
- 检索缺失时不要硬答：让 LLM 明确说"资料库中没有"，或触发智能补全流程。
