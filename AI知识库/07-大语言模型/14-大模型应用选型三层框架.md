# 大模型应用选型与项目落地决策：三层框架与商业分析

<p class="note-date">更新于 2026-11-05</p>
> 一句话概括：企业落地大模型先在"应用开发 → 微调 → 专有模型"三个层次中由浅入深选型，最大成本在数据而非算法；用户只为结果付费，token 成本杀死免费模式。

## 核心概念

大模型 AI 项目开发的三个层次（由轻到重）：

| 层次 | 手段 | 成本量级 | 适用 |
|---|---|---|---|
| 应用开发 | 调 API + 提示词工程 + RAG | 普通工程师即可 | 绝大多数场景，默认首选 |
| 微调 | 平台微调 / 开源模型 LoRA | 数千到数万条数据 + 训练算力 | 应用层遇到明确瓶颈时 |
| 专有模型 | 开源基座二次训练（行业大模型）/ 推理代码改造 | 500-1000 万起步（数据+算力+团队） | 行业壁垒型核心业务 |

应用开发的两种模式：
- **AI first**：以大模型为中心的会话式应用，适合从零创新的业务。
- **传统应用 + AI**：在成熟业务里嵌入翻译、分类、摘要等能力。

一个有用的类比：LLM 像一个全能数据库，**一个提示词就是一个接口**——定义了输入输出契约。

## 关键方法/模式

### 选型决策树（是否升级层次）
微调只在出现以下信号时启动，切忌"拿着锤子找钉子"：
1. 需要品牌自我认知（让模型以特定人设/身份回答）；
2. 意图识别、ReAct 参数抽取中存在提示词反复调都解决不了的 case；
3. 分类规模很大（上百类）时意图识别偏差明显。

微调的本质：**调整模型的单项能力，而不是灌知识**。知识类需求优先 RAG。

### RAG vs 微调（最常见的选型误区）
- 向量数据库（RAG）常常效果比微调好，且知识更新成本低（改文档即可，不用重训）。
- **时效性/频繁变化的数据（库存、价格、订单）绝不能靠微调**，只能 RAG 或查库。
- 微调解决的是"行为方式"（格式、风格、任务能力），RAG 解决的是"事实内容"。

### 专有模型的两种路线
- **行业大模型**：选开源基座 + 灌行业数据。两个核心投入：选对基模型、制高质量领域数据集。
- **插件开发**：不改权重，改推理代码赋予搜索/执行等能力，靠意图识别微调支撑。

### 分层微调架构
- 专有问题数据 = 私有函数；领域基础数据集（如电商的商品/评论/订单语料）= 底层函数。
- 先训领域基础能力，再训专有能力，类似软件的分层依赖。

### ToB 项目前期分析框架（建筑行业 AI 设计案例）
1. 先验证大模型与该行业数据结构的适配性——看底层格式：结构化文本 > 图片（类比 HTML 之于网页）；
2. 用提示词低成本模拟微调做能力实验：小数据 + 小任务先验证模型的学习能力，再决定投入；
3. 开发路线：小模型小数据起步 → 验证 → 放大。

### 成本结构认知
- **数据获取与标注才是最大成本和致命难点**（案例：1 万张标注图、标注成本 50-100 万、GPU 并行训练一次数百万），算法反而其次。
- 博士团队的真正作用是读论文、复现前沿——只有做有创新性的行业模型才需要。

### 应用期成本控制与优化清单
- **先压输出再压输入**：输出 token 单价更高，压输出比压输入更省；用 tokenizer 预估成本，简化输入可省约 50% token。
- **上下文与缓存**：长对话定期总结压缩历史；相似查询做缓存（精确缓存 + 语义缓存，见[应用开发核心模式](11-LLM%E5%BA%94%E7%94%A8%E5%BC%80%E5%8F%91%E6%A0%B8%E5%BF%83%E6%A8%A1%E5%BC%8F%EF%BC%9A%E5%B5%8C%E5%85%A5%E3%80%81%E8%AF%AD%E4%B9%89%E6%A3%80%E7%B4%A2%E4%B8%8E%E6%8F%90%E7%A4%BA%E5%B7%A5%E7%A8%8B.md)）；分段生成逐段校验。
- **模型级联**：便宜模型做粗活（抽取、分类），贵模型做精炼/审核/复杂推理；还可用贵模型当裁判建质量基准，再反哺小模型筛选。
- **限流与调度**：RPM/TPM 多维限流同时生效；指数退避要带随机化；读响应头剩余额度主动调度；非实时任务走批处理通道；小任务合并请求。
- 提示词层的省钱技巧（简化输入、删冗余、收窄职责）见[提示词设计方法论](../18-%E6%8F%90%E7%A4%BA%E8%AF%8D%E5%B7%A5%E7%A8%8B%E4%B8%8E%E5%AE%9E%E8%B7%B5/01-%E6%8F%90%E7%A4%BA%E8%AF%8D%E8%AE%BE%E8%AE%A1%E6%96%B9%E6%B3%95%E8%AE%BA%EF%BC%9A%E4%BB%8E%E7%BB%93%E6%9E%84%E5%8C%96%E6%8F%90%E9%97%AE%E5%88%B0%E5%9C%BA%E6%99%AF%E8%90%BD%E5%9C%B0.md)。

### 项目类型二分与成功规律（100 个 AI 创业项目观察）
| 类型 | 特征 | 成功率 |
|---|---|---|
| 传统型（AI 升级） | 已有业务和用户，用 AI 提效 | 高。如论文降重：抓住细分头部需求直接收费 |
| 创新型（追风口） | 从零造需求 | 低。必须"听起来惊艳且用起来惊艳"，缺一即死 |

五条规律：
1. **用户只为结果付费**，效率要有量级（百倍级）提升才成立；
2. **大模型 token 成本杀死免费模式**——与互联网"免费获客"打法的本质差异，每次调用都有边际成本；
3. 个人/小团队应选**足够细分的赛道深挖**（案例：小红书爆文 = 生成工具 + 社群课程服务 + 人机结合编辑器）；
4. 近乎完美的模式特征：结果可复用缓存 + 生成内容做 SEO 反哺获客 → 边际成本趋零；
5. AI 的价值 = 软件价值 × 效率价值，真正的价值点常在**内部运营提效**，而非预想的外部炫酷场景。

### 落地流程要点
- 先用最低成本手段（提示词实验）验证能力边界，再决定技术层次；
- 需求方最在意的往往不是自动化程度，而是**可干预、可修正**（保留人工空间）；
- 交付后建立坏例收集机制，数据飞轮持续改进。

## 经验与常见坑

- "向量库比微调好"是高频反直觉结论：很多团队微调失败后改 RAG 才达标。
- 微调数据里混入会过期的业务事实，会导致模型上线即过时——事实性内容永远外置。
- 有存量系统的企业慎用 Agent 托管平台：数据私有化难、存量功能要重写、双重成本，往往倾向自研。
- 低估行业数据工程难度是大模型 ToB 项目失败的头号原因；合同报价时数据成本常被严重漏估。
- "AI 嵌入原有工作流"比"AI 重造工作流"成功率高得多——存量流程里有信任和责任结构。
- 免费试用策略在 LLM 产品上要谨慎设计：每次调用都是真金白银。

## ⚠️ 时效性说明

ChatGLM/Qwen、讯飞星火 3.5、Coze、Dify、LLaMA-Factory 等为 2023-2024 年产品示例；具体标注单价、训练费用会随行业变化。三层选型框架、决策条件、成本结构逻辑（数据 > 算法、token 边际成本）是耐用结论。
