# 推理增强与多智能体：思维链谱系与 Agent 设计

<p class="note-date">更新于 2026-11-03</p>
> 一句话概括：推理增强有一条清晰的方法论谱系——CoT 线性分步 → Self-Consistency 频率投票 → ToT 树搜索 → ReAct 行动反馈闭环；多智能体则是把这条谱系拆成角色分工、记忆与护栏的工程学。

## 核心概念

- **思维链（CoT, Chain of Thought）**：用"Let's think step by step"等提示引导模型分步推理，避免直接跳结论出错；结构未必是线性链，可为树状/并行分支。o1 类推理模型即 CoT 的产品化。
- **Self-Consistency（自洽性/频率增强）**：同一问题多次推理，按答案出现频率取众数，本质是集成学习的特例。
- **ToT（Tree of Thoughts，树状思维链）**：在明确定义的问题空间内系统化树搜索——生成子节点、评估打分、择优、回溯剪枝；不是"把 CoT 画成树"那么简单。
- **ReAct**：推理（Thought）→ 行动（Act）→ 观察（Observation）循环，用环境反馈驱动下一步决策。
- **上下文学习（ICL, In-Context Learning）**：通过提示词中的指令+示例激活预训练模型的迁移学习能力，无需更新参数。
- **Reflexion（自我反思）**：任务失败后生成语言化的失败诊断与新计划，存入记忆供下轮使用，实现自我进化。
- **单一职责原则（多智能体）**：每个智能体只负责一个任务、持有独立上下文。
- **种子记忆（Seed Memory）**：写进系统提示词的关键信息（人设、行为规范），保证智能体多轮交互不偏航。
- **FSM（有限状态机）**：把多步任务流程建模为状态+转换规则，LLM 只负责自然语言 ↔ 结构化 JSON 的转换，状态转移由确定性代码执行。

## 关键方法/原理

### 1. 多步推理增强谱系（演进逻辑）
| 方法 | 机制 | 局限 |
|---|---|---|
| CoT | 线性分步推理 | 一步错步步错，无回溯 |
| Self-Consistency | 多次生成 + 频率投票（配高温采样增加路径多样性） | 搜索无序、纯靠算力换准确率、无回溯 |
| ToT | 生成候选 → 评估 → 择优 → 回溯剪枝 | 要求问题可形式化为问题空间（路径规划、24点、博弈） |
| ReAct | 行动后观察与预期差异，动态调整 | 依赖工具质量与环境反馈 |

- Self-Consistency 提取答案应取**最后一个数字**（中间数字多为推理过程值）。
- 长文本与推理的关系：长上下文中 LLM 指令理解能力显著下降，与 CoT"分解聚焦"正好互补——能检索/拆解解决的别硬塞全文（自注意力 O(n²)，成本平方级增长）。

### 2. 上下文学习的本质
- 少样本（Few-shot）= 指令确认任务 + 示例代替微调，是高性价比的迁移学习。
- **认知盲区**：零样本能力来自指令微调数据中"仅指令无示例"的样本——真正的 ICL 机制藏在零样本背后。
- 提示词设计最基础的工作：**明确区分"指令"与"示例"**。

### 3. 多轮对话状态管理
- 两个筛选维度：**近时性**（优先最近记录）与**相关性**（只留与当前任务相关者，需检索配合）。
- **对话压缩**：触发条件（如每 10 轮）后用 LLM 生成历史摘要，保留数字/地点等关键实体。
- **混合架构**：LLM 负责 NL↔JSON 转换，FSM 负责确定性状态转移——比"全交给 LLM"可靠得多。

### 4. 智能体的记忆系统（斯坦福 AI 小镇方案）
- **Reflexion 三角色**：Actor（执行，带记忆）、Evaluator（打分给奖励）、Self-Reflection（依奖励 + 轨迹 + 长期记忆生成语言化反馈）。
- **记忆流（Memory Stream）**：按时效性、重要性、相关性三维归一化加权评分筛选历史（示例权重 3:2:0.5），取 top-k，检索后更新最后访问时间。
- **反思树（Reflection Tree）**：叶节点为具体事件、非叶节点为抽象总结；事件累积到阈值触发反思，生成带证据引用的高层见解，原始细节归档。

### 5. 多智能体系统设计
- **为什么不用超级单体**：权限控制（ACL/RBAC 隔离敏感数据）、多方协作、上下文隔离减少记忆负担、职责清晰便于调试。超级单体的问题：上下文越长效率越低、出错难定位、权限过宽。
- **设计六步**：明确需求拆模块 → 设计人设（使命/专业领域/技能集，职责无交叉）→ 配置护栏 → 构建通信机制（消息队列/共享内存/事件驱动）→ 测试优化 → 上线监控。
- **种子记忆**写进系统提示词，含行为规范与语言风格，防角色漂移——没有坚固人设，长期工作中必然偏离。
- 各智能体在彼此眼中是"工具"——多智能体协作的通信本质仍是函数调用。

### 6. 具身智能（VLA）
- **VLA（视觉-语言-动作模型）**：视觉编码器 + 语言编码器 + 动作解码器协同，实现"感知 → 推理 → 物理行动"闭环。开源代表 OpenVLA（7B）。
- 行业判断：语言数据枯竭、token 边际收益递减，下一步增量在多模态/空间/动作智能；合成数据只能缓解、不能根治。

## 经验与常见坑

- 与其费力用提示工程哄模型给答案，不如让它调工具动态取数。
- 结构化输出（JSON）是能力质变：模型能稳定出 JSON 才能嵌入现有系统。
- 基础版与 Instruct 版用途不同：续写用 base，指令/对话/工具用 Instruct。
- 护栏不能只靠提示词：需规则引擎/策略表定义边界 + 日志监控 + 异常回滚，高风险行业（金融等）尤其必要。
- 推理增强的代价都是算力：SC 靠多次采样、ToT 靠树搜索——先评估任务价值再上重武器。

## ⚠️ 时效性说明

- 本篇实验以 LLaMA 3（8B-Instruct，8K 上下文）为载体；o1 类推理模型发布后，"推理时计算扩展"（test-time compute scaling）已成主流方向，CoT 从提示技巧升级为训练目标——谱系中的 SC/ToT 在强推理模型上需重新评估必要性。
- 记忆流/反思树参数（权重 3:2:0.5、触发阈值）来自斯坦福 AI 小镇论文的实验设置，是示例值不是标准。
