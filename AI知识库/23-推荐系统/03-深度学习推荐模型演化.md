# 深度学习推荐模型演化谱系

/> 来源：公开课程资料自学整理（整理于 2026-11-03）
> 一句话概括：推荐模型沿着"人工特征工程 → 自动特征交叉 → 深度表达 → 模拟用户行为过程（注意力/序列/强化学习/图）"的主线演进，每代模型都是对上一代某个具体短板的回应。

## 核心概念

- 推荐系统经典架构：**挖掘 → 召回 → 排序（融合）**。召回负责从百万级物品筛到几百级，排序对候选统一打分。
- **深度学习带来两大革命**（王喆总结）：① 强拟合能力——MLP 可拟合任意函数，解决点积/线性模型的欠拟合；② 结构灵活性——可用模型结构直接模拟注意力、兴趣演化等用户行为过程。
- **Embedding 是深度学习推荐模型的基石**：矩阵分解的隐因子向量、Word2vec 词向量、各类 2vec 本质同源——把高维稀疏 one-hot 压成几十到上百维稠密向量，且隐含相似度语义。
- 评价排序用 **AUC**（模型把正样本排在负样本前面的概率，0.5 为随机）；但 Wide&Deep 上线 AUC 提升不明显、线上却 +3.9%，说明 AUC 不是完美线下指标。
- 推荐数据多为**隐式反馈（One-Class）**：只有正样本，负样本要靠采样构造（按物品热度采样优于随机均匀采样）。

## 模型演化脉络

演化主线：协同过滤/矩阵分解 → LR → POLY2/FM/FFM → GBDT+LR → Embedding+MLP → Wide&Deep → 双塔召回 → DeepFM → DIN/DIEN → RL → GNN。

| 模型 | 年份/出处 | 核心思想 | 解决什么问题 | 代价 |
|---|---|---|---|---|
| 协同过滤 CF | 1990s | 用户/物品相似度共现 | 冷启动前最朴素的个性化 | 不泛化、矩阵爆炸、OOM |
| 矩阵分解 MF/ALS | Netflix 赛 (2006-)；Facebook 加权 ALS | 分解出用户/物品隐向量 | CF 泛化差；隐式反馈加权 ALS（置信度 1+αC，α 默认 40） | 只能 point-wise 预测评分，目标仍是排序 |
| BPR | 2009（三十六弉 | pair-wise 排序目标，sigmoid(分数差) 最大化后验 | MF 为排序绕路；直接优化 AUC 类目标 | 样本构造变四元组，训练量增大 |
| LR | 2000s 工业界 | 广义线性 + sigmoid 做 CTR 预估 | 简单、可解释、易并行、可在线学习（FTRL 2013 稀疏化） | 无特征交叉能力，全靠人工特征工程 |
| POLY2/FM/FFM | POLY2→FM 2010（Rendle）→FFM 2016 | FM 给每个特征学隐向量，二阶交叉=隐向量内积；FFM 分 field | 交叉组合爆炸、稀疏数据下交叉权重学不到 | 高阶交叉难，仍浅层 |
| GBDT+LR | Facebook 2014 论文 | GBDT 每棵树的叶子路径自动产出组合特征（one-hot），喂给 LR | 自动特征组合，替代人工 | 两阶段训练不联合；GBDT 不适合超高维稀疏 one-hot |
| Deep Crossing / Embedding+MLP | 微软 2016 | 类别特征 Embedding + Stacking + MLP 残差 + Scoring | 端到端、免人工组合特征，最经典通用结构 | MLP 内特征交叉低效（concat 后自由组合） |
| Wide&Deep | Google 2016（Google Play） | Wide（LR+交叉特征，记忆）+ Deep（Embedding+MLP，泛化）联合训练 | 记忆共现规则 vs 泛化稀疏组合，兼得 | Wide 侧仍需人工设计交叉特征 |
| NeuralCF | 2017（何向南） | 把 MF 的点积换成 MLP | 点积交叉过于简单导致欠拟合 | 召回侧算力↑ |
| DSSM/YouTubeDNN 双塔 | DSSM 2013 微软；YouTubeDNN 2016 | 用户塔+物品塔各自出向量，内积/softmax，线上近似近邻检索 | 召回侧海量物品的快速匹配（百万→数百） | 双方无深层交互，精细度不如排序模型 |
| DeepFM | 2017 哈工大+华为 | 用 FM 替换 Wide&Deep 的 Wide，FM 与 Deep 共享 Embedding 端到端 | 免人工交叉特征、自动学低阶+高阶交叉 | 训练慢；连续特征处理弱 |
| DIN | 阿里 2018 | 激活单元按候选商品给历史行为算注意力权重 | SUM Pooling 对历史行为"一视同仁"的弊端 | 未建模时间演化；序列长时开销大 |
| DIEN | 阿里 2019 | 兴趣抽取层（GRU）+兴趣进化层（AUGRU 带注意力门控） | 模拟兴趣随时间迁移 | GRU 串行、推理延迟 |
| DRN | 微软 2018 | DQN 双塔 + 竞争梯度下降（微更新）/全量重训（主更新） | 模型实时更新、即时反馈 | 工程-模型强耦合，落地极难 |
| 美团 RL | 美团 2018 博客 | DQN（Value+Advantage），State 用 CNN 提实时意图，预训练 Embedding 剥离上线 | 多轮交互场景实时调整推荐 | 全链路（Kafka/Flink/TF Serving）改造 |
| GraphSAGE/PinSage | 斯坦福+Pinterest 2018 | 采样 k 阶子图 → 聚合邻接点 Embedding → 预测 | 直接处理图结构（对比 DeepWalk 先游走再 2vec 的"搭桥"），i2i 相似推荐 | 图构建与采样工程量大 |

## 关键方法/原理

### LR 时代：特征海洋战术
- LR 做融合排序的好处：简单、可解释、可并行、可在线学习。权重学习要兼顾偏差（损失）与方差（正则），并追求稀疏（L1）。
- SGD 难以得到稀疏模型 → Google 2013 提出 **FTRL**（L1+L2 结合的在线优化），各公司沿用至今。
- 线性模型刻画不了"用户 233 且物品是钢笔"这类组合 → 只能人工做二阶/三阶特征，组合数爆炸且多数无效。

### FM 家族：交叉自动化
- POLY2：所有特征两两相乘各配一个权重——稀疏数据下未见过的组合学不到权重。
- FM：每个特征一个 k 维隐向量 vi，二阶交叉权重 = vi·vj 内积，**未见过组合也能靠隐向量泛化**，复杂度近似线性。
- FFM：按 field 进一步细分隐向量，精度更高但参数更多。

### GBDT+LR（Facebook 广告系统 2014，"经典中的经典"）
- 流程：样本（用户+物品+场景特征拼接）先过 N 棵 GBDT 树，每棵树从根走到叶子 → 每棵树输出一个 one-hot（叶子编号），共 ΣMi 维新特征 → 喂给 LR 输出 CTR。
- 本质：GBDT 同时完成高阶特征组合 + 特征离散化（每条根到叶路径即一组特征组合规则）。
- GBDT 原理：每棵新树拟合上一棵的**残差**（平方损失的梯度），树数/树深/叶子权值正则防过拟合；分类时换对数损失。
- 代价：两阶段训练无法联合优化；GBDT 对超高维稀疏特征效率低；超参（树深、叶数、学习率）多，对噪声敏感。

### Embedding+MLP（Deep Crossing，微软 2016）
- 五层：Feature（数值特征直连；one-hot 类别特征进 Embedding）→ Embedding（各特征独立，互不干涉）→ Stacking（拼接）→ MLP（多层残差单元，全连接交叉）→ Scoring（二分类 sigmoid / 多分类 softmax）。
- Embedding 层结构 = Word2vec 输入到隐层那一段；维度经验值几十到上百。

### Wide&Deep（Google Play 2016）
- **记忆能力**：Wide 侧直接学习历史共现频率（"装了 A 的用户会装 B"），单层 LR + 人工交叉特征（已安装应用 × 曝光应用）。
- **泛化能力**：Deep 侧 Embedding+MLP，从"25 岁男装 A、35 女装 A"泛化出"35 岁男装 A"这类从未见过的组合。
- 联合训练（非集成）：两端一起对目标函数负责。工程细节：类别特征 embedding 32 维、拼成约 1200 维进三层 ReLU（1024→512→256）；连续特征按累积分布分位数归一化；每次训练用上次模型参数热启动；新模型上线前跑冒烟测试；线上多线程并行打分压到 10ms 级。
- 论文优化器：Wide 用 FTRL+L1，Deep 用 AdaGrad。

### 双塔召回（DSSM / YouTubeDNN / NeuralCF）
- **NeuralCF**：MF 的点积层换成多层 MLP，任意函数拟合能力解决欠拟合；是"改变特征交叉方式"这一演化方向的代表。
- **YouTubeDNN 召回（Candidate Generation）**：
  - 结构：输入层（观看历史 embedding、搜索词 embedding、地理 embedding、用户基础特征，多值序列经 Embedding Lookup + **平均池化**变定长）→ 三层 ReLU 塔（1024→512→256）→ softmax 对全量视频做多分类，用户向量 u 与视频向量 v 内积后 softmax。
  - 训练技巧：**sampled softmax**（负采样把百万分类降维，num_sampled≈100 加速）；每用户取相同样本数使低活用户损失权重不被高活用户淹没；正样本=看完的内容。
  - **example age 技巧**：把"视频上传距今的年龄"作为特征（训练时设为 0 或真实值、预测时设 0），修正用户偏好新视频而模型偏好老视频的偏差。
  - 样本构造：拿历史预测未来（而非用全局观看历史），测试集取最后一次观看，防信息穿越，线上 AB 表现更好。
  - 线上：训练用 softmax 只为得到向量，serving 时用用户向量在 Faiss 等近似近邻索引里搜 topN，不必真算 softmax。
  - 代价：双塔内外积交叉太浅，精细化留给排序层。
- 召回候选打分还可用向量聚类：先对物品向量聚类，用户只与聚类中心算分，兼顾计算量与多样性控制。

### DeepFM（哈工大+华为 2017）
- 结构：Sparse Features（one-hot/field）→ Dense Embeddings（共享一套 embedding）→ 上分 FM Layer（线性部分 + 两两内积交叉部分）和 Hidden Layer（MLP）→ 输出 sigmoid(FM + Deep)。
- 关键设计：**FM 与 Deep 共享 embedding，端到端联合训练，无需 FM 预训练**，替代 Wide&Deep 的人工交叉特征。
- 特征交叉操作不限于内积：NFM 用**元素积（element-wise product）+ 池化**；concat/sum/average pooling、外积也都是可选交叉方式，效果靠业务实验定。
- 代价：深度模块拖慢训练；对连续特征处理简单；仍需按场景认真做特征。

### DIN / DIEN（阿里 2018/2019）
- DIN 动机：Base Model 对用户历史行为 SUM Pooling 一视同仁；预测"键盘"广告时，"鼠标"的权重应远大于"T恤"。
- 激活单元：输入=历史商品 embedding + 候选广告 embedding（连同其外积），过一个 MLP 输出注意力权重，加权求和历史行为。
- DIEN 三层：行为序列层（embedding）→ 兴趣抽取层（GRU 模拟兴趣迁移）→ 兴趣进化层（AUGRU=带注意力更新门的 GRU，只保留与目标广告相关的兴趣演化路径），末状态 h'(T) 即当前兴趣向量。
- 适用场景：行为序列长且兴趣会迁移的业务（电商购买）；兴趣稳定的 feed 流收益有限；GRU 串行推理有延迟压力。

### 强化学习：DRN 与美团案例
- 六要素：智能体（推荐系统/模型）、环境（App 推荐场景）、行动（推送列表）、奖励（用户反馈）、状态（用户意图/兴趣/场景的 embedding）、目标（多轮累积奖励期望最大）。
- **DRN（微软 2018，新闻推荐）**：DQN 双塔——用户塔输出状态向量，物品塔输出行动向量，互操作层给行动质量分 Q(s,a)。学习：离线预训练初始化；在线按时间段**微更新**——给当前网络 Q 加随机扰动 ΔW=α·rand(-1,1)·W 得探索网络 Q~，两网列表 Interleaving 穿插推送，Q~ 更好则替换（Dueling Bandit Gradient Descent）；阶段性**主更新**用全量数据重训。
- **美团"猜你喜欢"落地**：奖励 = wc·点击数 + wp·下单数（加权可调）；State embedding = 单层双尺度 CNN 提实时行为意图 + 场景/兴趣特征拼接；State 网络只离线预训练，在线只学 V(s)+A(s,a) 的融合参数与 action 相关参数。工程链路：Kafka 日志 → Online Joiner 拼样本 → Experience Collector 组列表样本 → TF 离线训练 + 在线更新 → TF Serving；针对 serving 切换模型响应抖动，切分加载/请求线程池并做 warm up 预热。
- 代价：强化学习把模型训练、线上服务、数据收集、实时更新全耦合，需架构师角色通盘协调，落地工程量在所有模型里最大。

### 图神经网络：GraphSAGE / PinSage
- 两种图表示学习路线：DeepWalk/Node2vec 是"搭桥"（随机游走转序列再 Word2vec，损失结构信息）；GNN 是"推土机"（直接输入图）。
- GraphSAGE = 采样-聚合-预测：随机定中心节点采 k 阶子图 → CONVOLVE（Aggregate 邻接点 embedding [可选平均/注意力/GRU]，与中心节点上一轮 embedding 拼接过全连接）逐层收敛 → 输出层换 LR 即有监督 CTR 任务，换 softmax 预测节点 ID 即无监督学 embedding。
- PinSage = Pinterest 版 GraphSAGE，在"用户-商品-收藏夹"pin 关系图上学商品 embedding，用于 i2i 相似推荐；不分析图片内容也能学到语义（找到同类培育图片，胜过视觉相似等对比算法）。

### 时间序列的起点：RNN 播单（Spotify）
- RNN 隐藏层 ht=F(Wxt+Uh(t-1))，把上一时刻状态传入本时刻，播单生成=歌曲多分类序列生成，是 DIEN 序列建模的思想源头（A-20）。

## 经验与常见坑

- **数据与特征优先于模型**：七分数据三分算法；Wide&Deep 线上 +3.9% 而 AUC 几乎不动——别迷信单一线下指标，以 AB 实验为准。
- 隐式反馈负样本：不能拿全部缺失值当负类（正负严重失衡），按物品热度采样更接近"真实曝光未反馈"；有曝光日志时"曝光未点击"是最准的负样本。
- YouTubeDNN 每用户固定样本数，防止高活用户主导 loss；训练样本"拿历史预测未来"并留最后一次行为做测试，防信息穿越。
- 逻辑回归特征需归一化/离散化（连续值按分位数桶化）；Embedding+MLP 中数值特征不标准化会严重拖垮训练（留言实测 56%→73%）。
- 双塔的 user/item embedding 只有当两侧在同一空间（点积/softmax 训练）时才能算相似度；排序模型里拼接出来的 embedding 不能直接拿来算相似度。
- Wide 侧交叉特征维度可到万级，注意与 deep 输出 concat 时的量纲平衡，防模型退化成 LR；Wide 用 FTRL、Deep 用 AdaGrad/Adam 是论文标准配置。
- 强化学习落地难在工程：模型-服务-数据流全链耦合，任一环节（如参数更新不及时）掉链子整体失效；TF Serving 换模型要做线程池隔离+warm up。
- 选型看业务：DIEN 适合兴趣会迁移的电商，feed 流兴趣稳定收益有限；行为序列短（点击两三次）的场景 DIN 也没用武之地。

## ⚠️ 时效性说明

- 文中模型集中在 2006-2019；此后 Transformer/自注意力序列（SASRec、BERT4Rec）、多任务多场景（MMoE/ESMM）、大模型语义召回已成业界主流，序列建模用 GRU 的做法基本被取代。
- 三门课程对同一模型表述有出入：B-24 称逻辑回归为"非线性回归模型"（不准确，LR 是广义线性模型）；B-25 称 DeepFM 输出层"用 FM 预训练向量初始化"（与原论文"无需预训练、端到端联合训练"相悖，以 C-20 王喆版本和原论文为准）；A-11 称 Faiss 用 ball tree（Faiss 核心是 IVF/PQ 等量化索引，ball tree 是 Annoy/NMSLIB 早期做法）。
- 代码示例基于 TF1.x/early TF2、deepctr/deepmatch、faiss.IndexFlatIP（B-22 中 IndexFlagIP 为笔误），复现时注意 API 已变。
