# A/B 测试统计基础与实验设计

<p class="note-date">更新于 2026-11-03</p>
> 一句话概括：A/B 测试的理论基础是假设检验，实验设计五步（目标假设→指标→实验单位→样本量→分析）中每一步都有统计原理支撑，选错检验方法、实验单位或样本量估算方式，结果就不可信。

## 核心概念

- **A/B 测试的本质**：控制变量的因果推断实验。把业务问题转换成"原因（产品/业务变化）→结果（业务目标）"的因果推断，通过随机分组控制其他变量，把结果差异归因到唯一变量上。
- **假设检验**：从样本数据推断总体结论。零假设 H0 = 两组指标相同；备择假设 H1 = 两组指标不同。实践中**推荐双尾检验**（不预设谁大谁小），理由：让数据主导决策；同时覆盖正面/负面两种结果。
- **两类错误**：
  - 第一类错误（假阳性，概率 α）：事实相同却判为不同。惯例 α=5%。
  - 第二类错误（假阴性，概率 β）：事实不同却判为相同。惯例 β=20%。
  - **Power = 1-β**：两组事实上不同时，实验能检测出不同的概率，即实验的"灵敏度"（雷达比喻：要探测越小的效应，需要越灵敏的雷达）。惯例 Power=80%。
- **P 值**：零假设成立时，观测到当前样本数据（或更极端）的概率。P<α → 拒绝零假设，结果"统计显著"。P 值不是"实验组更好的概率"，也不是效应大小。
- **置信区间（CI）**：指标/差值的波动范围，95% CI = 样本均值 ± Z分数×标准误差。判断两组差异：看**差值 δ 的置信区间是否包含 0**——包含 0 则可能无差异，不包含 0 则显著不同。
- **标准误差（SE）**：均值的标准差，表征指标波动性。概率类指标 SE=√(p(1-p)/n)；均值类指标 SE=√(s²/n)。
- **AA 测试**：两组体验完全相同的"假实验"。用途：(1) 验证分组随机性是否均匀；(2) 实测指标的波动范围/方差（代替公式计算）；(3) 检测指标稳定性。大样本一次 AA + Bootstrapping（随机可置换抽样）是业界更流行的省资源做法。

## 关键方法/原理

### 1. 指标的统计属性 → 选对检验方法
- 均值类指标（人均时长、客单价）→ 大样本下近似正态分布（中心极限定理，样本量>30）；总体方差不可知 → **T 检验**。
- 概率类指标（点击率、转化率）→ 本质二项分布，大样本下近似正态（经验公式 min(np, n(1-p))≥5）；方差可由样本求得 → **Z 检验（比例检验）**。
- 分布复杂、无法近似正态的指标（如 OEC、长尾分布的使用时长）→ **Bootstrapping**。
- A/B 测试统一选择：**双尾 + 双样本**检验（两组独立样本的比较）。

### 2. 实验设计五步
1. **确定目标和假设**：分析问题定位结果 → 提出大致方案 → 提取具体假设。好假设 = 明确的原因（变化）+ 量化的结果（目标）。"没有量化就没有办法提升"（如"提升用户留存"要落地为"下个月续订率"）。
2. **确定指标**：
   - 评价指标（驱动指标）：可归因（变化能归因到实验变量）、可测量、对实验变化敏感、对其他因素稳定。单次变化（推送/邮件）选短期敏感指标；永久变化（新功能）可选长期指标。
   - 护栏指标（Sanity Check）：业务品质（网络延迟、闪退率、人均收入/参与度）+ 统计品质（两组样本量比例、特征分布相似性）。
   - 多指标时构建 **OEC（总体评价标准）**：收益减去损失的加权综合（亚马逊邮件案例：OEC = (ΣRevenue − S×退订终身损失)/n，结果过半邮件 OEC 为负）。OEC 顺带避免多重检验问题。综合前各指标需归一化。
   - 指标置信度建立：定性+定量结合（用户调研找与目标强相关的行为）、回溯性分析（看历史变化时指标是否相应变化）、借鉴大厂同类实验。
3. **选取实验单位**（三大原则）：
   - 用户体验连贯性：变化用户可察觉（UI、新功能）→ 必须用用户层面单位，否则同一用户跨组体验不一致。
   - 实验单位 = 评价指标的单位 = 随机化单位：不一致会破坏 IID（独立同分布）前提。反例：随机化到页面但指标按用户算，同一用户多次浏览不独立。
   - 样本量尽可能多：仅在满足前两条的前提下，选颗粒度更细的单位（用户 > 访问/Session > 页面浏览）换取样本量。
   - 用户 ID 准确度排序：用户 ID > 匿名 ID（Cookie）/设备 ID > IP 地址。
4. **估算样本量**（见下）。
5. **分析测试结果**（见 72 篇）。

### 3. 样本量计算
公式：n = (Z_(1-α/2) + Z_(1-β))² / (δ/σ_pooled)²，即 n ≈ 8σ²_pooled / δ²（α=5%、Power=80% 时的简化）。

四因素关系：
| 因素 | 与样本量关系 |
|---|---|
| 显著水平 α | 反比（α 越小，n 越大）|
| Power (1-β) | 正比 |
| 综合方差 σ²_pooled | 正比 |
| 差值 δ（MDE，最小可检测效应）| 反比（要检测越小的差异，n 越大）|

- σ²_pooled 估算：概率类 = p_test(1-p_test) + p_control(1-p_control)；均值类用历史数据算样本方差的 2 倍。
- δ 估算：① 收支平衡法（变化总成本/单位收益 → δ_收支平衡，取 δ≥δ_收支平衡）；② 历史数据法（指标波动范围外取期望值，δ = 期望值 − 均值）。
- 网上样本量计算器几乎都只支持概率类指标（输入 baseline 转化率 + MDE + α + Power）；均值类指标必须用公式 + 历史数据自算。
- **实验组/对照组必须 50/50 均分**：最小样本量按每组计，非均分时瓶颈在较小组——要么准确度降低，要么延长测试时间。80/20 分流不会更快显著，反而更慢。
- 实验时长 = 总样本量 / 每天可得样本量，且**至少覆盖指标变化的一个完整周期**（如周中/周末差异 → 至少 7 天；算出来不足一个周期也按一个周期跑）。

## 术语表

| 术语 | 英文 | 含义 |
|---|---|---|
| 零假设/备择假设 | Null / Alternative Hypothesis | H0：两组相同；H1：两组不同 |
| 显著水平 | Significance Level (α) | 第一类错误率上限，惯例 5% |
| 统计功效 | Statistical Power (1-β) | 事实上有差异时检测出差异的概率，惯例 80% |
| 最小可检测效应 | MDE / Minimum Detectable Lift | 差值 δ，实验设计时希望能检测到的最小差异 |
| 综合方差 | Pooled Variance | 两组合并估计的方差，样本量公式的分母组成 |
| 标准误差 | Standard Error (SE) | 均值的标准差，表征指标波动性 |
| 置信区间 | Confidence Interval (CI) | 指标/差值的波动范围；差值 CI 含 0 = 不显著 |
| 评价指标 | Evaluation Metric / 驱动指标 | 直接评价实验效果的敏感指标 |
| 护栏指标 | Guardrail Metric | 保障业务长期价值和统计合理性的辅助指标 |
| 总体评价标准 | OEC (Overall Evaluation Criteria) | 多指标加权合成的综合评价标准 |
| 实验单位 | Experiment Unit | 随机分组的最小单位，须与指标单位一致 |
| AA 测试 | A/A Test | 两组体验相同的测试，验证分组均匀性与指标波动 |
| 回溯性分析 | Retrospective Analysis | 用历史数据检验指标敏感性的方法 |
| 触发型实验 | Triggered Experiment | 变化需满足条件才触发的实验，指标只算触达用户 |

## 经验与常见坑

- **样本量不是越多越好**：统计上越大越准，业务上越小越好（试错成本低、迭代快）。公式算出的是"达到显著性的最小样本量"，是二者的平衡点。⚠️ 样本量越大指标越敏感，但追逐微小显著差异可能没有业务价值。
- **不要提前查看结果**：样本量未达标时每次查看都是一次新实验，多重检验会大幅放大假阳性；提前"显著"极可能是假阳性。
- **指标波动范围是隐形杀手**：实验组 69% vs 对照组 66%，若历史正常波动范围是 [65%,70%]，差异只是正常波动——事先不知道波动范围就会建立错误因果。
- **单次推送类实验勿用长期指标**：续订率对单次推送不敏感，实验会"失败"，是指标选错而非变化无效。
- **触发型实验的分母只算触达用户**：把未触发用户算进分母会引入噪音、稀释效应。对照组中满足触发条件的用户也要计入分母（工程技巧：给对照组发 1 像素隐形弹窗以留记录）。
- **大厂数据**：A/B 测试得到显著结果并最终实施的概率不到 1/3，不显著是常态；每次实验的价值还包括沉淀方法论和发现工程/数据问题。
