# 推荐系统核心模型与架构精要

<p class="note-date">更新于 2026-11-03</p>
> 一句话概括：从流行度/协同过滤/内容推荐三代简单模型，到矩阵分解与分解机，再到 EE 探索机制、无偏估计与现代漏斗架构——推荐系统的模型演进与工程主线。

## 核心概念

### 1. 三代简单模型（冷启动与兜底工具）

**流行度推荐（Popularity-based）**
- 什么火推什么；非个性化；隐含假设"质量与流行度正相关"（仅是假设）。适合冷启动兜底与基线。
- 关键：不要用绝对计数，用**比值/概率**（CTR、CVR）。CTR 估计 = 伯努利参数估计：
  - MLE（点击数/展示数）的坑：分子分母为零时失效（新物品、零点击）；
  - **贝叶斯平滑**：Beta 先验 → Beta 后验（共轭），`(先验点击+实际点击)/(先验展示+实际展示)`，永不为零——至今是广告/推荐 CTR 估计标配思想；
  - **时间折扣**：上一时段数据 × 折扣系数作为下一时段先验，对抗流行度的时效性。
- 两个数据污染源：**时间偏差**（时段流量规律）与**位置偏差**（排名靠前天然多点击）。
- 工程解：留一部分随机展示流量收集无偏数据（epsilon-greedy 思想）。

**基于相似信息（协同过滤近邻法，CF）**
- 本质是"借用数据"：数据稀缺时把个体建模上升为群体建模。
- User-CF：预估分 = 用户自身均分 + Σ(相似用户对物品的"补充分" × 相似度)。补分要先减去该用户自己的均分（**去个人打分偏差**）；相似度常用皮尔森相关度，取 Top-K（约 100–200）；共同评分少的"高相似"用户要按样本量**重新加权**降权。
- Item-CF：对称地用已交互物品的相似物品加权。
- 致命缺陷：稀疏性（共同评分几乎为零）、冷启动、可扩展性（近邻计算爆炸）、天然偏向流行物品。
- ⚠️ 2026 视角：Item-CF 及改进（Swing）在召回层仍活着；User-CF 基本被向量召回（双塔/图 Embedding）取代。

**基于内容（Content-based）**
- 用**特征**表示用户/物品/交互，把推荐转化为**监督学习**。两大工作 = 特征工程 + 目标函数设计。
- 物品特征：文本（TF-IDF→话题模型→词嵌入降维）、类别/知识（缺失时用分类器补、知识图谱扩展）、图像等稠密向量。用户特征：性别/年龄/地域基本项 + 隐反馈（点击等 Implicit Feedback）画像。
- 目标函数：评分拟合已被公认不是真实目标；实际系统用 CTR/CVR/停留时长。

### 2. 隐变量模型（矩阵分解家族）

**矩阵分解（MF）**——起源 Netflix Prize
- `R(M×N) ≈ U(M×k) × V(k×N)`：每用户/物品一个 k 维隐向量，预估分 = 点积。本质是降维（百万用户 × 万物品 → 每人只存 100 个数）。
- 注意：未观测元素是"未知"不是 0；点积目标非凸，梯度下降得局部解。
- 大坑：**偏置项（Bias）比个性化更重要**——乐观用户普遍高分、热门物品普遍高分，大量方差来自与偏好无关的 bias，须分解为 bias + 个性化两部分分别建模。
- 其余坑：隐空间不可解释、只有正样本缺负样本（催生 BPR 等）。
- ⚠️ 2026 视角：MF 被吸收为深度表征学习的一部分（双塔、LightGCN、SASRec），但"embedding 点积做匹配"范式保留至今。

**基于回归的矩阵分解**
- 动机：MF 只能从交互学隐向量 → **新用户/新物品拿不到隐向量**（冷启动灾难），且其他信号塞不进去。
- 解法：显式特性（年龄/性别/品类等）经回归函数生成隐向量的**先验均值**（贝叶斯视角：隐向量是以回归输出为均值的高斯）。训练用层次贝叶斯/EM，复杂且只得局部解 → 工业界很少直接用。
- ⚠️ 2026 视角：思想被深度模型的特征侧输入（Wide&Deep 等）彻底吸收。

**分解机（FM，Rendle）**
- 动机：加**两两特征交叉**能捕捉"年龄段 × 品类"类交互；但 one-hot 交叉后特征空间爆炸、极度稀疏。
- 解法：每个特征配一个隐向量，交叉权重 = 两隐向量点积（对稀疏交叉矩阵做低秩分解）。
- 关键性质：特征只有用户 ID + 物品 ID 时 FM **退化为矩阵分解**——MF 是 FM 特例。
- 训练 SGD 直接解，远比回归式 MF 简单；冷启动好于 MF（有全局特征即可推断）。
- ⚠️ 2026 视角：FM→FFM→DeepFM/xDeepFM；交叉权重低秩分解思想活在所有 CTR 深度模型里。

### 3. EE 机制（Exploit & Explore）

| 算法 | 机制 | 优点 | 缺陷 |
|---|---|---|---|
| Epsilon-Greedy | 概率 P 贪心 + 1−P 随机 | 最简单 | 固定比例人群永远看随机内容；P 无最优值 |
| UCB | 估计均值 + 置信上界（约 2×标准差） | 无固定牺牲人群，探索度自适应 | **确定性算法**：同数据同打分，无真正随机；零展示物品打分全相同无法区分 |
| 汤普森采样 TS | 每物品维护 Beta 先验→后验，每轮**从后验采样**，取样本最大者 | 本质随机（参数相同采样值也不同）；先验天然利好冷启动；有理论保证 | 后验复杂时采样慢 |

- **被忽视的落地前提**（雅虎 Today Module 经验）：小而精的内容池（编辑精选约百篇）+ 海量用户（随机展示也快速收敛）。缺这两条，EE 造成优质内容曝光不足 → 体验下降 → 数据更少，恶性循环。
- 产品难点高于算法难点：上线粒度（每次访问决策会让同一用户前后看到迥异内容；按用户分桶又牺牲桶内体验）；体验损失难补偿也难评测。缓解思路：**反向 EE**（只对老用户探索）、**夹带私货**（探索内容与高质量内容伴行且高质量排前）。
- ⚠️ 2026 视角：独立 EE 排序层已少见，收敛为召回层小流量试探 + 冷启动通道；contextual bandit（LinUCB、contextual TS）在信息流仍常用。

### 4. 评测体系

**线下**
- 评分指标 RMSE 的"平均的暴政"：高频用户误差主导均值，指标变好可能只是牺牲多数人保重度用户；且单点评分精度不反映"从一堆里选一个"的排序场景。
- 实际标准：借用搜索的 Precision/Recall/NDCG，用**点击/购买作二元相关度代理**。坑：纯按历史点击优化会循环推旧物品，牺牲新物品与多样性。
- ⚠️ 2026 视角：演进为 AUC/GAUC、Recall@K + 无偏重放/反事实评估。

**线上 A/B**
- 建立**因果联系**的唯一完全可靠工具，基础是假设检验。两大现实难点：①随机分流后人群变量（性别/地域/未知变量）难以配平 → 差异无法归因；②多团队并行实验互相污染，用户穿越多组。
- 推荐特有指标：**驻留时间**（越长越好）、**空缺时间**（两次访问间隔，越短越依赖）。用户失望信号：访问间隔变长 + 单次停留变短 + 对推荐互动减少。

**无偏差估计（反馈回路的根源与矫正）**
- 偏差机制：系统只展示 A 类 → 用户永远无法表达对 B 类的喜好（缺失非随机）→ 模型只推 A → **偏差随 ML 循环放大**。这是线下线上不一致的根源。
- 矫正：**逆倾向加权（IPS）**——按展示概率反比给正样本加权，低曝光物品上的点击权重更大，得无偏 CTR 估计。
- 假设：每个物品展示概率非零——现实中难满足（为无偏而展示低质内容伤体验），与 EE 的随机小流量天然交汇。
- 2018 年 SIGIR 最佳论文级结论（Cañamares & Castells）：**只有在完全无偏差的世界里，按流行度排序才是最优的**；考虑曝光偏差后，模拟显示流行度排序比随机排序好不了多少，平均分排序反而更优。
- ⚠️ 2026 视角：IPS/去偏差推荐/因果推断已成独立研究领域（doubly robust、反事实 LTR 等），本文是该方向的通俗前瞻。

### 5. 现代推荐架构

**三大通用需求**：①一两百毫秒内返回；②对用户交互有响应（但不能一点就天翻地覆）；③用户覆盖率（不能只为部分用户服务）。

**架构一：纯离线预计算**——线下为每个用户算好全部物品分数存库，线上零计算。
- 优点：实现最简单，线上天然实时。缺点：无法响应交互（更新走完整离线流程），新用户/新物品在下轮全量重算前不可见。
- 量大缓解：活跃用户优先算、用户聚类共享推荐、缓存分级。
- **不变原则：把复杂计算放线下、线下换线上，是推荐架构第一思想。**

**架构二：多层搜索架构（漏斗）**——把搜索的多轮打分移植过来
- 第一层在**索引**上用简单函数（线性/布尔）从海量物品召回几百~几千候选；第二层**重排**用复杂模型精排；再往后是多样性/业务规则层。
- 实时性：第一层并行检索快；响应交互：日内变化交给重排层，且通常**只刷新特征数值**（如点击计数）而非重训模型——便宜且常用。
- 覆盖：索引存物品不存用户 → 新用户天然支持。短板：**新物品不在索引中召回不到**，需实时（近线）索引补。
- ⚠️ 2026 视角：这就是沿用至今的"召回→粗排→精排→重排"漏斗，第一层扩展为倒排 + 向量检索（ANN）多路召回。

**架构三：复杂场景取舍（经验法则）**
- 新用户多 → 选搜索架构（改特征比重算快）；冷启动兜底用年龄/性别/地域分人群热门推荐，与主结果混排。
- 新物品多（更棘手）→ 静态架构走"当日新物品单独库 + 预估分 + 混排"；搜索架构走"临时索引与主索引合并"。
- **活跃用户走多层搜索实时算，不活跃用户走离线预计算——两条路并存。**
- 快消内容（新闻）忌让模型记住"用户喜欢某个具体物品"（很快过时），需时间衰减；耐用品可复购。
- ⚠️ 2026 视角：近线层思想演化为 Lambda/Kappa 架构与实时特征平台。

### 6. 工业界三大套路（打通搜索与推荐）

1. **"推荐是无关键词的搜索"**：统一为多轮打分问题，特征工程/索引/排序学习两边复用。CF、MF 等模型退居第一轮**候选集选择（召回）**，第二轮交给基于特征的排序模型。是否把推荐看成多轮打分的搜索问题，是区分工业界与学术界推荐思维的重要标志。
2. **高频/低频用户分治**：高频用户数据足 → 重个性化（更多行为特征，甚至定制模型——全局模型本质是"平均结果"）；低频用户 → 按人口属性分组建模或直接推流行内容（最保险）。
3. **批量与实时权衡**：看似实时的场景常是"批量预下发 100–200 候选到端上 + 端上按新行为微调重排"——**实时感建立在批量预处理之上**。

## 术语表

| 术语 | 英文 | 含义 |
|---|---|---|
| 协同过滤 | Collaborative Filtering (CF) | 用相似用户/物品的群体行为补足个体数据 |
| 矩阵分解 | Matrix Factorization (MF) | 评分矩阵分解为用户/物品隐向量点积 |
| 分解机 | Factorization Machines (FM) | 特征交叉权重用隐向量点积低秩分解 |
| 隐变量 | Latent Variable | 数据背后不可直接观测的生成参数 |
| EE | Exploitation & Exploration | 利用已知最优 vs 探索不确定高收益 |
| UCB | Upper Confidence Bound | 均值 + 置信上界的确定性 EE 策略 |
| 汤普森采样 | Thompson Sampling | 从后验分布采样选臂的贝叶斯 EE 策略 |
| 贝叶斯平滑 | Bayesian Smoothing | Beta-Bernoulli 共轭先验修正小样本 CTR |
| IPS | Inverse Propensity Scoring | 按展示概率反比加权得无偏估计 |
| 位置偏差 | Position Bias | 排名靠前天然获得更多点击 |
| 驻留/空缺时间 | Dwell / Absence Time | 推荐系统的线上黏性指标 |
| 召回/重排 | Candidate Selection / Re-rank | 漏斗架构的第一层与后层 |
| 冷启动 | Cold Start | 新用户/新物品无交互数据时的建模难题 |
| 隐反馈 | Implicit Feedback | 点击等行为代替显式评分 |

## 经验与常见坑

- CTR 小样本必加平滑（贝叶斯先验/时间折扣），MLE 分母为零是新手必踩坑。
- 交互数据天生带偏差：无随机流量就无无偏估计；小流量随机既是 EE 也是评测的地基。
- MF 的 bias 项贡献常大于个性化项——先建好偏置再谈个性化。
- FM 是 MF 的超集；做特征交叉时先想 FM 而不是手工展开稀疏交叉。
- UCB 是确定性算法，同批物品打分恒同；要真正随机探索用汤普森采样。
- EE 难在产品不在算法：上线粒度、体验补偿、效果归因三题无统一解。
- RMSE 与全局平均模型都会牺牲长尾换头部精度。
- 架构选型看内容节奏：新闻类忌记具体物品、需时间衰减；商品类可复购。
- 实时感常是假象：批量预下发 + 端上重排。

## ⚠️ 时效性说明

- ⚠️ 深度学习之后的演进：召回侧已进入双塔/图 Embedding/序列模型（SASRec）与向量 ANN 检索；排序侧 FM 家族演化到 DeepFM/Wide&Deep/千亿参数稀疏模型；LDA/TF-IDF 类文本特征已被预训练语言模型语义向量取代。
- ⚠️ 全局流行度排序作为主模型已过时，仅存于冷启动兜底。
- ✅ 仍然耐用：漏斗架构与"线下换线上"原则、贝叶斯平滑、EE 三算法思想、IPS 去偏差、A/B 实验方法论、高/低频用户分治。
