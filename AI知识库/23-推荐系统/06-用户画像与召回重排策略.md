# 用户画像与召回、重排策略

<p class="note-date">更新于 2026-11-03</p>
> 一句话概括：用户画像的本质是"给机器看的向量化结果"而非酷炫标签云；召回靠画像+多路策略（规则/热度/关键词/兴趣），重排靠多样性与去重兜底，日志回采闭环让系统越转越准。

## 核心概念

- **是不是所有产品都需要个性化推荐**：不是。推荐适合"内容/物品供给量大、用户消费半径广、长尾丰富"的场景；供给少、需求刚性的产品（工具、强搜索型）加推荐收益有限，反而热门榜+搜索更经济。
- **用户画像（User Profile）的两层含义**：
  1. 营销/交互设计语境的 Personas：给人看的标签云、人物形象——**越酷炫的画像越没用**（对推荐而言）；
  2. 推荐系统语境的 User Profile：**用户向量化后的结果，是给机器看的**。它是构建推荐系统过程中关键环节的副产品，不是目的。
- **画像的两个关键因素：维度 + 量化**。维度名只要机器能两边对上即可（不必人可读）；量化不能拍脑袋，应以推荐效果（排序好坏、召回覆盖）反向优化——"不要为了画像而画像"。
- **画像构建三档方法**：
  1. **查户口**：直接用注册资料、人口统计、历史记录原样作画像。技术含量低，但对冷启动非常有用；
  2. **堆数据**：从历史行为挖掘标签并做统计，最常见的兴趣标签画像；
  3. **黑盒子**：机器学习学出的不可解释稠密向量（LDA 主题、矩阵分解隐因子、深度学习 Embedding）——最不被非技术人员重视，作用却最大。
- **物品画像（Item Profile）**：与用户画像对称，从物品文本/属性构建，再经由用户行为把物品画像"传递"给用户（用户消费了什么，物品的标签就成为其画像的一部分），与用户自身结构化信息合并。

## 关键方法/原理

### 从文本到画像（内容理解 pipeline）
两步：① 非结构化文本结构化；② 按用户行为把物品结构化结果传给用户，转化为特征选择问题（卡方检验 CHI、信息增益 IG 是常用方法）。

结构化的六类手段：
| 手段 | 说明 | 常用工具/算法 |
|---|---|---|
| 关键词提取 | 最基础的标签来源 | TF-IDF、TextRank |
| 实体识别（NER） | 人物/地点/作品/事件，序列标注问题 | 词典+trie-tree、HMM/CRF（工具 spaCy 效率优于 NLTK）|
| 内容分类 | 粗粒度结构化，冷启动探索兴趣常用 | 短文本经典 SVM，工业常用 FastText |
| 聚类 | 无分类体系时的无监督替代 | 传统聚类渐被主题模型取代 |
| 主题模型 | 文本→主题概率分布（软聚类，一文本可属多主题） | LDA（主题数 K 可实验选；工程并行化难，Gensim/PLDA）|
| 词嵌入 | 稠密语义向量，可算相似度扩充标签、合成文本向量 | Word2vec |
- TF-IDF 要点：TF=词在文中出现次数；IDF=ln(N/(n+1))，出现文档越少 IDF 越大；可只取动词名词、按 Top K 或权重均值过滤。
- TextRank：PageRank 思想——词窗口共现构图，权重互相分配迭代收敛，共现词互相支持成为关键词。

### 多路召回策略
1. **基于规则（兴趣点）召回**：从用户画像的标签/兴趣点出发，按标签建倒排索引取内容。实现简单、可控、可解释，适合冷启动和起步阶段。
2. **基于热度召回**：多行为加权算热度值（如转发 0.4 + 评论 0.3 + 点赞 0.2 + 阅读 0.1），倒序取 TopN。要点：
   - 热度要有**衰减**：参考牛顿冷却定律 `T = T₀/(t-t₀+1)^α`（或 Hacker News 式 `(P-1)/(T+2)^G`），冷却系数 α 按"过 B 时间增加 A 票热度不变"反解 `α = ln(1+A/C)/B`；
   - 突发热点需短时指数加权（热搜场景）；
   - 通常与**分模块召回**配合（各频道按权重分别取 TopN 再合并），避免同质化；定时任务做累加更新 + 衰减更新。
3. **基于关键词召回**：物品关键词倒排索引 × 用户兴趣关键词，匹配召回。
4. **基于 Embedding 的兴趣召回**：用户兴趣向量/行为序列向量与物品向量近邻检索（详见特征工程与 Embedding 篇）。
5. 多路召回合并：各路按权重加权融合取 TopN（工程上注意各路分数不可直接比较，需归一化；关注重复召回与遗漏召回）。

### 重排与后处理
- 为什么需要重排：纯按排序分输出会导致类别/形式扎堆（前 7 条全是视频）、过度依赖历史陷入局部最优——即 EE 问题在展示层的体现。
- 常用重排手段：
  1. **类别打散**：相邻元素不同类（洗牌 + 校验相邻不重复）；
  2. **多样性处理**：设多样性阈值（某类别至少/至多几条），不满足则从热度/最新内容池插入用户未读内容；
  3. **随机化**：加入少量随机内容促进探索（勿过度）；
  4. **运营处理**：运营位/置顶/广告插入（固定内容、Slot 技术、优先级、按标签插入），需平衡商业曝光与体验。
- 推荐列表最终公式：**推荐列表 = 运营推荐位 + 多样性排序算法位（含多路召回融合）+ 最新内容位**。

### 去重与采样（工程刚需）
- 两个去重场景：① 内容源去重（聚合类产品抓取内容重复，源自搜索引擎的网页去重）；② 不重复推荐（曝光过的不再推）。
- **Simhash（Google 2007）**：内容相似检测。分词→每词哈希成整数（0 变 -1）→按词权加权→累加→正负号化为 64 位指纹。低权重词不影响指纹；两指纹汉明距离 ≤3 判重复。绝对重复可直接 MD5 指纹。
- **Bloomfilter（布隆过滤器）**：判断"字符串（物品 ID）是否在已推荐集合中"。m 位二进制向量 + n 个独立哈希函数，元素置 1；查询全 1 即"可能在"。有极小误判率（把没推过的判为已推），可承受；标准版不支持删除（Counting Bloom Filter 为每位配计数器可删）。工程问题：一人一个过滤器时存储与持久化规模、按时间窗滚动切换。
- **加权采样**：
  - 有限集：`S = R^(1/w)`（R∈[0,1) 随机数，w 为权重）按 S 排序取前 k，采样概率正比于权重；或以权重为参数的指数分布随机数取最大 k 个；
  - 无限流：**蓄水池采样**（前 k 个入池，之后每个以 k/n 概率替换池中一个，任意时刻每样本入选概率 k/n）；加权蓄水池 = S 值比池中最小者大则替换。
  - 用途：召回时按权重采样用户标签（省算力、保留标签多样性、每次结果有变化）；热榜展示抽样制造"每次刷新略有不同"；活跃用户行为流取固定条数做实时更新。

### 数据采集与日志回采闭环
- 采集关键：曝光（带唯一曝光 ID）-点击-停留的完整链路；正负向行为都要区分（点"不感兴趣"是负向）。
- 日志四类：原始日志、点击日志、会话日志、反馈行为日志。
- 采集手段：客户端**埋点**（确定采集项→注册采集代码→埋点测试）；服务端在 Controller 切面（AOP）统一采集，经 Kafka 异步解耦（不拖慢主流程、保证可靠性），Logback 规范化输出。
- 闭环五步：建日志系统 → 日志分析（Spark/Hadoop）→ 影响评估（发现展现不足、兴趣不匹配）→ 改进系统 → 监控告警。日志回采产出新训练样本，驱动画像和模型持续更新。

### 推荐系统的攻防
- 有流量就有攻击动机：刷榜/刷热度、恶意评分/行为污染训练数据。危害：不靠谱的推荐结果伤体验与品牌、脏数据长期留存、直接经济损失。
- 防御思路：识别异常行为模式（频率、集中度）、对热门指标做去水分析（惩罚异常增量）、榜单与热度算法中剔除可疑投票、关键入口风控。设计热度/排行榜算法时就应假设"会被刷"。

## 经验与常见坑

- 给领导/客户看的"酷炫画像"和给机器用的画像完全是两回事；判断画像质量的标准只有一个：用了它推荐效果有没有变好。
- 画像量化不要主观拍脑袋定权重，应以线上效果反向调优；维度数量是算力与精细度的权衡。
- 朴素排行榜（纯计数排序）三大坑：易被刷、马太效应（破纪录物品霸榜）、不反映时间变化。时间衰减是榜单算法的必备件，冷却系数要按业务节奏（半天/一天/一周）设定。
- 热度衰减过慢旧闻霸屏、过快内容来不及被发现；衰减系数要结合日均行为量调。
- 布隆过滤器误判方向是"把没有判成有"——后果是漏推而非重推，可接受但要监控误判率；过滤器大小不能动态伸缩，大用户量下存储方案要提前设计。
- 加权采样成立的前提是权重相对大小合理；权重有正有负时不能直接套 R^(1/w)。
- 多路召回的分数不可直接比较，融合前必须归一化；重复召回（多路返回同一物品）与遗漏召回都要监控。
- 没有唯一曝光 ID 就没有可信的归因：日志回采、去重、A/B 分析全都依赖它，埋点要在第一版就做对。
- 探索/去重/重排策略上线后要盯负反馈（不感兴趣点击）与长期指标（留存），只盯 CTR 容易把系统调成同质化刷 CTR 机器。

## ⚠️ 时效性说明

- 文本结构化工具时代烙印明显：NER/分词现已被预训练模型（BERT 类）与大模型 API 大幅替代，FastText/SVM 分类、LDA 主题模型在工业内容理解中已非主流；但"文本→标签/向量→画像"的 pipeline 思想不变。
- 热搜/突发热点的加权今天多由实时数仓（Flink）+ 风控系统共同完成，比专栏时代的定时任务更实时。
- Simhash/Bloomfilter/蓄水池采样仍是耐用算法；大规模内容去重现在也常用向量指纹（Embedding + 近似检索）替代词级 Simhash。
