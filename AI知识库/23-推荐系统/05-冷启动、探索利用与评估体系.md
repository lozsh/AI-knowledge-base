# 冷启动、探索利用与评估体系

<p class="note-date">更新于 2026-11-05</p>
> 一句话概括：冷启动靠"引入数据 + 主动试探"（Bandit 是标配工具），探索利用靠"多数收割 + 少数播种"的权衡，评估则要搭一套"离线初筛 → 离线 Replay → Interleaving → A/B 测试"的四层漏斗，兼顾效率与正确性。

## 核心概念

- **冷启动三类**：
  1. **用户冷启动**：新用户无行为。对策：利用注册信息（人口属性）、热门兜底、快速试探（Bandit）、第三方登录/社交关系导入兴趣；
  2. **物品冷启动**：新物品无交互。对策：内容特征（文本/图像标签）、side information、带曝光保量的探索机制；
  3. **系统冷启动**：产品刚上线无任何数据。对策：基于规则的推荐（热度、时间、编辑精选），先积累数据再上算法。
  - 本质：冷启动没有通用解，"解决"它的方式就是**给它加热**——引入外部数据，或从已有数据中主动学习（半监督式试探）。
- **探索与利用（EE）问题**：Exploit = 收割已探明的兴趣；Explore = 探明未知兴趣。只利用会陷入信息茧房/局部最优（反复推荐同类），只探索会伤害当下体验。科学姿势是第三种："大部分推荐感兴趣的，小部分试探新兴趣"——边收韭菜边播种。
- **多臂赌博机（MAB / Bandit）**：一排吐钱概率未知的老虎机，如何选择最大化收益。推荐系统中的对应：臂 = 候选物品/策略/类别；回报 = 用户是否点击/消费；环境 = 用户。衡量指标是**累积遗憾（Regret）**：每次选择收益与最优选择收益之差的累积，遗憾增长越慢算法越好。
- **评估体系**：多种评估方式组成的、兼顾效率与正确性的分层方案。核心矛盾：线上 A/B 最公正但流量宝贵，离线评估快但不保证正确——用漏斗把两者结合起来。

## 核心原理

### Bandit 算法家族（解决 EE 与冷启动试探）
| 算法 | 核心机制 | 特点 |
|---|---|---|
| ε-greedy | 以 ε 概率随机探索，1-ε 概率选平均收益最大的臂 | 朴素有效，ε 控制探索强度 |
| UCB（置信上界） | 评分 = 平均收益 + Bonus（均值标准差量级；$T_{jt}$ 为截至时刻 $t$ 臂 $j$ 被选中的次数，选得越多 Bonus 越小） | 被选少的臂 Bonus 大、获得更多机会；"乐观冒险" |
| Thompson 采样 | 每个臂绑一个 Beta 分布（a=点击数，b=未点击数），各采样一个随机数取最大 | 一行代码可实现；a+b 大分布窄（确定）、a+b 小分布宽（不确定，有机会被探索）|
| LinUCB | 引入用户/物品/场景特征，岭回归拟合参数，按"期望收益 + 置信上界"选择 | 收敛比 UCB 快、可泛化到新物品、支持动态候选池（Yahoo 新闻推荐 2010）|
| COFIBA | LinUCB + 协同过滤：按物品类簇聚用户，相似用户集体决策，并根据反馈动态调整用户/物品聚类 | 加速收敛、延缓信息茧房 |
- 共同套路："小心翼翼地试"——越确定好的多选，越不确定的多给机会。
- 共同限制：**候选臂数量不能太多（几百以内）**，每臂都要算期望与置信区间；新臂/用户需各存一套参数。
- LinUCB 特征工程参考（Yahoo 做法）：用户特征（人口属性、地域、1000 维行为类别）+ 文章特征（URL 类别、编辑标签）→ 归一化 → 用 LR 拟合 W 矩阵把用户特征投影到物品特征空间（1000 维降到 80 维）→ 聚成 5 类 → 6 维上下文向量。
- 另一个策略对比视角：UCB 是**确定性算法**——同数据同打分，无真正随机，零展示物品打分全相同无法区分；汤普森采样本质随机（参数相同采样值也不同），先验天然利好冷启动且有理论保证，但后验复杂时采样慢。
- **被忽视的落地前提**（雅虎 Today Module 经验）：小而精的内容池（编辑精选约百篇）+ 海量用户（随机展示也快速收敛）。缺这两条，探索机制造成优质内容曝光不足 → 体验下降 → 数据更少，恶性循环。
- **产品难点高于算法难点**：上线粒度（每次访问决策会让同一用户前后看到迥异内容；按用户分桶又牺牲桶内体验）；体验损失难补偿也难评测。缓解思路：**反向探索**（只对老用户探索）、**夹带私货**（探索内容与高质量内容伴行且高质量排前）。
- 2026 视角：独立探索排序层已少见，收敛为召回层小流量试探 + 冷启动通道；contextual bandit（LinUCB、contextual TS）在信息流仍常用。

### 离线评估方法（五种）
1. **Holdout 检验**：随机切训练/测试集（如 70/30）。简单常用，但单次结果有随机波动。
2. **交叉检验（k-fold）**：分 k 份轮流做验证集，k 次指标取平均（常取 k=10）。更稳定。
3. **自助法（Bootstrap）**：n 次有放回采样构造训练集，未被抽中的作验证集。保持训练集规模，但改变了数据分布，可能引入偏差。
4. **时间切割**：按时间切（如前 25 天训练、后 5 天测试），从根源上切断"未来信息"。训练:测试经验比例 3:1 ~ 10:1。**推荐场景默认应优先时间切割**——随机划分会让训练集包含 $t_n$（更晚时刻）的数据去"预测"更早的事件，等于时光机作弊。
5. **离线 Replay**：测试样本按时间排序，模型在评估中按线上节奏增量更新后继续评估。最接近线上真实（动态），是强化学习类模型的唯一可行离线评估法；代价是工程复杂、评估耗时长。
- Replay 的工程核心仍是防特征穿越：8 月 20 日的样本只能用 8 月 1-19 日的数据生成"历史 CTR"特征。Netflix 解法是**时光机（Time Machine）**架构：每日 Snapshot Jobs 整合当天的场景信息（Context Set）与日志流（Prana），生成按日期目录保存的数据快照存 S3，对外提供统一 API——评估时直接取"彼时彼刻"的快照，如同时光旅行。

### 评估指标
- **低阶指标**：
  - 准确率（Accuracy）：类别极不均衡时失效（CTR 场景 90%+ 负样本，全猜负也有 95%+ 准确率）；
  - 精确率/召回率：推荐列表用 TopN 版本（Precision@N / Recall@N），二者此消彼长，F1 = 调和平均；
  - LogLoss：与 LR/softmax 输出层的损失函数同构，训练中监控收敛必备；
  - RMSE：回归型（评分预测）标配。⚠️ 注意"平均的暴政"：高频用户误差主导均值，指标变好可能只是牺牲多数人保重度用户；且单点评分精度不反映"从一堆里选一个"的排序场景。
- **高阶指标**：
  - **P-R 曲线**：从高到低移动正样本阈值生成；单点 P/R 不全面，曲线整体比较；
  - **ROC 曲线与 AUC**：横轴 FPR（FP/N）、纵轴 TPR（TP/P），移动截断点绘制；业界离线评估的默认权威指标；
  - **mAP**：先对每个用户算 AP（只取正样本位置的 Precision@N 求平均），再对用户平均；注意它是**分用户排序**计算，与 P-R/ROC 的全量排序不同。
- **其他必看指标**：NDCG（考虑位置折损的排序质量）、GAUC（分用户 AUC 的加权平均，比整体 AUC 更贴近个性化）、覆盖率 Coverage、多样性 Diversity、新颖性。
- 指标选择经验：默认 AUC 但需补 mAP 或分用户 AUC；CTR 类问题不能只看 Accuracy；TopN 推荐看 Precision@N/Recall@N/NDCG。

### 在线评估：A/B 测试与 Interleaving
- **A/B 测试**：按用户 ID 哈希分流，对照组用旧模型、实验组用新模型，统计线上业务指标（CTR、停留时长、转化率等）。是建立**因果联系**的唯一完全可靠工具；实现要点：分流哈希要稳定（同一用户始终进同一组）、实验间互不干扰（多团队并行实验互相污染、用户穿越多组是两大现实难题）、埋点完整。
- 推荐特有指标：**驻留时间**（越长越好）、**空缺时间**（两次访问间隔，越短越依赖）。用户失望信号：访问间隔变长 + 单次停留变短 + 对推荐互动减少。
- **流量紧张的两类解法**：
  1. **分层实验（Layer/Domain）**：把流量切成多层，每层内再分桶，不同层实验正交可叠加，同层内互斥——一个用户可同时处于多个不同维度的实验中；
  2. **Interleaving（交叉/交叠实验）**：不做用户分组，同一组用户看到模型 A、B 结果**交替混合**的列表（像野球场选人：掷硬币决定谁先选、ABAB 交替），分别累加 A/B 物品的效果对比。
- Interleaving 优势：省一半流量、灵敏度远高于 A/B（同样的差异用更少用户更快显著）。局限：只适合物品级指标（CTR、播放量、时长），**用户级指标（留存、付费转化）无法归因到单一模型**，不能完全替代 A/B。重叠物品的归属需事先约定（随机归属或双方计）。
- **实验平台要素**：分流服务（按 UID 稳定分桶）、参数配置下发、指标计算管道、实验管理与显著性检验。数据驱动落地的基础设施。
- A/B 测试与 Interleaving 的统计基础——假设检验、样本量与功效、序贯检验等实验设计细节见 08 篇《A/B 测试统计基础与实验设计》；结果解读与常见误区（SRM、多重比较、新奇效应）见 09 篇《A/B 测试结果分析与常见误区》。

### 技术权衡方法论
- "没有银弹"：模型结构、评估方法、架构选型都没有普适最优，只有场景适配。判断依据是业务指标 + 工程代价，而非论文 SOTA。
- 探索机制落地的现实约束（很少有公司认真做探索的原因）：产品生命周期短、探索收益长期才显现；用户时间碎片化；同质竞争激烈，探索翻车用户就流失；成熟平台缺乏动力。若要做：探索物品须保证质量底线、探索位置需要产品精心设计。
- 工业界三大套路（搜索与推荐打通的工程心法）：
  1. **"推荐是无关键词的搜索"**：统一为多轮打分问题，特征工程/索引/排序学习两边复用；协同过滤、矩阵分解等模型退居第一轮**候选集选择（召回）**，第二轮交给基于特征的排序模型。是否把推荐看成多轮打分的搜索问题，是区分工业界与学术界推荐思维的重要标志。
  2. **高频/低频用户分治**：高频用户数据足 → 重个性化（更多行为特征，甚至定制模型——全局模型本质是"平均结果"）；低频用户 → 按人口属性分组建模或直接推流行内容（最保险）。
  3. **批量与实时权衡**：看似实时的场景常是"批量预下发 100–200 候选到端上 + 端上按新行为微调重排"——**实时感建立在批量预处理之上**。

## 经验与常见坑

- 推荐系统的三大顽疾——冷启动、EE、安全（刷量攻防）——没有通用解，都要结合场景专门设计；且容易被忽视。
- 冷启动"解法"里最实用的是两条：给足内容特征（物品侧）和热门兜底（用户侧），Bandit 试探是锦上添花而非主力。
- 离线随机划分训练/测试集在推荐场景几乎总是错的（信息穿越）；"模型指标提升一个点"如果不说明是时间切割 + 什么指标，基本不可信。
- 离线指标与线上指标存在系统性差距（Offline-Online Gap）：AUC 涨了线上 CTR 未必涨。离线指标只用于**淘汰**不靠谱方案，上线结论必须 A/B 说了算。
- 评估体系的核心思想是漏斗：底层方法负责快速淘汰（30 个候选筛到 5 个），越往上越少越贵越正确；把宝贵的 A/B 流量留给幸存者。
- 探索机制的探索位必须守住内容质量底线：用户不感兴趣可以，但不能反感——探索失败伤害的是品牌。
- Bandit/探索类算法只适合小候选池（策略级、类目级、几百个臂），直接对百万物品跑 LinUCB 不可行。
- Interleaving 里的位置偏差必须处理：交替领先 + 等概率起始，否则排前面的模型白赚点击。

## ⚠️ 时效性说明

- Bandit 系算法（尤其 LinUCB、Thompson 采样）在冷启动和信息茧房治理中至今常用，属耐用内容；工业界大规模候选探索已更多采用深度强化学习或流量分级机制。
- Interleaving 的实践细节主要来自 Netflix 2016 前后的博客，方法本身仍有效；业界也常用"小流量 A/B + 序贯检验"替代部分 Interleaving 场景。
- 离线评估中 AUC/GAUC 仍是主流；近年榜单类离线评估更多引入多任务/长短期目标指标（如 watch time 预估、多目标 AUC），选型逻辑不变：贴近线上商业目标。
