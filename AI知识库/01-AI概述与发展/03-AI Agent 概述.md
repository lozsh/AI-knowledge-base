# AI Agent 概述

<p class="note-date">更新于 2026-11-03</p>

**一句话定义**：AI Agent 的核心公式是 **Agent = LLM + 上下文 + 工具**——大脑（LLM 负责思考决策）+ 眼睛（上下文决定能看到什么）+ 手脚（工具决定能做什么），三者缺一不可；好的架构设计原则能穿越模型迭代周期。

> ⚠️ 时效性说明：本文是某本书的引言，含大量 2025–2026 年的产品与版本动态（GPT-5.x、Claude Opus 4.x、Manus、DeepSeek R1 等），具体版本与产品格局会快速过时；核心架构原则与公式相对稳定。

## 背景：从基座模型到工程落地深水区

自 2025 年初 DeepSeek R1 发布后，AI 领域从单纯的基座模型（通用大语言模型底座）演进进入工程落地的深水区：

- **模型层**：通过智能体环境中的强化学习（Agentic RL）把工具调用能力训进模型参数，使模型掌握编程、数学、图形界面操作（computer use）等通用能力；模型迭代速度加快（主流模型半年一代）。
- **产品层**：Manus、Claude Code、OpenClaw 等通用 Agent 重新定义人机交互，把"代码生成 + 文件系统"这一架构范式推到主流视野。

## 核心原理：Agent 公式的三层表达

同一个对象的三种说法，表达层次不同：

| 层次 | LLM | 上下文 | 工具 |
|---|---|---|---|
| 实现层 | LLM | 上下文 | 工具 |
| 直觉层 | 大脑（思考与决策） | 眼睛（能看到什么信息） | 手脚（能做什么事） |
| 强化学习层 | Policy（策略） | Observation Space（观察空间） | Action Space（动作空间） |

"眼睛"只是粗略类比：上下文不仅包含环境信息和对话历史，还包含工具定义等内容——即 Agent "看到"的信息中也包括"有哪些手脚可用"。核心直觉是：**上下文是模型能感知到的一切信息**。

## 经验与常见坑："实践在前，命名在后"

书中作者的重要观察：Agent 业界陆续出现 Skill、harness、loop engineering 等新名词，但真实顺序是反的——不是 Anthropic 等公司先发明概念、其他 Agent 跟着用；而是大量 Agent 早已在这么做，头部公司才将其提炼、总结为架构设计原则。实践在前，命名在后。

作者在 Pine AI（能自主与真人交互、独立处理涉及金钱的敏感长程任务的通用 Agent，如替用户打电话协商账单、交涉退款、取消订阅，动辄几十轮交涉且任何一步出错都有真金白银的损失）的实战中，早于概念流行就采用了：

- **动态加载提示词**：解决提示词无限膨胀问题（后被称为 Skill）；
- **命令行执行工具**：解决工具列表无限膨胀问题；
- **系统状态栏**：解决 Agent 不感知执行环境、用户时间、工作状态的问题；
- **类 harness 方法**：解决工具调用不稳定、幻觉、危险操作、越权操作、指令不遵循等问题；
- **提议者-审核者（proposer-reviewer）**：解决模型过早宣布任务完成的问题——既防"一条路走不通就宣布办不了"的过早放弃，也防"闭环没走完就宣称已办妥"的假成功。核心是让 Agent 审阅自己输出的交付件（artifact）并迭代改进，**由验证而不是模型自己的感觉决定任务何时结束**（后被称为 loop engineering）。

对企业级 Agent 开发的实际含义：等到业界流行某个名词才去实践，就已慢了一步。要在名词流行之前就知道该怎么做，关键有两点：

1. **拥有一个对 Agent 能力上限有极高要求的真实业务**，并持续获得真实业务反馈。只有足够复杂的场景才会倒逼你构建 harness、解决模型当下做不到但业务必须完成的事；若模型稍一升级就够用，就没有动力打磨架构原则。
2. **建立评估（Evaluation）机制**：没有评估就没有进步。评估让你分辨一次改动是真变好了还是只是运气，让迭代方向不依赖直觉——用科学方法论做工程，评估是这套方法论的地基。

另一个观察：尽管底层模型不断升级、产品形态不断创新，几乎所有成功的 Agent 系统都遵循相同的架构模式——因为好的设计原则描述的不是某个模型的用法，而是**智能系统与世界交互的基本模式**。

## Richard Sutton 的视角：智能体是宇宙演化的新阶段

图灵奖得主、强化学习之父 Richard Sutton 说，宇宙演化经历了四个阶段：尘埃→恒星→生命→智能体（designed entities）。生物进化是盲目的（随机变异、自然选择），大多数生物不理解自己的工作原理。而 Agent 是宇宙演化史上全新的存在：**它能通过生成代码实现自举（bootstrap）和自我进化**——像一个程序员编写了另一个程序员，新的程序员又能继续编写下一个。Agent 能理解自身的运作机制，并根据目标创造全新的智能体，甚至改进自己。

## 该书的知识框架（供索引）

全书十章三大支柱：上下文（提示工程、KV Cache、压缩、Skills、状态栏、用户记忆、RAG、Agentic RAG）、工具（MCP、工具安全、异步事件架构、Coding Agent 与代码生成、代码即思考、Agent 自举）、模型（评估方法论、SFT 与强化学习后训练）。进阶篇：自我进化（经验学习、工具创造）、多模态与实时交互（语音、Computer Use、VLA 机器人）、多 Agent 协作（共享上下文/管理者/去中心化架构）。

术语约定（该书的翻译区分，值得沿用）：

- **reasoning 译"思考"**：模型展开中间推导、"想"的过程（思维链、思考模型如 o 系列/DeepSeek-R1）；
- **inference 译"推理"**：模型的前向计算与部署运行（推理时、推理成本、推理栈）；
- 例外：逻辑推理、多跳推理、空间推理等已固化的复合词沿用习惯译法。

Agent 的三种学习范式：**后训练**（Post-training，改权重）、**上下文学习**（In-Context Learning）、**外部化学习**（Externalized Learning）。
