# 环境与工具

<p class="note-date">更新于 2026-11-05</p>

**一句话定义**：深度学习环境与工具链 = 用 Miniconda 搭一个隔离、可复现的运行环境并装好框架，再配套 Jupyter 交互环境、云端/本地 GPU 算力，以及 Git 协作流程——围绕框架之外的全部基础设施。

深度学习实践的第一步不是写模型，而是搭一个可复现、不污染系统 Python 的运行环境。环境搭建的核心思路有三点：用 conda 做**环境隔离**（不同项目可绑定不同框架版本）；安装框架前先确认**硬件条件**（有无 NVIDIA GPU 及 CUDA 驱动，决定装 CPU 版还是 GPU 版）；最后安装项目配套包和示例代码，用 Jupyter Notebook 交互式运行。环境跑通之后，深度学习程序的计算量常超出本地机器能力，还需要四类配套工具：交互式运行环境（Jupyter）、云端 GPU（托管 SageMaker 与自建 EC2 两条路线）、自购 GPU 服务器的硬件选型要点，以及为开源项目贡献代码的标准流程。

## 标准安装流程

### 1. 安装 Miniconda

从 Miniconda 官网下载对应操作系统的安装脚本并执行：

```bash
# macOS (Intel) / Linux，文件名随版本变化
sh Miniconda3-py39_4.12.0-MacOSX-x86_64.sh -b
sh Miniconda3-py39_4.12.0-Linux-x86_64.sh -b

# 初始化 shell，使 conda 命令可直接使用
~/miniconda3/bin/conda init
```

初始化后**关闭并重开终端**生效。

### 2. 创建并激活独立环境

```bash
conda create --name d2l python=3.9 -y   # 创建名为 d2l 的环境
conda activate d2l                       # 激活；退出用 conda deactivate
```

### 3. 安装框架（区分 CPU / GPU）

安装前先检查机器是否有 NVIDIA GPU 并装好 CUDA 驱动。没有 GPU 也能跑入门章节，但要完整实践建议尽早配置 GPU 并安装 GPU 版框架：

```bash
pip install torch==1.12.0
pip install torchvision==0.13.0
pip install d2l==0.17.6   # 配套函数库
```

### 4. 下载示例代码并启动 Jupyter

```bash
mkdir d2l-zh && cd d2l-zh
curl https://zh-v2.d2l.ai/d2l-zh-2.0.0.zip -o d2l-zh.zip
unzip d2l-zh.zip && rm d2l-zh.zip
cd pytorch
jupyter notebook   # 浏览器打开 http://localhost:8888
```

## Jupyter Notebook

Jupyter 是深度学习最常用的交互式环境，`.ipynb` 文件由 markdown 单元格和代码单元格组成：

- 本地使用：进入代码目录运行 `jupyter notebook`，浏览器访问 `http://localhost:8888`；`Ctrl+Enter` 运行当前单元格；"Kernel → Restart & Run All" 重跑整个 notebook；"Help → Edit Keyboard Shortcuts" 自定义快捷键。
- **远程运行（端口转发）**：云服务器没有显示器，通过 SSH 隧道把远程端口映射到本地：

```bash
ssh myserver -L 8889:localhost:8888
# 之后在本地浏览器访问 http://localhost:8889（远程 jupyter 运行在 8888）
```

- **用 markdown 编辑 notebook**：`.ipynb` 内嵌大量运行输出等辅助数据，git diff 混乱、合并困难。用 notedown 插件可直接编辑 md 格式的 notebook：

```bash
pip install d2l-notedown
jupyter notebook --NotebookApp.contents_manager_class='notedown.NotedownContentsManager'
```

- **ExecuteTime 插件**：显示每个单元格的执行耗时（经 `jupyter_contrib_nbextensions` 安装）。

## 云端 GPU

### 托管路线：Amazon SageMaker

注册 AWS 账户（建议开启双因素认证、设置计费警报防忘记关机）→ 在控制台创建 notebook 实例（如 `ml.p3.2xlarge`：1×Tesla V100 + 8 核 CPU，足够大多数学习场景）→ 创建时可指定 GitHub 仓库让实例自动克隆 → "Open Jupyter" 开始使用。**用完必须停止实例，否则持续计费**。更新代码可在实例终端 `git reset --hard && git pull`。

### 自建路线：Amazon EC2（更便宜）

三步：请求 GPU Linux 实例 → 安装 CUDA（或选预装 CUDA 的镜像）→ 按本地安装流程装框架。要点：

- **地域**：选附近数据中心降低延迟（中国用户可选首尔/东京）；部分数据中心没有 GPU 实例。
- **配额**：新账号默认有 GPU 实例数量限制，需在 "Limits" 页申请提额（约一个工作日）。
- **实例类型**（当时）：p2（K80，Spot 便宜）、g3（M60，均衡）、p3（V100，FP16 高性能）、g4（T4，推理优化）；后缀数字 = GPU 数，如 p2.16xlarge 有 16 卡。
- **磁盘**：默认盘扩到 64GB（仅 CUDA 就占 4GB）。
- **密钥**：新建密钥对必须下载保存（SSH 登录唯一凭证），并 `chmod 400 key.pem` 收紧权限。
- **CUDA 安装**：更新驱动 → 按 NVIDIA 官方仓库的命令安装对应版本 → `nvidia-smi` 验证 → 把 `/usr/local/cuda/lib64` 加入 `LD_LIBRARY_PATH`。
- **关机语义**：*stop* 可重启但磁盘仍计少量费用；*terminate* 删除全部数据不可恢复。可把配好的实例做成 AMI 镜像作为模板，免去重装 CUDA。
- 降成本手段：Spot 竞价实例。

## 服务器与 GPU 硬件选型

GPU 是深度学习最具性价比的加速器，比 CPU 通常高一个数量级以上；工作站常见上限 4 卡（热/电/散热限制），8 卡需专用服务器或上云。

### 服务器配置要点

1. **电源**：单卡峰值可达 350W，电源不足会系统不稳定；
2. **机箱**：GPU 体积大、需辅助供电线空间，大机箱利于散热；
3. **散热**：多卡建议水冷或"公版（blower）"设计显卡——薄、可从卡间进气；多风扇非公版卡装满后卡间进风不足；
4. **PCIe 带宽**：建议 PCIe 3.0 x16；多卡时部分主板会降到 x8 甚至 x4（受 CPU PCIe 通道数限制），买前查主板说明。

分档建议（数量级参考）：1 卡 → 4 核 CPU + 32GB 内存 + 600W 电源；2 卡 → 4–6 核 + 64GB + 1000W + 两个 x16 插槽（卡间留 60mm 间距）；4 卡 → 高主频 CPU（如 Threadripper）+ 128GB + 1600–2000W（办公室插座可能带不动）；8 卡 → 专用服务器机箱 + 冗余电源（如 2+1×1600W）+ 双路 CPU + 256GB ECC + 10GbE 网卡，且要确认机箱兼容 GPU 外形——消费级 GPU 常因供电接口位置装不进服务器。

### GPU 选型三参数

| 参数 | 说明 |
|------|------|
| 计算能力 | 主要看 FP32；FP16 训练已主流，推理可用 INT8；Tensor Core 类加速单元可再提约 5 倍，但需库支持 |
| 显存大小 | 模型/批量越大越吃显存；HBM2 快但贵，GDDR6 便宜；建议 ≥4GB（8GB 更好） |
| 内存带宽 | 喂饱算力的前提；GDDR6 卡看总线宽度 |

经验规律：同代内价格与性能大致成正比；新一代性价比约为上一代的两倍；能耗与算力近似线性。选卡原则：买最新一代、避免用计算卡兼做显示输出（占用显存，必要时多留 2GB）。企业级（Tesla 系，被动散热 + ECC + 大显存）适合数据中心，价格约十倍于消费级（GTX/RTX 系）；个人与中小团队用消费级最划算。

## 开源贡献流程（Git + PR）

开源书/项目的协作模式：微小改动（改笔误）直接在 GitHub 网页上 "Edit this file" 发起 PR；大改动走标准流程——Fork 上游仓库 → `git clone` 自己的分支 → 本地编辑（notebook 中改完要清空输出，CI 会重新生成）→ `git add/commit/push` → 发起 Pull Request 并写清改动说明。多框架代码用 `#@tab pytorch` 等标记区分实现。经验：**不要提交巨型 PR**，拆成多个小 PR 更易审查合并。

## 经验与常见坑

- **每次使用前先 `conda activate d2l`**：跑示例代码、升级框架或 d2l 包之前都要激活环境，否则 pip 会装到错误的 Python 里。
- GPU 版安装失败多半是 CUDA 驱动与框架版本不匹配，先查驱动再选框架版本。
- Linux 下缺 `unzip` 用 `sudo apt install unzip` 安装。
- Windows 下需先把命令行定位到解压后的代码目录再运行 `jupyter notebook`。

## ⚠️ 时效性说明

- 安装命令反映约 2022 年的测试版本组合：Python 3.9、PyTorch 1.12 / torchvision 0.13、d2l 0.17.6。**新项目请勿照搬这些版本号**，应以 PyTorch 官网当前版本的安装命令为准；现代实践也常改用 `uv`/`venv` 替代 conda。
- 云 GPU 与硬件选型素材约成文于 2019–2023 年：CUDA 10.1、V100/K80/T4、GTX 1000 / RTX 2000 系列、SageMaker 的 ml.p3 实例、GTX/RTX/Tesla 产品线划分均已是上一代信息（Tesla 线后更名，数据中心现为主力 H100/B200 等；消费级为 RTX 40/50 系）。**选型思路（电源/散热/PCIe/带宽三参数/新一代性价比翻倍）仍然适用，具体型号与价格必须查当期资料。**
- 流程思路（环境隔离 → 按硬件选版本 → 装配套包）以及 Jupyter、SSH 端口转发的用法基本不变；现在也常以 VS Code Remote / JupyterLab 替代经典 notebook 界面。
