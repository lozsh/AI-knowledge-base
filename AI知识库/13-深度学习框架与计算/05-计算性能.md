# 计算性能

<p class="note-date">更新于 2026-11-05</p>

**一句话定义**：深度学习计算性能工程 = 围绕"数据集大、模型大、计算量大"这一现实，从执行模型（异步与自动并行）、硬件瓶颈认知（延迟数字、内存/存储/CPU/GPU/总线），到多 GPU 并行训练与参数服务器架构的完整优化路径。

好的系统设计可以让训练时间差出数量级——"一周训完"和"三个月训完错过截止日期"的差别往往就在这里。本章主线：先懂执行模型（异步、并行），再懂硬件（瓶颈在哪条总线上），最后落到多 GPU 训练的具体实现。命令式/符号式/混合式三种编程与执行模型的原理和权衡（编译器如何看全图做优化、eager 的派发税、torch.compile 等）是同一主题的框架视角，见 [ML 框架](04-ML%20%E6%A1%86%E6%9E%B6.md)，本章不再重复。

## 异步计算

PyTorch 的 **GPU 操作默认异步**：前端（Python）调用后只是把任务排入设备队列立即返回，实际计算由 C++ 后端自己的线程执行。NumPy vs PyTorch GPU 的 benchmark 差出几个数量级，很大一部分就是这种异步效应（计算还在跑，Python 已经返回）。

- **前端/后端解耦**：前端语言（Python/C++）只负责把操作入队；后端跟踪计算图中各步骤的依赖关系，依赖无关的任务可并行。需要打印结果或 `torch.cuda.synchronize()` 时，前端才真正等待后端算完。
- **收益量化**：若入队、执行、返回耗时为 t1/t2/t3，同步执行 10000 次约 10000(t1+t2+t3)；异步后约 t1 + 10000·t2 + t3——前端开销被摊平。
- **风险**：任务队列塞得过满会导致内存暴涨（排队任务的中间结果都滞留显存）。建议每个 mini-batch 做一次同步，让前后端大致步调一致。

## 自动并行

框架后端基于计算图自动并行化**互不依赖的任务**，无需用户写并行代码：

- **多 GPU 计算**：两个 GPU 上各自独立跑矩阵乘，不加同步语句时总时间 ≈ 单卡时间（而非两卡之和）——框架自动调度。
- **计算与通信并行**：GPU 计算结果回传 CPU 的通信慢（PCIe 总线是瓶颈资源）。关键技巧是 `non_blocking=True`：部分结果先算完就先传，实现"算 y[i] 的同时传 y[i-1]"的流水线。示例中计算 0.46s + 传输 2.35s 的串行组合，流水化后总耗时降到 1.77s。

## 硬件：每个深度学习从业者该知道的延迟数字

性能优化的前提是知道各层存储/互连差几个数量级：

| 操作 | 耗时（量级） |
|------|-------------|
| L1 缓存命中 / 浮点加乘 | ~1.5 ns |
| L2 / L3 缓存命中 | ~5 / ~16–40 ns |
| 主内存访问（本地 CPU） | ~46–75 ns |
| NVMe SSD 随机读 4KB | ~120 μs |
| 1MB 经 PCIe 传 GPU | ~80 μs（~12GB/s） |
| 1MB 经 NVLink 传 GPU | ~30 μs（~33GB/s） |
| 机械硬盘随机访问 | ~10 ms |
| 跨洲网络包往返 | ~150 ms |

**内存**：CPU 内存（DDR4，峰值 40–100GB/s）的首次随机读取要发地址、约 100ns，后续突发读取仅 0.2ns——首读成本是后续的 500 倍，因此**避免随机访问、用突发模式**；数据结构按 64 位边界对齐。GPU 显存要求更高，靠加宽总线（如 352 位）和高端内存（GDDR6 / HBM2）解决。

**存储**：HDD 约 100 IOPS、100–200MB/s，二十年没变，已沦为归档存储；SSD 10 万–50 万 IOPS、1–3GB/s，但按 256KB+ 块写入、随机小写性能差、单元有写入寿命（不适合做交换分区/大日志）；NVMe 走 PCIe 4 通道，可达 8GB/s。

**CPU**：核心数之外，关键在**矢量化**（x86 AVX2 / ARM NEON，单指令多数据，寄存器最长 512 位，支持乘加融合 FMA）和**缓存层级**（寄存器 → L1 32–64KB → L2 每核 256–512KB → L3 多核共享数 MB 到数百 MB）。算一笔账：4 核 2GHz + 256 位 AVX2 每周期需要 128 字节数据，即 256GB/s 带宽——内存接口差一个数量级，缓存就是为此而生。缓存也是双刃剑：错误共享（false sharing）会让多核互相等对方写回内存，反而更慢。

**GPU 与加速卡**：训练 vs 推理需求不同——训练要存中间结果算梯度、需 FP16+ 精度防下溢；推理只需前向、FP16/INT8 够用（如 T4 为推理优化、V100 为训练优化）。GPU 策略 = 更多核心 + 专门的矩阵加速单元（**张量核 Tensor Core**，优化 4×4~16×16 小矩阵运算；TPU 则用脉动阵列）。短板：不擅长稀疏数据和中断（图计算需要专门库如 Gunrock、DGL）。

**互连**：PCIe 点对点、个位数微秒延迟但通道数有限（消费级 CPU 仅 16–24 通道，限制了满速 GPU 数量）；以太网便宜、距离长但慢；交换机实现多设备全带宽互连；**NVLink** 每链路 300Gbit/s（V100 有 6 条），GPU 间高速传输推荐 NCCL 库。

**核心经验**：设备间传输要"量大次少"；矢量化是性能关键；训练留意低精度数值溢出；内存对齐（GPU 上卷积尺寸与张量核对齐）；把参数装进缓存可获得数量级加速；动手前先在纸上估算数量级；用 profiler 找瓶颈。

## 多 GPU 训练

### 三种拆分方式

1. **按网络拆分（流水线/模型并行）**：不同 GPU 负责不同层段。能跑更大网络，但层间同步难、激活值/梯度传输量大，除非框架原生支持否则不推荐。
2. **层内拆分**：把单层的通道/单元分到多卡（早期显存只有 2GB 时的 AlexNet 方案）。每层都依赖其他卡的结果，同步屏障多、通信量更大，同样不推荐。
3. **数据并行**：所有 GPU 持有完整模型副本，各自处理小批量的一部分，再聚合梯度。同步只需每个 mini-batch 一次、已算完的梯度可以先交换，且能自然套用到任何模型——**显存够时的首选**。局限：不能训更大的模型。

### 数据并行的训练循环（从零实现）

k 个 GPU 上的每次迭代：

1. 小批量样本均分成 k 份分发到各 GPU（`nn.parallel.scatter`）；
2. 各 GPU 用自己的参数副本计算损失和梯度；
3. **allreduce**：聚合 k 份局部梯度（求和）并广播回所有 GPU；
4. 各 GPU 用聚合梯度更新自己维护的完整参数。

```python
def allreduce(data):
    for i in range(1, len(data)):
        data[0][:] += data[i].to(data[0].device)   # 汇总
    for i in range(1, len(data)):
        data[i][:] = data[0].to(data[i].device)    # 广播
```

**配套调整**：批量大小应为 k 的倍数并随 GPU 数放大（等价于更大有效批量），学习率相应提高；批量归一化需为每个 GPU 保留独立统计量。注意：模型太小（如 LeNet + Fashion-MNIST）时 Python 开销淹没收益，多卡反而可能更慢；模型够大（ResNet-18）时并行收益才显现。

### 高级 API 简洁实现

`nn.DataParallel(net, device_ids=devices)` 一行完成分发与聚合，训练循环与单卡写法几乎相同。注意事项：模型须先初始化再访问设备参数；评估时输入在哪个 GPU 就在哪算。

## 参数服务器与环同步

单机多卡到多机多卡，互连带宽差异巨大（NVLink ~100GB/s vs PCIe4 x16 32GB/s vs 100GbE 实效 ~10GB/s），**同步策略必须适配网络拓扑**：

- **集中聚合的代价**：4 卡各持 160MB 梯度，全送到一个 GPU 聚合再广播需 ~60ms；全送 CPU 需 ~80ms；按参数切分、4 卡同时各聚合 1/4（利用 PCIe 交换机全带宽），只需 ~15ms。同一数学操作，策略不同差 5 倍。
- **计算通信重叠**：反向传播中靠后的参数梯度先算完，可以先开始同步，不必等全部梯度就绪（Horovod 的思路）。
- **环同步（Ring AllReduce）**：把 n 个节点连成环，梯度切成 n 块，每节点只向邻居传 1/n 的块，n−1 步完成聚合，总时间 ≈ (n−1)/n ≈ 常数——**聚合时间不随节点数增长**。对 NVLink 全互联拓扑（如 DGX-2），最优方案是把网络分解成两个环（一个双带宽环、一个常规带宽环）。常见误解：环同步与树算法本质不同——其实只是同步路径更精细。
- **多机 + 参数服务器**：机器内先聚合本地梯度 → 交给本地 CPU → 上送中央参数服务器聚合 → 参数广播回去。单参数服务器带宽有限、成为 O(m) 瓶颈（m 为工作节点数）；扩到 n 个参数服务器、各存 1/n 参数，时间降为 O(m/n)。实践中同一台机器可兼任工作节点与服务器。
- **键值存储抽象**：梯度聚合是可交换归约（顺序无关、各参数独立），于是可抽象为 `push(key, value)`（累积梯度）和 `pull(key, value)`（取聚合结果）两个操作——把统计建模者和分布式系统工程师的关注点解耦。

## 经验与常见坑

- 异步队列不要塞太满：逐 batch 同步一次，否则显存被排队任务的中间结果撑爆。
- 逐小批量把 GPU 结果搬回 CPU 打日志会触发同步 + GIL，拖垮吞吐。
- 判断数据并行的收益是否真实：小模型 + 小数据集上 Python/同步开销可能让多卡负优化。
- 换卡扩展时批量、学习率、BN 统计量都要跟着调，不是复制命令就行。
- 环同步不是万能最优，要匹配实际互连拓扑。

## ⚠️ 时效性说明

素材约成文于 2022 年：现在 PyTorch 官方主推 `torch.compile` 与更现代的导出路径；`nn.DataParallel` 已被官方标记为不建议新代码使用，多卡训练事实标准是 **DDP（DistributedDataParallel）**；V100/T4/Turing、DDR4、PCIe 4.0 等硬件均为上一代。原理（异步、allreduce、环同步、参数服务器、数据并行）仍是当前系统的基石，具体 API 请以最新文档为准。参见同目录 23 号笔记的 DDP 现代实践。
