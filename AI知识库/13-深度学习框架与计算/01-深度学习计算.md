# 深度学习计算

<p class="note-date">更新于 2026-11-03</p>

**一句话定义**：深度学习计算 = 框架层面的模型构建基础设施——以"块（block）"为单位组合层与模型，配套参数访问/初始化/共享、延后初始化、自定义层、模型读写与 GPU 设备管理，是从框架"基础用户"进阶到"高级用户"的核心知识。

深度学习框架（自 2007 年 Theano 起）的演进方向是抽象层级不断提高：研究者从考虑单个神经元，到从层（layer）的角度思考，再到以块（block）为单位设计架构——正如半导体设计从晶体管到逻辑电路再到写代码。本章不引入新模型，而是讲清框架的这些关键机制，后续的卷积网络、循环网络等高级模型章节都依赖于此。

## 层和块

**块（block）** 是比"层"更大、比"整个模型"更灵活的抽象单元：它可以描述单个层、多个层组成的组件，或整个模型本身。块可以递归组合成更大的组件——ResNet-152 的数百层正是由重复的层组（blocks of layers）模式构成，这类模式在视觉、NLP、语音领域普遍存在。

从编程角度看，块是一个类，必须提供的基本功能：

1. 接受输入数据作为前向传播函数的参数；
2. 通过前向传播生成输出（输出形状可与输入不同）；
3. 计算输出关于输入的梯度（由自动微分自动完成，无需手写反向传播）；
4. 存储和访问前向计算所需的参数；
5. 按需初始化参数。

```python
import torch
from torch import nn
from torch.nn import functional as F

net = nn.Sequential(nn.Linear(20, 256), nn.ReLU(), nn.Linear(256, 10))
net(X)   # 实际是 net.__call__(X)：依次把每个块的输出作为下一个块的输入
```

### 自定义块与顺序块

自定义块只需继承 `nn.Module`，实现 `__init__`（声明层）和 `forward`：

```python
class MLP(nn.Module):
    def __init__(self):
        super().__init__()                # 必须调用父类构造函数
        self.hidden = nn.Linear(20, 256)
        self.out = nn.Linear(256, 10)
    def forward(self, X):
        return self.out(F.relu(self.hidden(X)))
```

`nn.Sequential` 本质是一种特殊的 Module：维护一个 Module 的有序字典。自己实现一个简化版可以看清机制：

```python
class MySequential(nn.Module):
    def __init__(self, *args):
        super().__init__()
        for idx, module in enumerate(args):
            self._modules[str(idx)] = module   # 存入有序字典 _modules
    def forward(self, X):
        for block in self._modules.values():   # OrderedDict 保证按添加顺序执行
            X = block(X)
        return X
```

**关键点**：子模块必须挂在 `_modules`（或作为 `nn.Module` 属性）上，而不能用普通 Python 列表——参数初始化时系统只会到 `_modules` 字典中查找需要初始化的子块。

### 前向传播中执行代码

块的前向函数里可以写任意 Python 控制流和数学运算，包括使用**常数参数**（不参与梯度更新的固定量）：

```python
class FixedHiddenMLP(nn.Module):
    def __init__(self):
        super().__init__()
        self.rand_weight = torch.rand((20, 20), requires_grad=False)  # 固定权重，训练中不更新
        self.linear = nn.Linear(20, 20)
    def forward(self, X):
        X = self.linear(X)
        X = F.relu(torch.mm(X, self.rand_weight) + 1)
        X = self.linear(X)          # 复用同一层 = 参数共享
        while X.abs().sum() > 1:    # 前向传播中的控制流
            X /= 2
        return X.sum()
```

块可任意嵌套混搭（如 `nn.Sequential(NestMLP(), nn.Linear(16, 20), FixedHiddenMLP())`）。

### 效率注意

大量字典查找和 Python 代码有开销：Python 的全局解释器锁（GIL）会让高速 GPU 空等 CPU 执行 Python 代码，这是 Python 深度学习性能工程的核心矛盾之一。

## 参数管理

训练后需要检查、提取、保存参数。三个核心操作：访问、初始化、共享。

### 参数访问

- 按层索引访问：`net[2].state_dict()`，参数名（如 `2.weight`、`2.bias`）可唯一标识网络中每个参数。
- 参数是复合对象（`nn.parameter.Parameter`），包含值、梯度和额外信息：`.data` 取数值、`.grad` 取梯度（反向传播前为 `None`）。
- 一次性遍历：`net.named_parameters()` 返回所有 `(名字, 形状)`；嵌套块的名字按层级拼接（如 `0.block 1.0.weight`），也可像嵌套列表一样索引 `rgnet[0][1][0].bias`。

### 参数初始化

PyTorch 默认按输入/输出维度推断的范围做均匀初始化；`nn.init` 模块提供预置方法，通过 `net.apply(fn)` 递归施加：

```python
def init_normal(m):
    if type(m) == nn.Linear:
        nn.init.normal_(m.weight, mean=0, std=0.01)   # 高斯初始化
        nn.init.zeros_(m.bias)                        # 偏置清零

net.apply(init_normal)
```

- 内置方法：`normal_`、`constant_`、`xavier_uniform_` 等；可对**不同层施加不同初始化**（如第一层 Xavier、第三层常量 42）。
- 自定义初始化：先均匀采样再按条件置零，可实现任意分布规则。
- 始终可以直接赋值：`net[0].weight.data[0, 0] = 42`。

### 参数绑定（共享参数）

把同一个 `nn.Linear` 实例放进网络多个位置，层间即共享参数——它们不仅是值相等，而是**同一个张量对象**（改一处另一处跟着变）。反向传播时，共享位置的梯度会**累加**。典型用途：词嵌入共享、多任务共享底层。

## 延后初始化

定义网络时可以不指定输入维度，框架直到**数据第一次通过模型**才动态推断每层形状——称为延后初始化（deferred initialization）。过程：第一份数据进来 → 推断出输入维度 → 确定第一层权重矩阵形状 → 逐层推导后续形状 → 全部已知后初始化参数。

好处：写代码时无须提前知道维度（尤其卷积网络中图像分辨率影响所有后续层），大幅简化模型的定义和修改，避免常见的维度错误。

## 自定义层

- **不带参数的层**：继承 `nn.Module` 实现 `forward` 即可，如从输入减去均值的 `CenteredLayer`，可直接嵌入 `nn.Sequential` 使用。
- **带参数的层**：用 `nn.Parameter` 包装张量，自动获得访问、初始化、共享、保存/加载等管理能力，无须自己写序列化：

```python
class MyLinear(nn.Module):
    def __init__(self, in_units, units):
        super().__init__()
        self.weight = nn.Parameter(torch.randn(in_units, units))
        self.bias = nn.Parameter(torch.randn(units,))
    def forward(self, X):
        return F.relu(torch.matmul(X, self.weight.data) + self.bias.data)
```

自定义层定义后可像内置层一样在任意网络中使用。

## 读写文件

- **单张量**：`torch.save(x, path)` / `torch.load(path)`，也支持张量列表和"名字→张量"的字典。
- **模型参数**：`torch.save(net.state_dict(), 'mlp.params')` 保存；恢复时先**用代码重建架构**，再 `clone.load_state_dict(torch.load('mlp.params'))`。

**关键细节**：保存的是**参数而非整个模型**。模型可包含任意代码，难以序列化，所以架构必须由代码重建、参数从磁盘加载。此外，长时间训练应定期保存中间结果（checkpoint），防止断电丢失数天计算。

## GPU 与设备管理

自 2000 年以来 GPU 性能每十年增长约 1000 倍，深度学习离不开它。

- **设备表示**：`torch.device('cpu')` 代表所有物理 CPU 核与内存；`torch.device('cuda')`（等价 `cuda:0`）代表**一块** GPU 及其显存，第 i 块用 `cuda:i`。`nvidia-smi` 查看显卡状态。`torch.cuda.device_count()` 查询 GPU 数量。
- **张量与设备**：张量默认在 CPU 创建，创建时可用 `device=` 参数指定 GPU；查询用 `x.device`。**参与同一运算的所有张量必须在同一设备上**，否则报错；跨设备运算需先复制（`Z = X.cuda(1)`；若目标设备上已存在则原样返回、不复制）。
- **模型上 GPU**：`net = net.to(device=try_gpu())`；输入为 GPU 张量时计算自动发生在同一 GPU。

**性能经验**：设备间数据传输比计算慢得多，是并行化的主要障碍——多个小传输远比一次大传输糟糕。典型反模式：在 GPU 上逐 mini-batch 算损失后立刻打印/转 NumPy，会把数据拉回内存并触发 GIL，阻塞所有 GPU。正确做法是在 GPU 内部累积日志，只把最终汇总结果传回。

## 经验与常见坑

- 子模块用普通 Python 列表保存 → 参数不被注册，初始化/保存都会漏掉；必须用 `_modules` 或 Module 属性。
- 共享参数 ≠ 复制参数：后者是两个独立张量，梯度不合并。
- 保存 `state_dict` 而非整个模型对象，是跨环境部署的可靠方式；加载前需要先有架构代码。
- 跨设备运算忘掉 `.to()`/`.cuda()` 是最常见的运行时错误。
- 逐批把 GPU 结果搬回 CPU 做日志，会让 GIL 拖垮整卡吞吐。
