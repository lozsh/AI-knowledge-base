    数据工程流程：采集、清洗、变换与挖掘

    更新于 2026-11-03

    一句话概括：从原始数据到商业洞察要过四道关——采集、预处理（清洗/集成/变换）、挖掘（分类/聚类/预测/关联）、可视化，其中数据准备占掉 80% 的工作量，数据错了算法再对也是错的。

    核心概念

    • BI / DW / DM 三层关系：数据仓库（DW）是地基，把多源数据汇总、消除不一致；数据挖掘（DM）是炼金术；商业智能（BI）是基于 DW 经 DM 产出商业价值的整体过程。"数据仓库是金矿，数据挖掘是炼金术，商业报告是黄金。"
    • 数据库 vs 数据仓库：数据库面向事务（一项技术），数据仓库面向分析（量更庞大、多源汇总、消除不一致后供挖掘分析）。
    • 元数据 vs 数据元：元数据是"描述数据的数据"（图书的属性定义），数据元是最小数据单元（书名、作者各是一个数据元）。数据仓库的调度、抽取、转换都基于元数据。
    • 80/20 时间分配：数据清洗与准备约占数据分析 80% 的时间；好的数据分析师必是数据清洗高手。

    核心原理

    1. 数据采集

    • 一手数据：埋点/日志、业务库、问卷、爬虫；二手数据：公开数据集、行业报告
    • ⚠️ 具体工具（八爪鱼、Python requests 爬虫等）按需选择，模式不变：明确目标字段 → 定采集频率 → 考虑反爬与合规
    • 采集时就要标注：缺列名/缺口径的数据是第一号垃圾

    2. 数据清洗："完全合一"四准则

    准则 检查什么 典型问题与处理
    完整性 空值、空行、字段缺失 缺失值：删除 / 均值填充 / 高频值填充；空行整行删除
    全面性 整列数值的常识合理性 单位不统一（lbs vs kgs）→ 统一度量；大小写不一致 → 归一
    合法性 类型、内容、大小合法性 非 ASCII 字符、性别"未知"、年龄 >150、重量为负 → 删除或修正
    唯一性 行、列是否重复 一列含多个参数 → 拆列；多源汇总重复 → 去重

    顺序建议：先删全空行，再补缺失值（否则空行也被填充），最后去重并重置索引。

    3. 数据集成

    多数据源合并入统一存储。核心坑：同一实体多源标识不一致（跨系统用户 ID 打通）、口径不一致、重复数据。

    4. 数据变换（比算法选择更重要）

    五种常用变换： 1. 数据平滑：去噪声、连续数据离散化（分箱、聚类、回归） 2. 数据聚集：汇总（SQL 聚合函数 Max/Sum 等） 3. 数据概化：低概念→高概念（上海/杭州/北京 → 中国） 4. 数据规范化：缩放到可比区间（见下表） 5. 属性构造：由旧属性构造新属性（各科成绩 → 总分），即特征工程

    规范化方法 公式 特点
    Min-Max (x - min) / (max - min) 映射到 [0,1]；受极值影响大
    Z-Score (x - 均值) / 标准差 化为均值 0 方差 1；跨量纲可比（百分制 80 分 vs 500 分制 80 分的比较）；结果无实际量纲意义
    小数定标 x / 10^j（j=最大绝对值的位数） 移动小数点，简单快速

    5. 数据挖掘四大任务

    任务 定义 典型算法/场景
    分类 用带标签训练集学出模型，对新数据判类 决策树、朴素贝叶斯、SVM、KNN；训练集/测试集划分
    聚类 无标签，物以类聚自动分组 K-Means、EM 聚类；用户分群、图像分割
    预测 由历史数据预测未来趋势 线性/逻辑/多项式回归、时间序列
    关联分析 发现"买了 A 也买 B"的规则 Apriori（啤酒与尿布、Target 怀孕预测）

    挖掘流程：输入数据 → 预处理（清洗/集成/变换）→ 挖掘 → 后处理（如二分类概率按 0.5 阈值定标签）→ 输出。

    6. 数据可视化的角色

    • 可视化是"万金油"：Python 系（Matplotlib/Seaborn）或 BI 工具皆可，模式重于工具
    • 图表选型：直方图看分布（X 轴定量、柱间无间隔、柱宽有意义）vs 柱状图比大小（X 轴分类、柱间有间隔、等宽）；散点图看两变量关系（Y 轴从 0 开始、颗粒度合适、趋势线只能一条）

    7. 用户画像（标签化建模）

    • 三个问题：用户从哪来（统一唯一标识：手机号/设备号/Cookie，是画像的核心与前提）、用户是谁（打标签）、用户到哪去（画像关联业务提转化/降流失）
    • 标签四维"用户消费行为分析"：
    • 用户标签：性别、年龄、地域、收入、职业等基础属性
    • 消费标签：消费习惯、购买意向、促销敏感度
    • 行为标签：时间段、频次、时长、访问路径
    • 内容分析：浏览/停留内容偏好
    • 三层建模：数据层打事实标签（客观记录）→ 算法层算模型标签（分类结果）→ 业务层出预测标签（获客/粘客/留客手段）
    • 注意营销节奏造成的异常值（大促订单脉冲），画像需处理异常
    • 集团级用户标识统一要在顶层架构尽早做，事后打通极难

    8. 数据平台成长路径（工具选型的量力原则）

    阶段 团队 形态
    幼儿园 0-2 人 Excel + SQL + 云数据库 + Power BI 桌面版
    中学 5-10 人 数据仓库 + ETL 调度 + BI 展示（Tableau/Superset 等）
    大学 20+ 人 大数据平台（Hadoop/Spark/Kafka/ClickHouse）+ 数据治理（主数据/元数据）+ 挖掘
    博士 100+ 人 数据中台、自建+外采混合、算法引擎自研

    不要在企业小学阶段用博士的方法解决问题；合适场景用合适工具，Excel 也可能是最优解。

    术语表

    术语 定义
    BI 商业智能，基于数据仓库经数据挖掘产出商业价值的整体过程
    DW 数据仓库，多源汇总、消除不一致的分析型存储
    KDD 数据库中的知识发现，即数据挖掘全流程
    ETL 抽取-转换-加载，进入数据仓库前的搬运加工
    事实标签/模型标签/预测标签 画像三层：客观记录/算法分类/业务预测
    分箱 把连续值切进区间实现离散化平滑
    关联规则 形如"买 A → 买 B"的共现规则，支持度/置信度衡量
    过拟合/欠拟合 模型过分贴合训练细节/过度忽略规律，换数据即失效或丢失趋势

    经验与常见坑

    • 数据缺标注（无列名/口径）就分析：后面的每一步都在猜。
    • 不做变换直接混合多源数据：百分制 80 和五百制 80 直接比，算法再对结果也是错的。
    • 类别极不平衡时只看准确率：99 匹马 1 只鹿的例子里"全判马"准确率 99% 但毫无价值——改用精确率/召回率成对评估。
    • 清洗顺序错误：先填充后删空行，空行被均值污染。
    • 过采样只是复制少数类，不增加信息，可能过拟合；欠采样可能丢信息——两类都要配合验证。
    • 忽视用户标识统一：各部门各建一套 ID，画像与漏斗永远对不上。
    • 追新工具：团队 3 人上 Hadoop 平台是典型过度建设，维护成本吃掉全部产出。

    ⚠️ 时效性说明

    • 资料成文于 2018-2021 年，Pandas/Python2 风格代码示例已过时（Python2 弃维）；清洗准则、规范化公式、挖掘四任务长期有效。
    • 八爪鱼等采集工具、PowerBI/Tableau 具体产品格局随市场变化；现代栈还应有 dbt、Airflow、湖仓一体等，但"存储-加工-展示"三层模式不变。
    • 数据合规要求（个保法等）远严于早年，采集环节须补做合规评估。
