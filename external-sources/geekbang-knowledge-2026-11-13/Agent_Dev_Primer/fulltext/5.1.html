很多人最大的顾虑是「会不会又是一堆框架名词」。这篇把 Agent 开发拆成五个要素——它们并不神秘，每一个都对应课程里一周动手练的东西。

随便打开一个大模型对话框，你都有一个会聊天的 AI。但会聊天和能干活是两件事，中间差的那一截，就是 Agent 开发。

8 周下来要交的东西只有一个：一个能公网访问的 Agent 服务。别人点开就能聊，它有自己的资料和工具，花掉多少钱也记在账上。这样一套服务拆开看是五个要素，课程一周练一个。

模型：一次思考的智力（第一周）

Agent 的「大脑」，是一次又一次的模型调用。而调用质量的分水岭在提示词——郑晔老师在《程序员的 AI 三重境界》里给过一个公式：提示词 = 定义角色 + 背景信息 + 任务目标 + 输出要求。

第一周你从写一篇 System Prompt 开始，做一个文章总结器：粘贴长文，流式输出结构化总结。同时搞清楚一件反直觉的事：这个系统里哪些是确定性的（你的代码），哪些是概率性的（模型的输出）——这个区分，会贯穿你后面所有的设计决定。

记忆：会记，也要会忘（第二周）

模型本身没有记忆，每次调用都是初见。聊天机器人之所以「记得你」，是工程师把对话历史塞回请求里的结果。但上下文窗口既贵又有限——第二周你会先亲手触发一次超出上下文的报错，再实现两种记忆策略（滑动窗口、摘要记忆），并用 SQLite 把会话持久化。验收标准很直白：连续 20 轮对话人设不崩、重启历史不丢。记忆从玄学变成工程。

工具：从「会说」到「会做」（第三周）

只会输出文字的模型，什么也改变不了。给 Agent 接上工具——查文件、算数字、调接口——它才开始做事。第三周你设计自己的工具 Schema，跑通完整的工具循环，同时上一道闸：权限白名单与危险操作确认。能干活，但不越权。你也会搞清楚 MCP 与 Skill 各自解决什么问题——今天接工具，已经比一年前规范得多。

知识：让服务懂你的资料（第四周）

模型知道的是通用世界，不知道你的文档、你的业务。RAG 的思路很朴素：提问时，先把相关资料检索出来，连同问题一起交给模型。第四周你独立实现索引与检索两条流程，并且用 10 个测试问题度量命中率：答对 8 个以上、答案带出处，才算过。做知识库不难，难的是知道它什么时候答错、为什么答错。

循环：给目标，不给步骤（第五周）

单次调用是「问一句答一句」；Agent Loop 是「给个目标，它自己规划、调用工具、检查结果、决定下一步」。第五周你只给目标不给步骤，让服务自主完成一个至少 3 步的任务——同时装好三道护栏：最大循环次数、成本闸、计划批准。自主，不等于放任。

比实现更重要的：判断

五个要素学下来，比「都会做」更重要的是「知道该用哪几个」。课程里有一句贯穿始终的话：

提示词能解决的不上 RAG，规则能解决的不上 Agent。

每加一层，能力在涨，复杂度、成本和不可控性也在涨。成熟工程师的标志不是五层全用上，而是说得出「这个需求为什么到提示词就够了」。郑晔老师在企业里讲 AI 落地时给的是同一个判断：确定性需求用传统方式做，即便要做 Agent，也优选单 Agent。最后两周的工坊，你会对着自己的大作业做一次完整的分层选型判断，并算出月成本账。

8 周之后

五个要素各练一周，第六周部署上线（公网可访问、重启不丢、密钥不入库），最后两周是你的大作业工坊——中期检查、集中辅导，最后做展示答辩。最终它们组装成你的个性化 Agent 服务。至于这个服务做成什么样，取决于你走哪条路：见《先看这里：为什么训练判断力，比学会搭建 Agent 更重要》；每周你能做出什么、说清什么，见《8 周，三条路径，一个公网可访问的服务》。
