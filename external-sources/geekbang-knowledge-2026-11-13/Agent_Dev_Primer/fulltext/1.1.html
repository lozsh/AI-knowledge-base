这是这门课的课前材料。我们希望向你介绍它训练什么、怎么训练，再由你自己决定值不值得投入 8 周。

这门课与常见教学材料最大的区别，是它强调工程意识、训练判断力，而不是单纯堆砌技术名词，图个「量大管饱」。

多数教程会讲清「RAG 是什么、Agent 怎么搭建」，却很少回答更前面的问题：眼前这个需求该不该引入 RAG？单个 Agent 够不够用？对应的成本如何计算、划不划算？这类问题不会有现成答案，只能靠一次次在项目中的真实取舍练出来——这正是课程每周实践任务与结业答辩着重训练的。

开篇先建立两个共识：01 用五道判断，简单展示判断力是如何表现出来的；02 说明模型越来越强之后，判断力为什么反而更值钱——通用能力会不断被模型吸纳走，留在你手里的只有在特定领域下的判断。

本页和 01、02 同属第一组「开篇」；之后按顺序分四组，从不同角度认识这门课：

  1. 为什么学——AI 都能写代码了，还要不要学开发？（03-04）
  2. 怎么用 AI——个人怎么用它干活，企业为什么做不好？（05-06）
  3. 高手怎么练——怎么学，才算真的有效？（07-11）
  4. 进阶学习——如果跟这门课走，8 周能做出什么？（12-13）

结业只有一个标准，加深多少按需选

结业不分等级，标准只有一个：做出一个能公网访问、并且你讲得清怎么做的 Agent 服务。答辩时提交四项成果（项目仓库、可访问服务、演示录屏、答辩材料），按实现、判断、验证、复盘四条标准审核。基础代码课程提供，往哪个方向加深按需选：

  • 先把服务跑起来：在基础代码上修改提示词、调整配置项（模型、key、温度、人设），按自己挑选的应用场景发布一个能被公开访问、使用的服务，并讲清自己修改了什么。
  • 增加一个能力：挑选一个自己的场景，定向增加 1 个能力（记忆 / 工具 / RAG / 循环，四选一），做出属于自己的场景服务，并借鉴课程的路演框架讲清它的应用价值。
  • 往工程深处走：调用课程的选修 / 拓宽内容，在成本计算、安全护栏、效果数据对比上深入，上线一个「能扛住追问」的服务。

具体怎么选，对照课程详情页的说明即可。

这门课默认你掌握至少一门编程语言、愿意用 Python 完成参考路径：能读懂一段代码在做什么、愿意在 AI 辅助下把代码改到能跑、看到报错不慌。
