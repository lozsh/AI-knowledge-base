一些原来要自己动手做的能力，模型服务已经内置了。被拿走的只是通用的那部分，模型给不了的那些，才是这门课要练的地方。

一些曾经的 Agent 设计模式，正逐渐内化到大模型服务之中，于是，Agent 开发呈现出“一边建设新功能，一边拆除旧用法”的现象。

从 CoT 到深度思考

我们以很多人知道的“深度思考”为例来说明这个过程。

思维链（Chain of Thought，CoT），是 Google 研究者于 2022 年提出的一项提示词技术，他们发现，在给大模型的示例中加入推理过程，模型在算术、常识、符号等推理任务上的表现会大幅提升——模型不是不会推理，只是没人提醒的话，它会急着给出答案，跳过了中间的推理。

随后有人发现，甚至不用构造示例，只要在提示词里加一句“Let's think step by step”，就能激发出类似的效果。一句大白话，胜过千行工程，CoT 就此出圈，会不会写思维链提示词，一度是用好 AI 的分水岭。

之后几年，这门手艺越做越精细：手工雕琢推理步骤、思维树（Tree of Thought）分叉探索、自洽性（Self-Consistency）采样投票，各种技巧被框架封装起来，成了 AI 应用的标配。

转折发生在 2024 年 9 月，OpenAI 发布 o1，用强化学习训练模型“先想后答”，推理不再依靠提示词引导，而是模型内部自发生成。2025 年初，DeepSeek-R1 开源，推理能力不再是少数厂商的专利，各家模型纷纷跟进。

如今，深度思考已经是大模型的标配，我们所需要做的是，在向大模型提问之前，打开一个叫“深度思考”的开关。

内化，不止是 CoT

CoT 不是孤例，环顾 Agent 开发，同样的故事在各个角落上演：

  • 基于 ReAct 模式的工具调用，演变成向大模型传递工具参数。解析模型输出，从纯文本解析变成了读取结构化结果，出错的概率大幅度降低；
  • JSON 结构化输出，演变成通过参数指定应答格式，输出格式稳定，省掉了解析失败重试处理；
  • 联网搜索和图像识别，直接内置进了大模型服务，无需自行集成搜索 API 与视觉模型服务；
  • 模型的上下文正在变得越来越长，在某些场景下，我们甚至可以把整个文档直接交给模型：长文总结不必分段处理，简单的知识检索也不必引入 RAG；
  • 针对 Agent 开发中最通用的路由决策，甚至出现了专门优化的决策模型，显著降低决策成本。

这些方案诞生时，都是实实在在的工程能力，都曾在应用开发中扮演关键角色。而如今，它们都成了大模型服务的一部分：有的变成一个参数，有的变成一个开关，有的干脆成了服务内置的能力。

大模型服务的不断改进，带来的可能是坏消息，你辛苦构建的模块，也许会在某次升级后失去存在的价值；当然，也可能是好消息，原本要费力解决的问题，如今一个参数就搞定了。

趋势从何而来

为什么大模型服务会把越来越多的能力揽到自己身上？要理解这个趋势，我们得回到起点。大模型的核心原理是下一个词预测（Next Token Prediction，简称 NTP），本质上这是个文字接龙引擎，光靠它做不出复杂的应用。

于是，应用开发者们在模型外面想办法，用工程方案补齐能力，CoT、ReAct、结构化输出等等，都是这么来的。这些方案在大量的实践中被反复验证。渐渐地，大家发现，它们并非某个应用的特殊需求，而是几乎所有应用的通用需求。

既然是通用需求，模型厂商自然会把它们沉淀到大模型服务中，交互更少，延迟更低，成本更小，还能变成产品卖点。所以，这个趋势的本质是一次自然的能力演化：应用层是大模型的试验田，在试验田里验证过的通用能力，最终会内化到大模型服务之中。

我们可以做些什么？

趋势之下，我们看到 Agent 建设呈现出“一边建设新功能，一边拆除旧用法”的现象。我们建设的，是自己应用必不可少的能力；而拆除的，是被大模型服务内化的能力。大模型服务内化的是什么？是通用的能力。这给了我们一个启发。

开发者要有意识地区分自己构建的能力：

  • 通用能力，就是换一个模型、换一个场景依然需要的，比如推理增强、格式化输出、工具调用。这部分大概率会被内化，它们很可能只是临时的脚手架，我们可以做好隔离，必要时，该拆就拆。
  • 领域特有的能力，就是只在你的业务里成立的能力，比如对业务规则的理解、领域数据的积累、工作流的编排。这部分模型给不了，这才是一个 Agent 存在的核心价值。

内化不定期发生，如果有什么是我们立即可以做的，就是看看自己的模型服务支持哪些能力。比如，支持工具参数的话，你的 ReAct 模式就可以调整一下；支持 JSON 输出，输出处理的代码就可以简化。当然，如果不支持，原本的逻辑还得继续留着。

当然，用大模型服务代替工程，也不是处处适用。比如深度思考模式，如果你的业务有特定的推理步骤，CoT 就还是有价值的。顺带说一个实践细节：自己定制了推理步骤，就不要再开启深度思考模式，两套推理互相打架，token 花得更多，效果未必更好。

小结

说来说去，你会发现，能力内化的趋势，重塑了 Agent 开发的基本盘：推理、解析、检索、路由，这些曾经要亲手构建的工程，正一个个变成大模型服务的一部分；而你的业务、你的领域，这些模型给不了的东西，才是一个 Agent 存在的核心价值。

这一切还没有到头。大模型服务还会继续演化，能提供给我们的能力会越来越多，我们的开发方式也要跟着调整。但无论怎么变，有一个基本动作不会变：把通用的交给模型，把精力留给自己的领域。

这篇不是课程内容，是课程的前提：既然通用能力会被内化，要学的就不是把 CoT、ReAct、RAG 一个个搭起来，而是在具体需求面前判断——哪些该交给模型、哪些必须自己建。课程第 3 周划职责边界，第 4 周讲知识库，第 7 周算成本，练的都是这件事。

内化不会停在今天。想先看这种判断长什么样，回到最前面的 01。
