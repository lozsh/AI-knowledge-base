环境准备指引

训练营需要一套可以持续维护 12 周的本地客户交付工程。W1 会先运行标准会员运营 Agent，验证自己选择的模型，再判断它与青禾优选需求之间的差距。后续每周在同一个仓库中增加客户能力，留下代码、文档和运行证据。

W1 课程方提供什么

课程方提供完整源码和安装说明。标准产品在独立的虚构样例上，已经可以处理这样的请求：

找出近期消费下降的老会员，比较前后两个时段的消费情况，给出召回建议，并说明依据。缺少时间范围时，先向用户澄清。

W1 的产品包包括：

组成	可以做什么
标准会员运营 Agent	理解自然语言目标，澄清必要条件，选择业务工具，根据结果继续分析，给出建议、依据和限制
SQLite 与干净样例数据	导入会员、订单、门店和数据覆盖范围；按固定业务参考日期，筛选人群并比较两个时段
样例标签系统	在本地独立运行的有状态 Mock 服务，提供真实 HTTP API，可以查询、添加和撤销标签，并核对实际状态
动作示例与连接器	形成草案，经用户明确确认后调用标签 API；记录任务状态，识别重复请求，处理失败和查询结果
基础评估与运行记录	运行样例评估，查看模型与工具的调用轨迹，记录模型、数据、提示词和配置版本
配套工具	产品能力矩阵、接口与数据文档、环境自检、作业契约和 checker

分析任务默认只读。标签动作放在独立的样例演示中，确认权限由程序检查，用户修改对象或参数后需要重新确认。W1 的标签系统只模拟教学需要的业务能力；它是通过 HTTP 调用的独立系统，不是让 Agent 直接修改分析数据库中的动作表。

样例公司、数据和口径独立于青禾优选。后续课程按周发放青禾材料：学员清洗和适配客户数据，导入独立的青禾 SQLite 数据库，再扩展业务工具、客户策略和连接器。原始文件需要保留，导入过程需要可重复执行。

官方技术路径与自主选择

官方产品使用 Python 和 LangGraph。LangGraph 组织模型调用、工具执行及任务状态；确定性代码负责数据计算、权限、确认和外部动作约束。分析数据库采用 SQLite，随 Python 提供，不需要另外部署数据库服务器。

评估默认采用 Promptfoo，可观测采用 OpenTelemetry 和 Langfuse。W1 先提供可本地运行的基础评估和轨迹；W7 扩展客户评估集，W9 接入课程方提供的观测环境。开营前不需要自己部署评测或监控平台，也不要求 Docker。

学员可以选择两条实现路线：

复用官方标准产品。在客户层、业务工具和连接器中扩展；可以通过接口使用自己熟悉的后端语言。只有证明确有通用能力缺口时，才修改产品核心。
自行开发等价产品。可以选择自己的语言、Agent 框架、内部目录和数据库。课程方通过提供的数据、业务 API、运行行为和标准产出物验收。自建路线仍需完成相同的青禾客户任务和调优证据，底座开发是额外投入。

课程不按框架品牌判分。两条路线都需要真实模型根据目标选择工具，读取工具结果并完成任务。固定 SQL 和规则可以作为工具的实现，但不能用固定输入输出或按钮直连 API 替代 Agent 行为。

入营前准备这六项基础
基础	开营前完成标准
后端语言	能用一门语言读取文件、处理 JSON、编写简单程序
SQL	能使用 SELECT、WHERE、JOIN、GROUP BY 完成查询与聚合
HTTP API	能发出请求，读取正常响应，并处理鉴权失败、超时等错误
大模型 API	已用代码成功调用自己选择的模型，知道如何配置端点、模型名和密钥
本地环境	能运行 Python、安装项目依赖、查看日志并连接 SQLite
Git	能获取和维护仓库，保存修改，查看差异；不会把密钥提交到仓库

官方路径需要 Python 3.11 或更新版本，推荐使用发布包实际验证的版本。精确版本、安装命令和平台验证记录以正式包 README 为准。使用其他语言的学员，也需要能启动课程方的 Python 配套服务，再通过 HTTP 接入。

模型由学员自行选择。教师会使用神策提供的 deepseek-v4-pro 验证官方产品；这不能替代学员对自己模型的验证。教师密钥不随课程包发放。不同模型的工具调用格式、上下文处理和行为可能不同，W1 要先区分接口兼容问题和任务效果问题。

密钥通过环境变量或明确指定的本地配置管理，不写进代码、作业、日志或公开截图。不要在预习阶段猜测包内命令、创建同名空工程，领取正式版本后按其 README 安装。

客户交付工程怎样组织

官方仓库按工程责任划分：

platform/       标准产品与通用执行机制
customer/       客户语义、指标、策略、提示词和行业配置
connectors/     数据及业务系统适配
product/        标准能力、样例定义及产品配置
sample_data/    独立的干净样例与导入说明
evals/          评估集、版本基线和调优对照
patches/        有证据支持的产品通用能力补丁
tests/          自动验证
artifacts/wNN/  按周提交的结构化证据
docs/wNN/       按周提交的交付说明
tools/          启动、自检、验收等辅助入口


这是官方路径的责任划分。自主实现可以采用不同结构，但提交文件的位置、字段、稳定 ID、数据口径和接口行为必须符合当周任务书，才能由同一套验收工具检查。

W1 要完成哪些验证

W1 的重点是运行并理解已有产品、建立实际模型基线和首版适配判断。复用官方产品的学员本周不开发青禾业务功能；自建路线需要另外完成等价标准能力。

领取正式包后，依次完成：

安装并启动产品、SQLite 和独立标签 Mock，导入干净样例。
接入自己的真实模型，跑通一次包含工具调用与结果回填的业务任务。
验证缺少时间范围时先澄清；数据未覆盖时说明限制，不能把未知当成零。
查看两个时段的工具计算、证据和建议，识别模型说明与程序计算的边界。
演示标签草案、明确确认、HTTP 执行和状态查询；检查重复请求、拒绝与支持撤销的情况。
运行基础评估，保存失败样本及调用轨迹，区分模型协议、数据、工具和行为问题。
生成环境检查与运行证据，用 checker 检查，再根据产品能力矩阵完成 fit-gap。

固定输出的教学回放只用于理解机制，不能作为真实模型已验证的证据。artifacts/w01/environment_check.json 和 artifacts/w01/product_fit_gap.json 等交付物的完整字段，以正式包内契约和 W1 任务书为准，不手工把失败改成通过。

后续 12 周怎样继续开发

标准产品提供一个可运行的起点。青禾的口径、数据质量、系统接口、权限和业务目标仍需要逐项处理。

W2、W3 加载客户语义并实现指标；W4、W5 清洗导入客户数据、合并身份、扩展业务工具，完成青禾建议型 Agent。W6 加入客户权限和脱敏；W7 用客户评估集系统调优；W8 对接课程提供的青禾发券、标签 API；W9 完成审计、观测、成本和发布控制；W10 分析统一发放的模拟试点效果数据；W11 抽取可复用资产；W12 完整验收。

Agent 效果调优是 FDE 的持续开发任务。面对自己选择的模型和客户业态，学员需要调整提示词、上下文、工具设计及 Agent 执行策略，记录修改前后的效果，并解释取舍。评估框架负责测量，Agent Harness 指围绕模型的执行机制，两者需要区分。调优不能靠降低权限要求或修改指标口径来获得更高分。

W8 必须通过真实 HTTP 请求集成所提供的业务 API，不设置“直接写动作表”的替代验收路径。它使用教学 Mock，不代表连接了真实商业客户的生产系统。不可逆业务效果不能宣称可以通用回滚。

现在不需要提前学习什么

开营前不要求模型训练或算法基础，不要求先学完提示词工程、LangGraph、向量数据库，也不要求部署评估和观测平台。相关机制会在当周课程中结合沙盘任务讲解。

出现环境问题时留下什么

向助教提供操作系统、运行时版本、产品版本、执行命令、已经尝试的处理方式，以及遮挡密钥后的错误信息。只写“运行不了”，无法区分安装、网络、模型协议和产品行为问题。

完成基础检查后，等待正式包，按 README 执行安装、自检、模型验证和作业验收。正式包的版本与验证记录是运行要求的事实源。
