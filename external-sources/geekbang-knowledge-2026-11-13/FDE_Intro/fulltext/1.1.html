大家好，我是曹犟，神策数据的联合创始人与 CTO。在 TO B 软件这个行业，我做了十一年的研发与交付管理，更早之前，在百度做了七年大数据研发。最近一年，我自己也带着一个三人小团队，用 FDE 的方式驻场服务客户，同时在极客时间开设了《FDE 业务落地实战》专栏，讨论怎么在中国把 AI 真正交付出去。

开营前，先完成这四件事

它主要解决四个问题：先理解 FDE 是什么，遇到常用术语时不被卡住，知道自己目前的能力起点，同时把 W1 需要的本地环境准备好。

第一件事：读完四篇基础材料

“FDE 基础认知”一共四篇，是为对 FDE 这个方向感兴趣的朋友准备的公开材料，内容改编自我的专栏和我自己公众号上已发表的相关文章。四篇的顺序，就是我建议的阅读顺序：

  1. 什么是 FDE：先把这个最基础、也最容易被误解的概念说清楚，包括它的出身，以及怎么分辨真假 FDE。
  2. 为什么是现在：把工程师派到客户现场并不新鲜，为什么偏偏这两年 FDE 的价值明显提高了？
  3. 中国机会与争议：FDE 在国内会不会水土不服？六个现实问题都有依据，但 AI 也带来了新的解决条件。
  4. 就业市场与岗位画像：FDE 需要什么能力，面试考什么，谁适合做，以及什么时候不建议做。

这四篇能帮你建立对 FDE 的基本认知。至于怎么进场摸清客户的真问题、怎么把 demo 变成生产系统、怎么把现场经验沉淀回产品，这些实战层面的内容，我在专栏和训练营里会一步一步展开。

上述文章内容所有观点只代表我个人的看法，有错漏之处不可避免，还请大家谅解。读完之后，至少需要能够回答下面四个问题：

  1. FDE 和售前、咨询、外包、驻场实施有什么区别？
  2. 为什么 AI 能力越来越强之后，企业反而更需要 FDE？
  3. FDE 在中国落地时，会遇到哪些特有的机会和约束？
  4. 如果考虑从事 FDE，应该怎样判断岗位，也应该怎样判断自己？

阅读时抓住一条主线

进入客户现场只是 FDE 工作的起点，交付一个可以运行的系统也还不是终点。一个完整的 FDE 闭环还需要做到两件事：对可以衡量的业务结果负责，把现场得到的认知沉淀回产品，让第二个、第三个客户更容易被服务。

后面的 12 周沙盘，会把这条主线拆成一组连续任务。你会代表一家已经拥有标准 Agent 产品的厂商，从一封说不清楚的立项邮件开始，逐步完成需求澄清、数据治理、本体建模、客户化开发、系统集成、生产上线、效果归因、验收复盘和资产沉淀。这个过程既要把标准产品适配进青禾优选，也要判断哪些现场问题应该留在客户层，哪些值得沉淀回产品。预习阶段先把完整链路看清楚，开营后再逐周把每一段做出来。

读完后记录四句话

不需要写长篇读后感，只要用自己的话补完下面四句话：

  1. 我理解的 FDE 是：________________________________
  2. FDE 和我最熟悉的相近岗位，最大的区别是：________________________________
  3. 我认为 FDE 在中国落地最现实的机会或约束是：________________________________
  4. 如果让我进入一个客户现场，我目前最需要补的能力是：________________________________

这四句话不提交，也不评分。W12 回看时，可以用它们检查自己对 FDE 的理解是否发生了变化。

第二件事：浏览术语表

《FDE 核心术语表》收录了课程里会反复出现的 2B 交付、数据与 AI 工程术语。术语表不需要背诵，开营前先浏览一遍，后面遇到不熟悉的词再回来查即可。

每个术语分成两层：第一层是相对正式的定义，第二层是它在这门课里的具体含义。两层都要看，因为很多术语在字面上不难，真正进入客户项目以后，边界却很容易混淆。

第三件事：完成第一次能力自评

打开《FDE 能力自评》，完成开营前评分，并为每一项写下一条具体证据。这里没有标准答案，也不用于证明自己已经达到某个岗位级别。它只记录现在的起点。

W12 结营时，我们使用同一份问题再评一次。前后两次分数本身并不重要，真正需要对照的是：过去只能凭感觉回答的问题，12 周以后是否已经有项目产出、代码、文档或客户沟通记录作为证据。

第四件事：准备本地环境

按照《环境准备指引》完成基础检查。训练营允许使用自己熟悉的后端语言和技术栈，但官方参考路径使用 Python；W1 就会提供独立的本地标签 Mock 服务，官方产品和配套工具需要 Python 运行时。

开营前不强制提前学习提示词工程、模型微调、向量数据库或某一种 Agent 框架。需要准备的是更基础的东西：一门后端语言、基本 SQL、大模型 API 调用、本地数据库与开发环境。

课程方会提供可运行的标准会员运营 Agent、SQLite、干净样例数据和通过 HTTP 调用的样例标签系统。默认路线是在这套产品上完成青禾优选的客户交付；也允许学员自行开发等价产品，使用相同的数据、API 和验收契约。两条路线都需要完成数据处理、业务语义、系统集成、权限、评估、生产扩展，以及针对实际模型和客户业态的 Agent 效果调优。

完成预习的判断标准

  • 已按顺序读完四篇基础材料

  • 知道在哪里查询课程术语

  • 已填写开营前能力评分，并为问题的评分留下证据

  • 已完成本地环境的基础检查

  • 已妥善保存大模型 API 密钥，没有把密钥写入代码或提交到代码仓库

完成这五项，就可以进入 W1。W1 会领取、安装并运行标准 Agent 产品底座和客户交付仓库，通过官方 checker 完成数据库、模型 API、工具注册接口和课程工具的环境自检，并对照产品能力矩阵形成首版 fit-gap 清单。此后每周都在同一个客户交付仓库里继续施工，按统一的产出物契约留下代码、文档和验收证据。
