安全工程团队（Security Engineering team）专注于软件开发生命周期、供应链和开发环境的安全保障。他们大量使用 Claude Code 来编写和调试代码。

Claude Code 的主要用例

复杂基础设施调试（Complex infrastructure debugging） —— 处理事故时，他们把堆栈跟踪（stack trace）和文档喂给 Claude Code，让它追踪控制流在代码库中的走向。这显著缩短了生产问题的解决时间，让他们能在约 5 分钟内弄清原本要花 10–15 分钟人工扫描代码才能理解的问题。

Terraform 代码评审与分析（Terraform code review and analysis） —— 对于需要安全审批的基础设施变更，他们把 Terraform 计划（plan）复制进 Claude Code，问它「what's this going to do? Am I going to regret this?」。这样反馈循环更紧，安全团队也更容易快速评审（review）和批准基础设施变更，减少了开发流程中的瓶颈。

文档综合与运维手册（Documentation synthesis and runbooks） —— 他们让 Claude Code 摄取多个文档来源，生成 Markdown 运维手册（runbook）、故障排查指南和概览。他们把这些浓缩后的文档当作调试真实问题时的上下文（context），形成了比翻遍完整知识库更高效的工作流（workflow）。

测试驱动开发工作流（Test-driven development workflow） —— 不再沿用以往「设计文档 → 蹩脚代码 → 重构 → 放弃测试」的模式，他们现在向 Claude Code 要伪代码（pseudocode），引导它走测试驱动开发（TDD）的路径，并定期查看进展、在它卡住时加以引导，从而得到更可靠、更可测试的代码。

上下文切换与项目上手（Context switching and project onboarding） —— 在给「dependant」（一个用于安全审批工作流的 Web 应用）这类现有项目做贡献时，他们用 Claude Code 编写、评审和执行以 Markdown 撰写、存放在代码库中的规格说明，从而能在几天内、而非几周，做出有意义的贡献。

团队影响

事故解决时间缩短（Reduced incident resolution time） —— 通常要花 10–15 分钟人工扫描代码的基础设施调试，现在只需约 5 分钟。

安全评审周期改善（Improved security review cycle） —— 用于安全审批的 Terraform 代码评审快了很多，消除了开发者等待安全团队审批期间的阻塞。

跨职能贡献增强（Enhanced cross-functional contribution） —— 团队成员几天内就能对项目做出有意义的贡献，而无需数周的上下文积累。

文档工作流改善（Better documentation workflow） —— 从多个来源综合出的故障排查指南和运维手册，带来了更高效的调试流程。

来自安全工程团队的首要建议

大量使用自定义斜杠命令（Use custom slash commands extensively） —— 安全工程团队使用了整个单一仓库（monorepo）中所有自定义斜杠命令（slash command）实现的 50%。这些自定义命令精简了特定工作流，加快了重复性任务。

让 Claude 先说（Let Claude talk first） —— 与其针对代码片段提出有针对性的问题，他们现在会告诉 Claude Code「commit your work as you go」，让它自主工作并定期查看进展，从而得到更全面的解决方案。

把它用于文档（Leverage it for documentation） —— 除了编码，Claude Code 还擅长综合文档、生成结构化输出。他们提供写作样本和格式偏好，从而拿到能立即用于 Slack、Google Docs 和其他工具的文档，避免在界面之间来回切换的疲劳。
