引言

Anthropic 各团队使用 Claude Code 的场景，从排查生产环境问题、在陌生代码库中导航，一直到构建自定义自动化工具。下面就是他们的做法。

像 Claude Code 这样的智能体编程（agentic coding）工具，帮助开发者加速工作流（workflow）、自动化重复性任务，并攻克复杂的编程项目。随着这个领域不断演进，我们每天都能从用户——包括我们自己的员工——那里了解到新的应用方式。

为了进一步了解，我们与 Anthropic 各部门的员工坐下来聊了聊，了解他们在工作中如何使用 Claude Code。

他们的许多用例都在意料之中——调试、在代码库中导航、管理工作流；另一些则出乎我们的意料：律师搭建了电话树（phone tree）系统；营销人员在几秒钟内生成了数百条广告变体；数据科学家在不懂 JavaScript 的情况下做出了复杂的可视化。

一个规律变得清晰：智能体编程不只是在给传统开发提速。它正在消解技术性工作与非技术性工作之间的边界，把任何一个能够描述问题的人，变成能够构建解决方案的人。

以下是我们学到的。

代码库导航与理解

公司各团队都用 Claude Code 帮助新员工、乃至入职多年的员工快速熟悉我们的代码库。

我们基础设施团队（Infrastructure team）新来的数据科学家会把整个代码库喂给 Claude Code，以便尽快进入高效工作状态。Claude 会读取代码库中的各个 CLAUDE.md 文件，找出其中相关的文件，解释数据管道之间的依赖关系，并展示哪些上游数据源汇入哪些仪表盘，从而取代了传统的数据目录工具。

我们的产品研发团队（Product Engineering team）把 Claude Code 称作任何编程任务的「第一站」。他们让 Claude Code 找出：要修缺陷、做功能还是做分析，应该查看哪些文件——从而免去了在构建新功能之前手动收集上下文（context）的耗时过程。

测试与代码评审（review）

智能体编程工具之所以特别受青睐，在于它们能把两项关键却繁琐的编程任务自动化：编写单元测试和评审（review）代码。

产品设计团队（Product Design team）用 Claude Code 为新功能编写全面的测试。他们通过 GitHub Actions 把拉取请求（Pull Request）评论自动化了，由 Claude 自动处理格式问题和测试用例重构。

安全工程团队（Security Engineering team）把他们的工作流从「设计文档 → 蹩脚代码 → 重构 → 放弃测试」，转变为：让 Claude 给出伪代码（pseudocode），引导它按测试驱动开发（test-driven development）的路径推进，并定期查看进展。这样产出的代码更可靠、更可测试。

智能体编程还可以用来把测试翻译成其他编程语言。比如，推理团队（Inference team）需要用 Rust 这样自己不熟悉的语言测试功能时，他们说明想测什么，Claude 就会用代码库本身的语言把相应逻辑写出来。

调试与故障排查

生产环境问题要求尽快解决，但在压力下去推理一段陌生的代码，往往只会造成延误。对公司的许多团队来说，Claude Code 通过实时分析堆栈跟踪（stack trace）、文档和系统行为，加快了诊断和修复。

事故期间，安全工程团队把堆栈跟踪和文档喂给 Claude Code，追踪控制流在整个代码库中的走向。过去通常要花 10–15 分钟手动翻查的问题，现在的解决速度是原来的 3 倍。

有了 Claude Code，产品研发团队有了攻克陌生代码库缺陷的信心。他们会这样问 Claude：「Can you fix this bug? This is the behavior I'm seeing」，然后评审它给出的解决方案，不需要再依赖其他工程团队来帮忙。

有一个案例：Kubernetes 集群不再调度 Pod 时，数据基础设施团队（Data Infrastructure team）用 Claude Code 诊断问题。他们把仪表盘截图喂给它，Claude 带着他们在 Google Cloud 的界面里一个菜单一个菜单地排查，直到发现原因是 Pod IP 地址耗尽。随后 Claude 给出了创建新 IP 地址池并把它加入集群的确切命令，在系统宕机期间为他们省下了宝贵的 20 分钟。

原型开发与功能开发

按传统方式构建新功能，需要深厚的技术知识和大量的时间投入。Claude Code 支持快速做原型、甚至开发出完整应用，让团队无论编程水平如何，都能快速验证想法。

产品设计团队的成员会把 Figma 设计文件喂给 Claude Code，然后设置好自主循环（autonomous loop）：由 Claude Code 为新功能编写代码、运行测试、持续迭代。他们给 Claude 抛出抽象的问题，让它自主工作，然后在最终打磨之前评审它给出的方案。有一个案例，他们让 Claude 为自己构建了 Vim 键位绑定，只需极少的人工评审。

借由 Claude Code，产品设计团队发现了一种出乎意料的用法：把错误状态、逻辑流程和系统状态逐一梳理出来，在设计阶段就找出边界情况（edge case），而不是等到开发阶段才发现。这从根本上提升了他们初始设计的质量，也省去了之后数小时的调试。

数据科学家虽然并不精通 TypeScript，却用 Claude Code 构建出完整的 React 应用来可视化强化学习（RL）模型的性能。在沙箱（sandbox）环境里做过一次性提示（one-shot prompting）之后，这个工具就能从零写出整段 TypeScript 可视化代码，而他们自己完全不需要看懂这些代码。鉴于任务足够简单，如果第一条提示词（prompt）不够理想，他们就稍作调整再试一次。

文档与知识管理

技术文档常常散落在 wiki、代码注释和团队成员的脑子里。Claude Code 通过模型上下文协议（MCP）和 CLAUDE.md 文件把这些知识整合成便于取用的形式，让每个需要的人都能获得这些专长。

推理团队里没有机器学习（ML）背景的成员，靠 Claude 来解释模型特有的函数。过去通常要花一个小时的 Google 搜索，现在只要 10–20 分钟——研究时间减少了 80%。

安全工程团队让 Claude 摄取多份文档来源，生成 Markdown 运维手册（runbook）和故障排查指南。这些浓缩后的文档，成为调试真实生产问题时的上下文，往往比翻遍完整知识库更高效。

自动化与工作流优化

智能体编程工具帮助团队构建自定义自动化——这类工作放在过去，需要专门的开发者资源或昂贵的软件。

增长营销团队（Growth Marketing team）构建了一个智能体工作流（agentic workflow），用来处理装着数百条广告的 CSV 文件、找出表现不佳的广告，并在严格的字符数限制内生成新的变体。借助两个专门化的子智能体（subagent），这套系统几分钟就能生成数百条新广告，而不是几个小时。

他们还开发了一个 Figma 插件，可以识别画框（frame），并通过更换标题和描述，以程序化方式生成最多 100 条广告变体，把过去数小时的复制粘贴压缩到每批广告半秒钟。

在一个相当独特的用例里，法务团队（Legal team）搭建了「电话树」系统的原型，帮团队成员在 Anthropic 联系上对口的律师——这也展示了各部门如何在不依赖传统开发资源的情况下构建自定义工具。

用 Claude Code 解锁新的可能

这些故事揭示出一个共同的规律：当你聚焦于 Claude Code 能够增强的人类工作流时，它的表现最好。最成功的团队把 Claude Code 当作思考伙伴（thought partner），而不是代码生成器。

他们探索各种可能性、快速做原型，并在技术用户与非技术用户之间分享各自的发现。这种人机协作的方式，正在创造出我们才刚刚开始理解的机会。
