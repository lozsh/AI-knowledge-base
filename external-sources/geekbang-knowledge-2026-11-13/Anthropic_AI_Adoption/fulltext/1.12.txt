法务团队（Legal team）通过实验、以及出于了解 Anthropic 产品体系的愿望，发现了 Claude Code 的潜力。此外，一位团队成员还有一个个人用例：为家人打造无障碍（accessibility）工具，以及制作能向非开发者展示该技术威力的工作原型。

Claude Code 的主要用例

为家人定制的无障碍方案（Custom accessibility solution for family members） —— 团队成员为因医学诊断而说话困难的家人构建了沟通助手。仅用一个小时，他们就创建了一个预测文本（predictive text）应用：借助原生语音转文字（speech-to-text），给出建议回复，并用语音库（voice bank）把回复说出来，弥补了言语治疗师推荐的现有无障碍工具中的缺口。

法务部门工作流自动化（Legal department workflow automation） —— 他们创建了「电话树（phone tree）」原型系统，帮助团队成员联系上 Anthropic 内部合适的律师，展示了法务部门如何在没有传统开发资源的情况下，为常见任务构建定制工具。

团队协调工具（Team coordination tools） —— 管理者构建了 G Suite 应用，用来自动化每周团队更新，并跟踪各产品的法务评审（review）状态，让律师能通过简单的按钮点击快速标记需要评审的事项，而不必靠电子表格管理。

用于验证方案的快速原型（Rapid prototyping for solution validation） —— 他们用 Claude Code 快速构建可运行的原型，展示给领域专家（比如把无障碍工具展示给 UCSF 的专家），以便在投入更多时间之前验证想法、找出已有方案。

工作方式与影响

在 Claude.ai 中规划，在 Claude Code 中构建（Planning in Claude.ai, building in Claude Code） —— 他们采用两步流程：先在 Claude.ai 中头脑风暴和规划，再转到 Claude Code 实施，让它慢下来、一步一步地做，而不是一次性输出所有内容。

视觉优先的方法（Visual-first approach） —— 他们经常用截图向 Claude Code 展示想要的界面样子，然后基于视觉反馈迭代，而不是用文字描述功能。

原型驱动的创新（Prototype-driven innovation） —— 他们强调要克服分享「傻」或「玩具」原型的恐惧，因为这些演示能启发他人看到他们未曾考虑过的可能性。

安全与合规意识

MCP 集成方面的顾虑（MCP integration concerns） —— 作为产品律师（product lawyer），他们会立即识别出模型上下文协议（MCP）深度集成的安全影响，并指出随着 AI 工具访问更多敏感系统，保守的安全姿态（security posture）将形成障碍。

合规工具建设的优先事项（Compliance tooling priorities） —— 他们主张随着 AI 能力的扩展，快速构建合规工具，并认识到创新与风险管理之间的平衡。

法务部门的首要建议

先在 Claude.ai 中充分规划（Plan extensively in Claude.ai first） —— 在转到 Claude Code 之前，用 Claude 的对话式界面把你的整个想法充实起来。然后让 Claude 把一切总结成一个分步的提示词（prompt），用于实施。

逐步、可视化地工作（Work incrementally and visually） —— 让 Claude Code 慢下来，一次只实现一步，这样你复制粘贴时就不会不知所措。大量使用截图来展示你想要的界面样子。

不完美也要分享原型（Share prototypes despite imperfection） —— 克服把「玩具」项目或未完成工作藏起来的冲动——分享原型能帮助他人看到可能性，并在通常不互动的部门之间激发创新。
