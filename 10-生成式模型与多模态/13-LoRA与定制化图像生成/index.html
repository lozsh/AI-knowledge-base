    定制化图像生成：Textual Inversion、DreamBooth 与 LoRA¶

    /> 来源：公开课程资料自学整理（整理于 2026-11-03）

    一句话概括：让模型学会"指定的人/物/风格"有三条路——只学一个词向量（Textual Inversion）、全模型微调（DreamBooth）、冻结原模型学低秩增量（LoRA），LoRA 因插件化胜出。

    核心概念¶

    定制化 = 控制确定的内容¶

    普通 prompt 生成像开盲盒；定制化生成的目标是：控制"指定的某个人在某个地方做某件事"、"生成确定的某种风格"。LensaAI、妙鸭相机都是这类技术的产品化。

    三种方案一句话对比¶

    方案 学什么 参数量 效果
    Textual Inversion 一个新词的词嵌入向量 几百个浮点数（512/768 维） 弱，常不理想
    DreamBooth 整个绘画模型（UNet 乃至 CLIP） 与原模型相当 最好，但易过拟合、伤本体
    LoRA 原权重矩阵的低秩分解 A·B 原模型的千分之一量级（<200M） 接近 DreamBooth，插件化

    关键方法/原理¶

    Textual Inversion：学一个新词¶

    • 回顾 SD 的文本链路：prompt → tokenizer 分词得 token_id → 查词嵌入库取向量 → 拼接送 CLIP 文本编码器 → 交叉注意力注入。
    • 做法：新造一个符号 S，绑定新 token_id（如词表 2 万则编号 20001），冻结 CLIP 文本编码器和 UNet 全部权重，只训练这个词嵌入向量*。用 3~5 张目标图片按标准扩散训练流程学。
    • 优点：不影响基础模型、产物极小；缺点：可学习参数太少，表达力不足，生成效果常不理想。
    • 注意：学出的词向量与训练用的基础模型绑定，换基础模型不通用。

    DreamBooth：全模型微调¶

    • 不新增词向量，选一个罕见词（如 "CSS"）作关键词，打开 UNet 权重（CLIP 文本编码器也可打开，实测效果更好），用 3~5 张图微调整个模型。
    • 过拟合问题：只用几张图优化亿级参数，模型会把 "a CSS dog" 和 "a dog" 都画成训练用的那只狗——泛化能力被摧毁。
    • 解药：保留损失（preservation loss）——先用原模型自行生成一批同类图片（如普通狗），混入训练，强迫模型保住"狗"的一般概念，只把罕见词对准新主体。
    • 优点：定制效果最好；缺点：模型权重大（与原模型同级）、影响基础模型能力、需要防过拟合。

    LoRA：低秩适配，插件化之王¶

    • 数学基础：大权重矩阵 W（d×d，秩 r）可分解为两个小矩阵 A（d×r）与 B（r×d）的乘积。秩 = 矩阵提供的信息量/描述的空间维度，r 远小于 d。
    • 做法：W 冻结不动，只训练 A 和 B；使用时权重为 W + AB。
    • 体量对比：d=10000、r=100 时，原权重 100M 参数，AB 只要 1M——这就是基础模型 3~4GB 而 LoRA 文件最大不过 200M 的原因。
    • 出身：LoRA 原为大语言模型设计（Low-Rank Adaptation）。论文中 GPT-3（175B 参数）只训 37.7M 的 LoRA（约万分之二），指标全面超过全量微调。
    • 用于 AI 绘画的四大好处：
    • 插件化：基础模型不动，LoRA 可随时添加、删除、替换、组合（多个 LoRA 叠加）；
    • 训练参数少，效率高，消费级硬件也能训；
    • 可直接合并进原模型，推理速度零损耗；
    • 存储省：妙鸭类产品存用户 LoRA 而非整个 SD 模型。
    • 训练实践：即用 LoRA 方式微调 CLIP 文本编码器与 UNet 的权重（DreamBooth 训练法 + LoRA 参数化），配一个触发词。使用时 <lora:文件名:权重> 加进 prompt，权重 0~1。

    训练扩散/微调模型的通用配方（以自定义扩散模型为例）¶

    • 全量训练扩散模型：与 SD 训练一致（抽样图 → 随机 t → 加噪 → UNet 预测 → L2 损失）；
    • 微调：以预训练 SD 为底，小学习率、少量 epoch，在自有小数据集上继续；LoRA 版只放开 A/B 矩阵。

    经验与常见坑¶

    • 选型口诀：试风格快速验证用 Textual Inversion；追求极致单人/单物还原用 DreamBooth；绝大多数场景（IP 定制、风格包、产品化）用 LoRA。
    • DreamBooth 不加保留损失 = 模型废掉（什么 prompt 都画同一个主体）。
    • LoRA 权重不宜拉满：<lora:x:1> 常见，但画面崩时先降权重（0.6~0.8）再排查。
    • 多个 LoRA 叠加时注意风格冲突；多人物定制（甲乙丙丁）是难题：链式 DreamBooth 会画质/画风劣化，多 LoRA 同载可能人脸不一致——工程上倾向一人一 LoRA、推理时组合。
    • LoRA 与基础模型绑定：A/B 矩阵维度对应原模型结构，跨架构（SD1.5 的 LoRA 用在 SDXL 上）不可直接用。
    • Textual Inversion / DreamBooth 的关键词要选语料中罕见的词，避免与已有语义打架。

    术语表¶

    术语 含义
    定制化图像生成 控制"指定主体/风格"的生成任务，区别于开放式文生图
    词嵌入（embedding） token_id 到向量库的映射；Textual Inversion 直接学这个向量
    保留损失 DreamBooth 用原模型自生成图片混入训练，抑制过拟合
    LoRA 低秩适配：冻结 W，训练分解矩阵 A、B，用 W+AB
    秩（rank） 矩阵的信息量/线性空间维度，LoRA 的 r 即目标秩
    触发词 训练时绑定的罕见关键词，推理时用它唤起定制内容
    safetensors 社区主流模型权重文件格式（基础模型与 LoRA 均常用）
    Civitai / Hugging Face AI 绘画模型与 LoRA 的两大开源社区

    ⚠️ 时效性说明¶

    • 三种方案（2022-2023）至今仍是微调范式的基本盘；此后出现 LoRA 变体（LoCon、LoHa、LyCORIS）、DOM、以及文本编码器全量微调等增强，但"冻结大模型 + 训练小增量"思想一脉相承。
    • SDXL 及更新架构上训练 LoRA 的超参、显存需求与 SD1.5 不同；DiT 类模型（Flux 等）的 LoRA 生态在快速演进中。
    • 妙鸭相机类产品（2023 爆款）的火爆具有周期性，但其"LoRA 存档用户模型"的工程方案仍是头像定制类产品的参考模板。
