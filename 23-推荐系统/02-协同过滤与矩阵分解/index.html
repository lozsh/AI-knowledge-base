    协同过滤与矩阵分解

    更新于 2026-11-05

    一句话概括：协同过滤靠"大家一起帮你过滤"——用共现矩阵找相似用户/相似物品来推荐；矩阵分解把共现矩阵分解为用户/物品隐向量增强泛化，是后续一切 Embedding 类模型的源头。

    核心概念

    • 协同过滤（CF）：协同大家的反馈、评价和意见，对海量信息进行过滤，筛出用户可能感兴趣的内容。完全依赖用户-物品行为关系，不依赖内容特征。
    • 共现矩阵：用户×物品的稀疏矩阵，元素为评分或行为（0/1、-1/1、时长、次数等）。它是协同过滤的"命根子"，推荐问题即预测矩阵空白处的值。
    • 两大类别：
    • 基于记忆（Memory-Based / 邻域方法）：直接用共现矩阵算相似度。
      • UserCF（基于用户）："人以群分"——先找口味相似的用户，把相似用户喜欢而目标用户未消费的物品推荐给他。本质是给用户按兴趣聚类。
      • ItemCF（基于物品）："物以类聚"——先算物品相似度，把用户消费过的物品的相似物品推荐给他（"看了又看""买了又买"，1998 年亚马逊提出）。
    • 基于模型（Model-Based）：从矩阵中学习模型来填空白，代表是矩阵分解（隐语义模型 LFM）。
    • 矩阵分解（MF）：把 m×n 的共现矩阵 A 近似分解为用户矩阵 U(m×k) 和物品矩阵 V(n×k) 的乘积（k 远小于 m、n，常小两个数量级），每个用户/物品得到 k 维隐因子向量，预测分数 = 两向量点积。本质就是一种 Embedding 方法。
    • NetFlix Prize（2006）：悬赏百万美元征求 RMSE 降低 10% 的评分预测算法，催生了 SVD 系列矩阵分解模型，是推荐算法研究的分水岭。

    简单模型三件套与 CTR 平滑

    在协同过滤之前与之外，还有三代简单模型，至今仍是冷启动兜底与基线工具：

    • 流行度推荐（Popularity-based）：什么火推什么；非个性化；隐含假设"质量与流行度正相关"（仅是假设）。关键：不要用绝对计数，用比值/概率（CTR、CVR）。CTR 估计 = 伯努利参数估计：
    • MLE（点击数/展示数）的坑：分子分母为零时失效（新物品、零点击）；
    • 贝叶斯平滑：Beta 先验 → Beta 后验（共轭），(先验点击+实际点击)/(先验展示+实际展示)，永不为零——是广告/推荐 CTR 估计的标配思想；
    • 时间折扣：上一时段数据 × 折扣系数作为下一时段先验，对抗流行度的时效性。
    • 两个数据污染源：时间偏差（时段流量规律）与位置偏差（排名靠前天然多点击）；工程解：留一部分随机展示流量收集无偏数据（epsilon-greedy 思想）。
    • 基于内容（Content-based）：用特征表示用户/物品/交互，把推荐转化为监督学习。两大工作 = 特征工程 + 目标函数设计。物品特征：文本（TF-IDF→话题模型→词嵌入降维）、类别/知识（缺失时用分类器补、知识图谱扩展）、图像等稠密向量；用户特征：人口属性基本项 + 隐反馈画像。目标函数：评分拟合已被公认不是真实目标，实际系统用 CTR/CVR/停留时长。
    • 协同过滤（上文）与这两者构成三代演进：流行度（非个性化）→ 内容（单用户特征）→ 协同（群体行为）。

    核心原理

    UserCF 三步

    1. 准备用户向量：维度=物品数，稀疏，取值可为布尔或评分；
    2. 两两计算用户相似度，按阈值或 TopK 保留最相似用户；
    3. 推荐分数 = 相似用户对物品态度的相似度加权平均：R(u,i) = Σ sim(u,s)·R(s,i) / Σ sim(u,s)，去掉已消费物品后排序输出。
    4. 产出两样：相似用户列表（可推荐"相似粉丝"）+ 推荐结果。适合注重隐私口味、不受大 V 影响的场景。

    ItemCF

    • 物品向量的维度是用户（该物品被哪些用户以何种程度消费过），同样稀疏。物品数一般少于用户数，相似度计算不成为瓶颈；物品相似度比用户口味更静态，天然解耦兴趣迁移问题；物品的消费者多于用户共同行为，稀疏度更好。
    • 两种输出：
    • TopK"猜你喜欢"：对用户消费过的物品，汇总其相似物品的加权分数 R̂(u,i) = Σ sim(i,j)·R(u,j) / Σ sim(i,j)，离线算好存储；
    • 相关推荐："看了又看"，实时取当前物品的相似物品列表，无需预合并。
    • 改进：物品中心化（减物品评分均值，抑制铁杆粉丝刷分）、用户中心化（减用户均值，消除个人宽严标准差异）、惩罚热门物品、时间衰减。
    • Slope One：针对评分矩阵的 ItemCF 改良——不算相似度而是算物品两两平均分差（带共同评分用户数作为置信度），预测时按共同用户数加权平均；中间统计量可增量维护，支持在线更新。

    相似度计算方法选型

    方法 公式要点 取值范围 适用数据 特点/坑
    余弦相似度 点积 / 长度积 0~1 评分、文本均可 与向量长度无关，只看方向；对绝对值不敏感（1分2分 vs 4分5分会判为高度相似）
    调整余弦（修正余弦） 各维减去均值后再算余弦 -1~1 评分 消除评分基准差异；ItemCF 中减物品均值
    皮尔逊相关度 各自减向量均值（向量中心化）后算余弦 -1~1 评分类连续值 度量"同增同减"趋势；不适合布尔向量
    欧氏距离 坐标差平方和开方 转换 1/(1+d) 后 0~1 实数向量 度量绝对差异，适合能力模型（消费力等）；不适合布尔向量
    Jaccard 交集/并集 0~1 布尔向量（隐式反馈） 专为 0/1 行为数据设计
    - 底层假设：相似（距离近）的物体容易产生相同行为。
    - 工程优化：大向量用采样计算（Twitter DIMSUM，已入 Spark）或向量化运算；用户量大的两两相似度拆 MapReduce；数据量百万内且稀疏时单机库（KGraph、GraphCHI）反而更快。

    矩阵分解（SVD 家族）

    • 推荐里的"SVD"并非严格奇异值分解，而是 Koren 等人在 Netflix Prize 中的矩阵分解模型。学习即机器学习套路：损失函数 = \(\sum_{(u,i)} \left(r_{ui} - p_u \cdot q_i^\top\right)^2 + \lambda\left(\lVert q_i \rVert^2 + \lVert p_u \rVert^2\right)\)（\(r_{ui}\) 为用户 \(u\) 对物品 \(i\) 的评分，\(p_u\)、\(q_i\) 为用户/物品隐向量，\(\lambda\) 为 L2 正则系数），SGD/ALS 优化。
    • 逐级增强的四个版本：
    • 基础 SVD：\(p_u \cdot q_i^\top\)（用户与物品隐向量的内积）；
    • +偏置：μ + b_i + b_u + p_u·q_iᵀ（全局均值、物品偏置、用户偏置）——有的用户手松、有的物品粉丝打分虚高；
    • SVD++：再叠加隐式反馈物品向量和用户属性向量（|N(u)|^-0.5 Σ x_i + Σ y_a）——解决沉默大多数没有评分的问题，缓解冷启动；
    • time-SVD：引入时间因素（评分按时间加权、分时间区间学习隐向量、节日/周末单独建模）。
    • 处理隐式反馈：把行为次数/时长当数值或走隐式损失（ALS-WR 等）；注意行为数据没有显式负样本，需负采样。
    • 隐因子 k 的选择是超参数，无标签不可解释，但表达力强；MF 的输出可直接当用户/物品 Embedding 用（存 Redis、近邻检索、线上服务全套照搬）。

    矩阵分解的三个坑与两个扩展

    • 偏置项比个性化更重要：乐观用户普遍高分、热门物品普遍高分，大量方差来自与偏好无关的 bias，必须分解为 bias + 个性化两部分分别建模（上文 SVD+偏置版本正为此设计）。先建好偏置再谈个性化。
    • 其余坑：未观测元素是"未知"不是 0；点积目标非凸，梯度下降只得局部解；隐空间不可解释；只有正样本缺负样本（催生 BPR 等隐式反馈模型）。
    • 基于回归的矩阵分解：MF 只能从交互学隐向量 → 新用户/新物品拿不到隐向量（冷启动灾难）。解法：显式特性（年龄/性别/品类等）经回归函数生成隐向量的先验均值（贝叶斯视角：隐向量是以回归输出为均值的高斯）。训练用层次贝叶斯/EM，复杂且只得局部解 → 工业界很少直接用；思想被深度模型的特征侧输入（Wide&Deep 等）彻底吸收。
    • 分解机（FM，Rendle）：加两两特征交叉捕捉"年龄段 × 品类"类交互；但 one-hot 交叉后特征空间爆炸、极度稀疏。解法：每个特征配一个隐向量，交叉权重 = 两隐向量点积（对稀疏交叉矩阵做低秩分解）。关键性质：特征只有用户 ID + 物品 ID 时 FM 退化为矩阵分解——MF 是 FM 特例。训练 SGD 直接解，远比回归式 MF 简单；冷启动好于 MF（有全局特征即可推断）。演化路线 FM→FFM→DeepFM/xDeepFM，交叉权重低秩分解思想活在所有 CTR 深度模型里。
    • 2026 视角：MF 被吸收为深度表征学习的一部分（双塔、LightGCN、SASRec），但"embedding 点积做匹配"范式保留至今。

    隐式反馈与无偏估计

    行为数据（点击/停留）没有显式负样本，需要负采样或隐式损失（ALS-WR 等）。更深层的问题是反馈回路的偏差：系统只展示 A 类 → 用户永远无法表达对 B 类的喜好（缺失非随机）→ 模型只推 A → 偏差随 ML 循环放大——这是线下指标与线上表现不一致的根源。

    矫正：逆倾向加权（IPS）——按展示概率反比给正样本加权，低曝光物品上的点击权重更大，得无偏 CTR 估计。前提假设是每个物品展示概率非零——现实中难满足（为无偏而展示低质内容伤体验），与探索机制的随机小流量天然交汇。一个反直觉的研究结论（Cañamares & Castells 2018）：只有在完全无偏差的世界里，按流行度排序才是最优的；考虑曝光偏差后，流行度排序比随机排序好不了多少，平均分排序反而更优。IPS/去偏差推荐/因果推断（doubly robust、反事实 LTR 等）已发展为独立研究方向。

    NeuralCF 与双塔模型（深度学习改造 CF）

    • 洞察：把 MF 神经网络化——One-hot 输入 → Embedding 层（即用户/物品隐向量）→ 内积输出。薄弱环节：Embedding 之上只做内积，特征未充分交叉就输出，欠拟合。
    • NeuralCF（2017，NUS）：用多层神经网络替换内积层，让用户/物品隐向量充分交叉，拟合能力大增。
    • 双塔模型：NeuralCF 蕴含的一般化结构——用户侧模型（塔）+ 物品侧模型（塔）+ 互操作层（点积或 MLP）。塔内可以是 Embedding 层也可以是复杂网络；两侧可各自纳入丰富特征（YouTube 召回双塔：用户侧放正在看的视频/频道、观看数、历史观看 ID；物品侧放候选视频/频道、播放、点赞）。
    • 双塔最大优势：易上线、易服务——两塔顶输出即用户/物品 Embedding，可预存特征数据库，线上只做点积或浅层运算；是 YouTube、Facebook、百度等召回层标配。
    • 双塔局限：场景特征（时间、地点等强波动变量）不能简单塞进某一塔——否则 Embedding 无法预存、组合爆炸；需变体（如三塔）或线上实时推断。双塔对时效性强的内容（新闻）也不友好。

    经验与常见坑

    • 近邻方法的两个固有缺陷：物品间有相关性，信息量不随维度线性增加；矩阵太稀疏导致近邻结果不稳定，增减一个维度结果差异可能很大——这正是矩阵分解的动机。
    • UserCF 的痛点：用户量大时两两相似度计算成为瓶颈；用户兴趣变化快，相似度难以及时反映；用户间共同行为少且集中在热门物品。工业界更多用 ItemCF。
    • 余弦相似度"只看方向不看强弱"，对评分苛刻/宽松的用户会误判——需要中心化（调整余弦/皮尔逊）来救。
    • 两个只被同一个用户消费过的物品，余弦相似度为 1，但置信度极低；Slope One 用共同用户数加权即为此设计。相似度矩阵宜设阈值和 TopK 截断。
    • 给行为数据人为打分（点击 3 分、收藏 5 分）再套评分损失，效果常常不好——行为数据缺负样本，应改用隐式反馈模型或负采样。
    • 中小规模（用户/物品百万级以内）优先充分挖探单机性能，别急着上 Spark；矩阵分解几千万用户规模单机可行。
    • 评分预测是小众问题（评分数据难收集、易伪造、分布不稳定），行为预测（CTR）才是工业主流；别把 Netflix Prize 的 RMSE 思路照搬到隐式反馈场景。
    • 冷启动：CF/MF 对新用户新物品无能为力（无行为即无向量），需画像、内容特征或探索机制补位。

    ⚠️ 时效性说明

    • Netflix Prize 系（SVD/SVD++）主要服务评分预测场景，工业界现行排序已是深度 CTR 模型；但 MF 的隐向量思想是所有 Embedding 方法的直系祖先，作为概念必须掌握。
    • 有资料把 ItemCF 称为"基于内容的协同过滤"是不严谨表述：ItemCF 是基于物品共现行为的协同过滤，与"基于内容（Content-Based）推荐"（用内容属性算相似）是两个不同门派，勿混淆。
    • 有资料称 ALS 的 Spark 实现即 MF 标配；新版本 Spark MLlib 中 ALS 仍在，但分布式训练生态已向参数服务器/TensorFlow 等迁移。
