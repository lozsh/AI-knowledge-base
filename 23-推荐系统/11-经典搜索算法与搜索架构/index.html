    经典搜索算法与搜索架构（信息检索精要）

    /> 来源：公开课程资料自学整理（更新于 2026-11-03）

    一句话概括：从 TF-IDF/BM25/语言模型三大无监督文本匹配算法，到排序学习三范式与 LambdaMART，再到多轮打分架构、倒排索引与评测体系——这是理解一切"查询→召回→排序→重排"系统的地基。

    核心概念

    1. 无监督文本匹配三件套（2000 年前的经典 IR）

    TF-IDF（词频-逆文档频率） - 背后是向量空间模型（Vector Space Model）：Query 和文档都表示成词汇表维度的向量，用余弦相似度/点积算相关度。 - TF 假设：词在文档中出现越多越相关；IDF 假设：出现在越多文档中的词越没信息量（"the""的"等），用文档频率 DF 的倒数（再取对数）惩罚。 - 经典变种（思想比公式更耐用）： - TF 取对数压缩：1 + log(TF)——词频与相关度非线性，超过阈值后增益递减； - TF 按文档长度标准化——长短文档不能直接比词频； - IDF 用 (N+1)/DF 再取对数；查询与文档向量归一化为单位向量（等价余弦相似度）。

    BM25（Okapi BM25，"最佳匹配"） - 工业实践最重要的非监督排序基线，是概率相关模型（Probabilistic Relevance Model）的逼近，本质是迭代理出的经验公式。 - 三部分乘积求和：① 词与文档的相关度（非线性饱和的 TF + 文档长度/平均长度归一化，含 2 个可调超参数 k1、b 的前身）；② 词与查询的相关度（查询词频做类似标准化，经典版不做长度归一）；③ 词权重（IDF，或有监督的 RSJ 权重）。 - 核心洞察：词频对相关度的贡献有饱和上限——这一点被 TF-IDF 变种、语言模型平滑反复独立验证。 - 变种 BM25F：把标题/摘要/正文当多个"域"，各域当小文档算词频再加权合并。 - 工程上常把 BM25 与 PageRank 线性加权（早期网页搜索的标配组合）。

    语言模型（查询似然检索模型，Query Likelihood Retrieval） - 思想：每个文档是一个定义在词汇表上的概率分布（语言模型），Query 看作从该分布抽样出的样本；打分 = P(query|document)，取对数变乘为加。 - 参数估计：多项/类别分布 + 最大似然估计（MLE），解析解就是词频。 - 致命问题：未出现词概率为 0 → 平滑（Smoothing）不可或缺。最常用：文档频率与全集频率的加权平均（Jelinek-Mercer 式）、狄利克雷先验（Dirichlet）。代数变形后平滑项可写成类 TF-IDF 形式，平滑本身就削掉了流行词。 - 另一主流变种：Query 和文档各来自一个分布，用两分布的距离定义相关度（对称化）。

    2. 排序学习三范式（Learning to Rank，2000-2010 主旋律）

    范式 训练样本 建模目标 代表模型 问题
    单点法 Pointwise (query, doc) 对 单文档相关度（分类/回归） LR、SVM、GBDT 回归 目标错位：优化单点精度 ≠ 优化排序（NDCG）
    配对法 Pairwise (query, docA, docB) 两两偏序关系 RankSVM、RankNet、GBRank 两两关系全对也不能保证重构出全序（不一致性）；预测需算所有配对，复杂度高
    列表法 Listwise 整个排序列表 直接优化 NDCG 等列表指标 ListNet、ListMLE、AdaRank、LambdaMART（混合） 纯列表法复杂度高，工业收益有限
    • 配对法的三个隐含假设（都是坑）：①存在"完美排序"真值（电商场景常常不存在——同一 query 不同用户意图不同）；②学两两关系能重构全序（无保证）；③两两关系可用特征差值表示。
    • 列表法绕开"NDCG 非连续、非可微"的三条路：找连续可微的替代指标（SoftRank）；优化指标的上/下界（SVM-MAP）；设计允许不可微目标的优化算法（AdaRank）。

    3. 经典排序模型

    RankSVM：本质是 SVM，把样本换成文档对的特征差值，学习"差值→相对相关性"，线性、易解释，配对法代表。

    GBDT（梯度提升决策树） - 来源：Boosting（AdaBoost，关注降偏差）+ Friedman 的统计视角——AdaBoost 是加性模型上用类牛顿法优化指数损失。 - 核心机制：迭代地用一棵小决策树去拟合当前模型的残差/负梯度，再经线查找定步长叠加。梯度下降视角：每轮梯度≈一个弱学习器，学习率≈权重。 - 用于排序：配对法设定，拟合"两文档相关度差值"；雅虎 2007 年左右首次用于搜索，长期是商业搜索引擎主力模型。

    RankNet → LambdaRank → LambdaMART（微软 Burges 团队三部曲，Bing 核心算法） - RankNet：神经网络 + logistic loss 学两两偏序（ICML 2005，十年经典论文奖，深度学习大规模商用的早期案例）。 - 关键缺陷：不优化 NDCG。例：相关度 5 的文档在第 4 位、相关度 3 的在第 7 位时，RankNet 更愿意挪后者——但 NDCG 认为把高相关文档往前挪收益更大。 - LambdaRank 的洞察：梯度下降里目标函数只是推导梯度的手段——直接手工定义梯度。令两文档间的"损失梯度" = 两文档互换位置后 NDCG 的变化量（Λ 值），即可直接优化 NDCG，无需目标函数存在。 - LambdaMART：把 Lambda 梯度接入 GBDT 框架（树不再拟合普通梯度而是 Λ）。Yahoo! LTR 比赛冠军方案。树模型对排序问题异常有效，长期是工业标准配置。

    DSSM（深度结构化语义模型，CIKM 2013 微软） - 最早把深度学习用于搜索语义匹配的高引论文。革新点在"表达"：Query 和文档各自经过 word hashing（稀疏→稠密）+ 多层前馈网络（tanh 非线性），得到深层语义向量，用余弦距离匹配。 - 用点击数据构造正负例，建模为多类分类，端到端 SGD 训练。 - 意义：深度学习作为语义表示提取器取代人工特征，开创"双塔/语义向量检索"路线；当时绝对效果提升并不惊人（NDCG@10 约 0.5 vs TF-IDF 0.46），但方向影响深远。

    4. 链接分析（网页级质量信号）

    PageRank（1998，Brin & Page） - 定义：页面 I 的 PageRank = 所有输入链接按其输出链接数均分后传来的值之和（出链越多，每条分得越少）。 - 两处关键修正（缺一不收敛）： 1. 悬空结点（无出链的"黑洞"页）：视作可随机跳到全网任意页，把值均匀散出去； 2. 随机跳转机制：以 1-d 概率（d 通常 0.6~0.85）从任何页面随机跳到任意页面——整图变成完全联通图，保证唯一收敛解。 - 求解：矩阵形式 = 求随机矩阵主左特征向量，乘幂法（Power Method）迭代，少量轮次即收敛。 - 特点：查询无关（Query-Independent），可离线算好。

    HITS（1998，Kleinberg） - 每页两个值：权威值（被多少好枢纽指向）与枢纽值（指向多少好权威）——循环定义，迭代求解。 - 数学本质：邻接矩阵 L 上迭代 X=LᵀY、Y=LX，代数变形后归结为求 LᵀL / LLᵀ 的主特征向量——与 PageRank 殊途同归，都落入"图→矩阵→特征向量"框架，乘幂法同样适用。 - 与 PageRank 本质差异：HITS 是查询相关的（先按 query 取相邻子图再算），因此在线计算量大，工业落地远不如 PageRank；原始版本收敛但解不唯一，需加类 PageRank 的微概率联通处理。

    5. 搜索系统架构

    多轮打分（多阶段排序）——为什么和怎么做： - 不可能对全库（亿级文档）实时跑复杂模型（GBDT/NN 太贵，响应只有几百毫秒）→ 分层筛选： - 第一轮 Top-K 召回：在倒排索引上用简单模型（BM25、正系数线性模型如 WAND 操作符）从全库筛出几百~几千个； - 第二轮 重排：文档已入单机内存，才用得起配对法/列表法等复杂模型和更多特征； - 第三轮及以后：引入上下文特征、多样性、商业规则再精排（雅虎三轮打分）。 - 两条铁律：每轮候选数递减、每轮模型/特征复杂度递增。 - 结构性约束：第一轮跑在分片索引上、单机只见部分文档，只能做单点打分；配对/列表法只能上移到第二轮——两层模型效果差是架构决定的，需专门平衡。

    倒排索引 - 结构：字段（词）→ 包含该词的文档列表（存文档编号，非文档本身）；多词查询 = 多列表归并求交。 - 索引中常附带：词频 TF（支撑 BM25 等近似计算）、词位置（支持短语匹配"五道口电影院"、生成结果摘要）。 - 关键技术：压缩（差值编码 Delta Encoding——存相邻文档编号差值，代价是列表须按编号排序而非相关度排序）；跳过指针（Skipping——多词频率悬殊时，低频词驱动高频词列表跳跃前进）；查询策略分文档优先（Document-at-a-Time，优先队列保 Top-K）与词优先（Term-at-a-Time，逐词累加部分分）。 - 树模型至今难以直接下到索引层执行，第一轮仍是线性/简单模型的主场。

    6. 评测体系

    层级 方法 指标 特点
    线下·二元相关 静态测试集（Cleverdon 1955 起） Precision、Recall、F1（调和平均） 可反复复用、成本低；对排序位置不敏感，不是排序指标
    线下·多级相关 5 级相关度标注 DCG/nDCG（位置对数折扣 + 理想排序归一化） 至今仍是排序评测的标准指标；跨 query 可比
    线下比较两系统 多 query 平均 + 统计检验 配对 T 检验等 结论仅是统计意义的好坏，需批判看待
    线上 A/B 可控实验 CTR 等用户指标 建立因果联系的唯一完全可靠工具
    • nDCG 思想：整排序分 = 各位置相关度按 log(位置) 折扣加权和；除以理想排序 DCG 归一化。顶部位置损失远大于尾部。
    • 在线实验两大现实难点：①随机分流无法保证人群（性别/地域等已知变量，乃至未知变量）分布相当，需因果推断工具补刀；②多团队并行实验导致用户横跨多实验组，"唯一独立变量"难以保证。

    经验与常见坑

    • 词频与相关度是非线性饱和关系——三套经典算法独立得出同一结论；任何直接线性用原始词频的做法都值得怀疑。
    • 语言模型的平滑不是可选项；平滑本身承担了 ID F 式的流行词惩罚职责。
    • 排序学习的核心矛盾：训练目标（单点/两两）与评测目标（列表级 NDCG）天然错位；Lambda 系列的答案是"目标函数只是推导梯度的借口，直接定义梯度"。
    • 配对法预测阶段要对所有配对打分，非差值线性模型时复杂度爆炸。
    • 第一轮召回只能单点打分是索引分片架构决定的；两层模型效果差异要先从架构上理解。
    • 线下测试集把"用户"抽象掉了（假设相关度人人相同）；线下指标涨 ≠ 用户真实满意，最终裁决权在线上 A/B。
    • A/B 实验不是随机分完就完事：人群不均衡、多实验互相污染都会让因果结论失效。
    • HITS 查询相关的特性使它在线计算代价高，工业界几乎只用 PageRank 思路。

    ⚠️ 时效性说明

    • ⚠️ 深度学习演进（2015 后，专栏成文时正在发生）：语义匹配已从 DSSM 双塔演进到 Transformer 交叉编码、稠密检索（DPR 类）+ 近似最近邻索引（HNSW 等）取代部分倒排索引角色；第一轮召回也从 BM25 主导变成"倒排 + 向量检索"双路。
    • ⚠️ 排序模型：LambdaMART 之后工业界普遍转向深度排序模型（Wide&Deep、DIN 等），但 GBDT/LambdaMART 至今仍是中小规模数据和表格特征场景的强基线。
    • ⚠️ PageRank 原始网页级权重的地位已大幅下降：现代搜索靠行为数据（点击模型）与语义模型主导，链接分析更多用于反作弊和图表征学习。
    • ✅ 仍然耐用：TF-IDF/BM25 作为基线与特征、LTR 三范式的思想框架、多轮打分架构（现代粗排/精排/重排是其直系后代）、nDCG 评测、A/B 实验方法论。
